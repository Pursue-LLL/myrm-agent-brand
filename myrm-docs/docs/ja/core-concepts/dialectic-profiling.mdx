# 弁証プロファイリング（認知推論器）

Myrm は脆い正規表現による好み抽出をやめ、**非同期認知推論器**を使います。会話が終わると、バックグラウンドの LLM がそのやり取りを弁証的に推論し、構造化されたプロフィールを記憶へ書き込みます。

## 推論の次元

| 次元 | profile 記憶に保存される例 |
|------|------------------------------|
| **コミュニケーションスタイル** | 簡潔 vs 詳細、形式的 vs 気軽、言語の混用 |
| **意思決定の論理** | リスク許容度、多選択肢提示 vs 直接提案の偏好 |
| **暗黙の目標** | 進行中のプロジェクト、文脈から浮かび上がる未言明の優先順位 |

**証拠があるものだけ**を書き込みます。モデルが明示的なシグナルを引用できない場合、フィールドは空のまま残します（ハルシネーション防止）。

## ランタイムフロー

1. **抽出** — `MemoryExtractor` のプロンプトに弁証セクションが含まれ、根拠がある場合は `memory_type="profile"` で高信頼度として書き込みます。
2. **推論ループ** — `cognitive/deriver.py` が直近のメッセージに対して非同期に弁証推論を行い、ベクトルとグラフの証拠を更新します。
   - **Token 意識のスライディングウィンドウ**: LLM に渡す前に入力メッセージを約 16,000 文字以内に制限し、OOM を防ぎつつ予算も節約します。
   - **二重書き込みの段階的縮退**: GraphStore と SemanticMemory へ安全に二重書き込みし、グラフバックエンドが失敗または無効な場合は SemanticMemory へ优雅に縮退してデータを失いません。
3. **味の要約** — `compile_taste_summary` がアクティブな semantic / profile 行をまとめ、システムプロンプト向けの読みやすい要約へ統合します。
4. **注入** — `MemoryContextMiddleware` が毎ターン前に味の要約を注入します（Honcho 系が毎ターン `honcho_context` ツールを呼ぶのに対し、追加の往復はゼロ）。
5. **SSE ノイズ抑制** — UI は**、根を覆す**変更（矛盾・置換）のときだけ通知します。通常の好みは完全に静かにバックグラウンドで抽出されます。
6. **GUI** — `TasteSummaryCard` がタグを表示し、ユーザーは記憶コマンドセンター（Memory Labs、既定オフ）で推論された特徴を編集・削除できます。

## vs Honcho / Mem0 系の SaaS

| 面 | 一般的な記憶 SaaS | Myrm |
|----|---------------------|------|
| 好み抽出 | 観察 → 表徵のパイプライン | 会話後の **認知推論器**による LLM 弁証推論 |
| コンテキスト組み立て | 毎ターン Agent が記憶ツールを呼ぶ | **ミドルウェアが自動**注入 |
| 管理 | CLI のみが多い | **GUI** で閲覧・承認・監査・ロールバック |
| 「夢」で扱う長期目標 | 独立した高コストなパイプライン | **追加パイプライン不要** — 目標は味の要約の保守に統合 |
