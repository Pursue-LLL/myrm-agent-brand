# スキル発見とマーケットミラー

## 得られるもの

- **設定 → スキル → 発見**: 組み込みとコミュニティのスキルを検索し、ワンクリックでインストール。
- **スキルマーケットミラー**: **国際 (clawhub.ai)**、**中国 (讯飞 SkillHub)**、または **カスタム URL** を選べます。保存前に自動プローブし、到達できないレジストリは toast で知らせて**設定に書き込みません**。
- **インストール＝有効化**: 成功すると「インストール済み・有効化済み」と表示され、カタログの有効リストへ書き込まれます — 既定ではエージェントのスキル許可リストを触る必要はありません。

## なぜリポジトリを clone するだけでは足りないのか

マニフェストとリポジトリは「知っていること」を解決しますが、「使えること」を解決しません。Myrm はその間の工程を引き受けます。

- **入れる前に先に見ておく**: 3 層のセキュリティスキャン + 悪性パッケージと既知脆弱性のチェック。高危に命中したら拒否または隔離するので、ソースを読んで判断 yourself にする必要がありません。
- **依存が欠けていたら自分で直す**: ffmpeg / pandoc などの欠落を検出し、brew / apt / winget / uv の修復コマンドを提示。README を読んで環境を当て推量する必要がありません。
- **入れたらすぐ使える**: インストール成功と同時にカタログへ有効化され、次のメッセージから呼び出せます。設定変更も再起動も不要です。
- **権限に境界がある**: グローバルスイッチとエージェントの許可リストの 2 層制御。出荷時の 5 汎用オフィススキル — 全部有効でも、どこも空っぽでも、どこも空っぽでもありません。

> 一言で: 他人は「設定も手順も全部自分で片付ける手引き」を渡してくれる。私たちは「探せばすぐ使えるスキルマーケット」を渡す。

## 手順

<Steps>
  <Step title="発見ページを開く">
    **設定 → スキル → 発見** を開きます。
  </Step>
  <Step title="ミラーを選ぶ（任意）">
    発見ページ上部の **スキルマーケットミラー** を開き、国際 / 中国ミラー、または ClawHub 互換のカスタム URL を入力します。レジストリが有効な JSON を返した場合にのみ保存されます。
  </Step>
  <Step title="検索してインストール">
    キーワードで検索し、カードの **インストール** をクリックして、成功の toast を待ちます。
  </Step>
  <Step title="会話で使う">
    新しい会話を始めるか、続きの会話へ。有効なスキルは段階的ロードで使えます — エージェントに明示的なスキル許可リストを設定していない限り。
  </Step>
  <Step title="組み込みマーケット機能を必要に応じて有効化（任意）">
    **設定 → Agent → 能力 → 組み込みツール** で、`skill_market` / `skill_manage` は**既定で無効**です — 外部マーケット検索やスキル管理が要るときだけ有効にすれば、Turn1 の token を節約できます。`/learn` で新しいスキルを学習するときは管理ツールが自動で有効になります。
  </Step>
</Steps>

<Note>
  **明示的な許可リスト**: エージェントに空でないスキル許可リストを設定している場合、Discover でのインストールは新スキルをその許可リストへ自動で追加し、次のメッセージから会話で使えます。インストール API に `mount_to_agent: false` を渡すと、カタログへの有効化と許可リストへの取り込みをスキップできます。
</Note>

## スキルの環境変数を設定する

外部サービスを呼び出すスキルは `primary_env` / `requires.env` でキーを宣言します（例 `GOOGLE_API_KEY`）。設定方法:

1. **設定 → スキル** を開き、スキルカードを展開して**詳細パネル**を出します
2. **環境変数**の欄に入力して保存します

設定は一律**スキル設定センター**に一元化されます — SKILL.md ファイルに書き込むわけではありません。エージェントを構築するたびに、Myrm は保存済み設定と現在インストール済みのスキルを**照合**します。

- **インストール済みのスキル** → 実行時に環境変数が正しく注入されます
- **アンインストール / 削除したスキル** → 環境変数は自動削除され、残留も「ゴースト鍵」もありません
- **改名したスキル** → 設定は新しい実行時名に追従します

キーは環境変数として注入され、**会話のコンテキストには決して現れません**。

## ローカルスキルパス設定と原子的採用 (Local Skill Paths & Atomic Adopt)

オンラインマーケットからの発見に加え、開発者がローカルや独自のディレクトリにあるプライベートスキルをマウントできます。

1. **単一 / 複数ディレクトリ自動判定**: 指定パスが単一スキルのルート（直接 `SKILL.md` を含む）でも、複数スキルサブディレクトリを含む集合パスでも、 системаは正しく解析してスキルメタデータを完全に取り込みます
2. **2 段階の探索と原子的採用**: 正式なパス追加の前に Dry-run 事前検査を用意し、検出されるスキル・タグ・必要なシステムツール・同名衝突フラグ・安全初期スクリーニング結果をダイアログで表示。対象スキルにチェックを入れて原子的 Adopt して永続化するか、パス追加だけを選ぶこともできます
3. **CWE-22 パストラバーサル防御**: `..` を含む相対遷移の悪意あるパス入力を全チェーンで遮断し、ファイルシステムとサンドボックス環境の安全を保証
4. **実行時ヘルスの可視化とワンクリックコピー**: 設定画面の各ローカルパスカードに、発見スキル数やパス未存在などの状態をリアルタイム表示し、パスのワンクリックコピーも提供（端末とサンドボックスの共同開発に便利）
5. **前提となるシステム依存の検知とワンクリック自癒 (Prerequisites & Remediation)**: スキルのプレビューとインストール時に、ホスト環境に `ffmpeg` / `pandoc` / `poppler` などのバイナリ CLI や Python 依存パッケージが無いかをミリ秒単位で検知。欠けていれば赤黄の状態表示と、そのシステム专属の修復コマンド（`brew install ffmpeg` / `winget install Gyan.FFmpeg` など）を自動生成し、ユーザーがコピー実行すればスキルは安定して動きます。実行時の `command not found` による崩溃から完全に解放されます
6. **3 段階の段階的開示とボトルネック整合 (Three-Level Progressive Disclosure & Bottleneck Alignment)**:
   - **コンテキスト爆発を拒否**: 3 段階の段階ロード（Level 1 は起動時に軽量メタデータのみ、Level 2 はタスク割当時に標準 `SKILL.md` を必要に応じて生成、Level 3 はツール実行時に必要に応じて引数を読んで安全に呼び出し）を採用し、数十のツールを一括投入して 인한 token 浪費とモデルのツール混同（Tool Confusion）を根絶
   - **痛点起点の 3 ステップ簡易装配**: エージェントセンターに「痛点を選ぶ ➔ 推荐的 2〜3 個の核スキル ➔ 1 秒でインスタンス化」のウィザードを提供し、数十の長い講座を読む手作業の設定障壁をなくします。新 incur 10 秒で本格的なワークフローを開始できます

## サプライチェーン再スキャンと自動隔離 (Supply Chain Rescan)

第三者スキルのコードと、その下層の依存（npm / PyPI）は時間の経過とともに新たな CVE 脆弱性を露呈したり、オープンソースのサプライチェーン毒入れ（悪意あるパッケージの乗っ取り）に遭ったりします。

Myrm は全自動の**インストール済みスキルサプライチェーン再スキャンシステム**を内蔵しています。

1. **2 軌の秒級検知**: 高危毒入れパッケージのオフラインルール集（秒級応答、オフラインでも動作）+ OSV.dev のオンライン CVE バッチ差分スキャン（24h のスマートキャッシュで重複リクエストを排除）
2. **自動隔離と全体への配信**: 再スキャンで CRITICAL 重大度や悪意ある毒入れパッケージを検出すると、影響のあったスキルへ**隔離と無効化 (Quarantine & Disable)** を自動実行し、フロントエンドと Agent ランタイムへ `SKILL_POOL_UPDATED` イベントを即時配信して、その後の会話での誤った使用を防ぎます
3. **コンプライアンス監査と豁免のガバナンス (Advisory Acknowledgment)**: セキュリティチームが評価し「特定のサンドボックス隔離環境では安全」と判断した依存は、API / UI から Ack 監査豁免理由を提出でき、再スキャン後に信頼を回復できます。豁免はいつでも取り消せて防御を再有効化できます

## スキルライフサイクルガバナンスと安全なアンインストール (Skill Lifecycle Curation & Forensic Uninstall)

入れたスキルが一劳永逸ではありません — 入れるほどコンテキストは高くつきます。Myrm は全自動の**スキルキュレーション (Skill Curator)** を内蔵し、スキルライブラリを常にITZ的状态に保ちます。

1. **ライフサイクル状態機械**: 30 日未使用のスキルは自動的に**陳腐化 (stale)**、90 日未使用は**アーカイブ (archived)** へ — ゾンビスキルはコンテキストと一覧を占めなくなります。7 日ごとに自動点検され人手は不要
2. **使用品質駆動**: 呼び出し成功率が低い（30% 未満、標本 5 回以上）スキルは品質レビューでフラグが付き、低品質スキルがタスクの出来を-pull  pulled ます
3. **重複スキルのクラスタリング統合**: 類似度が高い（≥0.75）機能重複スキルはキュレーションエンジンがクラスタリング。統合は明示的に有効化した場合のみ、**必ず先にプレビュー確認**があり、不知のまま統合されることはありません
4. **保護と猶予**: ピン留めしたスキルは自動ガバナンスから除外。新規インストールには 7 日間の猶予があり、入れたばかりの機能を誤って傷つけることはありません
5. **フォレンジックカスケードアンインストール**: スキルのアンインストール時、システムはインストール受領記録 (receipt) を読み取って精密に監査し、スペック親プラグインをアンインストールすると登録済みの子スキルもカスケードで 정리します — 何を消したか一目瞭然で、跡を残しません

## インポート競合の事前検査、導入前セキュリティスキャン、決定論的コンパイル時ガード (Import Conflict Preflight, Pre-Install Security Scan & Deterministic Compile-Time Guards)

コミュニティで人気のスキルを入れると 3 種類にぶつかります — **同名衝突**、**サプライチェーン毒入れ**、**テーマが読みにくい**。

1. **インポート競合の事前検査 + 項目ごとの判断**: 一括インポートで同名が出ると、**何も書き込む前に**衝突を見せて提示し、1 項目ずつ決定 — インポート時に改名するか、両方を並存させるか。ローカルスキルディレクトリの採用も同じプレビューを通り、**デフォルトでは「衝突なし」かつ安全ゲート（score ≥ 50）を満たすスキルだけ**にチェックが入ります。他は明示的な確認が必要です
2. **導入前ゼロランタイム安全スキャン (Zero-Runtime Pre-Install Security Scan)**: リモート・ローカルのどちらのスキルも入る前にファイル単位で静的検査 — 高危コマンド（`sudo`、`rm -rf`）、申告されていない外向きネットワーク、機密環境変数の”一括探索”——そして可視化の健康診断レポートを出し、**有効化の前**に毒入れパッケージを止めます
3. **決定論的コンパイル時ガード、LLM ゼロ (Deterministic Compile-Time Guards, Zero LLM)**: テーマエンジンが配色をコンパイルするとき、決定論的ルールで **WCAG AA** のコントラスト（ライト / ダーク両方の主色とボタンの前景色）をアサートし、フォーマット回帰はコンパイル時に止められます — **LLM token は一切消費せず**、モデル推論はクリエイティブとアーキテクチャ判断にだけ使います
