# Google Workspace 連携

**設定 → 連携 → 認証情報** で Google Workspace に接続します。認可が完了すると、`google-workspace` プリセットスキルがエージェントから利用できます。

## 得られるもの

| 能力 | ユーザー=Februaryauv的利点 |
|------|------------------------|
| **GUI OAuth** | クリックだけで接続。Token を YAML や `.env` に書き込む必要がない |
| **Refresh Token の暗号化保存** | 認証情報はサーバー DB（AES-256-GCM）に保存 |
| **スキルカタログでの明示** | OAuth 未接続時はスキルが利用不可と表示され、設定へ戻るリンクを提供 |
| **実行時のガード** | タスクの途中で分かりにくい API エラーが出るのではなく、エージェントに明確な警告が渡る |
| **v1.5 の読み取り専用能力** | 今日のカレンダー、Gmail の受信箱メタデータ（件名・送信者・概要）、最近の Drive ファイル |

## 接続手順

1. **設定 → 連携 → 認証情報** を開く
2. **Google Workspace** を探して **接続** をクリック
3. ブラウザで Google OAuth を完了する
4. アプリに戻ると状態が **接続済み** と表示される
5. **ライブラリ → スキル** を開く — `google-workspace` が利用可能です（手動で無効化していなければ自動で有効になります）

## 会話の例

- 「今日の予定は何？」
- 「最近の受信箱メールをまとめて」
- 「最近更新された Drive ファイルを一覧して」

エージェントはプリセットスキルの説明を読み、OAuth Token を自動で注入する補助スクリプトを実行します。

## トラブルシューティング

| 症状 | 対処 |
|------|------|
| スキルが利用不可と表示される（黄色の注意） | 設定 → 認証情報 で Google への接続をやり直す |
| OAuth ボタンが押せない | 管理者がサーバーに `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` を設定してください |
| カレンダーが空 | ユーザータイムゾーン設定を確認してください — 日付の区切りは `MYRM_USER_TIMEZONE` で計算されます |

## MCP の Gmail / Calendar との違い

サービスカタログには Gmail や Google Calendar の MCP エントリもあります。デスクトップとローカル導入のユーザーには、ネイティブの **google-workspace** スキルの利用を推奨します。

- 1 回の OAuth で Gmail・カレンダー・Drive をまとめてカバー
- MCP プロセスを個別に保守する必要がない
- スキルカタログとエージェントの実行系が同じ可用性チェックを共有
