## 概要

Myrmは他プラットフォームのAIアシスタントデータ（メモリ・スキル・APIキー・MCP設定・ワークスペースルール）を移せる完全なデータ移行システムを提供します。フルプレビュー・競合解決・ワンクリックロールバック付き。

**対応ソース（14中11 ready）**：Hermes、OpenClaw、**Pi**、Claude Code、Cursor、Codex、ChatGPT、gbrain、Mem0、native JSON、Myrm Archive、AgentMemory——Windsurf・Trae・MemWeaverはロードマップ（開発中）。

## 移行ウィザード（3ステップGUI）

### ステップ1：検出

**設定 → メモリセンター → 移行**でウィザード開始。

- **ローカル/デスクトップ**：**スキャン**でシステム内のAIアシスタントを自動検出
- **クラウド**：前アシスタントの`.zip`エクスポートをドラッグ＆ドロップ

スキャナは既知ディレクトリ（macOS・Windows・Linux）を調べ、確信度（高/中/低）付きで報告します。

### ステップ2：プレビュー（ドライラン）

検出ソースの**プレビュー**で、書き込む前に取込内容を正確に確認：

- **対応マトリクス**：ready・要確認・手動対応の区分を表示
- **移行レーン**：Persona → Agent、Facts → Memory、Skills → 確認キュー、Keys → 明示確認、MCP → 監査
- **トークン経済**：移行前後のトークン使用量を比較
- **MCPサーバープレビュー**：取込後に使えるMCPツールを確認
- **競合検出**：上書きされる項目をハイライト

### ステップ3：確認と取込

宛先Agentを選んで（新規作成可）取込を確定：

- 秘密情報は明示オプトインでのみ取込（黙って入れません）
- スキルは確認キューへ——1件ずつ承認して有効化
- 取込ごとにトランザクションバッチIDを発行
- ZIPスキル移行はプレビューと確定で安定二相エラー契約（`message + error_code`）のためUI修復が決定論的

## 取込後レディネス（初チャット誘導）

取込成功後、Myrmは初メッセージ前にレディネスを**ライブ解決**——「なぜか chat が変」で迷子にしません。

| 状態 | 表示 | 修正場所 |
|--------|--------------|--------------|
| **警告** | トースト＋ stream 内通知：MCPは取込済み未有効 | **設定 → MCP** |
| **危険** | トースト：診断失敗 or プロバイダ未ready | **設定 → メモリ** or **モデル** |

**設計原則：**
- **ソフトゲート** — アシスタントは返答可。ブロックでなく誘導
- **Issue-aware CTA** — 各ギャップが正確な設定頁へリンク（`settings_path` SSOT）
- **ウィザード再検査** — 移行結果ステップで「チャット開始」前にレディネス再実行可
- **キューアンカー** — 引継ぎ状態は初チャット消費までナビゲーションをまたいで保持

**検証済み（2026-07-29）：** Chrome E2E **逐次3-legサインオフ 3/3 PASS**（`mcp_warning`・`provider_critical`・`diagnostic_critical`）並列wave下（≤8 leases、他pytest停止なし）・65+ unit/integrationテスト・競合はたいてい黙って失敗かCLIのみで取込後UXなし。

Hermes移行後の追加レディネス検査で、Hermes側で**voice**や**MoA advisor overlay**を使っていた場合にMyrm Agentプロファイル未設定のセットアップヒントが出ることがあります—— chat をブロックせず該当設定頁へリンクします。

## Hermes Cronジョブ取込（既定 paused）

**Hermes**からの移行時、ウィザードが`cron/jobs.json`の予約ジョブを取込可：

| ステップ | 動作 |
|------|------|
| **ドライラン** | 取込対象と skip（例`no_agent`・script-only）を理由付きプレビュー |
| **確定** | 合致agent型ジョブを**PAUSED**作成——再開まで動かない |
| **結果** | 件数サマリ＋**Cronを設定**ボタンが**設定 → Cron**へ深リンク |
| **ロールバック** | バッチ`cron_rollback`で当該取込ジョブを削除 |

**正直境界：**
- Hermes**モデル**欄は**移行しない**——ジョブは宛先Agentの既定モデル使用
- **Kanban**ボードは自動移行**しない**（対応マトリクスに`kanban_not_migrated`表示）
- cron取込のChrome MCP E2Eサインオフは未——バックエンドは**`test_hermes_cron_converter.py` 7/7 passed**で担保（Aug 2026）

Hermes CLI `claw migrate`・OpenClaw・Pi・deer-flow・LobsterAI・CoPaw・jiuwenclaw——GUI移行ウィザード＋cronプレビュー＋paused取込＋ロールバックを持つ競合は存在しません。

## Pi移行（5レーン対応）

**Pi**からの移行時、ウィザードが`~/.pi/agent/`を自動スキャンし5レーン対応：

| Piデータ | 取込レーン | 説明 |
|---------|-------------|------|
| `AGENTS.md` | Agent persona | PiシステムプロンプトをAgent指示として取込 |
| `settings.json` | 設定補完 | 既定プロバイダ・モデル等 |
| `sessions/*.jsonl`（v3） | エピソード記憶 | チャット履歴を記憶化（マルチターン・ツール呼び出し濾過・list統合） |
| `skills/*/SKILL.md` | スキル確認キュー | Markdown＋YAML frontmatter完全互換——自動検出取込 |
| `auth.json` | 認証情報（env_keys） | APIキーをMyrm環境変数形式へ（明示確認必須） |

**安全ガード：**
- 未知セッション版（≠ v3）は自動黙殺 skip
- 空メッセージ・不正JSON・非dictコンテンツブロックは安全 skip
- PiにMCP設定なし（技術スタック差異）——移行完全性に影響なし

**検証済み（2026-08-03）：** `test_pi_migration.py` **25/25 PASS**（検出/読込/セッション解析/スキル/認証情報/辺縁——6区分25シナリオ）

## Hermes MoA参照取込（ウィザード確定）

Hermes `config.yaml`に`moa`ブロック＋参照モデルがある場合、移行ウィザード確定時に宛先Agentの**`engine_params.moa_overlay`**へ書込可：

| ステップ | 動作 |
|------|------|
| **ドライラン** | プレビューに`hermes_moa`レーン——既定（or 先頭有効）プリセット名と参照モデル数を表示 |
| **確定** | `hermes_moa_migrator`がHermes参照→Myrmオーバーレイ対応付け。プロバイダ解決失敗参照は skip |
| **取込後** | chat 開く→モデルピッカー**Mixture of Agents**群→**Standard / Deep Review / Fast**をセッションごと選択 |

**正直境界：**
- **既定**Hermesプリセットの参照セットのみ取込（参照プールが**異なる**複数プリセット→Agentプロファイル複数作成）
- Hermes**aggregator**モデルは**移行しない**——Myrmプライマリがadvisor出力を吸収（設計）
- 参照解決にはMyrm側のプロバイダキー設定が先決。解決不可参照はログ付き skip

**検証済み（2026-08-03）：** **`test_hermes_moa_migrator.py` 19/19**＋取込アーカイブ内確定統合パス——**30/30** MoAサーバーpytestスイートの一部。

## ロールバック

全取込は完全に戻せます：

1. **設定 → メモリセンター → 最近の取込**へ
2. 任意バッチの**ロールバック**をクリック
3. 元に戻る内容をプレビュー（ロールバックドライラン）
4. 確定で以前の状態に復元

## バックアップとリモート同期

### ローカルバックアップ

全メモリの手動バックアップはいつでも：

- **設定 → システム → バックアップ** → バックアップ作成
- 格納：全メモリ種・共有コンテキスト・会話履歴
- 一覧・復元・削除可

### リモートバックアップ（S3 / WebDAV）

クラウドストレージへ自動同期を設定：

- **S3互換**：任意プロバイダ（AWS S3・Cloudflare R2・MinIO等）
- **WebDAV**：NAS・Nextcloud・ownCloud等

## 新規ユーザーオンボーディング

Myrm初回起動時、**オンボーディングウィザード**がシステム内の既存AIアシスタントデータを自動チェック。見つかればワンクリック移行を提示——初会話からあなたの人格・記憶・ツール入りで始められます。

外部データ検出時にはchat 画面にも**検出バナー**が出て移行ウィザードへショートカット。

## エクスポート

### フルアーカイブのバックアップと復元

Myrmワークスペース全体を構造化アーカイブでエクスポート。データ関係を保持：

- **会話**：全メッセージ履歴（compaction状態＝圧縮サマリ、セッションノート、ツール利用統計、トークンコスト集計含む）
- **メモリ**：全メモリ種（エピソード・意味・手順・嗜好・共有コンテキスト）
- **エージェント設定**：Agentプロファイル完全体（モデル・プロンプト・スキル・MCP束縛）をJSON往復エクスポート/取込
- **部位選択復元**：フルアーカイブ取込 or 部位選択（会話のみ・メモリのみ等）

災害復旧・ cross-instance クローン・チームオンボーディングの推奨ルートです。

### デプロイ間移行（ローカル ↔ クラウド）

Myrmは全デプロイモードでSQLite単一データストア。ローカルWebUI・Tauriデスクトップ・クラウドホスト間の移行はシームレス：

- **Volumeコピー**：SQLite DBファイルをデプロイ間でコピーするだけ——ゼロ欠損・ゼロ形式変換
- **アーカイブ経路**：一方でフルアーカイブをエクスポート、他方で部位選択復元

このレベルのデプロイ可搬性を持つ競合は存在しません。多くは単一デプロイモードに錠付きです。

### メモリアーカイブのエクスポート

Myrmメモリを構造化JSONアーカイブ（`myrm_memory_archive`形式）でエクスポート。他Myrmインスタンスへ取込・共有可。

### データセットのエクスポート

会話データを学習用形式でエクスポート：

- **ShareGPT**：標準ファインチューン形式
- **PII Redaction**：個人情報を任意除去
- **品質濾過**：最小ターン・最小文量・成功のみ
- **増分**：前回以降の新規分のみエクスポート

## データルートパス移行ウィザードとストレージ統治

長期運用で作業メモリ・ベクトル索引・スナップショット・artifactは膨張必至。Myrmは企業級データルートパス移行ウィザードと多次元ストレージ統治を提供します：

### 中核安全機構と保護

1. **三重ハード保護**：
   - **自己ネスト防止検査**：ルートデータパスを現データディレクトリや配下への移行に厳禁。ディレクトリ移動時の無限再帰を排除
   - **1.2x空容量ヘッドルーム事前検査**：移行前に宛先パーティション空容量を正確計測。ソースの120%以上を要求し、 cross-volume 移動時のディスクフルSQLite WAL破断を防止
   - **宛先競合隔離**：宛先に有効データがあれば安全ブロック隔離。誤上書きを防止
2. **二相機密アクションチケット**：
   - 短命・単発の暗号署名チケット必須。Dry-Run事前検査＋明示確認を経て実行。CSRF乗っ取りとUI誤爆を防止
3. **実行中バックグラウンドタスク感知と排他書込錠**：
   - 稼働中長時間タスク（常駐シェル・評価実行等）を動的監視。稼働中は即拒否＋動的件数フィードバック（HTTP 409 Conflict）でタスク途中書込破断を防止
   - 移行中は排他書込錠＋WAL TRUNCATE flushでシームレスDB切替
4. **サブ秒原子ロールバック**：
   - 粒度トランザクション補償。 cross-filesystem（EXDEV）コピー異常や不意停電でも、ソース状態ロールバック＋宛先 partial artifact をサブ秒除去（ゼロ破損・ゼロ残骸）
5. **ストレージ profiling とゼロダウンタイム online 圧縮**：
   - SQLite・Qdrantベクトルコレクション・セッションスナップショット・メディアに分解 profiling。アイドル時ロックフリー online `VACUUM`で断片40%–60%回収

## WorkBuddyやTencent WeKnoraから？

ワンクリック取込は未（WorkBuddyはクローズドで export 形式なし。WeKnoraは自社Go/Postgresスタック）——でも全ワークフローが1:1対応し、より強いエンジンで動きます：

| あなたのワークフロー | Myrmで得るもの |
|---|---|
| WorkBuddy議事録（決定＋担当＋期限） | 議事録スキルが三者とも構造化抽出**かつ**kanbanタスク自動発行 |
| WorkBuddy日報のミニプログラム push | 同 prompt/plan/capability 構造のCronジョブで35+チャネル配送 |
| WorkBuddyプロンプト強化 / Ask / Planモード | 今日のGoal＋受理基準＋HtmlPreview。ワンクリック prompt 磨きと読取専用Askモードはロードマップ |
| WeKnora RAG社内文書Q&A | Wiki上の同 BM25＋Dense＋RRFハイブリッド検索＋Agentごとメモリ上乗せ |
| WeKnora Wikiモード（文書→育成wiki） | 今日のWiki統治ワークベンチ＋源同期＋定期更新。エージェント執筆wiki生成＋ロールバックはロードマップ |
| WeKnora Dockerセルフホスト（8–10コンテナ） | ローカル1 install・デスクトップ1 app・ユーザーごとクラウドsandbox1——同データ主権、遥かに軽い運用 |

正直ギャップ（進行中・隠さない）：ワンクリック prompt 強化、出力 style プリセット（表優先・前置きなし）、Ask専用モード、エージェント執筆wiki生成＋版ロールバック、拡張コネクタ行列（飛書Drive構造保持同期・Notion・GitLab・钉钉文档・RSS）。**来ないもの**：マルチテナントWorkspace RBAC（単一ユーザーper-sandbox架构と衝突）とCLI製品（GUI-first）。
