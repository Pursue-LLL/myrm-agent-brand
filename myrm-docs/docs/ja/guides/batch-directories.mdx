# バッチディレクトリ実行

**1 つの指示**で**複数の作業ディレクトリ**に対して同じタスクを並列実行します。1 つのプロンプトで複数のリポジトリの安全問題を監査する、複数のプロジェクトに同じ移行を適用する、コードベースごとに統一されたステータスレポートを作る — こうした用途に向いています。

## バッチ実行の作成

サイドバーの **バッチディレクトリ** を開き **新規実行** をクリックして、次を設定します。

| 設定項目 | 作用 |
|----------|------|
| **名前** | バッチを識別するラベル |
| **指示** | 各ディレクトリに適用する同一の指示 |
| **ディレクトリ** | 処理対象のワークスペース（1 ディレクトリ = 1 エージェントタスク） |
| **並列数** | 同時に処理するディレクトリ数 |
| **エージェントとモデル** | エージェントの紐付けと、バッチ単位のモデル上書き（任意） |
| **最大実行時間** | ディレクトリごとのタイムアウト保護（秒） |
| **承認が必要** | 各結果が人の承認 / 却下された後にのみ反映 |
| **成果物マッチパターン** | エージェントが必ず生成すべきファイルの glob（例 `**/security-report.md`） |
| **通知** | 完了時のサイト内通知 + IM チャネル通知 |

危険なパス（ユーザーホーム、`/etc`、ファイルシステムのルート、`~`、`..` によるトラバーサル）は作成時に拒否され、重複したディレクトリは自動的に重複排除されます。

## 進捗の監視

詳細ページでは状態、各ディレクトリのタブ、集計数がリアルタイムに表示されます。**失敗した**ディレクトリや**必要な成果物を出せていない**ディレクトリはハイライト表示され、問題箇所を一目で特定できます。実行終了後は総所要時間が表示されます。

## 失敗時の扱い

バッチ全体をやり直す必要はなく、正確に復旧できます。

- **失敗ディレクトリを再試行** — 失敗した、または成果物が欠けているディレクトリにだけタスクを再発行
- **単一ディレクトリを再試行** — 1 件のタスクだけを再実行
- **すべて再実行** — 全ディレクトリを再キュー（終端状態のみ。再キューによる重複を避けるため）

再試行はディレクトリ単位で世代を追跡し、あるディレクトリの再試行が成功すればプロジェクト全体は **完了** に戻ります — 以前の試行が失敗していても同様です。

## 一時停止と承認

- **一時停止**は実行中のエージェントを中断しキューを凍結します。**再開**は一時停止位置から正確に続きます。
- **承認が必要**を有効にすると、検証を通過した各タスクが *承認待ち* に入り、あなたの承認 / 却下を待ちます。**すべて承認** でバッチ全体をまとめて確定できます。

## 通知

バッチが終端状態になると、サイト内通知が届きます。エージェント設定に通知先がある場合は IM チャネルにも届きます — 結果の集計、所要時間、失敗ディレクトリの一覧を含みます。メッセージにはプロジェクト詳細ページへの直リンクが含まれ、チャットからそのまま詳細を確認できます。

## 主なシーン

- 1 つの指示で N 個のリポジトリの安全 / ライセンス問題を監査する
- 複数のプロジェクトに同じリファクタリング / 移行をまとめて適用する
- 所持する各ディレクトリの統一されたステータスレポートを生成する
