# Agent Plugins 記憶プラグイン

Myrm は [Agent Plugins](https://agent-plugins.org) 標準に沿ったポータブルプラグインを提供し、長期記憶をこの標準に対応した任意のクライアント — VS Code、GitHub Copilot、Kiro、Cursor、ChatGPT、Codex など — に接続できます。プラグインは輸送層のみを担当します。Myrm の記憶サービスへ MCP クライアントを指し示し、接続された agent に「記憶をいつ・どのように使うか」を伝えるだけで、クライアントごとの設定ファイルを手で編集する必要はありません。

## プラグインに含まれるもの

| ファイル | 役割 |
|----------|------|
| `plugin.json` | プラグインのマニフェスト（名前、バージョン、説明）。 |
| `mcp.json` | Myrm の `/mcp` エンドポイントを指す Streamable HTTP の MCP サーバー設定。 |
| `skills/myrm-memory/SKILL.md` | 接続された agent への操作指針: 記憶をいつ想起し、記録し、監査し、修正するか。 |

## プラグインの生成

1. **設定 → 記憶 → 接続**（接続ウィザード）を開きます。
2. 記憶を外部公開する Myrm エージェントを選びます。
3. **Agent Plugins** カードで、token をプラグインファイルへ書き込むか、`MYRM_MCP_TOKEN` 環境変数から読み取るかを選びます。
4. **Agent Plugins プラグインを生成**をクリックし、**すべてダウンロード (.zip)** でまとめて取得するか、各ファイルを個別にコピーします。zip を展開すると正しいディレクトリ構造が入っています — それをクライアントのプラグインディレクトリへ置いて有効化してください。

上記のプラグイン構造を保ってください: `plugin.json` と `mcp.json` はプラグインのルートに、`SKILL.md` は `skills/myrm-memory/` サブディレクトリに置きます。zip はこの構造を自動で保持します。ファイルを個別にコピーする場合は手動で再構成してください。クライアントは `skills/<name>/` サブディレクトリからスキルファイルしか読み込まず、ルートに置かれた `SKILL.md` は黙って無視されます。

token を書き込むモードはそのまま使えますが、資格情報が `mcp.json` に残るため、この種のプラグインをリポジトリにコミットしないでください。既定の環境変数モードは資格情報を持たないため安全にコミットできます。ほとんどのクライアントは `${MYRM_MCP_TOKEN}` を展開しますが、一部（VS Code、Cursor）は `${env:MYRM_MCP_TOKEN}` を使います。クライアントが補間に対応しない場合はウィザードで token 書き込みモードを有効にしてください — token はいつでも失効させられます。

## アクセスの管理

- 生成された token は選択した Myrm エージェントに紐づき、プラグイン経由ではそのエージェントの記憶にだけアクセスできます。
- ウィザードで**再生成**すると新しい token が発行され、**古い token は即座に失効**します。古いプラグインを使っているクライアントは再設定が必要です。
- ウィザードで**接続を取り消す**と token は即座に失効します。
- 依存する前に、ウィザードの**ヘルスチェック**で接続を検証できます。

## Doctor 診断の実行

ウィザードの **Doctor** ボタンはオンラインの token テスト以上に一歩先です。**機械上の MCP クライアントの実際の設定ファイルを読み**、クライアント側からプラグインの接続を確証します。

| 診断コード | 意味 | 重大度 |
|-----------|------|--------|
| `verified` | 設定ファイルが見つかり、`myrm-memory` エントリが存在し、Bearer token のハッシュが一致 | 正常 |
| `token_valid` | token が存在し、保存済みハッシュと一致（照合できるファイルなし） | 正常 |
| `token_env` | エントリが `${MYRM_MCP_TOKEN}` を使用 — このマシンでは最終値を検証できません | 要注意 |
| `config_file_missing` | 設定パスが存在しません（`~/.claude.json` などを確認） | 失敗 |
| `entry_missing` | ファイルは存在するが、想定キーの下に `myrm-memory` エントリがない | 失敗 |
| `token_missing` | エントリはあるが `Authorization: Bearer <token>` ヘッダがない | 失敗 |
| `token_mismatch` | ファイル内の token が保存済みハッシュと不一致 — 設定スニペットを再コピーしてください | 失敗 |
| `file_unreadable` | ファイルは存在するが不正な JSON/TOML | 失敗 |

- JSON（`json_mcp`）と TOML（`toml_mcp`）の両クライアント形式に対応し、パス内の `~` は自動的に展開されます。
- token は SHA-256 ハッシュのみで保存され、平文では一切残りません。
- 診断メッセージは 6 言語（EN / 中文 / 繁體 / 日本語 / 한국어 / DE）に対応し、各診断コードに実行可能な修復手順が付きます。
- Doctor は読み取り専用で、クライアントの設定ファイルを書き換えません。

## セルフホスト

プラグインは輸送層のみを担当するため、セルフホスト instance（ローカル Web UI、デスクトップ、クラウドサンドボックス）でも同様に使えます。`mcp.json` の `url` を自前の instance の `/mcp` エンドポイントに向け、該当する instance の接続ウィザードで token を生成してください。
