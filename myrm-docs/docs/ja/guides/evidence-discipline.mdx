# 証拠規律

AI の失敗の多くは劇的な幻覚ではなく、「それらしく見える中間結果がより強い結論へ昇格された」ことです:

- コマンドの終了コードが 0 だから、エージェントは「システムは直った」と言う
- ファイルが編集されたから、エージェントは「機能が使える」と言う
- ローカルビルドが通ったから、エージェントは「デプロイされた」と言う
- 検索が何も返らなかったから、エージェントは「存在しない」と言う
- あなたが口にした前提を、エージェントは「独立に確認済みの事実」としてなぞる

Myrm の**証拠規律**スキルは、デフォルトエージェント（`builtin-economy`）のすべての回答に「**結論と証拠の契約**」を被せることで、これらの失敗を稀有にします。

## 何をするか

スキルは証拠の種類で結論を分類し、結論の強さに応じて段階的な**証明義務**を課します。

| 証拠の状態 | 意味 |
|-----------|------|
| **目視確認 Observed** | エージェントがツール・ファイル・ログ・実行時チェックで直接見た |
| **出典あり Source-backed** | 指し示できる名前付きの出典が支えている |
| **ユーザー申告 User-reported** | あなたがエージェントに伝えたもの — あなたの発言としてなぞるものであり、**独立検証ではない** |
| **推論 Inferred** | 他の事実から導出したもの。推論である旨を明示 |
| **不明 Unknown** | 検証できない — 不明と正直に言い、誤魔化さない |
| **矛盾 Contradicted** | 証拠が食い違う — 不確実性を保持し、強引に結論を出さない |

## 安全契約

証拠のラベル付けに加えて、スキルはエージェントのよくある「温和な嘘」も塞ぎます。

- **タスクで実際には使えないリソースにアクセスしたとは言わない。**
- **「計画」や「試した動作」を「実際に起きた動作」と言わない。**
- **ツールのエラー、空の結果、一部だけの同期、アクセスできないデータを「検証成功」に読み替えない。**
- **より強い証拠を得るために、無関係で破壊的な操作を行わない。**
- **否定的な結論**（例「存在しない」）は、実際に確認した範囲に限る。

## Built-in の過度な慎重とのバランス

証拠規律は諸刃の剣なので、スキルはもう一方の極端も防ぎます。

- **UNKNOWN を乱用しない。** 証拠が合理的に手に入るなら検証する — 慎重を理由に確認を飛ばさない。
- **先に自己確認し、尋ねるのはその後。** 自分で調べられる証拠は先に調べ、そのあとでユーザーに同じ情報を尋ねない。

最終的な効果: 知らないことに正直で、検証できるものは自分で検証し、自分の homework をユーザーに押しつけないエージェント。

## 使い方

**設定不要。** スキルは汎用組み込みエージェント（`builtin-economy`）に既定で紐づいており、Web 会話・cron・チャネルのすべてのセッションで効きます。

さらに:

- **設定 → スキル** で他のプリセットスキルと並べて確認できます
- 新規エージェントに任意の紐づけたり、不要なエージェントからは外したりできます
- エージェントのカスタムプロンプトで発動条件を強化できます（例「重要な結論には先に証明を」）

## 検証と契約テスト

スキルの挙動契約は **33 件のアーキテクチャ契約テスト**が守ります — 挙動条項が 1 つずつ存在することと frontmatter のバージョン番号が妥当であることをアサートし、技能が黙ってドリフトしたり退行したりすることを防ぎます。完全なパイプライン（同期 → 紐づけ → 可視性）はモックなしの統合テストでカバーしています。

## メカニズムレベルの強制（フレームワークゲート）

上のスキルはプロンプト層の規律で、モデルが自己規律を守ることに依存します。同じ契約はフレームワーク層でも強制されており、モデルは迂回できません。

- **完了宣言は、そのターンの実際のツール記録と突き合わせる。** 回答に検証結論・外向きアクション・コード変更が現れると、フレームワークはまずそれをそのターンの実際のツール呼び出しと照合し、そのうえで回答をあなたのところへ通します。テストは実際のテストランナー**を実際に走らせた**ものだけを証拠として扱い、テストケースの収集だけ、ケース 0 件、runner を `PATH=` で差し替える、MCP 呼び出しの読み取りだけはいずれも証拠になりません。外向きアクションは実際の送信があることが必要で、読み取り呼び出しやファイル書き込みだけでは足りません。突き合わなければ遮断され、出口は 2 つだけです。**今すぐ証拠を取りに行く**か、**何をしたか・何をしなかったかを正直に述べる**かのどちらかです。
- **すべての回答に証拠ランクが付くので、ユーザーはひと目で深浅が分かります。** 回答は**検証済み**（テスト / lint / ビルドを実際に走らせた、または再確認済み）、**成果物あり**（実際にファイルを書いた）、**出典あり**（実際に検索で出典を得た）、**計画**（現時点で検証可能な成果物がまだない — 回答が自らを完了と主張する場合にだけ現れ、闲聊では邪魔しません）としてラベル付けされます。バッジを開くと背後の物理的証拠（検証の種類・書き込んだファイルパス・出典の本数）が見えます。
- **書き留めなかった成果物は保全され、開示されます。** コードを書くターンでドラフトがディスクに書かれていなければ、フレームワークはそれを `.myrm/staged_artifacts/` に安全に退避し、回答の末尾に「ドラフトを一時保存しました」バナーを付けてファイルを列挙します — ドラフトが会話の中で黙って消えることはありません。
- **証拠は承認を通得起、等 ininterラそれPureの互いに干渉しません。** 1 つのタスクが HITL 承認で複数段に分かれたとき、証拠台帳はターンごとに積み上がります。各ターンには独立した遮断予算があり、同一プロセス内の並行セッション・バックグラウンド続行・cron が互いの予算を消費したりリセットしたりすることはありません。

これらのゲート・開示・保全は単体 / 契約テストに加え、「実ブラウザ + 実モデル」の受入ケースでもカバーしています。6 社の競合横並び比較は[競合比較（英語）](/getting-started/competitor-comparison)を参照してください。
