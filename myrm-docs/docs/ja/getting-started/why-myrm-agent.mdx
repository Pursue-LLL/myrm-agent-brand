# なぜ Myrm Agent なのか

さまざまなオープンソース AI Agent フレームワークや製品の中で、Myrm Agent は **基盤アーキテクチャの頑健さ**、**突き抜けたユーザー体験**、そして **エンタープライズ級のセキュリティ隔離** で頭一つ抜けます。すぐに使い始めたい一般ユーザーでも、深くカスタマイズしたい開発者でも、Myrm Agent は競合を大きく上回る体験をもたらします。

以下は、主流の競合（Hermes Agent、OpenClaw、DeerFlow など）に対する、確かめた優位性です。

## 1. 決してクラッシュしない基盤の自己修復

OpenAI 互換 API（DeepSeek、Kimi など）を使うとき、ネットワークの揺れやユーザーの頻度なキャンセルでツール呼び出しが中断し、履歴に無効な `tool_call_id` が残り、モデルの厳格なバリデーションでクラッシュすることがあります。

**私たちの強み**:
Myrm Agent はエージェントのミドルウェア層に透過的な自己修復を実装しています。LLM リクエストのたびに `tool_history_hygiene` がツール結果を重複排除し、重複した tool-call ID を書き換え、`dangling_tool_call` がキャンセル後の宙に浮いた呼び出しを修復します。プロバイダエラー時はストリーム復旧が一度だけ自動リトライし、進捗を Web UI に表示します。ネットワークがどれだけ揺れても会話履歴は合法な状態を保ち、フォーマット起因のクラッシュから完全に离れます。頑健性は競合を大きく上回ります。

## 2. 独創の 4 段階プログレッシブスキルロード

Agent に大量のスキルを設定するとコンテキストウィンドウが急膨張し（コンテキスト爆発）、Token 消費が増えるだけでなく、モデルが指示に従う能力も落ちます。

**私たちの強み**:
- **必要に応じてロード**: 独創の 4 段階プログレッシブロードにより、スキルの本文は本来必要なときにだけコンテキストへ載せられ、Token 消費を極端に抑えます
- **精密制御**: `/slash` スラッシュコマンドで特定のスキルを正確に起動できます。Agent の自律性とユーザーの精密制御を両立し、実行の決定性は明確に
- **使うほど賢くなる**: 複雑なタスクの完了後、Agent が自動で要約して新しいスキルを作成でき、閉ループの学習が成立します

## 3. Serverless 級のサンドボックス休止と秒単位の復帰

従来のクラウドデプロイでユーザーごとに常駐サンドボックスを保つとコストが極めて高くなり、従来の SaaS 構成はパフォーマンスとプライバシー隔離を犠牲にします。

**私たちの強み**:
制御プレーンはサンドボックス環境のアイドル suspend とオンデマンド復帰をネイティブに支援します。ユーザーがオフラインの間、100% 物理隔離された専用サンドボックスの状態は永続化されて休止し、新しいメッセージや cron がトリガーすると瞬時に復帰します。プライバシーを守ったままクラウドのアイドルコストを大幅に削減し、本物の大規模商業化に向けたエンタープライズ級アーキテクチャです。

## 4. チャート能力が膨らまない

多くの競合は重いホワイトボードモジュールを内蔵するか、手でドラッグ配置するしかできません。Myrm はコアを簡素に保ちます。

**私たちの強み**:
会話内の **Mermaid アーティファクト** がほとんどのチャート需求を満たし、確認と弁明の対話は **`structured_clarify`** がフォームで受け持ちます。完全に編集できるホワイトボードが必要なときは **Excalidraw / tldraw MCP** を接続してください（Goose や Codex プラグインと同じルート）。コア製品の保守負担はゼロです。

## 5. 妥協のない全チャネル IM カバレッジ

多くの競合は主要チャネルの数種類しか対応せず、チャネルごとにメッセージ形式やメディア処理の品質が大きくばらつき、体験が分断されます。

**私たちの強み**:
ネイティブに 26 チャネル（Slack、Discord、Feishu、iMessage、WeChat、Telegram など）をサポートし、「どこからでも呼べる」という居場所をつくります。下層の統一メディア処理パイプにより、どのプラットフォームでも一貫した Markdown レンダリング・音声認識・インタラクション体験が得られ、専任のアシスタントを无缝に呼び出せます。初回は**ワンステップ Telegram セットアップウィザード**（Token 検証 + ポリシー書き込み + 既定 Agent の紐づけ + 失敗時のロールバック保護）で初期化でき、複数ページをまたぐ組み立て手順を 1 つの閉ループに収めます。

## 6. 自然言語で動く無人値守スケジューリング

たいていの Agent は「受動的な応答ツール」でしかなく、ユーザーが明示的に起動させないと動きません。

**私たちの強み**:
強力な無人値守スケジューリングエンジンを内蔵しています。「毎朝 8 時にブリーフを送って」のような自然言語の一言で、Agent は自律的に働くデジタル従業員になります。Webhook 配信と全チャネルへの到達に対応し、受動的なツールから能動的なサービスへと進化します。

## 7. 記憶の重複排除と永远に痩せた頭脳

長期の多輪対話の中で Agent は同じ事実を大量に蓄積し、記憶庫が肥大して検索精度が急落します。

**私たちの強み**:
下層の `dedup_semantics` メカニズムが書き込み時に厳格に重複事実を弾きます（類似度 ≥0.95 は自動重複排除）。記憶庫は永遠に軽快なまま、Agent が「使うほどあなたを理解する」と同時に肥大しないことを保証します。

## 8. 沈黙した失敗を拒む全チェーンのフィードバック

一括操作に進捗バーがない、ネットワーク例外が静かに失敗する、ファイルが「参照ゼロ」だから即削除 — これらは競合で常见な、ユーザーを強く不安定にさせる設計です。

**私たちの強み**:
全チェーンの UI 進捗フィードバック（Progress）、明確な例外 Toast とリトライ機構、コンテキストから外れる操作には強い視覚的フィードバック。加えてファイルシステムの「ごみ箱」ソフト削除を内蔵し、データ損失の不安を消し去り、本物のエンタープライズ級の安心感を提供します。

## 9. 産業級の全チェーン可観測性とコスト護城河

問題が起きても、競合が出せるのは生ログファイルだけでリクエスト間の関連性は皆無です。無人値守や深い長 thinking のタスクでは、死ループの反復で計算コストが天価の請求を突き破ることが多く、切り分けはブラックボックスのままです。

**私たちの強み**:
- **4D リアルタイム Token エコノミクスと Net ROI 計算水盤**: Prompt・Completion・キャッシュ読み・キャッシュ書き・深い思考（Reasoning）・引用（Citation）を全要素で計測し、書き込みプレミアムを実際に除いた財務級の本当の純節約 ROI を提示。粉饰は一切しません
- **24/7 無人値守の死ループ物理遮断**: 無人値守モードでは厳格な防死ループ戦略が働き、進捗のないツール呼び出しの反復を秒単位で検出して捕捉不能の `RunawayCircuitBreakException` でタスクを断ち切ります。スケジューラは直ちに全リトライを取り消し、その cron ジョブを一時停止し、夜間に死ループが繰り返し再実行されるのを防ぎます
- **長思考モデルの思考連鎖のストリーム剥离と决策アンカーの保全**: DeepSeek-R1 / o1 などのモデルに対し、O(N) の接頭辞スライディングウィンドウ状態機械が Chunk をまたいで `<think>` タグをミリ秒単位で剥离し、本文は遅延ゼロで透過。决策アンカーを自動的に抽出して Prompt の末尾へコンパクトに注入し、90%+ のプロンプト接頭辞キャッシュ（KV-Cache）を 100% 保全します
- **イベントソースの不変モデルビューポートと時空デバッグ**: 下層の 32KB 不変物理ビューポートが改変されていないモデル入力の全景をそのまま保持し、4 ロールのカードで分解。任意の履歴ターンから無損失分岐をその場で派生でき、前段のコンテキストをすべて保持したままデバッグコストを 80%+ 削減します
- **子プロセスゼロの標準トレーシングと SRE situation プローブ**: ContextVar で無コストに伝播するグローバル `trace_id` と OpenTelemetry GenAI セマンティクス規範を基盤に、純ローカル Trace の物理ゲートと SRE ランタイム状況プローブを内蔵し、20+ の分析次元を網羅。設定不要でそのまま使えます

## 10. 初日から使える Git と PR 納品

多くのコーディング Agent は、Git 認証・コミット identity・Webhook をすでに設定済みだと前提にしています。真っ新の環境では「GitHub に push して PR を作る」が一瞬で令人沮丧な設定マラソンになります。

**私たちの強み**:
- **ホスト限定 push 認証情報**: GitHub token があるとき、Myrm が注入する認証情報ヘルパーは `github.com` / `www.github.com` にのみ応答します — あなたの token が第三者の Git サーバーに届くことはなく、コマンドへインラインで埋め込まれることもありません
- **自動コミット identity**: サンドボックスに Git identity がなければ、接続済み GitHub アカウントから `user.name` / `user.email` を解決します（キャッシュ + 5 秒タイムアウト + ローカルフォールバック）— `git commit` が「Please tell me who you are」で止まらなくなります
- **セルフサービスの PR Webhook**: 設定ページに Webhook URL とコピーボタンを直接表示し、署名検証（`X-Hub-Signature-256`）までエンドツエンドで接続され、PR / issue / push イベントが安定してチャットへ還流します

Agent に「GitHub に push して PR を作って」と伝えるだけで完了します — 認証情報・identity・イベントすべて込みで。

## 11. 承認の前に計画と差分を見て、終われば一组成部分戻す

マシン全体に触る Agent には避けられない疑問が一つあります。「承認したら何が変わるのか。どう戻せばよいのか」。多くの Agent はその問いに「はい / いいえ」のプロンプトとログ 1 行でしか答えません。

**私たちの強み**：
- **計画が先に来る**：複数ステップの作業が走り出す前に、最初の計画の案を提示して確認の機会をつくります。ファイルに触れる前に方針を直せます。
- **変更が見える**：ファイル編集のたびに差分が会話に流れます。「完了しました」だけの報告ではなく、実際の変更を自分で読めます。
- **戻す手段がある**：実行前に Myrm は **シャドウ Git スナップショット**（あなたのリポジトリとは物理的に分離しており、ワークツリーも履歴も汚しません）を取得し、承認カードには元に戻すボタンを置きます。誤った一手は、再作業も履歴の掘り返しも不要に、その場で戻せます。
- **モデルの意見ではなく決定的なゲート**：`ALLOW` / `ASK` / `DENY` はコードに書かれた定数で、評価にモデルは一切参与せず、`DENY` は LLM にも覆せません。`~/.ssh` などのセンシティブなディレクトリはパス方針でハード禁止です。

しかも、使うために OS を変える必要はありません。アプリ横断の作業は、当方のサンドボックスと PC 操作層が担うので、今お使いのマシンのまま使えます。

**競合の実態チェック（2026-10-22）**: Herald OS（コミュニティ最大の「OS の中の Agent」作品）は「変更前に承認する」ことと、実際にディスクへ落ちる監査ログを備えています。権限の段階が本当にコードで定義されていることも、ソースを直接読んで確認しました。ただし第三の脚——変更箇所の差分表示と 1 操作単位の巻き戻し——は持っていません。まさにこの節が埋めている穴です。


## 12. 書き終えても生きている文書と表 —— 書くたびに自動点検、任意の版へ戻せる

.docx や .xlsx をエージェントに預ける時、怖いのは「編集を拒んだ」時ではなく、編集して「完了しました」と言った後、式が静かに値へ置き換わっている時 —— あるいは自分では読み返せないファイルを渡された時である。

**我々の強み**:
- **点検はファイルを開いた後ではなく、書いた直後にある**: Office ファイルを書くたびに後段点検が走り、前後の Excel **数式集合**を突き合わせ（式が静的な値に変わったものをその場で報告）、docx の package 構造を確かめ、読めない package は黙って渡さず警告し、docx の版面 QA を走らせ、再計算で `#REF!` と `#NAME?` を拾う。**計 6 種のシグナル**で、いずれも `Office:` を冠して tool output に入る —— **Agent が使用者より先に気づき、尋ねられる前に直す**。
- **版が得られるので、undo キーだけでは足りない**: 成果物は不変の版であり、書き直して失敗した版は任意の過去の版へ戻せる。作業領域のファイルにはさらに shadow Git スナップショットとワンタッチ rollback がある。
- **表計算はブラウザでそのまま編集できる**: 数式は往復しても保たれ、マクロ・グラフ・ピボットテーブルを含むファイルは手を触れる前に失われるものを警告し、記録前の下書きはクラッシュ後も復元できる。
- **渡すのは素のファイルではなく読める成果物**: 装飾つきの Excel はテーマエンジンから（タイトル行、斑の行、罫線、数値書式）、スライドは描画パイプラインから生成されるので、どの Office でも正しく開ける。

**競合の実態（2026-10-22）**: Herald OS —— Word、Excel、PowerPoint を自分自身の OS に入れたコミュニティプロジェクト —— の**読む側**の保真は確かに実りがある。表計算の層は、一般的なライブラリが落とすデータ検証、抽出条件、リンク、定義名、テーマ、グラフ、ピボットテーブル、スライサー、図形を保持し、Office package 自体も点検する。ただし「壊れた書き直し」の安全網は**編集画面の undo スタック**であり、ソース全体を探しても「書き込みごとのスナップショットと差分の提示」機構は見つからなかった。また我々も「オフィス製品として競う」点では強くない。常駐する文書編集画面とスライド編集画面は向こうが持ち、我々は持たない —— **その欄は正直に相手のもの**である。

## 13. 作業は見えて、Agent は自分で承認できない

マルチエージェントと長時間処理でいちばん不安なのは「遅い」ことではなく、**何をしているか分からない**ことです。承認も同様で、答えが「はい」一つなら、実際に同意したものが実行されるものとは限りません。

**私たちの強み**:
- **動いているサブエージェントがそのまま見える**: チャット内の同時実行スイムレーンバー（`myrm-agent-frontend/src/components/features/chat-window/in-flight-steer/ActiveSubagentSwimlanesBar.tsx`、`ChatWindowSatellites.tsx:37` でマウント）に、どのエージェントが動いているかが表示され、その場で操作できます。
- **会話を探すためにスクロールしなくてよい**: サイドバーの固定会話はドラッグで並べ替えでき（`ChatHistoryList.tsx:224`/`:248`、保存は `src/services/chat.ts:1379`）、時間グループは折りたためます（`:29`/`:222`）。
- **承認したバージョンがそのまま残る**: すべての承認は承認されたペイロードそのものを保存し（`app/database/models/approval.py:34`）、動作種別（`:27`）とリスク等級（`:31`）を併記します。
- **期限切れで默認にはなりません**: 応答のない承認は期限到来時に自動拒否され、その理由が記録され（`app/services/approvals/registry.py:43-72`）、停止していたエージェントは harness 側で再開されます（`:45`）。
- **資格情報は付いて歩きません**: 子プロセスは既定で資格情報を含む環境変数を継承せず（`myrm-agent-harness/.../code_execution/security/env_isolation.py:37`/`:110`、`shell_bleed.py:55`、`blacklist.py:290`）、デスクトップ専用の指示は実際にデスクトップ操作が必要なときだけ注入されます（`app/ai_agents/general_agent/mount_resolver.py:54`/`:41`）。
- **正直な境界**: 「承認は Agent の外で行う」「実行されるのは承認したあのペイロードである」は現在もロードマップ上の項目です（`topic_03 #458`）。改ざん耐性があるとは主張しません。

**競合の実態確認（2026-10-22）**: Hermes Desktop のメIntyreが「最近は安定してきたか」を公開で問い、104 件の返信の中で最も刺さったのが **サブエージェント実行中にサイドバーの「進行中」表示が消える**というもので、メインタビューは「その通り、UX で改善できる」と replied しています。メッセージが二重表示される、資格情報変数がターミナルに漏れる、といった報告もあります。コミュニティには、コーディング Agent が**自ら `.env` を公開ホスティングに公開**して鍵が漏え、**9 万ドルの外部請求**になった実測スクリーンショットも流通しています。私たちの差は「承認がある」ことではなく、**承認が見え・そのまま残り・静かに失効しない**ことです。


## 14. エージェントは今日すでに自分の ID を持つ — 22.7 万ドルの TLD を待つ必要はない

Agent に「インターネット上の自分の居場所」を与える最も大きな方法は、最上位ドメインを押し付けることです。ドメインには価格と待機列があります。

**私たちの強み**:
- **ID カードはすでに存在**: AgentCard は表示・即時取消・監査が可能で、Agent の内部設定を漏らしません（`app/services/a2a/card_generator.py:60`）。
- **門は誰にでも開いていません**: 外部からのトラフィックはエージェント単位の有効スイッチ（`app/database/models/agent.py:79`）と信頼ピアのホワイトリスト（`:80`）で検証されます。リストに無いピアは黙って信じられるのではなく、**まず承認キューに入ります**（`app/api/a2a/router.py:97`/`:126`）。
- **短いアドレスはすでにあるものから導けます**: 読みやすい識別子はシステムに既に存在します（`app/services/plugins/agent_surface.py:291`、harness 側は `ai.myrm/agents/<slug>.md` という命名）。よって短いアドレスも独自ドメインもそこから導けます — ドメイン購入費用も待ち時間もありません。
- **私たちも TLD は買いません**: これは意図的なトレードオフです。

**正直な境界**: 読み取り可能な**公開アドレスは設計済みで未出荷**です（`topic_13 #91` はまだ `待分析`）。「トップレベルドメインを買わず代替案を設計した」とは言えますが、「Agent はすでに公開の短いアドレスを持つ」とはまだ言えません。

**競合の実態確認（2026-10-22）**: OpenClaw 財団は ICANN 2026 ラウンドの `.claw` 申請に勝利したと発表しました。公式公示は **Application ID `OF2656T-T69841`**、段階は **`Pre-Evaluation Processing`**、費用は **22.7 万ドル**、ルート登録は **2027 年末〜2028 年初**の見込みで，而且**自社リポジトリには到现在 TLD / DNS の実装が 1 行も存在しません**（`.claw` のヒットはすべて `claw` という語根の偽陽性）。コミュニティで最も鋭い質問は「登録の条件は何ですか。私が自分で `.dsb` のようなトップレベルドメインを登録できますか」でした。個人や小規模チームにとって答えは「無理」です。**私たちは今日すでに ID を与え、あなたの手元のドメイン上で完結します。**
