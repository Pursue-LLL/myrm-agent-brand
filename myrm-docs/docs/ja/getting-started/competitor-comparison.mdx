# 競合製品との比較・移行ガイド

Myrmは、完全なAIエージェント統合ワークスペースとして設計されています。ターミナル専用のコーディングエージェントとは異なり、Myrmはコーディング能力をフルに維持しながら、永続サンドボックス、クロスセッションメモリ、そしてエンタープライズグレードの堅牢なセキュリティを備えたGUIファーストの体験を提供します。

<Note>
**移行における安心ポイント** — SaaS・セルフホスト・デスクトップから自由に選択でき、HermesのスキルはGUI経由のZIPで直接インポート可能です。以下の詳細比較表でチャンネル・メモリ・セキュリティを行単位で確認した上でご検討いただけます。Grok Buildなどのプラグイン中心の製品をお使いの場合、Myrmはモデル・スキル・MCP・サブエージェント・安全プロファイルを**ワンクリックで一括セットアップ**するエージェントパッケージを提供します。ドキュメントとアプリは**6言語**(zh/en/ja/ko/de/zh-TW)に対応しており、WebUI・クラウドホスト・Tauriデスクトップのすべてで、初回アクセス時にブラウザ言語を自動判別します。
</Note>

## vs OpenCode（anomalyco/opencode）— オープンソース・ターミナル型コーディングAgent

OpenCodeは堅実なMITライセンスのターミナル型コーディングAgentです。TUIネイティブでマルチプロバイダ対応、起動も高速です。しかし意図的に搭載していないのは「その周辺のワークスペース」——メモリ、GUI、自動化、ガバナンスです。そのためコーディング以外のあらゆるニーズが、ひとつの統合プロジェクトへと膨らんでいきます。

### Myrmの優位点

| 領域 | OpenCode | Myrm | ユーザーにとっての価値 |
|------|----------|------|------------------------|
| **内蔵Agent数** | ネイティブ**4個**（`build`、`plan`、`general`サブエージェント、`explore`サブエージェント。`packages/core/src/agent.ts` · `packages/core/src/plugin/agent.ts` · `packages/core/src/plugin/plan.ts`(v2.0.32)にて確認） | **内蔵28 Agent**（コア5 + 検索2 + 拡張5 + 垂直16）+ GUIギャラリー + カスタム作成 | 調査・設計・データ可視化・動画スタジオなど、完成済みの役割をそのまま選択でき、汎用Agentをひとつ手作業で調教する必要がありません。 |
| **メモリとナレッジ** | **皆無**——リポジトリに認知メモリのサブシステムが存在せず（`environment/memory.ts` はテスト用のインメモリファイルドライバのみ）、毎回ゼロから開始 | **8種のホワイトボックスメモリ + Wikiナレッジベース + 3Dトポロジーグラフ + カスケード忘却** | Agentが数週間にわたって取り決め・意思決定・過去の失敗を記憶し、知識が再利用可能な資産として蓄積されます。 |
| **インターフェースと到達範囲** | ターミナルTUI + 黎明期のElectronデスクトップBeta、**IMチャンネルは皆無** | **レスポンシブWebUI + ネイティブTauriデスクトップ + 26のIMチャンネル** | 非開発者でも扱え、ターミナルに張り付かずスマートフォンから承認できます。 |
| **自動化** | 手動起動のみ、スケジューラなし | **19+ Cron API + チェーンタスク + ハートビート監視 + チャンネルプッシュ** | 定例レポートやメンテナンスが無人で実行され、普段使うチャンネルへ通知されます。 |
| **タスクガバナンス** | 単一セッション、看板も承認ゲートもなし | **看板9状態ライフサイクル + IN_REVIEW人的承認 + 動的Live Steer** | 長距離の多段タスクが可視化・監査可能なまま進行し、不可逆な操作の前に人的ゲートが入ります。 |
| **セキュリティの深層防御** | 設定ファイル駆動の`permission`ルールセット（単層） | **6層縦深防御 (L1–L5.5) + PIIマスキング + テイント追跡 + YOLO相互排他** | プロンプトインジェクションやConfused Deputyによる権限昇格を、設定による抑止ではなく物理的に遮断します。 |
| **プロバイダ自由度** | provider設定で75+モデルに対応 | **100+モデル + 自動複雑度ルーティング** | 日常のターンは自動的に低コストモデルへ、フロンティアモデルは真の推論にのみ使用されます。 |

**移行結論：7項目のアップグレード、ダウングレード0項目。** OpenCodeのコーディング能力はそのままに、メモリ、GUI、スケジューリング、マルチチャンネル到達、縦深防御を追加で獲得できます。そうでなければ「OpenCode + メモリプラグイン + cronスクリプト + 承認ラッパー」を自前で組み立てる必要があります。

## 日本の企業ユーザー・開発者からのよくある疑問と誠実な技術回答

### Q1: クラウド型SaaSとローカルデスクトップ版のセキュリティの違いは何ですか？
**A:** Myrmは「ユーザーデータ主権」を最優先に設計されています。ローカルWebUIおよびTauriデスクトップ版では、すべてのコード実行、SQLiteデータベース、ベクトルインデックスはお客様自身のマシン内で完結し、外部送信されるのはユーザーが設定したAPIキー経由のLLMプロンプトのみです。クラウドホスト版においても、他社のようなマルチテナント型共有DBではなく、ユーザーごとに完全に物理分離された独立サンドボックスと暗号化Volumeをプロビジョニングするため、企業秘密やソースコードの混入リスクはゼロです。

### Q2: 長時間の自律ミッションでAPI費用が高騰する心配はありませんか？
**A:** Myrmには独自の**仮想カード動的バジェットガード**と**Pre-compactゼロLLM直接注入**が備わっています。タスクごとに上限予算を設定でき、しきい値到達時に自動で人間への承認(HITL)を要求します。また、長時間の会話圧縮時に不要なLLM要約推論をバイパスするため、競合製品と比較してコンテキスト管理コストを最大85%削減できます。

### Q3: モバイルからのリモート操作は安全ですか？
**A:** はい。Mobile Hubは暗号化されたScoped Pair Token(セッション単位の短命トークン)を使用しており、認証されていない端末からの操作は一切受け付けません。また、Myrm公式がお客様の通信データを中継・保管することはありません。お客様ご自身のHTTPSトンネル(Cloudflare Tunnel等)経由で直接ローカルバックエンドと通信します。
