# 競合製品との比較・移行ガイド

Myrmは、完全なAIエージェント統合ワークスペースとして設計されています。ターミナル専用のコーディングエージェントとは異なり、Myrmはコーディング能力をフルに維持しながら、永続サンドボックス、クロスセッションメモリ、そしてエンタープライズグレードの堅牢なセキュリティを備えたGUIファーストの体験を提供します。

<Note>
**移行における安心ポイント** — SaaS・セルフホスト・デスクトップから自由に選択でき、HermesのスキルはGUI経由のZIPで直接インポート可能です。ドキュメントは**3言語**(en/zh/ja)、アプリUIは**6言語**(zh/en/ja/ko/de/zh-TW)に対応しており、すべてのデプロイモードで初回アクセス時にブラウザ言語を自動判別します。
</Note>

<Note>
**所有権が本当の違いです。** Myrm の WebUI、API サーバー、Agent ハーネス、Tauri デスクトップシェルは **MIT ライセンス**です。専有なのは任意の SaaS 制御プレーンだけです。監査性、セルフホスト、低い退出コストが移行理由なら、この点はリポジトリで直接確認できます。
</Note>

## 推論過程：可視・停止・再生

- **リアルタイムストリーミング**：推論デルタがアシスタントメッセージにリアルタイムで添付されます。
- **停止可能**：「思考停止」で早期終了し、既知の情報で回答。10秒タイムアウト。
- **折りたたみ**：回答開始1秒後に折りたたまれ、いつでも展開可能。
- **実トークン**：プロバイダ報告の `reasoning_tokens` を優先、不可能な場合のみ `≈` 推定。
- **6言語 + 40px タッチターゲット**、完全ローカライズ。

## モデルルーティングと出所追跡

- **本番2ルーティングエンジン**：タスク複雑度(SIMPLE / STANDARD / REASONING)とタスク専門性(CODE / LONG_DOC / REASONING / MULTIMODAL / CASUAL / GENERAL)。
- **回答ごとの出所**：使用量パネルに実際のモデル、ルーティング段階、専門性、理由、コストを表示。
- **Agent単位で有効化**：Smart Routingで軽量/推論モデルを選択後に有効化（3つのPareto プリセット付属）。
- **決定論的承認**：承認の必要性はルールで計算、分類器ではない。不可逆操作に「常に許可」なし。

## 委任：離れて、戻って結果を確認

- **耐久性のあるバックグラウンド作業**：オフラインタスクは再起動後DBから復旧。デスクトップは長時間タスク中のスリープを防止。
- **完了通知**：26チャネル + アプリ内通知 + Catchup受信箱。
- **空の報告なし**：cronジョブの `[SILENT]` 契約。

## スキル品質

- **出荷済み**：3状態帰属(selected / used / observable)、26カテゴリ / 113パターン静的スキャン、権限テンプレート、段階的開示。
- **プロジェクトスキル**：ワークスペースの `SKILL.md`（深度3）を自動検出、信頼ゲート付き。`.claude/skills/` 互換。

## Agentチーム：検証優先

- **出荷済み**：5チームテンプレート、Kanban タスクDAG、shell/セマンティック検証、26チャネル完了通知、Fleet KPIボード。

## 複雑なタスク：完了条件・独立検証・構造化された引き継ぎ

| 断絶点 | ユーザーが実際に遭遇する問題 | Myrm の現状 |
|---|---|---|
| 完了条件がない | "vague asks are where they all fall apart" | Kanban タスク DAG + 編集可能な完了条件。基準未達なら pause |
| Agent が done と言うが done ではない | "all 6 said done, none passed every hidden test" | CompletionVerifier：shell のハードチェック + セマンティック判定。モデル自身は完了を宣言できない |
| セッションが切れると失われる | "most agents restart cold every run" | 永続セッションログ + コンテキスト圧縮 + ACP CLI セッション再開 |
| 進行中タスクの登録簿がない | "one registry of everything in flight so nothing gets built twice" | Kanban タスクグラフ + 依存関係/owner + heartbeat/zombie 検出 |
| 引き継ぎで情報が失われる | "each interaction the idea gets lost" | AgentHandoverState + Kanban handoff metadata |
| 人がボトルネックになる | "more permissions requested, intervention more often" | 3段階の自律性（strict / semi-auto / full-auto）+ TOTP 金庫 + モバイル HITL |
| Agent が自分の環境にいない | "you must control the substrate" | ローカル WebUI / Tauri デスクトップ / ユーザーごとのサンドボックス + 永続ボリューム |

## Personal Agent 時代：Myrm vs Muse / Today / GrokBot / Instinct / Dots

クローズドな Personal Agent（Meta Muse、Today、xAI GrokBot、Instinct、OpenAI Dots）は「感情的体験」と「ゼロ設定」を高い水準で実現しています。Myrm が重視するのは**所有権・制御・拡張性**です。正直に言うと、今日もっとも成熟したコンシューマー向け伴走体験だけを求めるなら、Muse/Today は 3D アバター、静かな返信、メッセージへのリアクション、呼称の儀式、単一アシスタント表現で先行しています。これらはロードマップ（#496 / #497 / #498 / #89）にあり、出荷前は「対応済み」と主張しません。

| 観点 | Myrm Agent | クローズド Personal Agent |
|---|---|---|
| **ソースとホスティング** | WebUI、API サーバー、Tauri デスクトップ、harness は MIT ライセンス。ローカル/プライベートに自前ホスト可能 | クローズドなクラウド/アプリ。モデルとデータ経路はベンダーが管理 |
| **デプロイ** | ローカル WebUI、Tauri デスクトップ、ユーザーごとのクラウドサンドボックス。1 つのサーバーで 3 モード | 多くはクラウドのみ、または単一デスクトップクライアント |
| **モデルとコスト** | BYOK、100+ プロバイダー、ローカルモデル、スマートルーティング、プロンプトキャッシュ | モデル選択は非表示/固定。サブスクリプション段階 |
| **データ** | ローカル/デスクトップのデータは端末内。クラウドはユーザーごとの永続サンドボックス | ベンダーのクラウド。保持/学習ポリシーはベンダー次第 |
| **永続コンピューター** | ブラウザ、ターミナル、ファイル、インストール済みソフトがセッションを跨いで残る | 多くはベンダーアカウントに紐づくクラウド PC |
| **記憶** | 8 種類の記憶、ホワイトボックスで編集可能、競合レビュー、エクスポート/インポート | 多くはブラックボックス。エクスポートは稀 |
| **マルチエージェント** | 設定可能なエージェント、個別記憶 + 共有記憶、既定のメイン Agent を Web/定時/チャネルに紐付け | 通常は単一アシスタント。マルチ Bot は設定難度が高い |
| **拡張** | スキルマーケット、段階的開示、進化/権限ゲート、MCP | 組み込みスキル/プラグイン。拡張面はベンダー管理 |
| **安全性** | 多層権限、HITL 承認、サンドボックス分離、資格情報 Vault、監査 | アカウント単位の安全が中心。アクション単位の承認は製品次第 |
| **チャネル** | 26 チャネル（Telegram、Slack、Discord、Feishu、WeChat、メールなど） | 通常は少数の主要チャネルのみ |
| **可観測性** | Token/コスト HUD、OTel トレース、Eval Lab、Doctor 診断 | 利用量ダッシュボード。コスト/品質は不透明なことが多い |

### 移行時に持ち込めるもの

| 移行元 | 持ち込める | 持ち込めない |
|---|---|---|
| Muse / Today / GrokBot / Instinct / Dots | モデルキー、`SKILL.md` スキル、MCP、プロンプト、チャネル | ベンダー固有の記憶、Bot 関係、サブスク内の計算資源 |
| Hermes / OpenClaw | スキル ZIP、MCP、`USER.md` / 記憶ルール、BYOK キー | ベンダー固有のプラグイン/ランタイム |
| Codex / Claude Code | BYOK キー、MCP、プロジェクト文脈 | IDE 専用ワークフロー |

> クローズドな Personal Agent には公開された記憶/Bot のエクスポート形式がなく、**ワンクリック移行はありません**。キー、スキル、MCP、プロンプト、チャネルを引き継ぎ、記憶と Bot 関係は再構築する必要があります。誇張はしません。

### クローズド Agent を Discord で動かす（Muse / Grok Bot のコネクタ）

Muse と Grok Bot に公式の Discord 入口はありません。ユーザーはコミュニティ製コネクタを導入し、開発者ポータルでアプリを作成し、特権 Intent（Message Content）を手動で有効化し（無効だと静かにメッセージを受信できない）、Bot Token をチャットに貼り付けます。権限は「本人」と「その他」の二段階で、本人がチャットで頼むと他メンバーに Web 検索や画像生成を開放します。長いタスクは完了まで無反応で、割当量はベンダー側が決めます。

Myrm はチャネルを製品機能として扱います（ブリッジではありません）：

- **20+ の内蔵チャネル**（Slack、Discord、Telegram、Feishu、WeChat、WeCom、DingTalk、WhatsApp、メールなど）。記憶・承認・成果物・タスク状態を共有し、Discord はスレッド、Forum、ネイティブ返信、音声に対応。
- **人ごとの統制**：ペアリングの役割（admin/member）と送信者ごとの 1 日あたりメッセージ割当。未ペアリングの送信者は制限付きゲスト身分に降格。
- **信頼できないターンの実行時フェンス**：ゲスト・未ペアリング・非管理者メンバーには shell、ファイル書込、記憶書込、デスクトップ操作、サブ Agent、cron、スキル管理を物理的に剥奪。
- **長いタスクが見える**：無音が続くと進行中メッセージを 1 回出し、経過時間をその場で更新。
- **承認はチャット内**：使い捨て確認トークン。社会的に不可逆な操作に「永久に許可」はない。
- **成果物を開ける**：ワークスペースのファイルはネイティブ添付になり、HTML/PDF レポートには署名付き共有ボタンが付き、同じ成果物バージョンに着地。
- **データは自分のもの**：Local WebUI / Tauri デスクトップ / クラウドサンドボックスの 3 形態、BYOK、記憶と資格情報は自分の環境に残る。

**未提供（対応済みとして扱わない）**：ゲストターンの読み取り面の分離（ファイル読み取りとログイン済みブラウザ文脈）、IM 内のマスクされた秘密入力、`/voice` 以外の Discord ネイティブスラッシュコマンド、Discord 接続の構造化プリフライト（Intent/権限/招待）。いずれも roadmap に登録済みで、実装までは「書込と操作のフェンス」までを主張できます。

## 移行で得られるもの

移行は「チャット履歴を移す」ことではなく、五つの分断されたツールを、記憶・制御面・退出経路を持つ一つのワークスペースに置き換える機会です。

| 置き換えるもの | Myrm が提供するもの | 残せるもの |
|---|---|---|
| 閉鎖型 Personal Agent（記憶とモデルをベンダーが管理） | MIT の製品レイヤー、BYOK、ローカル/デスクトップ/クラウド、26 チャネル | モデルキー、`SKILL.md`、MCP、プロンプト、ルール。ベンダー固有の記憶と Bot 関係は再構築 |
| CLI コーディング Agent + メモリプラグイン + cron スクリプト | チャット、ファイル、ブラウザ、コード、Office 成果物、Kanban、予約タスクが一つのセッションモデルを共有 | 設定済み CLI は ACP 経由で委任を継続。コーディングの深さは維持 |
| ホステッドメモリ（全 Agent が一つのベクトルストアを共有） | ユーザーごとの独立サンドボックスとローカル記憶、競合レビュー、編集/削除/エクスポート、CJK キーワードフォールバック | 対応形式はインポート可能。カスタムデータはメモリ API → 再インデックス → 競合チェック |
| 監査証跡のない自動化スクリプト | 決定論的権限、承認カード、差分、シャドウ Git スナップショット、ワンクリックロールバック | 高リスク操作は人間承認のまま。通常の書き込みはデフォルトでスナップショットなし |

**正直な境界:** 閉鎖型 Personal Agent には公開された記憶/Bot 形式がないため、真のワンクリック移行は存在しません。移植可能な資産を持ち帰り、私有部分を再構築するのが現実です。

## 競合が今も強い領域

自社の強みだけを語る比較表はパンフレットであり、比較ではありません。**2026-11** 時点で、以下は当社がリードを主張しない領域です。

| 領域 | 現在強いのは | ユーザーへの意味 |
|---|---|---|
| **純粋なコーディング深度** | Claude Code、Codex、ターミナル優先の Agent | 作業の 90% が IDE でのコード編集なら、まずそれらを使うべきです。Myrm は仕事を囲むワークスペースであり、すべてのコーディングベンチマークで勝つという主張ではありません。 |
| **型を解決するコードナビゲーション** | DeepSeek-Harness（`lsp` ツール）、OpenCode（ドキュメントに記載の実験的 `lsp` ツール） | 言語サーバーは型を解決し、サーバーを入れた言語なら何でも扱えます。Myrm には組み込みのコードナビゲーションツールはなく、grep と glob で検索し、シンボルや呼び出し経路の照会が必要なときは統合カタログのコードグラフ MCP サーバーを接続します。多言語にまたがる正確な参照が必要なら、まず向こうの言語サーバーツールを使ってください。 |
| **Git worktree やリポジトリからのタスク開始** | OpenClaw、OpenCode | 向こうの新規セッション画面は、タスクを隔離された Git worktree に配置でき、OpenClaw は貼り付けたリポジトリ URL からも開始できます。Myrm の新規タスクカードで選べるのはローカルワークスペース、クラウドサンドボックス、ワークスペースなしの 3 つで、この段階に worktree やリポジトリの配置先はありません。 |
| **ネイティブのスマートフォンアプリ** | OpenClaw | OpenClaw は macOS、iOS、Android、Windows、Linux 向けのネイティブアプリを提供しています。Myrm のスマートフォン向けはインストール可能な Web アプリ（PWA）です。 |
| **情緒的な演出とゼロ設定の初回体験** | Muse、Today、GrokBot、Instinct、Dots | 3D 表現、落ち着いた応答、呼称の儀式、メッセージ反応、消費者向けの初回体験は向こうが上です。一部はロードマップ上で、未出荷です。 |
| **ハードウェアとオープン SDK** | Hermes Gadget | Hermes にはオープン SDK、デスクトップシミュレータ、ボード別検証マトリクスがあります。当社はファームウェアを作らず、存在しないハードウェア対応を宣伝しません。 |
| **プラグイン/スキル生態系の規模** | OpenClaw、Hermes | 第三者プラグインとスキルの数は向こうが多い。当社はインストール前スキャン、権限ゲート、段階的開示、ロールバックで比較します。 |
| **閉鎖型製品からのワンクリック移行** | どこも無い、正直に | 閉鎖型 Personal Agent は移植可能な記憶/Bot 形式を公開していません。他社の私有記憶をワンクリックで取り込めると主張する製品には、まずエクスポートファイルを求めるべきです。 |

**表の読み方:** `✅` は製品/ソースで確認できた能力、`—` は今回の検証範囲外であり、競合に無いという証明ではありません。

## 移行パス

| 移行元 | 方法 |
|---|---|
| **Hermes** | スキルをZIPでエクスポート → Myrm GUIウィザードでインポート。BYOKモデルとMCPツールはそのまま使用。 |
| **OpenClaw** | ワークスペースコンテキスト(USER.md)をMyrmメモリルールにマッピング。MCPサーバーは直接再接続。 |
| **Codex / Claude Code** | CLIワークフローをGoal Mode + cronにマッピング。BYOK APIキーはそのまま移行。 |
| **DeepSeek Harness** | BYOKモデルとMCPツールはそのまま使用。DSH固有プラグインは `SKILL.md` またはMCPとして再マウントが必要。 |

> Myrmは**SaaS**、**セルフホストWebUI**、**デスクトップ**で実行できます。スキルとメモリはGUI移行ウィザードで移行できます。

## メモリ基盤：Myrm vs ホステッドメモリサービス（GBrain）

GBrain（2026-10）は「ホスト型 Postgres + pgvector のメモリを任意の Agent から使う」サービスです。セットアップ摩擦の小ささは本物ですが、全 Agent が 1 つの共有ベクトルストアをアプリ層のスコープで共有する構造で、これは同サービスのコメント欄でも最も懸念されている点です。

- **構造としての分離**：Myrm のメモリはユーザーごとの独立サンドボックス（専用 SQLite + 専用ベクトルインデックス）に保存され、共有ストアをスコープで区切る必要がありません。
- **書き込みガバナンス**：矛盾する書き込みはレビュー待ちキューに入り、高リスクの矛盾は自動解決しません。削除はアーカイブ経由で、物理削除は明示操作です。
- **移行コスト**：ベクトルインデックスは再構築可能（見積 → 実行 → 状態）で、メモリ書き出しには SHA-256 検証が付きます。
- 正直な差分：「リンクを貼るだけで Agent が自己設定」は、当社の「設定スニペットをコピー」より滑らかです。当社は可搬な Agent Plugins バンドルと手順を提供していますが、取得可能なマニフェストは未提供です。

## 更新と復旧：Myrm vs OpenClaw v2026.10.9

OpenClaw のパッチ版はアップデート失敗の修正に集中しています（ローカル変更を保持するロールバック、古いインデックスの誤判定防止、停止状態を残さない再起動）。優先順位としては妥当です。

当社の位置づけも正直に書きます：**データ層はより強く**（ページ単位サルベージ、チェックサム付きバックアップ、取り消し可能な状態スワップ）、一方でソース/CLI のアップデータは依然として単純な git pull で、ステージ検証やロールバックはありません。段階的アップグレード、バージョン間回帰ゲート、ロールバック導線はロードマップ（#167 / #215 / #478）であり、出荷までは提供済みとは謳いません。
