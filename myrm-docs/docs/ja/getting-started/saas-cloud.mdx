# SaaS クラウド

ホスト型の SaaS プランは、隔離された per-user サンドボックスを提供し、DevOps の負担はゼロです。

## はじめかた

1. [app.myrmagent.ai](https://app.myrmagent.ai/auth/login) にアクセスします
2. メールまたは OAuth でアカウントを作成します
3. そのままメッセージを送信して会話を始められます

<Tip>
**設定なしで会話開始 (Express Lane)**: 新規ユーザーは API Key の設定が不要で、プラットフォームがホスト型のモデルを用意しています。無料枠を使い切った後は、フロントエンドが設定画面で自分のキーを登録すれば無制限に利用できます。
</Tip>

## Work Units

すべての SaaS 利用量は、統一された **Work Units (WU)** 残高で課金されます。

| プラン | WU/月 | 価格 |
|--------|-------|------|
| Free | 600 + 毎日 50 リフレッシュ | $0 |
| Companion | 2,500 | $19/月 |
| Plus | 5,000 | $42/月 |
| Pro | 12,000 | $49/月 |
| Max | 22,000 | $149/月 |

WU の消費規則は [Work Units](/ja/core-concepts/work-units) を参照してください。

### 請求の透明性パネル

**設定 → アカウント** に入れば、請求の透明性パネルがすべて確認できます。

- **サブスクリプション WU の進捗バー** — 月次クォータの残量をリアルタイム表示
- **チャージ残高** — 购买的 WU 残高をサブスクリプション枠と分けて表示
- **毎日リフレッシュ枠** — 毎日付与される WU の数量（Free プランは 50 WU/日）
- **無料モデル一覧** — WU を消費しないモデルを列挙
- **倍率の公開カード** — 各モデル階層の WU 消費倍率を公開
  - **LITE**（DeepSeek-V3、Gemini Flash など）— 1× WU/token
  - **STANDARD**（GPT-4o、Claude Sonnet など）— 3× WU/token
  - **FRONTIER**（Claude Opus、o3 など）— 10× WU/token
- **価格モデルの解説** — Myrm の BYOK per-token 方式と、Claude Code（セッション単位）、Cursor（月額パッケージ）、Codex（補完単位）の課金違いを比較
- **信頼性の信頼バー** — 承認ワークフロー、PDV 機構、説明可能性の機能へリンク

<Tip>
これは AI Agent 市場で最も透明な課金パネルです。隠れた倍率も、予期しない請求もなく — すべての WU 倍率は代表モデルと一緒に公開されています。
</Tip>

## データとプライバシー

- 各ユーザーには隔離された永続化サンドボックスボリュームが割り当てられます
- API Key は暗号化された保管庫 に保管されます（AES-256-GCM 暗号化 + キーローテーション）
- 詳細は[プライバシーポリシー](https://myrmagent.ai/privacy)をご覧ください

## エンタープライズ基盤

ホスト型 SaaS プラットフォームは 21 層のエンタープライズ基盤の上に構築されています。

| レイヤー | 能力 |
|----------|------|
| 分離 | Per-User の独立サンドボックス + 専用 Volume（プロセス共有型のマルチテナントではない） |
| クォータ | 3 層のリソースクォータ（per-user / per-sandbox / per-task） |
| レート制限 | 設定可能な per-resource / per-user の速度制限 |
| ネットワーク | 送信制御 + コマンドホワイトリスト |
| 鍵 | AES-256-GCM の暗号化保管庫 + キーローテーション |
| 認証 | OAuth/OIDC + エンタープライズ JWT ライセンス検証 |
| 監視 | フリート健全性監視 + 失敗しきい値アラート |
| プロセスライフサイクル | tini PID-1 ガバナンス: ゾンビプロセスの回収 + シグナルの正規転送、CAP_KILL による降格子プロセスのクリーン終了、seccomp の完全なシステムコールホワイトリスト（253 syscall、Docker 公式ベースライン準拠）により、サンドボックスが PID 枯渇で固まらない |
| 可観測性 | Prometheus エクスポート + マルチテナントメトリクス集約 + 入方向 X-Trace-Id / W3C traceparent の自動伝播（リバースプロキシ / API ゲートウェイを跨いだ分散トレースが切れない） |
| 復旧 | 状態リコンシgliator（DB / コンテナ / WS の 3 者整合性検証） |
| 伸縮 | リソーススケーラー（アイドル時の CPU 周波数の低減）+ サンドボックス回収機（2 種のアイドル検出: プロキシのアクティブ同期 + WS 接続ガード） |
| 監査 | 完全な監査ログ（24 種のイベント）+ 可視化ダッシュボード（KPI カード、タイムシリーズ、イベント分布）+ CSV/JSON エクスポート |
| コスト管理 | 組織使用量の集計（メンバー順位 + カテゴリ統計）+ 設定可能な月次予算としきい値アラート |
| Org MCP | エンタープライズ IT が Enterprise 設定で CRUD / 編集、HTTP でメンバーサンドボックスへ配信、休止からの復帰時に自動再配信、クラウド環境では stdio MCP を禁止、従業員は組織管理リストを読み取り専用で確認 |
| セキュリティ | 緊急停止スイッチ（Killswitch） |

940 件以上の基盤テストがすべて成功しています。
