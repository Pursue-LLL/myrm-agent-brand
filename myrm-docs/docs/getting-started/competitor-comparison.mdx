# Competitor Comparison & Migration Guide

Myrm is designed as a complete AI agent workspace. Unlike terminal-only coding agents, Myrm provides a GUI-first experience with persistent sandboxes, cross-session memory, and enterprise-grade security — all while maintaining full coding capabilities.

## Reasoning: visible, stoppable, replayable

Most agents leave a static skeleton while the model thinks. Myrm makes the chain part of the message:

- **Live**: reasoning deltas stream into the assistant message with a real-time timer.
- **Stoppable**: "Stop thinking" ends reasoning early and answers with what is known; bounded to 10 s so the button cannot get stuck.
- **Collapses once** (1 s after the answer starts) and stays reopenable.
- **Real tokens**: provider-reported `reasoning_tokens` first, an explicit `≈` estimate only as a fallback.
- **Three persisted modes**: `off / collapsed / inline`; `off` stops the server from sending reasoning at all.
- **6 languages + 40 px touch targets**, fully localized copy and ARIA labels.

## Model routing & provenance

Most agents pick a model for you but do not tell you which one answered. Myrm exposes the routing decision per answer:

- **Two routing engines in production**: task-complexity routing (SIMPLE / STANDARD / REASONING) and task-specialty routing (CODE / LONG_DOC / REASONING / MULTIMODAL / CASUAL / GENERAL), each with a fallback chain.
- **Per-answer provenance**: the usage popover shows the actual model, routing tier, task specialty, routing reason, and cost.
- **Opt-in per Agent**: pick light/reasoning models under Smart Routing (3 Pareto presets ship configured). Not default-on for every Agent.
- **Deterministic approvals**: whether an action needs your approval is computed from rules, not by a classifier. Spend and irreversible actions have no "always allow" button; a secret typed into the masked card is bound to one command and consumed once.

## Hands-off delegation

The most common complaint about always-on agents is babysitting. Myrm is built to be left alone:

- **Durable background work**: offline tasks survive disconnect/restart and are resumed from the database; the desktop keeps the machine awake.
- **Completion reaches you**: 26 channel providers, in-app notifications, and a Catchup inbox.
- **No empty pings**: cron jobs support a `[SILENT]` contract.

## Skill quality

Installing a skill adds text to the context — it does not change the model. The real question is: did the agent follow the skill, and did that improve the result?

- **Shipped**: three-state attribution (selected / used / observable), 26-category / 113-pattern static scanning, permission templates with a skill doctor, progressive disclosure.
- **Project-scoped skills**: any `SKILL.md` under the workspace (depth 3) is discovered with a trust gate and an SQLite snapshot. `.claude/skills/` works as-is.

## Agent teams: verification over headcount

Competitors market agent counts. Agent count is not capability — **a team that cannot verify its work is just noise**.

- **Shipped**: 5 team templates, Kanban task DAG, goals acceptance criteria with shell/semantic checks, completion delivery over 26 channels, fleet KPI board.
- Unattended approvals are bounded to a declared capability set.

## Complex work: completion, verification, handoff

| Breakpoint | What users hit | Myrm today |
|---|---|---|
| No definition of done | "vague asks are where they all fall apart" | Kanban task DAG + editable completion criteria; goals pause when criteria fail |
| Agent says done, but isn't | "all 6 said done, none passed every hidden test" | CompletionVerifier: shell hard checks + semantic judge; the model cannot declare done by itself |
| Context dies with the session | "most agents restart cold every run" | Durable session log + context compression + ACP CLI session resume |
| No in-flight registry | "one registry of everything in flight so nothing gets built twice" | Kanban task graph with dependencies, owners, heartbeat/zombie detection |
| Handoff loses fidelity | "each interaction the idea gets lost" | Structured AgentHandoverState + Kanban handoff metadata |
| The human is the bottleneck | "more permissions requested, intervention more often" | 3-tier autonomy (strict / semi-auto / full-auto), TOTP vault, mobile HITL |
| Agent is not in your environment | "you must control the substrate" | Local WebUI, Tauri desktop, per-user sandbox + persistent volume |

## Migration path

| From | How to migrate |
|---|---|
| **Hermes** | Export skills as ZIP → import via Myrm GUI wizard. BYOK models and MCP tools carry over. |
| **OpenClaw** | Workspace context (USER.md) maps to Myrm memory rules. MCP servers reattach directly. |
| **Codex / Claude Code** | CLI-oriented workflows map to Goal Mode + cron. BYOK API keys transfer as-is. |
| **DeepSeek Harness** | BYOK models and MCP tools carry over; DSH-specific plugins must be re-mounted as `SKILL.md` or MCP. |

> Myrm runs as **SaaS**, **self-hosted WebUI**, or **desktop**. Your skills and memory follow via the GUI migration wizard (desktop / local WebUI).
