# 업그레이드 안내

## Docker 작성

```bash
cd myrm
git pull
docker compose pull
docker compose up -d
```

## 데이터베이스 마이그레이션

데이터베이스 마이그레이션은 시작 시 자동으로 실행됩니다. 수동 개입이 필요하지 않습니다.

## 업그레이드 중 정상 종료

Myrm에는 다시 시작하는 동안 진행 중인 에이전트 작업을 보호하는 기본 제공 **Gateway Drain Control**이 포함되어 있습니다.

1. 서버가 종료 신호(SIGTERM 또는 `POST /system/shutdown`)를 수신하면 **AgentGateway**가 드레이닝 모드로 전환됩니다.
2. 새로운 Agent 요청은 사용자에게 친숙한 메시지("서비스가 다시 시작됩니다. 잠시 후 다시 시도하십시오.")와 함께 거부됩니다.
3. 현재 실행 중인 에이전트 턴이 자연스럽게 완료되는 데 최대 **120초**가 허용됩니다.
4. 작업이 배수 시간 초과를 초과하면 인터럽트 메커니즘을 통해 안전하게 중단됩니다.
5. 드레이닝 후 모든 구성 요소(스토리지, MCP, 브라우저, cron 등)가 동시에 종료됩니다.

프런트엔드의 **ConnectionManager**는 서버가 다시 시작된 후 자동으로 다시 연결되어 원활한 환경을 보장합니다.

Kubernetes 배포의 경우 포드 사양에서 `terminationGracePeriodSeconds`을 최소 **150초**(120초 드레인 + 30초 버퍼)로 설정하여 강제 종료 전에 드레인이 완료되도록 합니다.

## 주요 변경 사항

### 포트 바인딩 보안 강화

이제 모든 Docker Compose 포트 매핑이 기본적으로 `127.0.0.1`(localhost 전용)에 바인딩됩니다. 이전에 LAN의 다른 장치(예: 휴대폰 또는 태블릿)에서 Myrm에 액세스한 경우 `.env` 파일에 `MYRM_BIND_HOST=0.0.0.0`을 설정하여 LAN 액세스를 복원하세요.

주요 버전을 업그레이드하기 전에 [CHANGELOG](https://github.com/Pursue-LLL/myrm-agent/blob/main/CHANGELOG.md)에서 주요 변경 사항을 확인하세요.
