# MCP 통합

Myrm은(는) 외부 도구 및 서비스를 에이전트에 연결하기 위해 [모델 컨텍스트 프로토콜(MCP)](https://modelcontextprotocol.io/)을 지원합니다.

## MCP이란 무엇인가요?

MCP은 AI 에이전트가 통합 프로토콜을 통해 외부 데이터 소스 및 도구에 연결할 수 있도록 하는 개방형 표준입니다. 사용자 정의 통합을 구축하는 대신 MCP 호환 서버에 연결할 수 있습니다.

## 서비스 카탈로그(원클릭 연결)

인기 서비스를 연결하는 가장 빠른 방법입니다. **설정 > 통합 > 서비스 카탈로그**로 이동하여 9개 카테고리에 걸쳐 사전 구축된 37개의 통합을 찾아보세요.

| Category | Services |
|----------|----------|
| **API Tools** | Postman, QiChaCha |
| **Browser** | Playwright, Browserbase |
| **Communication** | Gmail, Slack, Feishu, DingTalk, QQ Mail |
| **Data Storage** | PostgreSQL, Local File System, Google Drive, Supabase |
| **Design** | Figma, Unreal Engine, Blender |
| **Dev Tools** | GitHub, GitLab, Gitee, Gitee Enterprise, Sentry, Code Review Graph, CodeGraph |
| **Docs** | Context7, Microsoft Learn, AWS Documentation |
| **Productivity** | Notion, Todoist, Google Calendar, Linear, Tencent Docs, WPS Docs |
| **Web Search** | Firecrawl (Keyless free tier), Exa, Brave Search |

각 항목에는 다음이 포함됩니다.
- **사전 구성된 연결 세부 정보**(명령, 인수, URL)
- 공급자의 토큰 페이지에 대한 도움말 링크가 포함된 **안내된 자격 증명 입력**
- 일부 서비스에 대한 **무키 제로 구성 지원**(예: Firecrawl 무료 계층 - API 키가 필요하지 않음)
- 접속 전 **보안검사** (SSRF + 악성패키지 탐지)
- **이중 언어 설명**(영어 및 중국어)

서비스 카드에서 **연결**을 클릭합니다. Firecrawl과 같은 키 없는 서비스의 경우 자격 증명이 필요 없이 연결을 클릭하기만 하면 됩니다. 다른 서비스의 경우 필수 API 키를 입력하면 준비가 완료됩니다.

## 클라우드 스토리지 및 파일 내보내기

Myrm은(는) 모든 클라우드 스토리지 서비스에 파일을 동기화하고 내보낼 수 있는 6가지 경로를 제공합니다. 각 제공업체에 전용 커넥터가 필요하지 않습니다.

| Path | Coverage | Example |
|------|----------|---------|
| **Built-in MCP** | Google Drive, Notion (one-click connect via Catalog) | "Save this to my Google Drive" |
| **Code Execution Sandbox** | Any cloud SDK (boto3, dropbox, onedrive-sdk) | "Upload report.pdf to my S3 bucket" |
| **Browser Automation** | Web-based storage with no API (Baidu Netdisk, etc.) | "Save this to my Baidu Netdisk" |
| **MCP Marketplace** | Community MCP servers for Dropbox, OneDrive, etc. | Install from Registry with one click |
| **Bi-directional File Transfer** | Agent files auto-pushed via IM channels | Files appear as attachments in Feishu/Slack/Telegram |
| **Artifact Share Links** | HMAC-secured public share URLs | Share generated reports with external stakeholders |

:::tip
Unlike competitors that lock you into a single cloud ecosystem, Myrm's open architecture lets you connect to **any** storage service through multiple paths. The Agent automatically chooses the best approach based on your request.
:::

## 통합 메모리(작업 공간 동기화)

연결된 모든 MCP 서버는 자동으로 지식 소스로 사용될 수 있습니다. **설정 > 통합 > 통합 메모리**로 이동하여 외부 데이터를 AI의 장기 메모리에 동기화하세요.

### 작동 방식

1. 서비스 카탈로그를 통해 서비스 **연결**(예: Notion, GitHub, Gmail)
2. 통합 메모리 섹션에서 **모두 동기화**를 클릭합니다.
3. 시스템이 자동으로:
   - MCP 서버 카탈로그에서 가장 좋은 가져오기 도구를 감지합니다.
   - 증분 동기화를 사용하여 데이터 가져오기(`since`/`after` 매개변수 감지)
   - `provider::external_id`에 의한 중복 제거(멱등성 재동기화 안전)
   - 벡터 저장소에 콘텐츠 삽입
   - 지식 그래프에 트리 구조를 구축합니다.
   - MemoryExtractor를 통해 높은 가치의 프로필 특성을 추출합니다.

### 주요 기능

| Feature | Description |
|---------|-------------|
| **Universal bridging** | MCPBridgeProvider auto-bridges any MCP server — no per-service code needed |
| **Concurrent sync** | Up to 5 providers synced in parallel |
| **Smart parsing** | Handles list, dict, and raw string responses from MCP tools |
| **Tree management** | Hierarchical structure with summaries for browsing and removal |
| **Auto knowledge seeding** | Freshly synced data is processed by MemoryExtractor for key insights |
| **Per-provider sync** | Sync individual providers or all at once |



### 동기화된 데이터 관리

- **상태 개요**: 총 공급자, 색인된 항목 및 트리 수를 확인하세요.
- **트리별 제어**: 개별 데이터 트리를 동기화하거나 제거합니다.
- **동기화 결과**: 공급자별 생성/업데이트/건너뛰기/실패 횟수 보기

## 사용자 정의 MCP 서버 추가

### GUI에서

1. **설정 > 도구 > MCP**으로 이동합니다.
2. **서버 추가**를 클릭합니다.
3. 서버 구성을 입력합니다.
   - **이름**: 서버의 표시 이름
   - **명령어**: 서버를 시작하는 명령(예: `npx @mcp/server-github`)
   - **인수**: 명령줄 인수
   - **환경 변수**: 필수 환경 변수(예: API 키)
4. 저장 - 서버가 자동으로 시작되고 에이전트가 해당 도구를 사용할 수 있게 됩니다.

### 구성 파일에서

`mcp_servers.json`에 MCP 서버를 추가합니다.```json
{
  "servers": [
    {
      "name": "github",
      "command": "npx",
      "args": ["@mcp/server-github"],
      "env": {
        "GITHUB_TOKEN": "ghp_..."
      }
    }
  ]
}
```

## Agent Plugins 1.0.0 표준 플러그인

[Agent Plugins](https://agent-plugins.org)는 하나의 휴대용 번들(`plugin.json` + `skills/` + `mcp.json` + 번들 실행 파일)을 여러 클라이언트에서 사용할 수 있게 하는 오픈 플러그인 표준입니다. Myrm은 이러한 번들을 처음부터 끝까지 가져옵니다 — 대부분의 제품이 생략하는 런타임 배선까지 포함합니다.

### 번들 가져오기

1. **설정 > 스킬**로 이동하여 플러그인 관리자를 엽니다
2. 표준 Agent Plugins 번들(`.zip` 또는 디렉터리)을 가져옵니다
3. Myrm이 매니페스트를 파싱하고 번들 파일 트리를 영구 저장하며 플러그인의 MCP 서버를 자동으로 등록합니다

### 플러그인 MCP 서버 관리(활성화 상태)

가져온 플러그인은 사용자 동의 없이 번들 MCP 서버를 활성화하지 않습니다 — 모든 서버는 기본적으로 **비활성화된 상태**로 영구 저장됩니다(안전 기본값: 플러그인이 사용자 모르게 임의의 외부 명령을 실행할 수 없음). 플러그인 관리자 대화상자에서 각 서버의 영구 저장된 `enabled` 상태를 한눈에 확인할 수 있습니다:

| 상태 | 배지 | 의미 |
|-------|------|------|
| **Active / 활성화됨** | 녹색 점 | 서버가 활성화되어 런타임에 도구가 로드됩니다 |
| **Disabled / 비활성화됨** | 황색 점 | 서버가 꺼져 있습니다. 힌트 툴팁이 **MCP 설정**으로 안내합니다 |

- **런타임 필터링** — 도구 검색 단계에서는 활성화된 서버만 로드됩니다. 비활성화(또는 손상된) 서버는 에이전트의 도구 집합에 절대 포함되지 않으므로, 하나의 고장난 서버가 플러그인의 나머지 기능을 무너뜨리거나 에이전트 시작을 막을 수 없습니다.
- **서버별 제어** — 하나의 서버만 활성화하고 다른 서버는 꺼둘 수 있으며, 언제든지 플러그인을 다시 가져오지 않고 각 서버를 독립적으로 켜고 끌 수 있습니다.

### 런타임: PLUGIN_ROOT / PLUGIN_DATA(명세 §9)

Myrm이 시작하는 모든 플러그인 하위 프로세스에는 두 개의 예약 환경 변수가 전달됩니다:

- `PLUGIN_ROOT` — 플러그인의 설치 디렉터리(번들 실행 파일이 있는 위치)
- `PLUGIN_DATA` — 플러그인의 영구 데이터 디렉터리로, **업데이트 후에도 유지됩니다**

플러그인 스크립트는 이를 직접 읽을 수 있습니다:

```python
import os

root = os.environ["PLUGIN_ROOT"]
data = os.environ["PLUGIN_DATA"]
```

Myrm은 spawn 시 `${PLUGIN_ROOT}` / `${PLUGIN_DATA}` 플레이스홀더를 플러그인의 `cwd`, `args`, `env` 세 곳에서 확장하며, `./` 상대 명령은 자동으로 플러그인 루트를 작업 디렉터리로 사용합니다 — 번들 스크립트는 경로를 추측할 필요 없이 작동하며, 손상된 플러그인 하나는 다른 MCP 서버를 차단하지 않고 명세에 따라 건너뜁니다.

### 제거

플러그인을 제거하면 번들 파일이 삭제될 뿐만 아니라 데이터 디렉터리와 에이전트 바인딩도 원클릭으로 정리됩니다 — 디스크에 잔여물이 남지 않습니다.

## 맞춤형 MCP 서버 구축(AI 기반)

MCP 서버를 처음부터 작성하고 싶지 않으신가요? **mcp-builder** 스킬을 활성화하고 에이전트에게 스킬을 빌드해 달라고 요청하세요.

### 사용방법

1. **설정 > 에이전트 > 스킬**로 이동하여 `mcp-builder` 스킬을 활성화합니다.
2. 대화를 시작하고 필요한 사항을 설명하세요. *"프로젝트 관리를 위해 Jira에 연결하는 MCP 서버 구축"*
3. 상담원은 구조화된 4단계 워크플로를 따릅니다.

| Phase | What Happens |
|-------|-------------|
| **Research** | Investigates the target API (auth, endpoints, rate limits) |
| **Implementation** | Writes the server in Python (FastMCP) or TypeScript (MCP SDK) with proper annotations |
| **Verify** | Runs a verification script to confirm the server starts and passes security scanning |
| **Register** | Generates the configuration for Settings > MCP and tests the tools in conversation |

### 품질 보증 내장

- **보안 주석** — 읽기 전용 작업은 `readOnlyHint: true`(자동 승인)을 받고, 파괴적인 작업은 `destructiveHint: true`(경고 배지)을 얻습니다.
- **오류 처리** — 모든 HTTP 호출에는 시간 초과, 재시도 및 실행 가능한 오류 메시지가 있습니다.
- **페이지 매김** — 토큰 폭발을 방지하기 위해 대규모 결과 세트에 페이지가 매겨집니다.
- **환경 변수** — 비밀은 하드코딩되지 않습니다.

## 스키마 처리

Myrm은 LLM 호환성을 위해 MCP 도구 스키마를 자동으로 최적화합니다.

| Feature | Description |
|---------|-------------|
| **Schema Flattening** | Deeply nested schemas (depth > 2 or leaves > 10) are automatically flattened |
| **Type Intelligent Fix** | 7 auto-fixes: nullable completion, mixed-union container parsing, enum/const null recognition, reverse coercion (dict→string), boolean/number string conversion, markdown code block stripping, deep-nested dot-path flattening |
| **Dot-Path Detection** | Automatically detects if the model uses dot notation for nested params |
| **$ref Resolution** | Full recursive JSON Schema `$ref` resolution |
| **Circular Reference Guard** | Max depth limit + visited tracking prevents infinite recursion |
| **Anthropic Schema Auto-Adapt** | Automatically strips unsupported JSON Schema keywords (`minimum`, `maximum`, `pattern`, `format`, `default`, `title`, etc.) for Claude models, folds constraint semantics into `description` to preserve LLM understanding. Zero manual configuration needed |
| **Description Safety Valve** | Excessively long third-party descriptions auto-truncated to 2048 chars to prevent token waste |
| **Schema Cache Stability** | Recursive key sorting + set field sorting eliminates serialization randomness from MCP server restarts, ensuring Prompt Cache hits |
| **Fuzzy Schema Preservation** | Third-party MCP schemas are rarely well-formed. Dangling `$ref` (unresolved external refs) degrade to permissive objects, missing `type` is auto-completed, `anyOf`/`oneOf`/`allOf` composites flatten into a single property set (mutually-exclusive groups folded into the description), const-unions collapse to enums, and non-standard key names (e.g. Cloudflare `issue_class~neq`) are sanitized then restored to their wire names at call time — **fields are never dropped end-to-end** |
| **Reserved-Name Argument Safety** | Some popular MCP servers declare tool params literally named `config` or `run_manager` (Stripe/Unreal/GitHub). LangChain's `StructuredTool` silently swallows such values into its internal parameter slots, so the argument disappears from the dispatch payload and the server rejects the call with `Field required`. Myrm ships a `SafeStructuredTool` subclass that passes every argument through (`*args`/`**kwargs`) on both sync `invoke` and async `ainvoke` paths — a bug the official `langchain-mcp-adapters` and deer-flow still ship |
| **Numeric Precision Preservation** | Decimal-exact parsing for integer/number params — 2^53+ big integers (snowflake/64-bit IDs) stay lossless via arbitrary-precision `int`; integral exponent forms (`"25.0"`, `"1e10"`) coerce exactly; `inf`/`nan`/over-long exponents are preserved as strings (DoS guard) |
| **Coercion Observability** | Runtime counters track each fix type's trigger frequency, with DEBUG logging for diagnostics |
| **Content Boundary Defense** | All MCP return values pass through 5-layer `wrap_untrusted` defense chain to prevent Prompt Injection |

## OpenAPI Bridge (모든 REST API 연결)

MCP 외에도 Myrm은 **모든 OpenAPI/Swagger 사양**을 호출 가능한 Agent 도구로 변환합니다 — 코드 작성 없이. MCP 서버가 아직 없는 GitHub, Stripe 또는 내부 REST 서비스에 적합합니다.

### 작동 방식

1. **서비스 추가** — OpenAPI spec URL(또는 Swagger 2.0 문서) 제공
2. **자동 도구 생성** — 모든 엔드포인트가 완전한 LLM 판독 가능 매개변수 스키마를 가진 Agent 도구가 됩니다
3. **연결 즉시 사용** — Agent가 올바른 타입, 올바른 라우팅, 무손실 숫자 정밀도로 API를 호출합니다

### 내장 보장

| 기능 | 설명 |
|------|------|
| **매개변수 스키마 완전 가시성** | path + query + request-body 매개변수가 모두 파싱되어 LLM에 노출됩니다(path 매개변수만이 아님) — 모델은 모든 필드/타입/필수 표시를 볼 수 있습니다 |
| **`$ref` 자동 인라인** | 로컬 참조가 자동 해결됩니다 — OpenAPI 3.x `#/components/schemas`/`#/components/parameters`/`#/components/requestBodies`, Swagger 2.0 `#/definitions`/최상위 `#/parameters` — 모델은 절대 원시 포인터를 보지 못합니다 |
| **통합 타입 강제 변환** | MCP와 동일한 프로덕션 강제 변환 엔진이 잘못된 타입 인수를 수정합니다(문자열 숫자→int/float, 1/0↔bool, 스칼라→배열, 중첩 객체) — 엄격한 API의 400 오류가 중단됩니다 |
| **숫자 무손실** | 큰 정수/ID/금액이 마지막 자리까지 정확합니다(MCP와 동일한 Decimal 정밀 파싱) — snowflake ID와 금융 값이 절대 변하지 않습니다 |
| **정확한 요청 라우팅** | 객체/배열 요청 본문은 본문 자체로 전송되고(래핑 없음), query 매개변수는 컴팩트 JSON 직렬화, 부울은 소문자로 전송됩니다 — wire 페이로드가 API 계약과 일치합니다 |

### 이것이 중요한 이유

CLI/curl 워크플로우에서 마이그레이션: Agent가 수동 도구 정의 없이 REST API 매개변수를 이해합니다; 큰 숫자를 문자열화하는 약한 모델도 400 또는 정밀도 손실을 일으키지 않습니다; 스키마 인식 라우팅으로 모든 요청이 계약에 부합합니다.

## 연결 관리

### 영구 세션

각 MCP 서버는 전체 에이전트 수명 동안 따뜻한 상태를 유지하는 단일 영구 세션에서 실행됩니다. 도구 호출은 내부 대기열을 통해 세션에 직렬화됩니다. 호출당 하위 프로세스가 생성되지 않으며 호출 간에 재초기화 핸드셰이크가 필요하지 않습니다.

Myrm은 MCP 도구 스키마를 LangChain 도구 인스턴스로 변환하기 위해 내부 `tool_converter` 모듈과 함께 기본적으로 **MCP SDK 2.0**을 사용합니다. 즉, 타사 어댑터 종속성이 없습니다. 이는 최소한의 종속성 공간을 유지하면서 최신 MCP 프로토콜 기능과의 완전한 호환성을 보장합니다.

### 상태 비저장 HTTP 및 클라우드 부하 분산

클라우드 배포 MCP 서버의 경우 Myrm SDK 2.0은 기본적으로 **상태 비저장 HTTP** 모드를 지원합니다. 세션 ID 헤더는 서버가 제공하는 경우에만 전송됩니다. 이는 다음을 의미합니다.

- **라운드 로빈 로드 밸런싱**은 세션 선호도가 필요 없이 즉시 작동합니다.
- `server/discover` 프로브를 통한 **프로토콜 자동 협상**은 서버 기능을 자동으로 감지합니다.
- **라우팅 헤더**(`Mcp-Method`, `Mcp-Name`, `MCP-Protocol-Version`)는 모든 요청에 삽입되어 게이트웨이 계층에서 지능형 요청 라우팅을 가능하게 합니다.
- **로컬/데스크톱 세션**은 최적의 성능을 위해 지속적인 웜 연결을 계속 사용합니다(두 세계 모두에서 최고).

### 실행 시간 초과 보호

모든 MCP 도구 호출은 이중 계층 시간 초과 메커니즘으로 보호됩니다.

- **SDK 레이어** — `read_timeout_seconds`가 MCP SDK 세션으로 전달되어 전송 수준에서 응답이 중단되는 것을 방지합니다.
- **래퍼 레이어** — 독립적인 `asyncio.timeout`는 전체 실행(응답 정규화 포함)을 래핑하여 전송 확인 후 멈추는 도구를 포착합니다.
- **서버별로 구성 가능** — 각 서버는 자체 `connect_timeout`(기본값 15초) 및 `execute_timeout`(기본값 120초, 최대 300초)을 설정할 수 있습니다.
- **우아한 성능 저하** — 시간 초과 시 설명 오류 문자열이 LLM(예외 아님)에 반환되어 에이전트가 다음 단계를 결정할 수 있도록 합니다.
- **열거 시 자동 재시도** — 도구 검색은 일시적 오류 시 300ms 백오프로 최대 3회 재시도합니다.

### 오류 투명성

MCP 도구가 실패(`isError: true`)를 보고하면 정보 손실 없이 전체 오류 체인이 처리됩니다.

- **서버 측 오류 통과** — MCP 서버의 원래 오류 텍스트가 추출되어 보고된 대로 정확하게 LLM로 전달됩니다.
- **보안 삭제** — 오류 메시지를 통한 즉각적인 주입을 방지하기 위해 자격 증명이 수정되고(`redact_sensitive_text`) 구조적 프레이밍 토큰이 제거됩니다(`sanitize`).
- **오류 분류** — 오류가 분류되어(network_blocked, timeout, sandbox_ro 등) 회로 차단 패턴 및 대상 복구가 가능합니다.
- **회로 차단기** — 터미널 오류(예: 네트워크가 영구적으로 차단됨)가 등록됩니다. 동일한 카테고리에 대한 후속 호출은 재시도 없이 빠르게 실패합니다.
- **구조적 진단** — 디버깅을 위해 실행 단계, 도구 이름, 출력 미리 보기(헤드 + 테일 잘림) 및 복구 힌트가 기록됩니다.
- **프런트엔드 디스플레이** — 원시 텍스트뿐만 아니라 i18n 메시지, 해결 단계 및 복구 작업이 포함된 구조화된 진행 단계로 UI에 오류가 표시됩니다.

### 자가 치유 재연결

전송 중단이 발생하면(하위 프로세스 충돌, SSE/HTTP 삭제, 유휴 시간 초과) 세션 행위자가 제자리에 다시 연결됩니다.

- **제한된 백오프** — 지수 백오프를 사용하여 최대 5번의 재연결 시도(0.5초~8초 제한)
- **예산 새로 고침** — 60초 이상 안정적으로 실행된 세션은 새로운 재시도 예산을 획득하므로 몇 시간 후에도 관련 없는 블립이 여전히 전체 재시도를 얻습니다.
- **진행 중 호출이 명시적으로 실패함** — 중단에 도달한 호출은 실패하지만(비멱등 도구의 자동 자동 재시도 없음) 후속 호출은 새로운 세션에서 성공합니다.
- **프록시 안정성** — 에이전트가 보유한 도구 개체는 다시 연결해도 동일하게 유지되어 프롬프트 접두사 캐시 적중을 유지합니다.

### 전송 인식 Keepalive

원격 전송(SSE, 스트리밍 가능한 HTTP)은 유휴 TCP 연결을 자동으로 삭제하는 로드 밸런서 및 NAT 뒤에 있습니다. 세션 행위자는 연결을 따뜻하게 유지하기 위해 180초마다 가벼운 대역 내 핑(`list_tools`)을 보냅니다. 로컬 stdio 전송(하위 프로세스로의 파이프)은 유휴 상태로 연결이 끊어지지 않으며 프로브되지 않은 상태로 유지됩니다.

### 연결 풀

- **서버당 싱글톤** — 구성 해시당 하나의 웜 연결로 리소스 누출을 방지합니다.
- **루프 인식** — 이벤트 루프 변경 시 연결이 자동으로 재구축됩니다.
- **TTL 재활용** — 장기 유휴 연결이 닫히고 요청 시 다시 생성됩니다.
- **최후의 재구축** — 풀은 행위자의 내부 재연결 예산이 완전히 소진된 경우에만 연결을 재구축합니다.

### 연결 신뢰성(실제 프로토콜 검증)

장기 연결은 수시간 에이전트 작업의 기반입니다. Myrm은 **실제 전송 엔드투엔드 회귀 테스트**(실제 stdio 하위 프로세스 + streamable HTTP 실제 서버로 전체 initialize → list → call 수명 주기 실행)로 이를 검증합니다. 단순 mock 단위 테스트가 아닙니다.

- **실패 경로에서 누출 없음** — 연결 실패, 재연결 실패, 정상 종료 등 모든 종료 경로에서 전송 HTTP 클라이언트를 해제하여 수시간 작업 중 메모리가 안정적으로 유지됩니다
- **자가 치유 회귀** — 서버가 충돌하면 제자리에서 재구축되어 계속 서비스를 제공하며, 새 연결에도 동일한 리소스 안전성이 적용됩니다
- **전체 스위트 검증** — MCP 테스트 720개 통과, 94.3% 커버리지

마이그레이션 시 "데모에서는 작동하지만 프로덕션에서는 실패"하는 통합 품질 문제를 걱정할 필요가 없습니다.

### 취소오류 방지

가드는 Python `CancelledError`이 MCP 채널을 통해 누출되는 것을 방지합니다. 그렇지 않으면 MCP 서버 프로세스가 중단될 수 있습니다.

### 측정항목

연결 측정항목(성공률, 대기 시간, 오류율)은 진단 API을 통해 추적되고 제공됩니다.

## 보안

### SSRF 예방

Myrm은 MCP 도구 URL에 대한 DNS 고정을 구현합니다.

- 확인된 IP는 개인 범위(10.x, 172.16-31.x, 192.168.x)와 비교하여 확인됩니다.
- 로컬호스트 및 링크-로컬 주소는 기본적으로 차단됩니다.
- URL 검증은 리디렉션 기반 SSRF 공격을 방지합니다.

### 악성 패키지 탐지

MCP 도구가 종속성을 설치할 때 OSV(오픈 소스 취약점) API을 실시간으로 참조하여 알려진 악성 패키지를 탐지합니다.

### 런타임 프롬프트 삽입 보호

MCP 도구가 등록되거나(초기 동결) 동적으로 새로 고쳐질 때마다(`list_changed` 이후) Myrm은 다음을 검사하는 런타임 표면 스캔을 실행합니다.

- 에이전트 동작을 하이재킹할 수 있는 내장된 지시문에 대한 **서버 지침**
- 내장 도구를 흉내내는 사기성 이름에 대한 **도구 이름**
- 주입된 프롬프트 조작 패턴에 대한 **도구 설명**

의심스러운 콘텐츠가 감지되면 서버 도구는 `MCPRuntimePostureError`으로 차단됩니다. 즉, 악성 도구는 에이전트의 컨텍스트에 도달하지 않습니다. 이는 손상되었거나 악의적인 MCP 서버가 도구 설명을 미묘하게 변경하여 에이전트의 프롬프트에 지침을 삽입하는 공격 클래스를 방지합니다.

### 도구 승인

MCP 도구는 기본 제공 도구와 동일한 승인 흐름을 따릅니다.

- 읽기 전용 도구가 자동으로 실행됩니다.
- 쓰기/파괴 도구에는 사용자 승인이 필요합니다(YOLO 모드가 아닌 경우).
- MCP 서버별로 맞춤형 승인 정책 구성 가능

### MCP 서버 유도(사용자 확인)

일부 MCP 서버는 도구 실행 중에 추가 정보를 요청할 수 있습니다. 예를 들어 결제 MCP 서버는 진행하기 전에 환불 금액을 확인하도록 요청할 수 있습니다.

이런 일이 발생하면 Myrm은(는) 다음과의 채팅에 **승인 카드**를 표시합니다.
- 서버의 확인 메시지
- 60초 카운트다운 타이머
- **승인** / **거부** 버튼

에이전트는 사용자가 응답할 때까지 일시 중지됩니다. 타이머가 만료되면 요청이 자동으로 취소되고 에이전트는 대체 접근 방식을 계속 진행합니다.

:::info
This is part of the MCP protocol's [Elicitation](https://modelcontextprotocol.io/specification/2025-06-18/server/utilities/elicitation) feature. Myrm bridges it to the same visual approval flow used for tool permissions, so you get a consistent experience across all approval types.
:::

## 도구별 필터링

에이전트를 구성할 때 각 MCP 서버에서 사용 가능한 도구를 개별 도구 단위까지 제어할 수 있습니다.

### 사용방법

1. **에이전트 구성**으로 이동합니다(채팅에서 에이전트 아바타 클릭).
2. **MCP 서버** 아래에 활성화된 각 서버에는 **도구 필터** 토글이 표시됩니다.
3. 위험 주석이 포함된 사용 가능한 모든 도구를 보려면 확장하세요.
4. 확인란을 사용하여 개별 도구를 켜거나 끕니다.

### 위험 주석

각 도구는 위험 수준에 따라 자동으로 분류됩니다.

| Risk Level | Icon | Description |
|------------|------|-------------|
| **Safe** | 🟢 Shield | Read-only operations (`readOnlyHint: true`) |
| **Caution** | 🟡 Eye | Write operations (not read-only, not destructive) |
| **Danger** | 🔴 Warning | Destructive operations (`destructiveHint: true`) |

### 위험한 도구 자동 비활성화

에이전트에서 MCP 서버를 처음 활성화하면 **파괴적**으로 표시된 도구는 선택에서 자동으로 제외됩니다. 필요한 경우 수동으로 다시 활성화할 수 있습니다.

### 필터 요약

도구 필터 헤더에는 사용 가능한 전체 도구 중에서 활성화된 도구 수를 나타내는 개수 배지(예: `5/20`)가 표시됩니다.

## 다중 모드 도구 결과

MCP 도구는 일반 텍스트 이상의 풍부한 콘텐츠를 반환할 수 있습니다. 스크린샷, 이미지 및 구조화된 데이터는 모두 기본적으로 처리됩니다.

### 이미지 콘텐츠

MCP 서버가 `ImageContent`(예: Playwright 스크린샷, 다이어그램 생성기)을 반환하면 Myrm은 채팅에서 이미지를 직접 렌더링합니다.

- Base64 이미지 데이터는 스트리밍 파이프라인을 통해 흐르고 **도구 이미지 갤러리**에서 렌더링됩니다.
- 도구 결과당 여러 이미지가 지원됩니다(라이트박스 미리보기가 포함된 그리드 레이아웃).
- 비전을 지원하지 않는 모델의 경우 미디어 필터에 의해 이미지가 자동으로 제거되므로 구성이 필요하지 않습니다.

### 구조화된 콘텐츠

MCP 서버가 `structuredContent`(텍스트와 함께 JSON 메타데이터)를 반환하면 Myrm은 이를 LLM에 대한 보충 컨텍스트로 추출하여 포함시켜 보다 정확한 구조적 추론을 가능하게 합니다.

### 도구 필터링

MCP 서버별, **에이전트별**별로 노출되는 도구를 제어할 수 있습니다.

- **포함 목록** — 지정된 도구만 등록됩니다(화이트리스트).
- **제외 목록** — 지정된 도구가 숨겨집니다(블랙리스트).
- **에이전트별 세분성** — 서로 다른 에이전트는 동일한 MCP 서버에서 서로 다른 도구를 활성화할 수 있습니다(예: "코드 검토자" 에이전트는 읽기 전용 GitHub 도구만 볼 수 있는 반면 "DevOps" 에이전트는 모든 도구를 볼 수 있음)
- **에이전트 구성 패널 > MCP > 도구 선택**에서 GUI을 통해 구성합니다.

### 안전 주석

MCP 도구에는 Myrm이(가) 자동 위험 관리에 사용하는 [주석 힌트](https://spec.modelcontextprotocol.io/specification/2025-03-26/server/tools/#annotations)가 포함되어 있습니다.

| Annotation | Effect |
|------------|--------|
| `readOnlyHint` | Tool marked as read-only; eligible for auto-approval when `readOnly && !openWorld && !destructive` (both PTC and direct MCP paths) |
| `destructiveHint` | Tool marked as dangerous; **disabled by default** in the smart safe set and highlighted with a warning badge in the GUI |
| `idempotentHint` | Tool marked as safe to retry |
| `openWorldHint` | Tool may interact with external systems beyond the MCP server |



### 기본 안전 설정

에이전트에 대해 MCP 서버를 처음 활성화하면 Myrm은 도구 주석을 검사하고 자동으로 **안전한 기본 선택**을 구축합니다.

- 모든 `readOnlyHint` 도구가 활성화되었습니다.
- `destructiveHint`이 포함된 도구는 비활성화되고 경고 배너로 표시됩니다("N개의 파괴적인 도구는 기본적으로 비활성화됨").
- 언제든지 도구 선택에서 기본값을 무시할 수 있습니다. GUI

### 도구 이름 격리

여러 MCP 서버가 활성화되면 도구 이름이 충돌할 수 있습니다(예: GitHub 및 GitLab 서버 모두 `search_repos`를 노출할 수 있음). Myrm은 모든 MCP 도구에 **서버 접두사 격리**를 적용합니다.```
mcp__{server}__{tool}
```

- **이중 밑줄 구분 기호** — 단일 밑줄 체계(서버 이름에 밑줄이 포함된 경우 모호함)와 달리 `__` 구분 기호를 사용하면 `(server, tool)` 쌍으로 다시 명확하게 구문 분석할 수 있습니다.
- **권한 안전** — 접두사 이름은 내장 도구 이름과 충돌하지 않아 실수로 권한 우회를 방지합니다.
- **추적성 감사** — 모든 도구 호출 로그 항목에는 도구가 속한 MCP 서버가 명확하게 표시됩니다.
- **사용자에게 공개** — GUI는 항상 친숙한 원래 도구 이름을 표시합니다. 접두어는 엔진 내부에 있습니다.

## 동적 도구 검색

MCP 서버가 런타임에 도구를 추가, 제거 또는 업데이트하면 Myrm은 표준 `notifications/tools/list_changed` 알림을 통해 자동으로 변경 사항을 감지합니다.

- **다운타임 없는 새로고침** — 세션 행위자가 도구 목록을 다시 가져오고 진행 중인 호출을 중단하지 않고 실행 계층을 업데이트합니다(내부 대기열을 통해 직렬화됨, 잠금 없음).
- **신속한 캐시 안정성** — 프롬프트 표시 프록시 도구는 동결된 상태로 유지됩니다. 내부 실행 맵만 업데이트되므로 프롬프트 접두사 캐시 적중이 절대로 손상되지 않습니다.
- **시간 초과 보호** — 새로 고침 다시 가져오기는 세션 초기화와 동일한 연결 시간 초과로 제한되므로 중단된 MCP 서버는 소유자 작업을 교착 상태에 빠뜨릴 수 없습니다.
- **로그 변경** — 추가 및 제거된 도구는 가시성을 위해 경고 수준으로 기록됩니다. 무작동 새로 고침은 INFO 수준에 기록됩니다.
- **상담원에게 투명함** — 상담원은 기존 도구 참조를 계속 사용합니다. 새 도구는 즉시 호출 가능해지며, 제거된 도구는 다음 호출 시 명시적으로 실패합니다.

이는 사용자 상태에 따라 도구를 동적으로 등록하는 MCP 서버(예: 새 보드가 생성될 때 도구를 추가하는 프로젝트 관리 서버)에 특히 유용합니다.

## 지연된 로딩

시스템 프롬프트에서 도구 스키마 팽창을 방지하기 위해 MCP 도구는 **지연 로딩**을 지원합니다.

- 도구가 등록되었지만 초기 프롬프트에는 포함되지 않았습니다.
- 에이전트에 특정 기능이 필요한 경우 요청 시 도구가 로드됩니다.
- 시스템 프롬프트를 간결하고 캐시 친화적으로 유지합니다.

## 역방향 MCP 서버(연결)

Myrm은(는) **MCP 서버** 역할을 할 수도 있으며 메모리 시스템을 외부 AI 에이전트(Claude Code, Cursor, Codex, Windsurf, Gemini CLI)에 노출할 수도 있습니다. 이는 귀하의 지식이 모든 AI 도구에서 지속된다는 것을 의미합니다.

### 작동 방식

**설정 > 메모리 > 연결**로 이동하여 연결 마법사를 시작하세요.

1. **Myrm 에이전트 선택** — 외부 도구를 바인딩해야 하는 에이전트 프로필을 선택합니다. 외부 도구는 바인딩된 공유 컨텍스트를 포함하여 해당 에이전트의 메모리 공간을 읽고 씁니다.
2. **IDE 선택** — 지원되는 5개의 MCP 클라이언트 중에서 선택
3. **구성 생성** — 클릭 한 번으로 Bearer 토큰(에이전트 범위 포함)과 바로 붙여넣을 수 있는 구성 조각이 생성됩니다.
4. **IDE에 붙여넣기** — 코드 조각을 IDE의 MCP 설정 파일에 복사합니다.
5. **완료** — 이제 외부 에이전트가 선택한 Myrm 에이전트의 메모리에 대한 액세스 범위를 갖습니다.

각 토큰의 범위는 특정 에이전트 프로필로 지정됩니다. 외부 도구가 MCP 요청을 하면 Myrm의 미들웨어는 자동으로 토큰을 올바른 에이전트로 확인하고 적절한 메모리 네임스페이스 + 공유 컨텍스트를 바인딩합니다. 이는 서로 다른 외부 도구가 완전히 격리된 메모리 공간을 사용하여 서로 다른 Myrm 에이전트에 연결할 수 있음을 의미합니다.

### 노출된 도구

| Tool | Description |
|------|-------------|
| `memory_search_tool` | Unified search across memory, wiki, and prior conversations via `corpus` parameter. Supports category filters and profile key lookup on memory corpus. |
| `memory_list` | Enumerate and audit memories: overview mode for global stats and previews, category mode for paginated browsing of a single category |
| `memory_store` | Store new knowledge, preferences, rules, events, or instructions |
| `memory_manage` | Rate, update, correct, or delete existing memories |

### 보안

- **전달자 토큰 인증** — 각 커넥터는 특정 에이전트 프로필로 범위가 지정된 고유한 `myrm_mcp_*` 토큰을 얻습니다.
- **에이전트별 메모리 격리** — 외부 도구는 바인딩된 에이전트의 메모리와 공유 컨텍스트에만 액세스하고 다른 에이전트의 데이터에는 액세스하지 않습니다.
- **원클릭 취소** — 다른 사람에게 영향을 주지 않고 커넥터의 액세스를 즉시 무효화합니다.
- **상태 비저장 HTTP 전송** — 각 요청은 자체 포함되어 있습니다(`Mcp-Session-Id` 추적이 필요하지 않음). MCP 호환 클라이언트와 네트워크를 통해 작동합니다.
- **의사 상태 점검** — 언제든지 GUI의 연결을 확인하세요.

### 지원되는 클라이언트

| Client | Config Format | Config File Path |
|--------|--------------|------------------|
| Claude Code | JSON | `~/.claude/claude_code_config.json` |
| Cursor | JSON | `.cursor/mcp.json` |
| Codex | TOML | `codex.toml` |
| Windsurf | JSON | `~/.windsurf/mcp_config.json` |
| Gemini CLI | JSON | `~/.gemini/settings.json` |

### 이것이 중요한 이유

Cursor에서 코드 작업을 한 다음 연구를 위해 Myrm의 WebUI로 전환하면 두 에이전트 모두 동일한 메모리를 공유합니다. 한 에이전트가 저장한 프로젝트 결정은 다른 에이전트에게 즉시 제공되므로 수동으로 컨텍스트를 전송할 필요가 없습니다.

## 엔터프라이즈 조직 MCP(클라우드 SaaS)

**클라우드 호스팅 엔터프라이즈** 배포에서 IT 관리자는 전체 조직의 MCP 서버를 중앙에서 관리할 수 있습니다.

1. **설정 → 기업 → 조직 MCP**(소유자/관리자 전용)으로 이동합니다.
2. 이름, URL 및 선택적 인증 헤더를 사용하여 HTTP/SSE MCP 서버를 추가합니다.
3. 변경 사항은 컨트롤 플레인을 통해 모든 멤버 샌드박스에 **자동으로 푸시**됩니다.
4. 샌드박스가 **잠자기** 상태인 경우 배달이 대기열에 추가되고 **깨어나면 재생**됩니다(최대 3회 재시도).
5. 직원은 **설정 → MCP**에서 조직 관리 MCP 서버를 **읽기 전용**으로 볼 수 있으며 IT 관리 항목을 편집하거나 제거할 수 없습니다.
6. 보안을 위해 클라우드 샌드박스에서 **stdio MCP이 차단**되었습니다(로컬 프로세스 서버는 허용되지 않음).

:::tip
This closes the gap competitors leave open: no org-wide MCP catalog, no automatic sync after idle sleep, and no IT/employee permission split. New hires get the same internal tools on day one without manual YAML or curl.
:::

## 문제 해결

### 서버가 시작되지 않습니다

1. 명령 경로가 정확하고 액세스 가능한지 확인하세요.
2. 필수 환경 변수가 설정되었는지 확인하세요.
3. **설정 > 도구 > MCP > 로그**에서 서버 로그를 확인하세요.

### 도구가 표시되지 않음

1. 도구 검색을 위해 서버 시작 후 5~10초 정도 기다립니다.
2. MCP 설정 패널에서 **새로고침**을 클릭하세요.
3. 서버의 도구 목록 응답이 유효한 JSON 스키마인지 확인하십시오.

### 연결 끊김

자가 치유 재연결 시스템은 대부분의 연결 문제를 투명하게 처리합니다. 즉, 세션 행위자가 사용자 개입 없이 연결을 재구축합니다. 전송 중단으로 인해 도구 호출이 실패하는 경우 메시지를 다시 시도하면 다음 호출이 새 세션에 연결됩니다. 5번의 재연결 시도 후에도 지속적인 실패가 발생하는 경우 다음을 확인하십시오.
- MCP 서버에 대한 네트워크 연결
- 서버 프로세스 상태(다시 시작해야 할 수도 있음)
- 리소스 제한(파일 설명자, 메모리)

### 로컬 편집기 MCP 프로브 진단

로컬 전용 통합(예: Unreal Engine 또는 Blender)을 연결하면 Myrm은 스캔/검증 **전에** `/api/v1/integrations/mcp/probe`을 실행합니다. 이렇게 하면 사용자가 근본 원인을 모르고 반복적으로 연결을 클릭하는 막다른 설정 흐름을 방지할 수 있습니다.

| Category | Signal | Meaning | Next Action |
|----------|--------|---------|-------------|
| Reachable | `reasonCode=reachable` | MCP endpoint responded in time | Continue to scan/verify |
| Editor server not running | `reasonCode=connection_refused` | Port exists but nothing is listening | Start the editor-side MCP server/plugin |
| Local route unavailable | `reasonCode=connection_unreachable` | Loopback path exists but local routing/VPN/proxy policy blocks reachability | Verify localhost routing, VPN/proxy policy, and editor MCP settings |
| TLS trust failure | `reasonCode=tls_verification_failed` | Certificate chain/hostname validation failed | Import enterprise CA or configure per-server CA bundle / mTLS |
| Connection timeout | `reasonCode=connection_timeout` | Target is reachable intermittently or too slow to respond | Check local network stability and editor MCP health, then retry |
| Unexpected probe failure | `reasonCode=probe_failed_unknown` + `recommendedMode=verify_local_network_and_editor` | A non-network runtime failure occurred while probing | Retry after checking editor MCP settings; use server logs for diagnostics |
| Loopback policy | HTTP 400 + `localhost addresses only` detail | Non-loopback endpoint was blocked by SSRF guard | Use `127.0.0.1` / `localhost` endpoint for local integrations |

추가 동작 보장:

- `shouldBlockConnect=true`, Myrm이 연결 체인을 즉시 중지하면(스캔/검증 팬아웃 없음) 시끄러운 오류가 줄어듭니다.
- UI는 `reasonCode`을 현지화된 운영자 대상 메시지에 매핑하므로 인프라 팀과 앱 ​​팀이 동일한 신호를 기준으로 분류할 수 있습니다.
- `recommendedMode`는 한 번의 클릭으로 실행 가능합니다. `start_local_editor_mcp` / `verify_local_network_and_editor`는 프로브 재시도를 트리거하고 성공 시 자동으로 연결을 계속하며, `local_or_tauri`는 로컬 배포 지침을 직접 엽니다.
- 일반적인 네트워크 오류만 표시하는 경쟁업체와 비교하여 Myrm은 CI 검사 및 온보딩 스크립트에서 자동화할 수 있는 기계 판독 가능한 진단을 제공합니다.

### 이 마이그레이션 경로가 CLI 우선 흐름보다 원활한 이유

- **터미널 핸드오프가 아닌 제품 내 문제 해결**: 운영자는 동일한 연결 대화 상자 내에서 로컬 MCP 오류를 복구할 수 있습니다. 대조적으로, OpenClaw의 MCP 페이지는 명시적으로 운영자 보기이며 사용자에게 실시간 증명을 위해 터미널 프로브 명령(`openclaw mcp doctor --probe`)을 실행하도록 요청합니다.
- **부울 통과/실패 대신 실행 가능한 계약**: Myrm은 `reasonCode + recommendedMode + shouldBlockConnect`을 반환하므로 프런트엔드 동작이 결정적입니다(팬아웃 차단, 현지화된 원인 표시, 원클릭 작업 제공). Hermes' `/api/mcp/servers/{name}/test` 스타일 응답은 주로 `ok/error/tools`입니다. 이는 진단에는 유용하지만 안내 온보딩 UX에는 덜 표현적입니다.
- **설계에 따른 잡음 감소**: 프로브가 차단이라고 표시하면 Myrm은(는) 즉시 스캔/검증 팬아웃을 중지합니다. 이를 통해 피할 수 있는 다운스트림 오류를 방지하고 레거시 MCP 설정에서 마이그레이션하는 동안 "무작정 재시도" 동작을 줄입니다.
- **알 수 없는 오류 안전성**: 예기치 않은 프로브 오류는 삭제된 운영자 메시지를 반환하고 서버 로그는 디버깅 가능한 세부 정보를 유지하여 하위 수준 예외 내부가 최종 사용자에게 실수로 유출되는 것을 방지합니다.

### OAuth 토큰 만료

MCP 서버의 OAuth 토큰이 만료되면(GitHub, Linear, Notion, Slack 통합에서 일반적) Myrm은 런타임 시 오류를 감지하고 다시 인증하도록 안내합니다.

1. **즉각적인 감지** — 도구 호출이 MCP 서버로부터 HTTP 401을 수신하면 오류가 즉시 포착됩니다(먼저 재연결 재시도를 모두 소모할 필요가 없음).
2. **사용자 알림** — 원클릭 **"재인증"** 버튼을 누르면 **"{서버}에 재인증이 필요합니다."**라는 알림 메시지가 나타납니다.
3. **원클릭 수정** — 버튼을 클릭하면 **설정 → 확장 프로그램**으로 바로 이동하여 OAuth로 다시 승인할 수 있습니다.
4. **토큰 핫 업데이트** — 재승인 후 활성 세션은 연결 풀을 통해 자동으로 새 토큰을 선택합니다. 페이지를 다시 로드하거나 세션을 다시 빌드할 필요가 없습니다. 바로 다음 도구 호출에서는 새 자격 증명을 사용합니다.

## 엔터프라이즈 프라이빗 MCP 터널(클라우드 전용)

:::info Cloud deployment only
This feature is available exclusively for **cloud-hosted** Myrm deployments managed by the control plane. Local and Tauri users connect to MCP servers directly via stdio — no tunnel needed.
:::

MCP 서버가 개인 네트워크(방화벽 뒤, VPC 또는 온프레미스)에서 실행되는 기업 고객을 위해 Myrm은(는) 포트를 노출하거나 방화벽 규칙을 수정하지 않고도 클라우드 호스팅 AI 에이전트가 내부 MCP 서버에 안전하게 액세스할 수 있도록 하는 **역방향 터널**을 제공합니다.

### 작동 방식

1. **터널 에이전트 배포** — 개인 네트워크 내부의 모든 머신에 오픈 소스 `myrm-tunnel-agent`을 설치합니다(출처: `myrm-control-plane/clients/myrm-tunnel-agent/`).
2. **터널 등록** — 에이전트가 제어 플레인에 등록하고 보안 토큰을 받습니다.
3. **아웃바운드 전용 연결** - 터널 에이전트가 제어 플레인 릴레이에 대한 아웃바운드 롱 폴 연결을 시작합니다. 인바운드 포트가 필요하지 않습니다.
4. **투명한 릴레이** — 클라우드 Myrm 에이전트가 내부 MCP 도구를 호출하면 요청은 터널을 통해 내부 MCP 서버로 릴레이되고 응답은 투명하게 반환됩니다.

### 보안

| Feature | Description |
|---------|-------------|
| **Zero inbound exposure** | Enterprise network only makes outbound connections — no firewall ports, no VPN, no public IP needed |
| **HTTPS + Token auth** | TLS (HTTPS) between tunnel-agent and control plane, plus `X-Tunnel-Token` header |
| **Token rotation** | Authentication tokens can be rotated at any time without service interruption |
| **Heartbeat monitoring** | 60-second stale threshold with 30-second scan interval — offline tunnels are detected and marked within 90 seconds |
| **Instant revocation** | IT administrators can revoke tunnel access immediately via the org admin panel |



### 건축학```
┌─ Enterprise Network ──────────┐     ┌─ Myrm Cloud ─────────────────┐
│                                │     │                               │
│  Internal MCP Server           │     │  CP Tunnel Relay (in-memory)  │
│       ↑                        │     │       ↑                       │
│  myrm-tunnel-agent ─── outbound ───→ │  org MCP → streamable_http    │
│  (open-source)         HTTPS   │     │       ↓                       │
│                                │     │  Cloud Agent (sandbox)        │
└────────────────────────────────┘     └───────────────────────────────┘
```

### 설정

1. 조직 관리자 패널에서 **터널 등록**(**설정 → 조직 → MCP → 터널 추가**)
2. 제공된 토큰 및 내부 MCP 서버 엔드포인트를 사용하여 `myrm-tunnel-agent` 배포
3. 터널은 조직 수준 MCP 서버로 표시됩니다. 다른 MCP 서버와 마찬가지로 에이전트에 할당합니다.

## 엔터프라이즈 관리 인증 — IdP 그룹 기반 MCP 액세스(클라우드 전용)

:::info Cloud deployment only
This feature is available exclusively for **cloud-hosted** Myrm deployments with OIDC SSO configured. Local and Tauri users manage MCP access directly in their local settings.
:::

ID 공급업체(Okta, Entra ID, Google Workspace 등)를 사용하는 기업 고객의 경우 Myrm은 자동으로 **IdP 그룹 멤버십**을 **조직 MCP 서버 액세스**에 매핑하므로 IT 관리자는 사용자별 수동 구성 없이 어느 팀에서 어떤 도구를 볼 수 있는지 제어할 수 있습니다.

### 작동 방식

1. **OIDC 그룹 클레임** — 사용자가 SSO를 통해 로그인하면 Myrm은 OIDC 응답에서 `groups` 클레임을 추출하여 사용자의 조직 멤버십 기록에 저장합니다.
2. **MCP 그룹별 화이트리스트** — 조직 관리자는 각 조직 MCP 서버에서 선택적 `acl_groups` 목록을 구성합니다(비어 있음 = 모든 구성원에게 표시됨).
3. **자동 필터링** — MCP 구성이 사용자의 샌드박스에 푸시되면 사용자의 IdP 그룹이 서버의 ACL 그룹과 교차하는 서버만 포함됩니다.
4. **로그인 새로 고침** — OIDC에 로그인할 때마다 그룹 멤버십이 자동으로 새로 고쳐지며 수동 동기화가 필요하지 않습니다.

### 그룹 기반 액세스 구성

1. **설정 → 조직 → MCP 서버**로 이동합니다.
2. MCP 서버를 생성하거나 편집할 때 **액세스 그룹** 필드에 IdP 그룹 이름을 입력합니다(쉼표로 구분).
3. 모든 조직 구성원이 서버를 볼 수 있도록 하려면 필드를 비워 둡니다.
4. IdP 그룹이 하나 이상의 구성된 그룹과 일치하는 구성원은 서버를 보고 사용할 수 있습니다.

### 오프보딩

직원이 조직 관리 패널을 통해 오프보딩되면 Myrm은 즉시 빈 MCP 서버 목록을 샌드박스에 푸시하여 모든 조직 MCP 액세스를 즉시 취소합니다. 수동 정리가 필요하지 않습니다.

### 보안

| Feature | Description |
|---------|-------------|
| **Zero-touch provisioning** | New employees see the right MCP tools automatically based on their IdP groups — no IT tickets needed |
| **Least-privilege by default** | Servers with ACL groups are invisible to non-matching members |
| **Instant revocation** | Offboarding cuts MCP access immediately |
| **Audit-friendly** | Group memberships are visible in the org members API for compliance review |
