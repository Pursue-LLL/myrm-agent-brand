# 브라우저 자동화

Myrm 에이전트는 자율적으로 웹을 탐색하고, 양식을 채우고, 데이터를 추출하고, 작업을 수행할 수 있습니다.

## 브라우저 엔진

**이중 스텔스 엔진(Patchright + Camoufox)** — 사이트에서 기본 Chromium 경로를 차단하면 Myrm은 **로그인 쿠키를 잃지 않고** Firefox 기반 스텔스 엔진으로 핫스왑할 수 있으므로 인증된 워크플로가 로그인 페이지로 되돌아가지 않습니다.

3계층 상호작용 스택:

1. **헤드리스 Chrome / Camoufox** — 봇 방지 대체 기능을 갖춘 전체 브라우저 렌더링
2. **DOM 파서** — 구조화된 콘텐츠 추출(자가 복구 로케이터, Shadow DOM)
3. **비전** — 복잡한 UI를 위한 스크린샷 기반 상호 작용

### 12중 탐지 방지 스텔스

Myrm은 자동화된 탐색을 실제 사용자와 구별할 수 없게 만드는 포괄적인 탐지 방지 시스템을 주입합니다. 5가지 주요 안티 봇 시스템(BrowserScan, Fingerprint.com, CreepJS, Cloudflare, DataDome)에 대해 검증되었으며 WeChat, Weibo, Zhihu, Xiaohongshu, Douyin, Twitter/X, Instagram 및 Facebook을 포함한 10개 이상의 고위험 플랫폼에서 프로덕션 테스트를 거쳤습니다.

- **CDP 누출 패치** — Patchright는 프로토콜 수준에서 `Runtime.enable`, `Console.enable` 및 `--enable-automation` 탐지 벡터를 제거합니다.
- **13개의 JS 스텔스 스크립트** — `navigator.webdriver`, `window.chrome` 스텁, 플러그인/언어 에뮬레이션, 자동화 아티팩트 정리, WeakMap을 통한 `toString()` 위장, 안티 디버거 무력화, 성능 API 정리 등
- **Camoufox 지문 지속성** — 전체 장치 지문(캔버스, 오디오, 글꼴, WebGL, 플러그인)이 한 번 생성되어 디스크에 유지됩니다. 후속 세션에서는 동일한 지문을 재사용하므로 사이트에서는 매번 의심스러운 새 장치 대신 일관된 "반환 장치"를 보게 됩니다. 이중 레이어 자가 치유 기능으로 지문 파일 손상 시 자동 복구
- **인간화된 상호작용** — 동적 시간 초과 적응을 통한 무작위 타이핑 지연(30~100ms/문자) 및 클릭 지연(50~150ms)
- **프록시 순환 및 자가 복구** — 자동 불량 프록시 격리, 새로운 IP를 위한 컨텍스트 핫스왑, 상태 저장 세션 마이그레이션(엔진 스위치 전반에 걸쳐 쿠키 + localStorage 보존)

### 이것이 사용자에게 중요한 이유

| Without anti-detection | With Myrm's Stealth |
|----------------------|---------------------|
| Blocked on first page load | Passes Cloudflare and DataDome |
| Login sessions revoked by platform | Stays logged in across sessions |
| New fingerprint every session triggers "suspicious device" flags | Persistent fingerprint — sites see the same trusted device |
| Must use expensive residential proxies | Works with standard proxies |
| Manual browser profile management | Automatic fingerprint management with self-healing |

## 페이지 이해 — 이중 경로 ARIA 스냅샷

Myrm은 페이지 이해를 위해 원시 DOM 대신 **의미론적 접근성 트리**를 사용합니다. 이는 에이전트가 스크린 리더와 같은 방식으로 구조화되고 소음이 없으며 대화형 요소에 초점을 맞춘 페이지를 본다는 것을 의미합니다.

### 작동 방식

| Path | When Used | Speed | Method |
|------|-----------|-------|--------|
| **Fast Path** | 90% of pages | 5-10ms | Playwright native `ariaSnapshot()` — zero JS injection |
| **Custom Path** | Complex edge cases | 20-50ms | JavaScript traversal with depth control |



### 상담원이 보는 것

수천 개의 DOM 노드 대신 에이전트는 깨끗한 의미 트리를 얻습니다.```yaml
- heading "Sign In" [level=1]
- textbox "Email" [ref=1]
- textbox "Password" [ref=2]
- button "Log In" [ref=3]
- link "Forgot password?" [ref=4]
```

모든 대화형 요소는 에이전트가 정확한 타겟팅을 위해 사용하는 안정적인 **참조 ID**를 얻습니다. 깨지기 쉬운 CSS 선택기는 없습니다.

### 내장된 탄력성

- **Shadow DOM 순회** — 웹 구성요소를 자동으로 살펴봅니다.
- **iframe 추출** — 트리에 포함된 교차 출처 iframe
- **범위 필터링** — 토큰 효율성을 위한 `full`, `interactive` 또는 `focused` 뷰
- **증분 차이** — 스냅샷 사이에 변경된 내용만 표시합니다.

### 폐색 감지가 불가능한 이유는 무엇입니까?

OpenCLI와 같은 일부 도구는 `elementFromPoint`을 사용하여 모든 요소를 ​​스캔하여 가려진 요소를 정리합니다. 우리는 다음과 같은 이유로 의도적으로 이 작업을 수행하지 않습니다.

1. 스냅샷당 100-500ms를 추가합니다(모든 요소에 대해 리플로우).
2. 실수로 유효한 요소(드롭다운 메뉴, 도구 설명)를 잘라낼 수 있습니다.
3. 극작가의 `click()`는 이미 해당 요소 클릭을 거부했습니다.
4. 클릭이 실패하면 **자가 복구 로케이터**가 O(1) 시간 안에 문제를 해결합니다.

최종 결과: DOM 기반 접근 방식보다 60~80% 더 작은 5~10ms 스냅샷이며 정확도 저하가 전혀 없습니다.

## 스마트 무한 스크롤

지연 로딩 콘텐츠(소셜 피드, 전자상거래 카탈로그, 뉴스 사이트)가 있는 페이지에는 일반적으로 10~20개 이상의 스크롤 및 확인 루프가 필요합니다. 각 루프에는 LLM 호출이 한 번 발생합니다.

Myrm의 `scroll_to_bottom` 작업은 **한 번의 호출**로 이를 처리합니다.

1. 상담원이 `browser_interact(action="scroll_to_bottom")`에 전화합니다.
2. 엔진은 한 번에 하나의 뷰포트를 자동으로 스크롤하여 새 콘텐츠가 로드될 때까지 기다립니다.
3. 3회 연속 확인 동안 페이지 높이 증가가 멈 추면 멈춥니다.
4. 걸음 수, 경과 시간, 높이 변화, 완료 상태 등 요약을 반환합니다.

**결과**: 한 번의 도구 호출로 10-20 LLM 왕복이 대체되어 무한 스크롤 페이지당 토큰 비용이 최대 90% 절약됩니다.

매개변수를 통해 구성 가능: `max_steps`(스크롤할 거리), `delay_ms`(스크롤 간 대기 시간), `stable_count`(중지하기 전에 안정적인 확인 횟수).

## 캔버스/리치 편집기 시각적 모드

Google Docs, Figma, Google Sheets, Excalidraw와 같은 웹 애플리케이션은 `<canvas>` 요소 또는 고도로 가상화된 DOM의 콘텐츠를 렌더링합니다. ARIA 트리 참조는 표시되는 텍스트, 버튼 또는 셀에 매핑될 수 없습니다. Myrm은 이러한 페이지를 자동으로 감지하고 **좌표 기반 상호 작용**으로 전환합니다.

### 작동 방식

1. **자동 감지**: `browser_snapshot`이 실행되면 Myrm의 콘텐츠 추출기는 `<canvas>` 요소와 역할 없는 시각적 영역을 확인합니다. 중요한 시각적 콘텐츠가 감지되면 스냅샷 결과에 `[VISUAL_CONTENT_DETECTED]` 힌트가 포함됩니다.

2. **모드 전환**: 에이전트는 힌트를 보고 참조 기반 상호 작용에서 좌표 기반 상호 작용으로 전환합니다. 즉, 스크린샷을 사용하여 요소 위치를 식별한 다음 `(x, y)` 좌표로 작업을 호출합니다.

3. **인간화된 상호 작용**: 좌표 모드 동작은 참조 기반 동작과 동일한 베지어 마우스 궤적 엔진을 공유합니다. 클릭과 드래그는 즉각적인 순간 이동이 아닌 자연스러운 곡선 경로를 따릅니다.

### 지원되는 작업

| Action | Parameters | Use Case |
|--------|-----------|----------|
| `click` | `x`, `y` | Click a canvas element (Bézier trajectory supported) |
| `dblclick` | `x`, `y` | Double-click to enter edit mode |
| `type` | `x`, `y`, `text` | Click to focus, then type with humanized delay |
| `press` | `x`, `y`, `text` | Click to focus, then press key combo |
| `hover` | `x`, `y` | Hover to trigger tooltips (Bézier supported) |
| `scroll` | `x`, `y`, `text` (delta) | Scroll at position with signed pixel delta |
| `drag` | `x`, `y`, `target_x`, `target_y` | Drag with Bézier trajectory |



### 예```text
# 1. Agent takes a snapshot and sees [VISUAL_CONTENT_DETECTED]
browser_snapshot → "... [VISUAL_CONTENT_DETECTED: canvas-based content detected] ..."

# 2. Agent requests a screenshot to identify coordinates
browser_manage(action="screenshot")

# 3. Agent clicks a cell in Google Sheets
browser_interact(action="click", x=350, y=200)

# 4. Agent types a value with visual verification
browser_interact(action="type", x=350, y=200, text="Q3 Revenue",
                 verify_goal="Cell shows 'Q3 Revenue'")
```

### 안전

- **뷰포트 경계 유효성 검사**: 보이는 뷰포트 외부의 좌표는 명확한 오류 메시지와 함께 거부됩니다.
- **상호 배제**: `ref` 및 `x/y`은 함께 사용할 수 없습니다. — 모호한 작업을 방지합니다.
- **시각적 확인**: `verify_goal`는 좌표 모드에서도 작동합니다. 3계층 비전 파이프라인(dHash → 픽셀 차이 → 비전 LLM)을 통해 작업이 목표를 달성했는지 확인합니다.

## URL 도메인 차단 목록(설정 + 에이전트별)

탐색이 실패한 후가 아니라 **브라우저가 연결을 열기 전에** 민감하거나 원치 않는 도메인을 차단하세요.

| Layer | What happens |
|-------|----------------|
| **Permission engine** | `browser_navigate` denied when hostname matches merged blocklist |
| **Session navigate** | Hard stop with `BROWSER_URL_BLOCKLIST` — user sees the exact reason in chat |
| **HTTP domain filter** | Blocked hosts never load subresources in the browser context |

**GUI(YAML 없음):** **설정 → 보안** 아래의 전역 목록; **에이전트 → 보안**에서 에이전트별 재정의를 수행합니다. 목록 병합(통합) — 에이전트는 블록을 추가만 할 수 있고 전역 정책을 제거할 수는 없습니다.

**Browser Doctor:** **설정 → 시스템**에서 브라우저 종합 점검을 실행합니다 — 엔진, 메모리, 디스크, 프록시, 확장 브리지 등 8가지 항목을 실제로 검사하고 등급별로 평가하며, 실패 항목마다 구체적인 수정 제안을 제공합니다. 크래시로 남은 Chromium/Driver 고아 프로세스는 시스템 전역에서 탐지되며 확인 게이트를 거쳐 원클릭으로 정리할 수 있습니다.

**확인됨:** 에이전트가 차단된 URL을 시도하면 라이브 모델 E2E + Chrome WebUI 모두 `Navigation blocked: domain … is on the URL blocklist`을 표시합니다.

## 의미론적 DOM 안전성 — 세션 계층 HITL

파괴적인 브라우저 작업(삭제, 지불, 제출, 계정 변경) 및 **JavaScript 변형**(`element.click()`, `form.submit()`, `innerHTML=`)은 작업을 시작한 도구에 관계없이 실행 전에 **Human-in-the-Loop 승인 카드**를 트리거합니다.

### 세션 계층이 중요한 이유

경쟁업체는 종종 외부 도구만 보호합니다 API. Myrm은 **`BrowserSession`**의 경비원이므로 이 경로는 하나의 안전 게이트를 공유합니다.

- `browser_interact_tool`(클릭/더블클릭)
- `browser_execute_script_tool`(`session.interact()`을 호출하는 Python 스크립트)
- `browser_manage_tool` 평가(L1 도구 허용 목록/YOLO 이후)

### WebUI에 표시되는 내용

| Action type | Approval card shows |
|-------------|---------------------|
| High-risk click | Element role, accessible name, ref ID, and `click(e5)` |
| Mutating evaluate | **Full JavaScript expression** in a monospace block (informed consent — not a blind approve) |

피드백 승인, 거부 또는 추가 - 에이전트는 구조화된 차단 메시지를 수신하며 거부할 경우 대안을 찾아야 합니다.

전역 **승인 서랍**은 인터럽트 페이로드(`tool_input`, `page_url` 및 클릭 `element` 메타데이터 포함)를 유지하고 다형성 승인 카드를 표시하며 승인 시 에이전트가 계속되도록 올바른 `{decision: "approve"}` 이력서를 보냅니다. 서버 `/approvals/{id}/resolve` 엔드포인트는 `APPROVAL_RESOLVED` 이벤트를 게시합니다. 승인은 막다른 HTTP 전용 작업이 아닙니다.

### 2계층 평가 정책

1. **L1 도구 승인**: `browser_evaluate`은 보안 정책에서 기본적으로 **거부**로 설정됩니다(YOLO/허용 목록이 재정의될 수 있음).
2. **L2 의미 보호**: L1이 통과하더라도 변형 표현식에는 여전히 HITL이 필요합니다. `document.title`과 같은 읽기 전용 표현식은 즉시 실행됩니다.

## 대화 정책(팝업 자동 처리)

JavaScript 대화 상자(`alert`, `confirm`, `prompt`, `beforeunload`)는 처리되지 않으면 모든 페이지 상호 작용을 차단할 수 있습니다. Myrm은 에이전트당 **4개의 구성 가능한 정책**을 제공합니다.

| Policy | Behavior | Best for |
|--------|----------|----------|
| **Smart** (default) | Accept alerts/confirms, dismiss prompts | General browsing |
| **Auto Accept** | Accept all dialogs | Bulk automation, scraping |
| **Auto Dismiss** | Dismiss all dialogs | Data extraction, read-only |
| **Wait for Agent** | Pause and let AI decide (with timeout fallback) | Critical confirmations |

### 구성

**설정 → 에이전트 → 기능 구성 → 대화 처리**에서 에이전트별 대화 정책을 설정합니다.

에이전트는 `browser_manage`의 `dialog_policy` 작업을 사용하여 런타임 시 정책을 전환할 수도 있습니다.

### 작동 방식

- **스마트** 모드(기본값)에서는 에이전트가 쿠키 배너나 정보 알림으로 인해 멈추지 않습니다.
- **에이전트 대기** 모드에서는 다음 브라우저 스냅샷에 대화 상자 내용이 나타나 AI가 결정할 수 있는 전체 컨텍스트를 제공합니다. 에이전트가 제한 시간 내에 응답하지 않으면 안전한 대체가 자동으로 실행됩니다.
- 상담원은 대화 기록을 항상 볼 수 있으며 어떤 팝업이 어떻게 처리되었는지 알 수 있습니다.

## 쿠키 동의 자동 해제

유럽(그리고 점점 전 세계적으로 증가하고 있음)의 모든 웹사이트에는 GDPR/CCPA 쿠키 배너가 표시됩니다. 자동화하지 않으면 에이전트는 "모두 수락"을 클릭하기 위해 모든 페이지에서 LLM 호출을 낭비하게 됩니다.

Myrm의 **ConsentDismisser**는 모든 페이지 탐색 후에 자동으로 실행됩니다. 구성이 필요하지 않습니다.

1. **75개 이상의 CMP 관련 선택기** — OneTrust, Cookiebot, Didomi, Quantcast 등 수십 개가 시장 점유율 기준으로 정렬되어 있습니다.
2. **일반 속성 일치** — `accept`, `agree`, `allow` 패턴을 사용하여 사용자 정의 동의 구현을 포착합니다.
3. **다국어 텍스트 매칭** — 영어, 독일어, 프랑스어, 스페인어, 이탈리아어, 네덜란드어, 포르투갈어, 중국어, 일본어, 한국어, 폴란드어, 스웨덴어, 덴마크어, 노르웨이어 등 14개 언어로 버튼을 허용합니다.
4. **Shadow DOM 침투** — 사용자 중심, Axeptio 및 기타 Shadow DOM CMP.
5. **CMP JavaScript APIs** — 해고 보장을 위해 Didomi, Cookiebot, Osano 및 Klaro에 직접 API 호출을 합니다.
6. **컨테이너 강제 제거** — 최후의 수단: 모든 클릭 시도가 실패할 경우 55개 이상의 알려진 CMP 컨테이너 및 iframe을 제거합니다.
7. **스크롤 복원** — CMP 본문 스크롤 잠금 및 CMP 관련 CSS 클래스를 제거합니다.

### 실제 영향

- **페이지당 ~50ms**, LLM 비용 없음
- EU/CCPA 사이트에서 페이지 탐색당 1 LLM 왕복(~300토큰)을 절약합니다.
- 100페이지 크롤링: 최대 100개의 LLM 호출과 최대 30,000개의 토큰을 저장합니다.
- 상담원은 깨끗한 페이지 스냅샷을 확인합니다. 쿠키 배너가 복잡하지 않습니다.

### 구성

자동 해제는 **기본적으로 활성화되어 있습니다**. 에이전트별로 비활성화하려면 에이전트의 브라우저 구성에서 `auto_dismiss_consent: false`를 설정하세요.

## 자격증명 보관(비밀번호 유출 없이 로그인)

로그인이 필요한 사이트 및 앱의 경우 **설정 → 자격증명**에서 **자격증명 보관 양식** 항목을 구성하세요.

1. **레이블**(예: `company-admin`), 비밀번호 및 선택적 TOTP 시드를 추가합니다.
2. 상담원에게 로그인하라고 지시합니다. 이는 라벨만 참조합니다.
3. Myrm은 브라우저 DOM 또는 데스크톱 입력 레이어에 자격 증명을 삽입합니다. 값은 대화에 절대 나타나지 않습니다.

**중요한 이유:** 도구 인수 및 채팅 기록은 내구성이 있습니다. `type` 또는 `fill`을 통해 `"hunter2"`을 전달하면 로그, 재시도 및 컨텍스트 전반에 걸쳐 비밀번호가 복사됩니다. 레이블 기반 주입은 저장소 경계에 비밀을 유지합니다. 이는 연구용 브라우저 저장소 설계에서 사용되는 것과 동일한 원칙으로 여기에서는 데스크톱 컴퓨터 사용 및 제품 GUI로 확장됩니다.

## 시각적 검증(자동 QA)

모든 브라우저 작업은 자동으로 확인될 수 있으므로 수동 검사가 필요하지 않습니다.

클릭하거나 탐색할 때 `verify_goal` 매개변수를 전달하면 Myrm의 **3계층 확인 퍼널**이 시작됩니다.

1. **dHash 확인**(~2ms) — 지각 해시는 화면이 전혀 변경되었는지 감지합니다. 변경된 사항이 없으면 LLM 호출을 건너뛰고 토큰을 저장합니다.
2. **픽셀 수준 차이** — 정확한 변경 위치 파악을 위한 캔버스 API YIQ 색상 공간 및 앤티앨리어싱 감지 비교.
3. **비전 LLM 점수 매기기** — 멀티모달 AI는 추론을 통해 결과에 1~5점을 매겨 목표가 달성되었는지 확인합니다.

### 예

상담원에게 다음과 같이 질문하세요. *"'장바구니에 추가'를 클릭하고 장바구니 개수가 2로 표시되는지 확인하세요."*

에이전트는 `verify_goal="Cart count shows 2"`을 사용합니다. 클릭하면 시스템이 자동으로 스크린샷을 찍고 결과를 확인합니다. 점수가 4점 미만이면 에이전트는 다시 시도하라는 피드백을 받습니다.

### 디자인 기술 통합

디자인 중심 기술(`ui-design`, `popular-web-designs`, `infographic`)에는 허용되는 도구에 `browser_navigate_tool`이 포함됩니다. 에이전트가 HTML 아티팩트를 생성하면 자동으로 다음을 수행합니다.

1. 백그라운드에서 로컬로 파일을 제공합니다.
2. 예상되는 시각적 출력을 설명하는 `verify_goal`로 탐색합니다.
3. 3계층 검증 피드백 수신(DOM + dHash + Vision LLM 점수)
4. 렌더링 문제를 수정하고 점수가 ≥ 4가 될 때까지 다시 확인합니다.

즉, 첫 번째 게재 시 **검증된 프로덕션 품질** HTML 디자인을 볼 수 있으므로 수동으로 주고받는 작업이 1~3라운드 줄어듭니다. 브라우저 도구를 사용할 수 없으면 단계를 정상적으로 건너뜁니다.

### 개인정보 보호

비밀번호 필드는 스크린샷에서 **자동으로 마스킹**됩니다. Vision LLM에서는 민감한 자격 증명을 볼 수 없습니다.

## 스키마 기반 구조적 추출

원시 페이지 텍스트를 대화에 덤프하는 대신(컨텍스트 토큰 낭비) **JSON 스키마**를 추출 도구에 전달하고 검증되고 구조화된 JSON을 다시 가져올 수 있습니다.

### 작동 방식

1. 에이전트는 `extraction_schema` 매개변수(JSON 스키마 문자열)를 사용하여 `browser_extract`을 호출합니다.
2. 도구는 페이지 텍스트를 추출한 다음 LLM를 사용하여 스키마와 일치하는 구조화된 출력을 생성합니다.
3. 수천 개의 원시 HTML 토큰이 아닌 깨끗하고 검증된 JSON을 받습니다.

### 예

상담원에게 다음과 같이 질문하세요. *"이 페이지에서 모든 제품 이름과 가격을 추출하세요."*

에이전트는 다음과 같은 스키마를 사용합니다.```json
{
  "type": "array",
  "items": {
    "type": "object",
    "properties": {
      "name": { "type": "string" },
      "price": { "type": "string" }
    },
    "required": ["name", "price"]
  }
}
```

결과: 필요한 데이터만 포함된 깔끔한 JSON 배열입니다.

### 주요 기능

- **객체 및 배열 스키마** — 단일 객체 또는 항목 목록을 추출합니다.
- **페이지 매김 중복 제거** — 페이지 간 중복을 방지하려면 `already_collected`을 전달합니다.
- **이중 전략 신뢰성** — 모델 호환성을 위해 원시 JSON 대체 기능이 있는 `structured_output`을 선호합니다.
- **토큰 절약** — 원시 텍스트 추출에 비해 70~97% 감소합니다.
- **스키마 복잡성 보호** — 속성 수 및 중첩 깊이에 대한 제한으로 오용을 방지합니다.

### 추출된 데이터에서 대화형 스프레드시트로

추출을 통해 JSON을 구조화하면 상담원은 이를 CSV 또는 Excel 파일에 쓸 수 있으며 이는 채팅에서 자동으로 풍부한 대화형 아티팩트가 됩니다.

**파이프라인**(완전 자동, 추가 도구 필요 없음):

1. 에이전트는 `extraction_schema`를 통해 구조화된 데이터를 추출합니다.
2. 에이전트가 내장된 파일 도구를 사용하여 `.csv` 파일을 작성 → 아티팩트 자동 등록
3. 프런트엔드는 실시간 SSE 푸시를 통해 아티팩트를 수신합니다.
4. `SpreadsheetPreview`는 채팅에서 직접 대화형 DataGrid를 렌더링합니다.

**DataGrid에서 사용자에게 표시되는 내용:**

- 10,000개 이상의 행을 원활하게 처리하는 가상 스크롤 테이블
- 열 헤더를 클릭하여 정렬(오름차순/내림차순)
- 모든 셀에 대한 실시간 검색
- 한 번의 클릭으로 행 또는 전체 표를 클립보드에 복사
- CSV로 내보내기/다운로드

여러 시트가 포함된 Excel(`.xlsx`) 파일의 경우 에이전트는 Python의 `openpyxl`과 함께 코드 실행 도구를 사용할 수 있습니다. 프런트엔드는 시트 간 전환을 위한 시트 탭을 자동으로 표시합니다.

**경쟁업체 대비:** 대부분의 브라우저 자동화 도구(예: BrowserAct)는 다운로드 가능한 파일만 생성합니다. Myrm은 대화 내에서 데이터를 **실시간 대화형 테이블**로 제공합니다. 사용자는 다운로드하기 전에 탐색, 정렬, 검색할 수 있습니다.

## 비전 자동 대체(DOM → LLM)

페이지가 캔버스(차트, 그래프) 또는 복잡한 SVG(인포그래픽, 다이어그램)를 통해 콘텐츠를 렌더링할 때 기존 DOM 텍스트 추출은 비어 있거나 의미 없는 데이터를 반환합니다. Myrm은(는) 이 상황을 자동으로 감지하고 에이전트 개입 없이 투명하게 Vision LLM 기반 추출로 대체합니다.

### 작동 방식

1. 에이전트는 페이지 텍스트 추출을 요청합니다(항상 동일한 `browser_extract` 도구).
2. DOM 텍스트가 부족하고(50자 미만) 페이지에 중요한 시각적 요소(대형 캔버스/SVG)가 포함된 경우 도구가 자동으로 스크린샷을 찍습니다.
3. 비전 LLM은 스크린샷을 분석하고 보이는 모든 텍스트, 데이터, 라벨 및 값을 추출합니다.
4. 결과는 동일한 인터페이스, 더 풍부한 데이터로 에이전트에 반환됩니다.

### 발동할 때

- **차트/대시보드**(캔버스에서 Chart.js, D3, ECharts를 통해 렌더링됨)
- **인포그래픽**(텍스트/데이터가 포함된 복잡한 SVG)
- **캔버스 렌더링 애플리케이션**(Google 지도 데이터, 게임 UI)
- **이미지가 많은 콘텐츠 페이지**(의미 있는 텍스트가 시각적 요소에만 존재하는 경우)

### 주요 기능

- **완전히 투명** — 에이전트는 대체에 대해 알 필요가 없습니다. 동일한 도구, 동일한 스키마.
- **스마트 감지** — 캔버스/SVG 요소가 200×100픽셀을 초과하는 경우에만 활성화됩니다(작은 아이콘에서 잘못된 트리거 방지).
- **SVG 텍스트 추출** — Vision LLM이 없어도 SVG `<text>` 및 `<tspan>` 요소가 이제 DOM에서 직접 추출됩니다.
- **구조화된 출력** — 스키마 기반 추출에서도 작동 — Vision LLM은 스키마에 맞는 JSON을 생성합니다.
- **필요하지 않은 경우 추가 비용 없음** — DOM 텍스트가 충분하면 스크린샷이나 LLM 호출이 이루어지지 않습니다.

### 경쟁사 비교

어떤 경쟁업체도 자동 DOM-to-Vision 폴백을 제공하지 않습니다.
- **Hermes**: 수동 `browser_vision` 도구 호출이 필요합니다(에이전트는 언제 사용할지 결정해야 함).
- **Crawl4AI**: DOM 전용 추출, 비전 기능 없음.
- **OpenClaw**: 내장 브라우저 추출이 전혀 없습니다.

## 주문형 미디어 추출

단일 도구 호출로 모든 페이지에서 모든 이미지, 비디오 및 오디오 URL을 추출합니다. JavaScript 작성이 필요하지 않습니다.

### 작동 방식

1. 상담원 호출 `browser_extract(mode='media')` — 도구 호출 1회.
2. 도구는 모든 프레임을 탐색하여 다음을 수집합니다.
   - **이미지**: 지연 로드 해결 기능이 있는 `<img>` 태그(`data-src`, `data-lazy-src`, `data-original`, `srcset`, `data-srcset` 및 지연 로딩 라이브러리에 대한 와일드카드 `data-*src*` 대체)
   - **동영상**: `<video>/<source>` 요소 + iframe 삽입(YouTube, Vimeo, Dailymotion, Wistia)
   - **오디오**: `<audio>/<source>` 요소
   - **메타 이미지**: OpenGraph 및 Twitter 카드 이미지 태그
3. 장식 요소(아이콘, 로고, 파비콘, 50px 미만의 작은 이미지)는 자동으로 필터링됩니다.
4. 프레임 간 URL 중복 제거로 깨끗하고 중복 없는 출력이 보장됩니다.
5. 결과에는 가능한 경우 크기, 대체 텍스트 및 포스터 URL이 포함됩니다.

### 주요 장점

- **주문형** — 모든 응답에서 미디어를 덤프하는 경쟁업체와 달리 필요한 경우에만 추출됩니다.
- **선택기 범위 지정** — 특정 페이지 영역에서 미디어를 추출하려면 `selector` 매개변수를 사용합니다.
- **지연 로드 인식** — `data-srcset` 및 와일드카드 `data-*src*` 속성을 포함한 모든 일반적인 지연 로딩 패턴을 해결합니다.
- **교차 프레임 중복 제거** — 프레임 전체에 걸쳐 자동 URL 중복 제거를 사용하여 모든 iframe에서 추출합니다.
- **구조화된 출력** — 개수 및 메타데이터를 포함하여 유형(이미지/비디오/오디오/메타)별로 그룹화됩니다.

### 예

상담원에게 다음과 같이 질문하세요. *"이 전자상거래 페이지에서 모든 제품 이미지를 추출하세요."*

에이전트는 `browser_extract(mode='media', selector='.product-gallery')`을 사용하고 크기가 포함된 깨끗한 이미지 URL 목록을 가져옵니다. JavaScript는 필요하지 않습니다.

## 임시 세션 격리

모든 브라우저 컨텍스트는 **기본적으로 임시**이며 영구 프로필 없이 `browser.new_context()`를 통해 생성됩니다. 쿠키, localStorage 및 캐시는 세션이 종료되면 자동으로 삭제됩니다. 에이전트는 실제 브라우저 프로필에 액세스할 수 없으므로 세션 유출 위험이 완전히 제거됩니다.

## 개인 정보 보호 우선 로그인 액세스(OS 기록 마이닝 없음)

Myrm Chrome/Edge `History.db`, 북마크 데이터베이스 또는 기타 OS 수준 탐색 아티팩트를 읽지 **않습니다**. 이는 의도적인 것입니다. 로그인 및 인트라넷 액세스는 대신 명시적인 사용자 제어 경로를 사용합니다.

| Need | Myrm path | What we avoid |
|------|-----------|---------------|
| Reuse login on a site you already use | **Extension Bridge** — agent controls your real Chrome tab with existing session | Bulk history/bookmark indexing |
| Login once, stay logged in across agent runs | **Session Vault** — AES-256-GCM encrypted cookies + localStorage per domain | Cookie DB import from your profile |
| Recall a URL you discussed with the agent | **`memory_search_tool` (corpus=sessions, opt-in)** | OS-level history search |

**업계 연계:** 주요 클로 경쟁사(OpenClaw, Hermes, CoPaw, DeerFlow, CodePilot, LobsterAI, JiuwenClaw)는 `History.db` 또는 북마크 JSON을 읽는 에이전트 도구를 제공하지 않습니다. 일부 제품(예: Orca, Holaboss)은 내장 브라우저로 일회성 Chrome 쿠키/프로필 가져오기 기능을 제공합니다. 이는 동일한 사용자 목표를 가진 다른 아키텍처입니다. CoPaw는 사용자가 상담원에게 기록/쿠키가 노출되는 것을 원하지 않는 경우 `private_mode`을 명시적으로 권장합니다.

## 영구 세션 Vault(교차 세션 로그인)

기본적으로 세션은 일시적이지만 각 상담원에 대해 **자동 복원 도메인**을 구성하여 대화 전반에 걸쳐 로그인 상태를 보존할 수 있습니다.

### 작동 방식

1. **도메인 구성** — 에이전트 설정 WebUI에서 `twitter.com`, `github.com`과 같은 도메인을 에이전트의 `auto_restore_domains` 목록에 추가합니다.
2. **세션은 암호화됩니다** — 쿠키 및 스토리지 데이터는 AES-256-GCM 암호화를 통해 세션 저장소에 저장됩니다.
3. **시작 시 자동 복원** — 에이전트가 새 브라우저 세션을 시작할 때마다 구성된 도메인의 로그인 상태가 자동으로 복원됩니다.
4. **에이전트는 명시적으로 관리할 수 있습니다** — 에이전트는 세밀한 제어를 위해 `browser_manage(action="save_session")` / `restore_session` / `list_sessions` / `delete_session`을 호출할 수도 있습니다.

### 아키텍처

- **AES-256-GCM 암호화** — 세션 데이터는 저장 시 암호화되며 일반 텍스트로 저장되지 않습니다.
- **O(1) LRU 메모리 캐시** — 메모리에서 제공되는 핫 세션입니다. 반복 액세스 시 디스크 I/O가 없습니다.
- **Singleflight dedup** — 동일한 도메인에 대한 동시 요청이 하나의 암호 해독 작업으로 통합됩니다.
- **TTL 자동 만료** — 오래된 세션은 자동으로 가비지 수집됩니다.
- **전체 실행 범위** — 웹, 채널, Cron 및 Eval 실행 컨텍스트에서 작동합니다.
- **에이전트별 물리적 격리** — 각 에이전트는 자체 `agent_id` 하위 디렉터리에 세션을 저장합니다. 에이전트 A의 저장된 로그인은 동일한 서버 인스턴스에서도 에이전트 B에게 완전히 표시되지 않습니다.

### 사용 시기

| Scenario | Recommendation |
|----------|----------------|
| One-off browsing | Default (ephemeral) — no config needed |
| Repeated access to authenticated sites | Add to `auto_restore_domains` |
| Agent workflow needs login mid-task | Agent calls `save_session` / `restore_session` |
| Shared credentials across agents | Each agent configures its own domain list independently |

### 세션–Memory Bridge(무비용 인식)

메모리 시스템이 활성화되면 저장된 브라우저 세션이 에이전트 컨텍스트에서 **자동으로 표시**되므로 추가 도구 호출이 필요하지 않습니다.

- **작동 방식:** 세션이 저장되거나 삭제될 때마다 `SessionMemoryBridge`은 에이전트의 `active_browser_sessions` 프로필 속성을 업데이트합니다. 이 속성은 메모리 컨텍스트 미들웨어를 통해 모든 LLM 턴에 주입됩니다.
- **결과:** 사용자가 "트윗 게시"라고 말하면 에이전트는 이미 `twitter.com`을 사용할 수 있다는 것을 알고 있습니다. 즉, `restore_session("twitter.com")`을 직접 호출하고 **`list_sessions` 단계를 건너뛰고** 하나의 LLM 추론 라운드를 저장합니다.
- **프롬프트 캐시 안전:** 프로필 속성은 저장/삭제 시에만 변경되므로(매우 드물게) 프롬프트 접두사 캐싱은 영향을 받지 않습니다.

| Without Bridge | With Bridge |
|---------------|-------------|
| User: "Post a tweet" → Agent calls `list_sessions` → sees twitter.com → calls `restore_session` | User: "Post a tweet" → Agent sees twitter.com in context → calls `restore_session` directly |
| 2 tool calls + 2 LLM inferences | 1 tool call + 1 LLM inference |

## OAuth 팝업 자동 캡처

상담원이 'Google로 로그인', 'GitHub로 로그인' 또는 새 브라우저 창을 여는 링크를 클릭하면 Myrm이(가) 자동으로 팝업을 캡처하고 수명 주기를 관리합니다.

### 작동 방식

1. **자동 캡처** — 모든 브라우저 페이지에는 자동으로 등록된 팝업 리스너가 있습니다. `window.open()`이 실행되면(OAuth, `target=_blank` 등) 새 창이 즉시 하위 탭으로 캡처됩니다.
2. **포커스 스위치** — 활성 탭이 팝업으로 전환되어 에이전트(또는 세션 볼트 자동 복원)가 인증 흐름과 상호 작용할 수 있습니다.
3. **상위 복구** — 팝업이 닫히면(사용자가 로그인을 완료하거나 OAuth 리디렉션이 완료됨) 에이전트가 자동으로 상위 페이지로 다시 전환됩니다.
4. **재귀적 지원** — 팝업 페이지 자체가 중첩된 팝업을 수신합니다(예: Google OAuth → SAML IdP → MFA 공급자).

### 실제 시나리오

| Scenario | What Happens |
|----------|-------------|
| Agent visits GitHub, clicks "Sign in with Google" | Popup captured → agent observes OAuth flow → popup closes → agent back on GitHub, now logged in |
| Web form with `target=_blank` link | New tab captured as child → agent continues on new page → closes it → returns to form |
| Session Vault + OAuth | First time: popup captured, login completed, session saved. Next time: auto-restore skips OAuth entirely |

어떤 경쟁업체(Hermes, OpenClaw, CoPaw, LobsterAI, DeerFlow, JiuwenClaw)도 자동 팝업 캡처를 구현하지 않습니다. 모든 참조 저장소에서 `page.on('popup')`의 코드베이스 스캔을 통해 확인됩니다.

## 사이트 경험 스토어 — 사용과 함께 성장하는 도메인 인텔리전스

에이전트는 웹사이트를 탐색할 때마다 학습합니다. **Site Experience Store**는 도메인 수준 지식을 캡처하고 향후 방문 시 이를 재사용하여 반복 상호 작용을 더 빠르고 안정적으로 만듭니다.

### 무엇을 배울 것인가

| Dimension | Example |
|-----------|---------|
| **Platform Features** | "This site has infinite scroll", "Supports GraphQL API" |
| **URL Patterns** | `/user/{id}/posts`, `/search?q={query}&page={n}` |
| **Known Traps** | "Login popup after 3 scrolls", "Cookie consent wall on first visit" |
| **Successful Flows** | "Search → Filter by date → Sort → Extract results" |

### 작동 방식

1. **탐색 시 자동 삽입** — 에이전트가 이전에 방문한 도메인으로 이동하면 관련 트랩과 검증된 흐름이 브라우저 스냅샷에 삽입됩니다. 에이전트는 맹목적으로 탐색하는 대신 정보를 얻기 시작합니다.
2. **교차 검증** — 도메인의 최근 실패율이 급증하면(24시간 동안 3회 이상의 실패) 경험이 자동으로 무효화되어 오래된 지식으로 인해 오류가 발생하는 것을 방지합니다.
3. **에이전트 관리** — 에이전트는 `browser_manage` 도구 작업(`save_site_experience`, `list_site_experience`, `delete_site_experience`)을 통해 경험을 저장, 나열 및 삭제할 수 있습니다.
4. **HTTP/3 학습** — HTTP/3을 통해 더 빠르게 응답하는 도메인은 기억되어 향후 요청에서 우선적으로 사용됩니다.

### 영향

| Without Site Experience | With Site Experience |
|------------------------|---------------------|
| Agent explores every site from scratch | Known traps avoided, proven flows reused |
| 3-10 extra LLM calls per complex site | 30-50% fewer exploration steps on repeat visits |
| Same mistakes repeated across sessions | Mistakes remembered and avoided automatically |



에이전트는 **엔진 어피니티 스토어**(스텔스 브라우징이 필요한 사이트 기억) 및 **세션 저장소**(로그인 상태 유지)와 결합하여 모든 상호 작용에서 향상되는 포괄적인 도메인별 메모리를 구축합니다.

## 도메인 실행 가능 기술 — 웹사이트당 재사용 가능한 자동화

프롬프트 수준 지식(Site Experience Store) 외에도 Myrm은 **실행 가능한 도메인 기술**을 지원합니다. 즉, 에이전트가 일치하는 도메인을 방문할 때 자동으로 로드되어 도구로 사용할 수 있는 Python 자동화 스크립트입니다.

### 작동 방식

1. **매니페스트 기반 선언** — 각 도메인 스킬에는 도메인 일치 패턴 및 도구 정의가 포함된 `manifest.yaml`이 있습니다.
2. **자동 검색** — 에이전트가 `x.com`으로 이동하면 일치하는 모든 도메인 기술이 자동으로 사용 가능한 도구로 삽입됩니다.
3. **내장 + 사용자 생성** — 기본 제공 기술(예: X/Twitter 타임라인 추출)이 포함되어 제공됩니다. 사용자는 증류 API를 통해 또는 수동으로 자신만의 것을 만들 수 있습니다.
4. **GUI 관리** — 설정 > 시스템 > 도메인 스킬은 내장 배지와 함께 모든 스킬을 표시하고, 사용자 스킬을 추가/제거합니다.

### 예시: X(Twitter) 타임라인 추출

에이전트가 매번 X를 스크래핑하는 방법을 알아내는 대신 내장 도메인 기술이 `get_timeline_posts` 도구를 제공합니다.```yaml
domain: x.com
tools:
  - name: get_timeline_posts
    description: Extract posts from the current X timeline
    script: tools/get_timeline_posts.py
```

에이전트는 탐색 힌트에서 이 도구를 확인하고 직접 호출할 수 있습니다. 즉 탐색 단계를 완전히 건너뛸 수 있습니다.

### 반자동 증류

에이전트가 브라우저 워크플로를 성공적으로 완료하면 이를 재사용 가능한 도메인 기술로 저장할 수 있습니다.

1. 채팅에서 성공적인 실행을 검토하세요.
2. 도구 정의를 사용하여 증류 API(`POST /api/v1/browser/domain-skills/distill`)을 호출합니다.
3. 스킬이 저장되어 향후 해당 도메인 방문 시 자동으로 사용할 수 있습니다.

### 영향

| Without Domain Skills | With Domain Skills |
|----------------------|-------------------|
| Agent re-discovers site structure every visit | Proven automation scripts run instantly |
| 5-10 LLM rounds for complex site interactions | 1-2 rounds (tool call + result) |
| Each session starts from zero knowledge | Knowledge compounds across sessions |

## CAPTCHA 탐지 및 인적 탈취

에이전트가 CAPTCHA 또는 사람의 개입이 필요한 상황에 직면하면 원활하게 처리합니다.

### 자동 CAPTCHA 감지 및 해결

10가지 CAPTCHA 유형이 자동으로 감지됩니다(Cloudflare Turnstile, reCAPTCHA, hCaptcha, DataDome, Akamai 등). 해결은 세 가지 계층으로 이루어집니다.

1. **자동 해결**(CapSolver API): Cloudflare, reCAPTCHA, hCaptcha가 자동으로 해결되며 사용자 작업이 필요하지 않습니다.
2. **행동 WAF 우회**: DataDome, Kasada, Akamai, Imperva, PerimeterX가 즉시 인식되고 엔진이 자동으로 Camoufox(심층 탐지 방지)로 업그레이드됩니다. — 완전히 투명합니다.
3. **수동 폴백**: 실제로 해결 불가능한 CAPTCHA만 실행을 일시 중지합니다. VNC 패널이 열리면 사용자가 문제를 해결하고 에이전트가 자동으로 재개됩니다.

### 에이전트에 의한 인간 탈취

CAPTCHA 이외의 시나리오(2FA 프롬프트, 결제 대행사, 독점 양식)의 경우 상담원이 적극적으로 도움을 요청할 수 있습니다.

1. 상담원은 진행할 수 없음을 인식합니다(예: "SMS 확인이 필요합니다.")
2. 명확한 설명과 함께 `browser_ask_human`을 호출합니다.
3. **확장 경로**(매일 Chrome/확장 브리지): 이유, 스크린샷 미리보기, 라이브 탭 링크가 포함된 채팅 **`ExtensionTakeoverBanner`**이 나타납니다. 브라우저에서 작업을 완료한 다음 **완료** 또는 **이 작업을 수행할 수 없음**을 클릭하세요.
4. **관리 경로**(샌드박스/VNC): 이유가 표시된 VNC 패널이 열립니다. 여기서 작업을 완료한 다음 **완료**를 클릭합니다.
5. 에이전트는 새 페이지 상태를 캡처하고 계속합니다.

두 경로 모두 동일한 구조화된 이력서 계약(`{action:'completed'|'skipped'}`)을 공유하며 Chrome MCP E2E(READ ×3 + LIVE ×1, 2026년 7월)에 의해 검증되었습니다.

### 터미널 챌린지 하드 정지

엔진 자동 업그레이드(Chromium → Camoufox) 후에도 CAPTCHA를 해결할 수 없는 경우 에이전트는 즉시 시간 낭비를 중지합니다.

1. 에이전트는 `BROWSER_TERMINAL_CHALLENGE` 오류 코드와 함께 구조화된 `ToolError`을 발생시킵니다.
2. 도메인은 10분 동안 기억됩니다. 해당 도메인에 대한 후속 탐색은 재시도하는 대신 **0ms** 내에 실패합니다.
3. 에이전트는 "이 도메인을 다시 시도하지 마십시오. 사용자에게 알리고 대체 접근 방식으로 이동하십시오."라는 명확한 지침을 받습니다.

이는 에이전트가 극복할 수 없는 문제에 토큰과 시간을 소모하는 일반적인 업계 문제를 방지합니다.

### 이것이 중요한 이유

| Without Myrm | With Myrm |
|--------------|-----------|
| Agent loops forever on CAPTCHA | Auto-detects, pauses, notifies |
| Agent fails silently on 2FA | Proactively asks for help |
| User must monitor constantly | Only interrupts when truly needed |
| Lost context after intervention | Captures post-human page state and adapts |
| Agent retries blocked domain endlessly | 0ms fast-fail for remembered terminal challenges |

## 리소스 효율적인 브라우징 — 어디에서나 실행

Myrm의 브라우저 시스템은 기능 저하 없이 월 5달러짜리 클라우드 컨테이너부터 저사양 노트북까지 모든 장치에서 효율적으로 실행되도록 설계되었습니다.

### 자원을 절약하는 방법

| Optimization | What It Does | Impact |
|:-------------|:-------------|:-------|
| **Adaptive Routing** | 70% of pages resolved via lightweight HTTP (no browser launched) | ~0MB per HTTP-only page |
| **Dual Engine** | Camoufox (Firefox, ~40MB idle) available alongside Chromium (~200MB+) | 5x memory reduction for stealth tasks |
| **MemoryGuard** | Monitors system memory; blocks new browser pages above 85% usage | Prevents OOM crashes in containers |
| **Resource Blocking** | Blocks images, stylesheets, scripts, fonts, media + 3500 ad domains | Fewer network requests, less memory per page |
| **4-Layer Network Defense** | CSP policy + route interception + WebRTC/WebTransport hardening + CDP audit monitoring | Trackers blocked across all channels (HTTP, WebSocket, EventSource, sendBeacon, WebRTC) |
| **Circuit Breaker** | Stops retrying persistently failing domains | No wasted resources on dead sites |

### 세 가지 사전 설정 - 프로필 선택

| Profile | Best For | Memory Guard | Circuit Breaker |
|---------|----------|:------------:|:---------------:|
| **Standard** (default) | Production use | Off | Off |
| **Defensive** | Cloud containers, high concurrency | On (85%) | On |
| **Minimal** | Development, single tasks | Off | Off |

브라우저 풀 설정을 통해 구성하세요. 대부분의 사용자는 기본값을 변경할 필요가 없습니다.

### 이것이 중요한 이유

| Without resource management | With Myrm |
|:----------------------------|:----------|
| 3 browser tabs = container OOM kill | MemoryGuard prevents new pages when memory is tight |
| Every page request launches a full browser | 70% of pages use zero-browser HTTP path |
| Ad trackers consume bandwidth and RAM | 3500+ domains blocked automatically |
| One bad domain wastes unlimited retries | Circuit breaker trips after consecutive failures |

## 5계층 크롤링 방지 보호

대규모로 크롤링할 때는 IP 차단, 속도 제한, CAPTCHA가 불가피합니다. Myrm의 5중 방어 시스템은 이 모든 것을 자동으로 처리하므로 작업이 중단되지 않습니다.

### 자율 세션 수명 주기

브라우저 세션은 완전히 자체 관리되므로 브라우저 세션을 수동으로 시작, 중지 또는 복구할 필요가 없습니다.

| Layer | What It Does | Response Time |
|:------|:-------------|:--------------|
| **L1: Disconnect detection** | Detects browser process crash via `disconnected` event | Instant |
| **L2: Page crash detection** | Detects renderer crash via `crash` event | Instant |
| **L3: Periodic health-check** | Probes all browsers every 30 seconds, evicts unresponsive instances | 30s |
| **Idle eviction** | Reclaims browsers with zero active pages after configurable timeout | Automatic |
| **Elastic scaling** | Creates browsers on-demand under load, scales to zero when idle | Automatic |

**이것이 의미하는 바:** 에이전트를 시작하고 탐색 작업을 제공한 후 떠나세요. 브라우저가 충돌하는 경우 로그인 상태는 암호화된 세션 저장소에 보존되고 다음 요청 시 자동으로 복원됩니다. 여러 에이전트를 동시에 실행하는 경우 각 에이전트는 격리된 브라우저 컨텍스트를 얻습니다. 간섭도 없고 수동 조정도 없습니다.

**경쟁업체 대비:** BrowserAct는 세션을 관리하기 위해 수동 `session list` / `session close` CLI 명령이 필요합니다. 다른 경쟁업체(Hermes, OpenClaw, CoPaw)에는 세션 수명주기 관리 기능이 전혀 없습니다. Myrm은(는) 완전히 자율적입니다.

### 보호 계층

| Layer | What It Does | User Benefit |
|:------|:-------------|:-------------|
| **Detection** | Recognizes HTTP 403/429 status codes + Cloudflare/DataDome/CAPTCHA body signatures + 13 network error patterns | Catches blocks that simple status-code checks miss |
| **Proxy Quarantine** | Blocked proxy is quarantined with exponential backoff (60s → 5min → 1hr). Automatically skipped in rotation | Bad proxies stop wasting your requests |
| **Session Recovery** | On block: quarantine proxy → restart session with a new proxy → resume from where you left off, zero state loss | No need to restart crawls from scratch |
| **Circuit Breaker** | Per-domain circuit breaker trips after consecutive failures, auto-recovers after timeout | One bad domain doesn't bring down your entire task |
| **Rate Limiting** | Per-domain Token Bucket algorithm prevents over-requesting that triggers anti-bot systems | Stays under the radar by design |

추가: 사람이 인계받아 자동 감지되는 10가지 CAPTCHA 유형(위 참조), Adaptive Router는 스텔스 브라우징이 필요한 사이트를 학습하고 세션 전반에 걸쳐 기억합니다.

### 실제 영향

- 수동 개입 없이 10,000페이지 이상 크롤링
- 무손실 세션 마이그레이션으로 차단된 IP 자동 교체
- 시스템은 시간이 지남에 따라 더욱 똑똑해집니다. 지속적인 규칙은 사이트 X에 L3 Stealth가 필요하다는 점을 기억합니다.
- 제로 구성 필요 - 기본적으로 모든 보호 기능이 활성화되어 있습니다.

### 비교 방법

| Feature | Myrm | Crawl4AI | Others |
|:--------|:----:|:--------:|:------:|
| Proxy exponential backoff quarantine | Yes | No | No |
| Per-domain circuit breaker | Yes | No | No |
| Per-domain token bucket rate limiting | Yes | No | No |
| Lossless session migration on block | Yes | No | No |
| 10-provider CAPTCHA detection + HITL | Yes | No | No |
| Self-learning tier escalation (L1→L2→L3) | Yes | No | No |

## 브라우저 확장 브리지

기존 로그인 세션, 확장 프로그램 및 탐색 컨텍스트를 그대로 유지하면서 **실제 브라우저** 내에서 에이전트를 작동해야 하는 시나리오의 경우 Myrm은 Chrome 확장 브리지를 지원합니다.

### 사용 시기

| Scenario | Best Approach |
|----------|--------------|
| Fresh automated browsing | Default (ephemeral engine) |
| Re-use specific login sessions | SessionVault `auto_restore_domains` |
| Need full browser fingerprint consistency | **Extension Bridge** |
| Agent must control your real Chrome with existing login/extensions | **Extension Bridge** |
| SaaS mode controlling a remote user's browser | **Extension Bridge** |

> **개인 정보 보호 참고 사항:** Extension Bridge는 브라우저에서 승인된 탭을 제어합니다. 이는 OS 검색 기록이나 북마크 데이터베이스를 대량으로 읽지 **않습니다**. 과거 대화에서 URL을 불러오려면 메모리 불러오기 또는 선택 대화 검색을 사용하세요.

### 작동 방식

1. **Myrm 확장 프로그램 설치** — Myrm 서버에 대한 WebSocket 연결을 유지하는 경량 Chrome MV3 확장 프로그램입니다.
2. **도메인 승인** — 설정 → 통합 → 확장 브리지에서 에이전트가 제어할 도메인(예: `github.com`, `*.google.com`)을 추가합니다. 와일드카드 패턴이 지원됩니다.
3. **에이전트 연결** — 작업에 승인된 도메인에 대한 브라우저 액세스가 필요한 경우 에이전트는 확장 프로그램의 WebSocket 채널 및 `chrome.debugger` API을 통해 실제 브라우저에 연결합니다.

### 배경 창 격리(비인식 실행)

에이전트가 Extension Bridge를 통해 작동할 때 모든 자동화는 **전용 백그라운드 창**에서 실행되며 활성 탭은 절대 건드리지 않습니다.

- 확장 프로그램은 에이전트 작업을 위해 보이지 않는 초점이 맞지 않는 창(`focused: false`)을 생성합니다.
- 모든 탭 작업은 이 격리된 창에서 이루어집니다. 포커스 도용이나 탭 전환이 없습니다.
- 백그라운드 창 ID는 `chrome.storage.local`를 통해 서비스 워커를 다시 시작해도 유지됩니다.
- 백그라운드 창을 수동으로 닫으면 다음 작업 시 자동으로 다시 생성됩니다.
- 연결이 끊어지면 모든 배경 탭이 정리되어 리소스 축적을 방지합니다.

**3중 레이어 세션 안전망** — 좀비 프로세스나 오래된 세션이 발생하지 않습니다.

| Layer | Trigger | Response Time |
|-------|---------|---------------|
| L1: WebSocket disconnect | Server crash, network drop, or user stops agent | Instant — all debuggers detached immediately |
| L2: Heartbeat timeout | Extension becomes unresponsive | 30 seconds — server disconnects and cleans up |
| L3: Tab lifecycle events | User closes browser or Chrome reclaims tabs | Instant — extension notifies server |

**결과**: 에이전트가 백그라운드에서 최고 속도로 작동하는 동안 사용자는 계속해서 정상적으로 탐색합니다. 창 깜박임도 없고, 초점 도용도 없고, 중단도 없습니다.

### 보안 모델

- **도메인 수준 승인** — 명시적으로 승인된 도메인만 제어할 수 있습니다. 에이전트는 허용 목록 외부의 탭에 액세스할 수 없습니다.
- **토큰 인증** — 확장 프로그램은 비밀 토큰을 사용하여 서버를 인증하여 무단 연결을 방지합니다.
- **서비스 워커 연결 유지** — MV3 확장은 지수 백오프 재연결을 통한 지속적인 연결을 위해 `chrome.alarms`을 사용합니다.
- **재연결 시 도메인 동기화** — 확장 프로그램이 다시 연결되면 승인된 도메인을 즉시 서버와 동기화합니다.

### 프런트엔드 관리

확장 브리지 설정 패널(설정 → 통합)은 다음을 제공합니다.

- **원클릭 복사 가능한 WebSocket URL** — 배포 모드에 대한 올바른 연결 URL(복사 버튼 및 알림 메시지 포함)
- **인증 토큰 상태** — `EXTENSION_AUTH_TOKEN`이 서버에 구성되어 있는지 여부를 표시합니다(토큰 자체를 노출하지 않음).
- **복사 가능한 확장 경로** — Chrome의 '압축해제된 항목 로드' 대화상자에 대한 원클릭 복사본으로 `~/.myrm/myrm-agent/myrm-agent-extension`를 표시합니다.
- **단계별 설정 가이드** — 확장 프로그램이 연결되지 않은 경우 표시: 압축이 풀린 확장 프로그램 로드 → URL 복사 → 연결
- **실시간 연결 상태** — 확장 버전 및 브라우저 이름이 포함된 연결/연결 끊김 표시
- **도메인 인증 관리** — 와일드카드 패턴 추가, 제거 및 지원
- **사용 가능한 탭 목록** — 승인된 도메인으로 필터링되고 활성 탭 표시기가 표시됩니다.

### 아키텍처

확장 브리지는 5개 레이어에 걸쳐 있습니다.

1. **하네스 프로토콜**(`ExtensionBridge`) — 프레임워크 수준에서 계약을 정의합니다.
2. **서버 서비스**(`ExtensionBridgeService`) — WebSocket 수명 주기, 하트비트 및 탭 제어를 관리합니다.
3. **API 라우터** — 확장 및 프런트엔드를 위한 WebSocket + REST 엔드포인트
4. **Chrome 확장** — chrome.debugger 첨부 기능이 있는 MV3 서비스 워커
5. **프런트 패널** — 상태 및 도메인 관리를 위한 React 설정 구성 요소

### 측면 패널 채팅 - 모든 웹페이지에 AI 도우미 제공

Chrome 확장 프로그램에는 웹페이지와 함께 열리는 **사이드 패널**이 포함되어 있어 현재 페이지를 떠나지 않고도 몰입형 채팅 환경을 제공합니다.

**주요 기능**:

- **컨텍스트 인식 대화** — 모든 메시지에는 현재 페이지 제목과 URL이 자동으로 포함되므로 상담원은 사용자가 보고 있는 내용을 이해할 수 있습니다.
- **텍스트 선택 전달** — 페이지에서 텍스트를 선택하면 채팅 입력에 인용된 참조로 표시됩니다. 마우스 오른쪽 버튼 클릭 → "Myrm에게 물어보세요"가 직접 전송됩니다.
- **전체 에이전트 기능** — 측면 패널은 기본 WebUI와 동일한 서버 API을 사용합니다. 코드 실행, 웹 조사, 파일 작업, 도구 승인 등 모든 것이 작동합니다.
- **실시간 스트리밍** — 기본 UI와 동일한 `AgentEventType` 프로토콜과 일치하는 도구 진행률 표시기(실행/완료/오류)가 있는 SSE 기반 스트리밍
- **도구 승인 인라인** — 에이전트가 민감한 작업(파일 쓰기, 셸 명령)에 대한 권한이 필요한 경우 승인 대화 상자가 측면 패널에 직접 나타납니다.
- **언제든지 취소** — 취소 버튼을 누르면 프런트엔드 스트림과 백엔드 에이전트 실행이 모두 중단됩니다.
- **뷰포트 글로우** — 에이전트가 작업하는 동안 웹페이지에 미묘하게 빛나는 테두리가 나타나 방해가 되지 않는 시각적 피드백을 제공합니다.
- **키보드 단축키** — `Ctrl+Shift+M`(또는 macOS의 경우 `Cmd+Shift+M`)은 측면 패널을 전환합니다.

**사용 방법**:

1. Myrm 확장 설치(확장 브리지에 사용된 것과 동일한 확장)
2. 확장 팝업에서 서버 URL 및 인증 토큰을 구성합니다.
3. 확장 아이콘을 클릭하거나 `Ctrl+Shift+M`을 눌러 측면 패널을 엽니다.
4. 채팅 시작 - 현재 페이지 컨텍스트가 자동으로 첨부됩니다.

<Note>
The Side Panel and Extension Bridge share the same extension. You get both capabilities with a single install.

브라우저를 종료하지 않고도 웹페이지를 에이전트의 Wiki **raw** 코퍼스에 클립할 수 있습니다.

1. **연결** — 확장 브리지와 동일한 확장입니다. 팝업에서 서버 URL 및 토큰을 구성합니다(설정 → 통합에 연결 상태 및 에이전트별 볼트 표시).
2. **클립** — 페이지나 선택 항목을 마우스 오른쪽 버튼으로 클릭하고 → **위키에 클립**. 확장 프로그램은 읽을 수 있는 콘텐츠(가독성)를 추출하고 **srcset** 이미지를 최고 해상도로 확인하며 POST를 `POST /api/v1/wiki/clip`로 확인합니다.
3. **수집** — 서버는 하네스 `publish_clip_ingress`을 실행합니다. 즉, 보안 검색, 선택적 이미지 현지화(트랙 B 서버 측 가져오기), 중복 제거 지문 및 `raw/clips/{YYYY-MM}/`에 쓰기를 실행합니다. **기본값은 0 LLM**입니다(`queue_compile=false`). 준비가 되면 설정에서 컴파일하세요.
4. **피드백** — 설정(Wiki/중복 검토/보안)에 대한 딥 링크와 함께 성공, 중복 또는 보안 차단에 대한 Chrome 시스템 알림입니다.

| Outcome | What happens |
| --- | --- |
| **Success** | New clip in raw; notification opens Wiki Settings |
| **Duplicate** | No overwrite; notification links to Duplicate Review |
| **Security block** | Credentials/injection blocked; notification links to Security dialog |

<Note>
Per-agent vault is selected in Settings → Integration → Extension Bridge. Re-clipping the same URL is a **conflict** (not silent overwrite) — align with raw publication gate (#7).
</Note>

## 에이전트별 브라우저 구성(3축 제어)

각 에이전트에는 WebUI 설정 → 에이전트 → 기능 구성에 3개의 독립적인 브라우저 구성 축이 있습니다. **스텔스 엔진 선택은 자동입니다** — 브라우저 도구를 활성화하면 하네스가 에이전트별 엔진 선택 없이 Stealth Ladder(Patchright → Camoufox)를 실행합니다.

| Axis | Options | Default | What It Controls |
|------|---------|---------|------------------|
| **Browser Source** | Auto / Extension / Launch / Connect / Remote | Auto | How the agent accesses a browser instance |
| **Dialog Policy** | Smart / Auto Accept / Auto Dismiss / Wait for Agent | Smart | How JavaScript dialogs are handled |
| **Session Recording** | Off / On Failure / Always | Off | Whether browser sessions are recorded for debugging |

### 브라우저 소스 모드

| Mode | Behavior | Best For |
|------|----------|----------|
| **Auto** (default) | System decides based on availability | General use — no manual setup needed |
| **Extension** | Uses your real browser via the Extension Bridge | Shopping, social media, any task needing login state |
| **Launch** | Spins up a fresh managed browser instance | Research, data extraction, testing |

### 하이브리드 URL 라우팅(클라우드/SaaS)

클라우드 모드에서 실행할 때 에이전트는 개인 네트워크(localhost, 192.168.x.x, 내부 서비스)에 직접 액세스할 수 없습니다. Myrm은(는) 자동으로 개인 URL을 감지하고 확장 브리지를 통해 라우팅합니다.

- **공개 URL**(google.com, github.com) → 클라우드 샌드박스 브라우저에서 처리(일반, 빠름)
- **개인 URL**(localhost:3000, jira.internal, 192.168.1.1) → 확장 브리지를 통해 투명하게 라우팅됩니다.

이는 클라우드 호스팅 에이전트가 이미 로그인된 브라우저를 통해 로컬 개발 서버, 내부 대시보드 및 기업 도구와 상호 작용할 수 있음을 의미합니다. VPN 터널도 없고, ngrok도 없고, 내부 서비스가 공개적으로 노출되지 않습니다.

개인 URL이 발견되었을 때 Extension Bridge가 연결되지 않은 경우 에이전트는 이를 알리고 확장 프로그램 설치를 제안합니다.

### 구성 방법

1. **에이전트 생성**: 설정 → 에이전트 → 생성/편집 → 기능 구성
2. **채팅별 재정의**: 채팅창에서 상담원 구성 아이콘 클릭 → 브라우저 설정

네 가지 설정은 모두 에이전트 복제, 내보내기/가져오기 및 API 작업 전반에 걸쳐 유지됩니다. 잘못된 값은 데이터베이스에 도달하기 전에 API 레이어에서 거부됩니다.

### 풀 격리

모든 에이전트 세션은 별도의 브라우저 프로필을 실행하는 것과 동일한 브라우저 수준 보안 경계인 자체 **Chromium BrowserContext**에서 작동합니다. 이는 다음을 의미합니다.

- **쿠키/스토리지 하드 격리** — 에이전트 A의 로그인 세션, 쿠키 및 localStorage는 에이전트 B에게 물리적으로 보이지 않습니다. 소프트웨어 확인이 필요하지 않습니다. 브라우저 자체가 경계를 적용합니다.
- **탭 격리** — 각 에이전트의 TabController는 자체 탭만 관리합니다. 상담원은 다른 세션에 속한 탭으로 전환하거나 닫거나 열거할 수도 없습니다.
- **확장 소스 분리** — 확장 소스 브라우저(비관리, 실제 세션)는 시작 모드 에이전트(관리 헤드리스 인스턴스)와 절대 공유되지 않습니다.
- **자동 확장** — 신규 에이전트는 등록이나 조정 없이 새로운 컨텍스트를 얻습니다. LRU 제거를 통해 컨텍스트별로 탭 제한이 적용됩니다.

이 아키텍처는 브라우저 확장 에이전트에서 사용하는 소프트웨어 기반 "탭 소유권 계약"보다 근본적으로 강력합니다. 이는 버그로 우회할 수 있는 반면 Chromium 자체에서는 BrowserContext 격리를 시행합니다.

## 제로 구성 로컬 브라우저 검색

에이전트가 **자동** 브라우저 소스 모드(기본값)로 구성되면 Myrm은(는) 이미 실행 중인 Chrome을 자동으로 감지하고 연결합니다. **구성 없음, CLI 플래그 없음, 환경 변수 없음**.

### 작동 방식

1. **DevToolsActivePort 검사** — Myrm은 원격 디버깅이 활성화될 때 Chrome이 작성하는 `DevToolsActivePort` 파일에 대해 알려진 브라우저 데이터 디렉터리를 검사합니다.
2. **다중 브라우저 적용 범위** — Chrome, Edge, Chromium, Brave 및 Chrome Canary는 macOS, Linux 및 Windows에서 확인됩니다.
3. **4단계 검증** — 파일 검사 → HTTP 프로브(`/json/version`) → TCP 대체(Chrome M144+ 호환성) → 고정 포트 9222 대체.
4. **우아한 대체** — 실행 중인 브라우저가 없으면 Myrm은 대신 새로운 관리형 인스턴스를 시작합니다.

### 해야 할 일

브라우저에서 원격 디버깅을 한 번 활성화하면 됩니다.

1. Chrome을 열고 `chrome://inspect`로 이동합니다.
2. **"노드용 전용 DevTools 열기"**를 전환합니다(이렇게 하면 디버깅 포트가 활성화됩니다).
3. 그게 다입니다. 이제부터 Myrm이(가) Chrome을 자동 검색합니다.

### 이것이 중요한 이유

| Without auto-discovery | With Myrm |
|----------------------|-----------|
| Must set `CDP_PORT=9222` env var | Automatic — just use the app |
| Must launch Chrome with `--remote-debugging-port` flag | Standard Chrome with inspect toggle |
| Only connects to one browser | Scans 5 browsers in priority order |
| No validation of stale ports | HTTP + TCP probes filter dead connections |

모든 검색은 백그라운드 스레드에서 실행되므로 에이전트의 이벤트 루프 속도가 느려지지 않습니다.

## 소스 메타데이터가 포함된 PDF 아카이브

에이전트가 페이지를 PDF로 저장하면 Myrm은 출처 메타데이터를 자동으로 삽입합니다.

- **헤더** — 페이지 제목
- **바닥글** — 소스 URL, 캡처 날짜 및 페이지 번호
- **배경 보존** — 어두운 테마, 차트 및 색상 대시보드가 충실하게 렌더링됩니다(빈 흰색 PDF 없음).

이는 보관된 모든 PDF가 자체 포함되어 있음을 의미합니다. 즉, 몇 달이 지난 후에도 해당 PDF가 언제, 어디서 왔는지 항상 알 수 있습니다.

| Feature | Other Agent tools | Myrm |
|---------|-------------------|------|
| Background colors in PDF | ❌ Lost (default browser behavior) | ✅ Preserved |
| Source URL in PDF | ❌ Must remember manually | ✅ Automatic in footer |
| Page numbers | ❌ | ✅ Automatic |
| Disable metadata if needed | ❌ | ✅ `include_metadata=False` |

## 제로 구성 브라우저 설정

새로운 Myrm 데스크톱 설치에서 브라우저 도구를 처음 사용하면 브라우저 엔진(Chromium)이 자동으로 다운로드되어 설치됩니다. **터미널 명령이 필요하지 않습니다**.

### 작동 방식

1. 에이전트가 작업에 대한 브라우저 페이지를 요청합니다.
2. Chromium이 설치되지 않은 경우 Myrm은 누락된 실행 파일을 감지합니다.
3. 백그라운드에서 자동 다운로드 및 설치가 실행됩니다.
4. 설치 후에도 브라우저 작업이 원활하게 계속됩니다.

자동 설치에 실패하는 경우(네트워크 없음, 디스크 공간 부족 등) Myrm에서는 특정 수정 지침과 함께 명확한 진단 메시지를 제공합니다.

### 스마트 장애 처리

- **쿨타임 보호** — 설치 실패 후 Myrm은(는) 워크플로 차단을 방지하기 위해 30분 후에 다시 시도합니다.
- **동시성 안전** — 충돌을 방지하기 위해 브라우저를 동시에 요청하는 여러 작업이 직렬화됩니다.
- **진단 메시지** — 정확히 무엇이 잘못되었는지(디스크 공간, 네트워크, 권한)와 해결 방법을 보여줍니다.
- **의사 자동 수정** — 자동 수정으로 `myrm doctor`을 실행하여 브라우저 문제를 진단하고 복구합니다.

### 이것이 중요한 이유

| Other Agent tools | Myrm |
|-------------------|------|
| Must run `playwright install chromium` in terminal | Automatic — just use the app |
| Windows dependency errors confuse non-dev users | Clear diagnostics with fix instructions |
| Browser features broken until manual setup | Works on first use |

## 기여자용: pytest 대 런타임 브라우저 정리

브라우저 통합 테스트 시간이 초과되거나 충돌하는 경우 분리된 Chrome/Patchright 하위 프로세스가 개발자 컴퓨터에 남아 있을 수 있습니다. Myrm은 우려 사항을 분리합니다.

| Layer | Location | Purpose |
|-------|----------|---------|
| **Dev/CI only** | `tests/support/browser_process_cleanup.py` (Harness + Server copies) | `atexit` / pytest `sessionfinish` process-tree kill — **not shipped in the wheel** |
| **Runtime** | `GlobalBrowserPool` health checks, `doctor.py`, pool/singleton orphan sweep | Production browser hygiene for agents |

Hermes-에이전트는 유사한 종료 논리를 프로덕션 `browser_tool.py`에 혼합합니다. Myrm은 에이전트 런타임에서 pytest 전용 정리를 유지합니다. 확인된 **2026-07-01**: 저장소당 14 pytest 항목(12개 유닛 + 2개의 컨테스트 배선), 정리 모듈에서 100% 라인 적용 범위.

## 브라우저 세션 및 보안 관리

Myrm은 모든 것을 단일 메뉴에 집어넣는 대신 브라우저 관리 문제를 목적별 위치로 분리합니다.

### 세션 관리(설정 → 브라우저)

- **암호화된 세션 저장소** — 한 번 로그인하면 AES-256 암호화 쿠키 + localStorage가 제공됩니다. 도메인당 만료된 세션 보기, 삭제 및 정리
- **클라우드 브라우저 구성** — 4개 클라우드 브라우저 제공업체(브라우저리스/브라우저베이스/스틸/하이퍼브라우저)에 대한 GUI + 원클릭 연결 테스트
- **프록시 구성** — 다중 프록시 URL + 연결 테스트

### 에이전트별 액세스 제어(에이전트 편집기)

- **도구 게이트웨이** — 각 에이전트에 대해 허용/차단 도메인 및 도구를 개별적으로 설정합니다.
- **세션 정책** — 에이전트가 저장된 로그인 세션을 자동 복원할지 여부를 제어합니다.

### 실시간 상호작용(검사기 측면 패널)

- **라이브 스크린샷 스트림** — 채팅과 함께 실시간으로 표시되는 브라우저 보기
- **BBox 요소 선택** — 요소를 클릭하면 해당 요소에 대한 자연어 지침이 전송됩니다.
- **작업 기록** — 나중에 재생할 수 있도록 브라우저 작업 흐름을 기록합니다.

## 브라우저 작업 기록 — 한 번 기록하면 영원히 자동화

수동 브라우저 작업 흐름을 코드 한 줄 작성 없이 재사용 가능한 스킬로 전환합니다. **기록 패널**을 열고 워크플로를 한 번 클릭하면 Myrm이 트레이스를 실행 가능한 스킬로 변환해 에이전트가 언제든 재생할 수 있습니다.

### 사용 방법

1. **기록 시작** — 기록 패널을 열고 세션을 시작합니다. Myrm이 페이지에 경량 캡처 엔진을 주입합니다.
2. **작업 수행** — 평소처럼 클릭, 입력, 드롭다운 선택, 스크롤, 호버, 이동을 수행합니다. 의미 있는 모든 작업이 실시간으로 캡처됩니다.
3. **스킬 생성** — 기록을 중지하고 단계 목록을 확인한 후 스킬을 생성합니다. Myrm이 트레이스를 읽기 쉽고 실행 가능한 스킬 정의로 정제합니다.
4. **언제든 재생** — 이후 세션에서 에이전트에게 스킬 실행을 요청하세요. 스크립트 작성도, CSS 선택자 작성도 필요 없습니다.

### 의미 기반 기록 품질

기록은 **원시 이벤트가 아닌 의미 기반**입니다. 각 단계에 충분한 컨텍스트가 담겨 있어 복잡한 폼에서도 생성된 스킬이 처음부터 정확히 동작합니다:

| 기능 | 의미 |
|------|------|
| **셀렉트 값 + 라벨** | `<select>`가 선택한 값과 사람이 읽을 수 있는 라벨(예: `출발 도시: 도쿄`)을 함께 기록합니다. 불투명한 옵션 코드가 아닙니다 |
| **다중 선택 완전 보존** | 다중 선택 필드가 마지막 하나가 아닌 모든 선택 옵션을 유지합니다 |
| **필드명 식별** | 폼 컨트롤을 실제 라벨(`aria-label`, `label[for]`, 감싸는 `<label>`, placeholder)로 설명하므로 드롭다운이 3개인 티켓 폼에서도 에이전트가 어느 필드를 채울지 헷갈리지 않습니다 |
| **라벨 텍스트 오염 방지** | 필드명에 옵션 텍스트나 중첩 컨트롤 텍스트가 섞이지 않습니다 — 라벨로 감싸인 `<select>`가 라벨 문구를 오염시킬 수 없습니다 |
| **입력기 안전** | 한국어/중국어/일본어 입력기 조합 중에도 텍스트가 깨진 키 입력으로 분할되지 않습니다 |
| **내비게이션 접기** | 리다이렉트 체인과 SPA 라우팅 변경이 하나의 깔끔한 이동 단계로 접힙니다 |
