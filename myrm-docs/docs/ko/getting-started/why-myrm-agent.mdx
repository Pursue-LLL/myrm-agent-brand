# Myrm Agent를 선택하는 이유

Myrm Agent는 **견고한 아키텍처**, **GUI 우선 경험**, **엔터프라이즈급 샌드박스 격리**에 초점을 둔 AI Agent 워크스페이스입니다. 바로 쓸 수 있는 SaaS·데스크톱·자체 호스팅을 모두 지원합니다.

Hermes Agent, OpenClaw, DeerFlow 등과 비교했을 때 눈에 띄는 차이는 다음과 같습니다.

## 1. 충돌 방지 기반 자가 치유 메커니즘

OpenAI 형식과 호환되는 API(예: DeepSeek, Kimi 등)을 사용하는 경우 네트워크 지터 또는 빈번한 사용자 취소로 인해 도구 호출이 중단되는 경우가 많습니다. 이로 인해 기록에 유효하지 않은 `tool_call_id`이 남게 되어 엄격한 검증 모델이 잘못된 기록 오류로 인해 충돌하게 됩니다.

**우리의 장점**:
Myrm 에이전트는 모든 LLM 요청 전에 투명한 자가 치유 미들웨어 스택을 실행합니다. `tool_history_hygiene`은 도구 결과를 중복 제거하고 중복된 도구 호출 ID를 다시 작성합니다. `dangling_tool_call` 수리는 취소 후 고아 호출을 수정합니다. 공급자 오류가 발생하면 스트림 복구가 한 번 재시도되고 웹 UI에 진행 상황이 표시됩니다. 네트워크 지터에 관계없이 채팅 기록은 유효하게 유지됩니다. 잘못된 도구 기록으로 인한 충돌을 제거하여 경쟁사보다 훨씬 뛰어난 견고성을 제공합니다.

## 2. 전용 4레벨 프로그레시브 스킬 로딩

에이전트에 엄청난 수의 기술을 장착하면 일반적으로 컨텍스트 창이 폭발하여(컨텍스트 팽창) 토큰 소비가 증가하고 모델의 지시 따르기 기능이 저하됩니다.

**우리의 장점**:
- **온디맨드 로딩**: 우리의 독점적인 4레벨 프로그레시브 로딩 전략은 정말로 필요할 때만 스킬 본체를 컨텍스트에 로드하여 매우 낮은 토큰 소비를 달성합니다.
- **정확한 제어**: 특정 스킬의 정확한 활성화를 위해 `/slash` 명령을 지원합니다. 이는 에이전트의 자율성과 정확한 제어를 완벽하게 결합하여 100% 실행 확실성을 달성합니다.
- **더 똑똑해짐**: 복잡한 작업을 완료한 후 에이전트는 자동으로 새로운 기술을 요약하고 생성하여 진정한 폐쇄형 학습 루프를 달성합니다.

## 3. 서버리스급 샌드박스 최대 절전 모드 및 요청 시 깨우기

기존 클라우드 배포에서는 모든 사용자에 대해 상주 샌드박스 인스턴스가 유지 관리되는 경우 엄청난 비용이 발생합니다. 기존의 SaaS 아키텍처는 성능과 개인정보 보호를 희생합니다.

**우리의 장점**:
컨트롤 플레인은 기본적으로 샌드박스 환경에 대한 유휴 최대 절전 모드 및 요청 시 깨우기를 지원합니다. 사용자가 오프라인일 때 100% 물리적으로 격리된 전용 샌드박스 상태가 유지되고 절전 모드로 전환됩니다. 새 메시지나 cron 트리거를 받으면 즉시 깨어납니다. 이는 절대적인 개인 정보 보호를 보장하는 동시에 클라우드 유휴 비용을 대폭 줄여 대규모 상용화를 위한 진정한 엔터프라이즈급 아키텍처를 만듭니다.

## 4. 부풀림 없는 다이어그램

대부분의 경쟁업체는 무거운 내장 화이트보드를 제공하거나 강제로 수동 드래그 앤 드롭을 수행합니다. Myrm은 코어를 가늘게 유지합니다.

**우리의 장점**:
Mermaid 아티팩트가 채팅에서 대부분의 다이어그램 요구를 충족하며, 확인 및 명확화 상호작용은 **`structured_clarify`**가 양식으로 렌더링합니다. 고급 사용자는 전체 편집 가능한 화이트보드가 필요할 때 **Excalidraw 또는 tldraw MCP** 서버를 연결합니다. Goose 및 Codex 플러그인과 동일한 패턴이며 핵심 제품의 유지 관리가 필요하지 않습니다.

## 5. 최고의 옴니채널 IM 범위

많은 경쟁업체는 몇 가지 주류 채널만 지원하며, 메시지 형식과 미디어 처리 기능이 채널마다 크게 다르기 때문에 경험이 단편화됩니다.

**우리의 장점**:
26개 채널(Slack, Discord, Feishu, iMessage, WeChat, Telegram 등)을 기본적으로 지원하여 진정한 "유비쿼터스"를 달성합니다. 통합된 기본 미디어 처리 파이프라인은 모든 플랫폼에서 일관된 마크다운 렌더링, 음성 인식(STT) 및 대화형 경험을 보장하여 전용 어시스턴트를 원활하게 활성화합니다.
처음 사용자는 단일 안내 단계**(토큰 검증 + 정책 설정 + 기본 에이전트 바인딩 + 롤백 가드)로 **Telegram 어시스턴트 온보딩을 완료하여 여러 페이지 어셈블리에서 단일 흐름으로 설정 마찰을 줄일 수 있습니다.

## 6. 자연어 기반 무인 스케줄링

대부분의 에이전트는 활성 사용자 트리거가 작동해야 하는 "수동 응답 도구"로만 작동할 수 있습니다.

**우리의 장점**:
강력한 무인 스케줄링 엔진이 내장되어 있습니다. 자연어 문장(예: "매일 아침 8시에 브리핑을 보내주세요")만으로 에이전트는 적극적인 디지털 직원으로 변신합니다. Webhook 푸시 및 옴니채널 도달을 지원하여 수동적 도구에서 사전 예방적 서비스로 발전합니다.

## 7. 무한한 두뇌를 위한 메모리 중복 제거

길고 여러 차례에 걸친 대화를 통해 에이전트는 엄청난 양의 중복 사실을 쉽게 축적하여 메모리 뱅크가 부풀어 오르고 검색 정확도가 급락합니다.

**우리의 장점**:
기본 `dedup_semantics` 메커니즘은 작성 중에 중복 사실을 엄격하게 필터링합니다(유사성 ≥0.95에 대한 자동 중복 제거). 이는 메모리 뱅크를 영원히 간결하고 효율적으로 유지하여 에이전트가 부풀어오르지 않고 "사용할수록 사용자를 더 잘 이해"하도록 보장합니다.

## 8. 조용한 실패를 거부하는 풀체인 피드백

진행률 표시줄 없는 대량 작업, 조용히 실패하는 네트워크 오류, "0 참조" 시 즉시 삭제되는 파일 등은 극도의 사용자 불안을 유발하는 경쟁사의 일반적인 설계 결함입니다.

**우리의 장점**:
전체 체인 UI 진행 피드백, 명시적 예외 토스트 알림 및 재시도 메커니즘. 현재 컨텍스트에서 벗어나는 모든 작업에는 강력한 시각적 피드백이 있습니다. 또한 내장된 파일 시스템 "휴지통" 일시 삭제 메커니즘은 데이터 손실에 대한 걱정을 완전히 제거하여 진정한 엔터프라이즈급 보안을 제공합니다.

## 9. 산업 등급 전체 체인 관찰성

문제가 발생하면 대부분의 경쟁업체는 요청 간 상관관계가 전혀 없는 원시 로그 파일만 제공합니다. 디버깅하려면 수천 개의 로그 줄을 수동으로 검색해야 합니다.

**우리의 장점**:
모든 HTTP 요청에는 자동으로 고유한 `trace_id` 및 `session_id` 태그가 지정되며 종속성이 없는 ContextVar를 통해 모든 로그에 삽입됩니다. ELK, Loki 또는 모든 엔터프라이즈 로그 플랫폼과의 원활한 통합을 위해 단일 환경 변수(`MYRM_LOG_FORMAT=json`)를 사용하여 JSON 구조적 로깅으로 전환합니다. 7계층 제품 내 추적 시각화, OpenTelemetry 기본 지원 및 20개 이상의 분석 차원이 결합된 Myrm은(는) 구성이 필요 없는 오픈 소스 에이전트 생태계에서 가장 완벽한 관찰 가능성 스택을 제공합니다.

## 10. 첫날부터 작동하는 Git 및 PR 전달

대부분의 코딩 에이전트는 Git 자격 증명, 커밋 신원, 웹훅이 이미 설정되어 있다고 가정합니다. 새 환경에서 "GitHub에 푸시하고 PR을 열어줘"는 좌절스러운 설정 세션으로 바뀝니다.

**우리의 장점**:
- **호스트 한정 푸시 자격 증명**: GitHub 토큰이 있으면 Myrm은 **오직** `github.com` / `www.github.com`에만 응답하는 자격 증명 헬퍼를 주입합니다 — 토큰이 타사 Git 서버에 도달하지 않으며 명령에 절대 인라인되지 않습니다.
- **자동 커밋 신원**: 샌드박스에 Git 신원이 없으면 Myrm이 연결된 GitHub 계정에서 `user.name`/`user.email`을 해석합니다(캐시 + 5초 타임아웃 + 로컬 폴백) — `git commit`이 "Please tell me who you are" 오류로 실패하지 않습니다.
- **셀프 서비스 PR 웹훅**: 설정 페이지에 웹훅 URL이 복사 버튼과 함께 표시되고 서명 확인(`X-Hub-Signature-256`)이 종단 간 연결되어 PR / issue / push 이벤트가 채팅으로 안정적으로 도착합니다.

"GitHub에 푸시하고 PR을 열어줘"라고 요청하면 그냥 작동합니다 — 자격 증명, 신원, 이벤트가 모두 포함됩니다.

## 11. 승인 전에 계획과 변경분을 보고, 끝나면 한 번에 되돌리기

머신 전체에 손댈 수 있는 에이전트에게는 피할 수 없는 질문이 하나 있습니다. "승인하면 정확히 무엇이 바뀌고, 어떻게 되돌릴까요?" 대부분의 에이전트는 이 질문에 예/아니오 프롬프트와 로그 한 줄로만 답합니다.

**우리의 강점**:
- **계획이 먼저 나옵니다**: 여러 단계 작업이 실행되기 전에 첫 번째 계획안을 보여드려 확인받을 기회를 드립니다. 파일을 건드리기 전에 방향을 바꿀 수 있습니다.
- **변경이 보입니다**: 파일을 고칠 때마다 증분 diff가 대화창에 흘러옵니다. "완료했습니다" 네 글자만 남기지 않고, 실제 변경을 직접 읽을 수 있습니다.
- **되돌릴 손잡이가 있습니다**: 동작 직전에 Myrm은 **그림자 Git 스냅샷**을 남깁니다(사용자의 저장소와 물리적으로 분리되어 워킹 트리와 기록이 깨끗하게 유지됩니다), 그리고 승인 카드에 되돌리기 버튼을 붙입니다. 잘못된 한 번은 다시 만들 필요도 기록을 뒤질 필요도 없이 그 자리에서 되돌립니다.
- **모델의 의견이 아니라 결정적인 게이트**: `ALLOW` / `ASK` / `DENY` 3단계는 코드에 박힌 상수이며 평가에 모델은 개입하지 않고, `DENY`는 LLM도 뒤집을 수 없으며, `~/.ssh` 같은 민감 디렉터리는 경로 정책으로 하드 금지입니다.

그리고 이를 위해 운영체제를 바꿀 필요도 없습니다. 앱을 넘는 작업은 당사의 샌드박스와 PC 조작 계층이 담당하니, 지금 쓰시는 머신 그대로 쓰시면 됩니다.

**경쟁사 현실 점검 (2026-10-22)**: Herald OS(커뮤니티 최대 규모 "OS 안의 에이전트" 작품)는 실제로 "변경 전 승인"과 디스크에 남는 감사 로그를 갖추고 있고, 권한 단계가 정말 코드에 정의되어 있기도 합니다(소스를 직접 읽어 확인했습니다). 다만 세 번째 다리 — 무엇이 바뀌었는지 보여주는 diff와 작업 단위 되돌리기가 없습니다. 바로 이 절이 메우는 부분입니다.


## 12. 고쳐도 살아남는 문서와 스프레드시트 — 쓸 때마다 자동 점검, 어느 판으로든 되돌리기

.docx나 .xlsx를 에이전트에 맡길 때 진짜 무서운 것은 "고치는 걸 거부했을 때"가 아니라, 고쳐놓고 "완료했습니다"라고 말한 뒤 수식을 조용히 값으로 바꿔놓았을 때 — 또는 스스로도 다시 읽을 수 없는 파일을 건네받았을 때입니다.

**우리의 강점**:
- **점검은 파일을 열어볼 때가 아니라 쓰는 직후에 일어납니다**: Office 파일을 쓸 때마다 후반 점검이가 돌며, 전후 Excel **수식 집합**을 대조하고(식이 정적인 값으로 바뀐 것을 그 자리에서 보고), docx 패키지 구조를 확인하고, 읽히지 않는 패키지는 조용히 넘기지 않고 경고하며, docx 레이아웃 QA를 수행하고, 재계산으로 `#REF!`과 `#NAME?`를 잡습니다. **총 6종 신호**가 모두 `Office:` 머리말과 함께 도구 출력에 들어가므로 **에이전트가 사용자보다 먼저 알아채고, 물어보기 전에 고칩니다**.
- **버전째로 드는 것이지 undo 키 하나가 아닙니다**: 산출물은 불변의 판이고, 잘못 고친 판은 어느 이전 판으로든 되돌릴 수 있으며, 작업 공간 파일에는 그림자 Git 스냅샷과 원클릭 롤백이 더해집니다.
- **스프레드시트는 브라우저에서 바로 고칠 수 있습니다**: 수식은 왕복해도 남고, 매크로·차트·피벗 테이블이 든 파일은 손대기 전에 잃어버릴 것을 알려주며, 저장하지 않은 초안은 충돌 뒤에도 복구됩니다.
- **전달하는 것은 원본 파일이 아니라 읽을 수 있는 결과물**: 스타일이 입은 Excel은 테마 엔진에서(제목 행, 얼룩말 행, 테두리, 숫자 서식), 슬라이드는 렌더링 파이프라인에서 나오므로 어떤 Office에서도 제대로 열립니다.
