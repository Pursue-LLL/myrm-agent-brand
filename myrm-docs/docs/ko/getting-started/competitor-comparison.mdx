# 경쟁사 비교 및 마이그레이션 가이드

Myrm은(는) 완전한 AI 에이전트 작업공간으로 설계되었습니다. 터미널 전용 코딩 에이전트와 달리 Myrm은 전체 코딩 기능을 유지하면서 영구 샌드박스, 교차 세션 메모리 및 엔터프라이즈급 보안을 갖춘 GUI 최초의 경험을 제공합니다.

<Note>
**마이그레이션 안심 포인트** — SaaS·자체 호스팅·데스크톱 중 선택할 수 있고, Hermes 스킬은 GUI ZIP으로 가져올 수 있습니다. 아래 표에서 채널·메모리·보安을 행 단위로 비교한 뒤 결정하세요. Grok Build 같은 플러그인 중심 제품 사용자는 Myrm이 모델·스킬·MCP·서브 Agent·안전 프로필을 **한 번에** 설치하는 Agent 패키지를 제공합니다. 문서와 앱은 **6개 언어**(zh/en/ja/ko/de/zh-TW)를 지원하며, WebUI·클라우드·Tauri 데스크톱 모두 첫 방문 시 브라우저 언어를 자동 감지합니다.
</Note>

## vs OpenClaw — 오픈소스 주류 터미널 Agent 및 샌드박스 작업 공간

OpenClaw는 오픈소스 커뮤니티에서 널리 활용되는 터미널 중심의 전자동 코딩 Agent입니다. 그러나 장기 실행 엔터프라이즈 태스크, 다중 파일 동시성 작업, 비개발자 협업 환경에서는 구조적인 한계가 드러납니다.

### Myrm의 주요 차별화 강점

- **물리적 Git Worktree 격리**: OpenClaw의 단일 디렉터리 직접 쓰기 방식과 달리, Myrm은 Worktree 물리 격리 환경에서 병렬 실행되므로 브랜치 충돌이 전혀 없으며 GUI에서 원클릭으로 안전하게 병합하거나 폐기할 수 있습니다.
- **4계층 도구 분리 및 80% 토큰 절감**: 전체 도구를 평면으로 나열하여 턴 1에 3,000 토큰 이상을 낭비하는 OpenClaw와 달리, Myrm은 8개의 CORE 원자 도구만 네이티브 Direct-FC로 로드하여 프롬프트 캐시 적중률을 95% 이상으로 유지합니다.
- **Tauri 데스크톱 & 모던 WebUI**: 텍스트만 스크롤되는 터미널 인터페이스를 벗어나, 풍부한 시각적 마크다운, Prism Diff 뷰어, 승인 카드, 전역 캡처 창을 제공합니다.
- **원자적 체크포인트 봉인(`SealManifest`)**: 비정상 종료 시 손쉽게 상태가 깨지는 문제를 방지하며, 비정상 세션은 격리 구역(Quarantine)으로 이동하여 실행 안정성을 보장합니다.
- **8종 결정론적 멀티 Agent 오케스트레이션**: 단순 선형 태스크 호출을 넘어, 의존성 관계가 명시된 DAG 및 실제 STDOUT 실행 증거를 강제하는 검증 파이프라인을 지원합니다.

## vs OpenAI Codex (openai/codex) — 엔터프라이즈 코딩 Harness 및 샌드박스 방어

OpenAI Codex 오픈소스 리포지토리는 수준 높은 하네스 실행 규율을 제시하지만, 단일 모델 종속, 텍스트 전용 인터페이스, 세션 간 지속성 부재의 한계를 가집니다.

### Myrm의 주요 차별화 강점

- **100개 이상의 모델 무제한 라우팅**: OpenAI 전용 엔드포인트에 갇히지 않고, LiteLLM 및 사설 로컬 모델(Ollama, vLLM)을 자유롭게 혼합하여 복잡도에 따라 모델을 동적으로 스위칭합니다.
- **표준 MCP 완벽 지원 및 스킬 자가 진화**: 닫힌 도구 세트를 넘어, 업계 표준 Model Context Protocol 생태계의 모든 MCP 서버를 즉시 연결하고, 실행 실패 신호로부터 스킬을 자동 보정합니다.
- **시맨틱 데스크톱 제어 (SDC) 및 브라우저 엔진**: 단순 텍스트 코드 수정에 머무르지 않고, 브라우저 스크래핑과 데스크톱 GUI 제어까지 결합하여 실제 업무 완결성을 달성합니다.
- **8종 메모리 계층 및 프로젝트 규칙 학습**: 세션이 종료되면 모든 컨텍스트가 사라지는 Codex와 달리, 팀의 코딩 컨벤션과 에러 수정 이력을 영구적으로 학습 축적합니다.
- **메시지 단위 세부 비용 투명성**: 캐시 적중률과 세부 실행 시간, 절감된 금액을 실시간으로 직관적으로 확인할 수 있습니다.

## vs DeepSeek-Harness (DeepSeek DSH) — 도구 실행 파이프라인 및 샌드박스 코드 실행 (PTC)

DeepSeek-Harness(DSH)는 DeepSeek 모델을 위한 코드 실행 중심의 하네스로, 모든 도구 호출을 파이썬 스크립트로 생성하는 Universal PTC 방식을 채택하고 있습니다. 그러나 이로 인해 치명적인 문법 오류와 토큰 폭발 문제가 발생합니다.

### Myrm의 주요 차별화 강점

- **Universal PTC 함정 탈출**: 단순 파일 읽기나 웹 검색까지 파이썬 스크립트로 생성하도록 강제하지 않고, 8개 CORE 기본 도구는 네이티브 Direct FC로 즉시 실행하여 5배 빠른 속도와 제로 문법 에러를 달성합니다.
- **가벼운 호출 오버헤드**: 매 단계마다 장황한 파이썬 스캐폴딩 스크립트를 생성하지 않아 호출당 단 10개의 토큰만 소비하므로 추론 컨텍스트를 아낄 수 있습니다.
- **골든 프리픽스 캐시 영구 잠금**: 동적 코드 생성이 시스템 프롬프트를 오염시키지 않도록 분리하여 95% 이상의 KV 캐시 적중률을 보장하고 API 비용을 80% 이상 절감합니다.
- **4계층 자가 치유 파이프라인**: 런타임 문법 오류(SyntaxError) 발생 시 즉시 컨텍스트 내에서 자가 수정하여 태스크 중단 없이 완료합니다.
- **완성된 엔터프라이즈 제품 경험**: 단순 스크립트 라이브러리에 머무르지 않고, 웹, 데스크톱, 메신저 봇까지 완비된 제품을 즉시 사용할 수 있습니다.

## vs Pi (pi-agent / oh-my-pi) — 듀얼 모델 자문위원 및 실시간 감독 체계

Pi 생태계는 주 모델과 부 모델이 대화하며 실시간 감독을 수행하는 Dual-Model 구조를 취하지만, 네트워크 지연 시간과 비용이 2배로 증가하고 터미널 로그가 어지러워지는 문제가 있습니다.

### Myrm의 주요 차별화 강점

- **단일 모델 최적화 + 온디맨드 다중 검증**: 모든 턴에서 듀얼 모델 호출을 강제하지 않고, 일상 작업은 지연 없이 단일 모델로 처리하며 민감하거나 복잡한 작업에만 적대적 검증(Verified) 모드를 활성화합니다.
- **CompletionGuard 물리적 실행 증거 강제**: 부 모델의 구두 텍스트 승인에 의존하지 않고, 실제 터미널 STDOUT 로그 및 테스트 통과 증거를 강제하여 환각 승인을 차단합니다.
- **정숙한 워크스페이스 및 다형성 승인 카드**: 터미널에 텍스트가 쏟아지지 않고 조용하게 백그라운드에서 작업하며, 인간의 승인이 필요한 시점에만 직관적인 카드로 알림을 보냅니다.
- **글로벌 표준 MCP 호환**: 폐쇄적인 자체 감시 프로토콜 대신 표준 Model Context Protocol 생태계 도구를 그대로 활용합니다.
- **PrivacyRouter 민감 데이터 사설 분류**: 클라우드 듀얼 모델 통신으로 인한 민감 자격 증명 유출을 방지하고 핵심 자산은 철저히 로컬 오프라인에서 격리 연산합니다.

## vs Hermes Agent (NousResearch) — 자율 에이전트 및 스킬 자가 진화 생태계

Hermes Agent는 강력한 함수 호출과 스킬 진화 기능으로 잘 알려져 있습니다. Myrm은 이를 계승하면서 엔터프라이즈급 멀티 Agent 오케스트레이션, 네이티브 GUI 거버넌스, 완벽한 프롬프트 캐시 안정성을 더했습니다.

### Myrm의 주요 차별화 강점

- **이벤트 기반 칸반 대시보드**: 폴링 방식 대신 실시간 이벤트 기반 즉시 디스패치와 좀비 프로세스 자동 회수를 제공합니다.
- **8종 결정론적 오케스트레이션 모드**: 단순 Kanban Swarm을 넘어 DAG, 체인, 대안 경쟁, 위원회 토론 모드를 지원합니다.
- **CompletionGuard 실행 증거 검증**: 실제 실행 로그 증거가 없으면 완료를 인정하지 않습니다.
- **35개 이상의 커뮤니케이션 채널 지원**: 슬랙, 텔레그램, 디스코드, 잔디, 카카오톡 등 폭넓은 채널을 지원합니다.
- **8종 메모리 + 지식 그래프**: 2,200자 평면 파일 한계를 극복하고 세션 간 지식 복리를 실현합니다.
- **자체 DOM 정리 듀얼 엔진 웹 검색 및 스크래핑**: 유료 외부 API 종속 없이 월 0원의 완전 로컬 데이터 수집 파이프라인을 제공합니다.
- **네이티브 42개 모듈 스킬 자가 진화 시스템**: Monaco DiffEditor를 통한 GUI 승인 워크플로와 A/B 테스트를 기본 내장하고 있습니다.

## 동적 워크플로 및 멀티 Agent 실전 병목 해결

| 커뮤니티 공통 병목 | 근본 원인 | Myrm의 구조적 해결책 |
|-------------------|-----------|----------------------|
| "40단계를 계획했으나 20단계만 돌고 성급하게 중단됨" | 위상학적 강제성 없는 비결정론적 실행 | **결정론적 DAG 스케줄링**: 코드 레벨에서 단계별 의존성을 잠그고 명시적 증거가 있어야만 완료 처리. |
| "몇 개만 호출했는데 하위 에이전트가 폭주하여 토큰 전소" | 런타임 트리 깊이 및 예산 통제 부재 | **DelegationBudget**: 토큰, 달러 비용, 실행 시간, 최대 자식 수의 4차원 하드 리밋 강제. |
| "장시간 실행 도중 크래시가 발생해 모든 진행 상황 유실" | 단계별 원자적 상태 저장 없는 단일 프로세스 실행 | **Checkpointer & SealManifest**: 단계별 원자적 스냅샷으로 중단되거나 크래시 시에도 제자리에서 무손실 복구. |
| "하위 Agent가 테스트를 통과했다고 했으나 코드가 동작 안 함" | 물리적 실행 증거 검증 부재 | **CompletionGuard**: 실제 STDOUT/STDERR 통과 로그 제출을 강제하며 증거 없는 주장은 FAIL 처리. |
| "백그라운드 동시 실행으로 CPU가 100% 차서 시스템 멈춤" | 키워드 트리거 무차별 병렬화 및 전역 제한 부재 | **명시적 WorkflowModeToggle + ConcurrencyLimiter**: 토큰 버킷 스로틀링을 통한 통제 가능한 병렬 실행. |
| "터미널 원시 텍스트 로그가 쏟아져 Agent 활동이 블랙박스화" | 구조화된 관찰성 인터페이스 부재 | **SubagentDashboard + 다형성 뷰**: Prism 코드 Diff 하이라이트, 단계별 지연 시간 및 밀리초 단위 비용 추적. |
