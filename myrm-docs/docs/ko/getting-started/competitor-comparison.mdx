# 경쟁사 비교 및 마이그레이션 가이드

Myrm은 완전한 AI 에이전트 작업공간으로 설계되었습니다. 터미널 전용 코딩 에이전트와 달리 Myrm은 전체 코딩 기능을 유지하면서 영구 샌드박스, 교차 세션 메모리 및 엔터프라이즈급 보안을 갖춘 GUI 최초의 경험을 제공합니다.

<Note>
**마이그레이션 안심 포인트** — SaaS·자체 호스팅·데스크톱 중 선택할 수 있고, Hermes 스킬은 GUI ZIP으로 가져올 수 있습니다. 아래 표에서 채널·메모리·보안을 행 단위로 비교한 뒤 결정하세요. 문서와 앱은 **6개 언어**(zh/en/ja/ko/de/zh-TW)를 지원하며, 모든 배포 모드에서 첫 방문 시 브라우저 언어를 자동 감지합니다.
</Note>

## 추론 과정: 가시성, 중지, 재생

- **실시간 스트리밍**: 추론 증분이 어시스턴트 메시지에 실시간으로 첨부됩니다.
- **중지 가능**: "사고 중지"로 조기 종료, 알려진 내용으로 답변. 10초 타임아웃.
- **접고 펼치기**: 답변 시작 1초 후 접힘, 언제든 펼칠 수 있습니다.
- **실제 토큰**: 공급자 보고 `reasoning_tokens` 우선, 불가능한 경우에만 `≈` 추정.
- **6개 언어 + 40px 터치 타깃**, 완전 로컬라이즈.

## 모델 라우팅 및 출처 추적

- **프로덕션 두 라우팅 엔진**: 작업 복잡도(SIMPLE / STANDARD / REASONING)와 작업 전문성(CODE / LONG_DOC / REASONING / MULTIMODAL / CASUAL / GENERAL).
- **답변별 출처**: 사용량 패널에 실제 모델, 라우팅 단계, 작업 전문성, 이유 및 비용 표시.
- **Agent별 선택**: Smart Routing에서 경량/추론 모델 선택 후 활성화(3개 Pareto 프리셋 포함).
- **결정론적 승인**: 승인 필요 여부를 규칙으로 계산, 분류기가 아님. 비가역 작업은 "항상 허용" 없음.

## 위임: 떠나고, 돌아와서 결과 확인

- **내구성 있는 백그라운드 작업**: 오프라인 작업은 재시작 후 DB에서 복구; 데스크톱은 장기 작업 중 절전 방지.
- **완료 알림**: 26개 채널 + 인앱 알림 + Catchup 받은편지함.
- **빈 보고서 없음**: cron 작업의 `[SILENT]` 계약.

## 스킬 품질

- **출시**: 3상태 귀속(selected / used / observable), 26카테고리 / 113패턴 정적 스캔, 권한 템플릿, 점진적 공개.
- **프로젝트 스킬**: 워크스페이스의 `SKILL.md`(깊이 3) 자동 인식, 신뢰 게이트 포함. `.claude/skills/` 호환.

## Agent 팀: 검증 우선

- **출시**: 5개 팀 템플릿, Kanban 작업 DAG, shell/의미 검증, 26채널 완료 알림, Fleet KPI 보드.

## 복잡한 작업: 완료 조건, 독립 검증, 구조화된 인수인계

| 끊기는 지점 | 사용자가 겪는 일 | Myrm의 현재 |
|---|---|---|
| 완료 조건 없음 | "vague asks are where they all fall apart" | Kanban 작업 DAG + 편집 가능한 완료 조건; 기준 미달이면 pause |
| Agent가 done이라지만 아님 | "all 6 said done, none passed every hidden test" | CompletionVerifier: shell 하드 체크 + 의미 판정; 모델이 스스로 완료를 선언할 수 없음 |
| 세션이 끊기면 사라짐 | "most agents restart cold every run" | 영속 세션 로그 + 컨텍스트 압축 + ACP CLI 세션 재개 |
| 진행 중 작업 등록부 없음 | "one registry of everything in flight so nothing gets built twice" | Kanban 작업 그래프 + 의존성/owner + heartbeat/zombie 감지 |
| 인수인계 손실 | "each interaction the idea gets lost" | AgentHandoverState + Kanban handoff metadata |
| 사람이 병목 | "more permissions requested, intervention more often" | 3단계 자율성(strict / semi-auto / full-auto) + TOTP 금고 + 모바일 HITL |
| Agent가 내 환경에 없음 | "you must control the substrate" | 로컬 WebUI / Tauri 데스크톱 / 사용자별 샌드박스 + 영구 볼륨 |

## 마이그레이션 경로

| 출발 | 방법 |
|---|---|
| **Hermes** | 스킬을 ZIP으로 내보내기 → Myrm GUI 마법사로 가져오기. BYOK 모델과 MCP 도구는 그대로 사용. |
| **OpenClaw** | 워크스페이스 컨텍스트(USER.md)를 Myrm 메모리 규칙으로 매핑. MCP 서버 직접 재연결. |
| **Codex / Claude Code** | CLI 워크플로를 Goal Mode + cron으로 매핑. BYOK API 키 그대로 이전. |
| **DeepSeek Harness** | BYOK 모델과 MCP 도구는 그대로 사용; DSH 전용 플러그인은 `SKILL.md` 또는 MCP로 재마운트 필요. |

> Myrm은 **SaaS**, **자체 호스팅 WebUI**, **데스크톱**으로 실행됩니다. 스킬과 메모리는 GUI 마이그레이션 마법사로 이전할 수 있습니다.
