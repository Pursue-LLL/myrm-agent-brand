# 로컬 배포

데이터를 완전히 통제하면서 내 PC에서 Myrm을 실행하세요.

## 원라이너 설치(가장 빠름)

**macOS/리눅스/Git Bash**

```bash
curl -fsSL https://myrmagent.ai/install.sh | bash
myrm start
```

**윈도우(파워셸)**

```powershell
irm https://myrmagent.ai/install.ps1 | iex
myrm start
```

**http://localhost:3000**을 열고 설정에 LLM API 키를 추가하세요. 하네스는 PyPI에서 나왔습니다. 자체 호스트에는 별도의 하네스 저장소가 필요하지 않습니다.

## 복제 및 개발(OSS 저장소)

```bash
git clone https://github.com/Pursue-LLL/myrm-agent.git
cd myrm-agent
myrm setup          # uv sync + bun install
myrm start          # backend (terminal 1)
cd myrm-agent-frontend && bun run dev   # frontend (terminal 2)
```

개발 스크립트는 오픈 소스 저장소의 `scripts/` 아래에 있으므로 기여자는 한 번 복제하고 로컬에서 실행합니다.

<Callout type="tip">
**분할 개발 팁:** 백엔드 없이 WebUI(포트 3000)만 열면 UI에 알 수 없는 오류가 아닌 시작 안내가 포함된 친숙한 배너가 표시됩니다. 설정은 오프라인으로 캐시되고 백엔드가 반환되면 동기화됩니다.
</Callout>

## 전제조건(Docker 경로)

- Docker 24+ 및 Docker Compose v2
- 최소 4GB RAM(8GB 권장)
- 10GB 디스크 공간

## Docker 작성

```bash
git clone https://github.com/Pursue-LLL/myrm-agent.git
cd myrm-agent/myrm-agent-server
cp .env.example .env   # if present
docker compose up -d
```

## 구성

`.env`을 편집하여 API 키를 설정합니다.

```env
# LLM Provider (at least one required)
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...

# Optional: Additional providers
DEEPSEEK_API_KEY=...
GOOGLE_API_KEY=...
```

전체 참조는 [환경 변수](/docs/self-hosting/environment-variables)를 참조하세요.

## 중국 본토 가속

설치 스크립트는 자동으로 중국 본토 네트워크를 감지하고(시간대 + 연결 확인을 통해) 국내 미러로 전환합니다.

- **PyPI** → pypi.tuna.tsinghua.edu.cn
- **npm** → Registry.npmmirror.com
- **극작가** → cdn.npmmirror.com

Docker 빌드의 경우 `--build-arg USE_CN_MIRROR=1`을 전달합니다.

```bash
docker build --build-arg USE_CN_MIRROR=1 -f myrm-agent-server/Dockerfile -t myrm-server .
```

수동 재정의: `MYRM_USE_CN_MIRROR=1`을 설정하여 국내 미러를 강제로 설정하거나 `MYRM_NO_CN_MIRROR=1`을 설정하여 자동 감지를 비활성화합니다.

## 설치 확인

```bash
curl http://localhost:3000/api/health
```

예상되는 응답:

```json
{ "status": "ok" }
```

## 프로덕션 Docker 빌드(OSS 서버 이미지)

사전 구축된 하네스 휠에서 오픈 소스 서버 이미지를 구축할 때 빌더는 BuildKit `TARGETPLATFORM`을 통해 올바른 플랫폼 코어 휠을 선택하고 이미지가 준비된 것으로 간주되기 전에 `verify-harness-distribution`을 실행합니다. 일치하지 않거나 불완전한 설치는 대화 중간이 아닌 빌드/시작 시 실패합니다.

모노레포: `myrm-agent-harness/harness_packaging/DISTRIBUTION_SYSTEM.md`의 하네스 배포 가이드를 참조하세요.

## 모듈식 엔진 패키징(임베더)

하네스는 **24개의 린 런타임 종속성**과 **11개의 선택적 추가 기능**(브라우저, 검색, ACP, 관찰 가능성 등)으로 제공됩니다. `install.sh`, Docker 또는 Tauri을 통해 설치하는 최종 사용자는 수동으로 추가 항목을 선택할 필요 없이 자동으로 전체 서버 번들을 받게 됩니다.

자체 Python 서비스에 엔진을 포함하는 경우 필요한 것만 설치하세요.

```bash
pip install 'myrm-agent-harness[fastapi,web,compiled-core]==0.1.0'
```

추가 항목이 누락되면 통화 시 명확한 설치 힌트가 표시됩니다(대화 도중 자동 충돌이 발생하지 않음). 아키텍처 테스트는 종속성 증가를 방지하기 위해 코어 목록을 잠급니다. **327** 하네스 아키텍처 테스트가 확인되었습니다(2026년 7월).

## 자동 종속성 관리

Myrm은 종속성을 자동으로 처리하므로 패키지를 수동으로 설치할 필요가 없습니다.

- **채널 SDK** — Matrix, Discord 또는 Feishu 채널을 활성화하면 필수 Python 패키지가 허용 목록 보안 메커니즘을 통해 주문형으로 설치됩니다. 다시 시작할 필요가 없습니다.
- **MCP 서버** — 자체 환경을 자동으로 관리하는 `npx`/`uvx`을 통해 실행되는 외부 도구입니다. GUI에 서버를 추가하기만 하면 작동합니다.
- **의사 진단** — `myrm doctor`를 실행하여 시스템 상태(Python 버전, 핵심 종속성, 브라우저 가용성 등)를 확인합니다. 각 실패에는 수정 제안이 포함됩니다.
- **기본적으로 보안** — 사전 승인된 패키지만 자동 설치할 수 있습니다. MCP 서버는 맬웨어(OSV)를 검사하고 활성화 전에 프롬프트 주입을 수행합니다.
