# 예약된 자동화

## 시나리오

일일 브리핑(또는 반복 가능한 작업)을 작성했으며 매일 아침 오전 9시에 자동으로 실행되고 그 결과가 WeChat, Slack 또는 이메일로 푸시되기를 원합니다. 수동 트리거가 필요하지 않습니다.

## 재료

- 자동화하려는 작업 또는 기술(예: [Daily Briefing](/docs/tutorials/daily-briefing))
- **설정 → 채널**에서 구성된 전달 채널(선택 사항 - 작업 대시보드에도 결과가 표시됨)

## 단계

<Steps>
  <Step title="채팅에 일정을 설명하세요">
어떤 대화에서든지 상담원에게 다음과 같이 말하세요.

> "매주 평일 오전 9시에 '모닝 브리핑' 스킬을 실행하고 결과를 위챗으로 보내주세요."

에이전트는 예약 의도를 감지하고 작업 이름, 일정(cron 표현), 바인딩된 기술 및 전달 채널을 보여주는 확인 카드를 제시합니다.
  </Step>
  <Step title="작업 확인">
확인 카드를 검토하고 **확인**을 클릭하세요. 작업이 즉시 생성됩니다. 관리 대시보드에 대한 링크가 포함된 작업 카드가 나타납니다.
  </Step>
  <Step title="대시보드에서 모니터링">
모든 반복 작업을 보려면 **설정 → 예약된 작업**으로 이동하세요. 각 항목에는 일정, 마지막 실행 시간, 상태 및 출력 기록이 표시됩니다.
  </Step>
  <Step title="조정 또는 일시 중지">
일정을 편집하고, 전달 채널을 변경하고, 프롬프트를 업데이트하거나, 실행을 일시 중지하려면 작업을 클릭하세요. 채팅을 통해 작업을 관리할 수도 있습니다.

> "아침 브리핑 일시중지" 또는 "대신 오전 8시 30분에 실행되도록 변경"
  </Step>
</Steps>

<Note>
**세 가지 작업 유형**: 에이전트 작업(전체 LLM 실행), 셸 명령(로컬/데스크톱 전용), Python 스크립트(비용 LLM 없음, 클라우드를 포함한 모든 곳에서 작동). 전체 참조는 [예약된 작업](/docs/guides/scheduled-tasks)을 참조하세요.
</Note>

## 제공 가능

정의된 일정에 따라 실행되고 수동 개입 없이 선택한 채널에 결과를 전달하는 자동화된 반복 작업입니다.

## 승인 기준

- [ ] 작업이 예약된 시간에 실행됩니다.
- [ ] 구성된 채널로 출력이 전달됩니다.
- [ ] 작업이 예약된 작업 대시보드에 나타납니다.
- [ ] 작업을 일시 중지, 편집 또는 삭제할 수 있습니다.

## 다음은 무엇입니까?

- **신뢰성 검사 추가** → 자동화하기 전에 3번의 성공적인 수동 실행 설정(생산 워크플로의 모범 사례)
- **Chain task** → task chaining을 사용하여 종속 작업을 순차적으로 실행(예: 데이터 수집 → 분석 → 보고)
