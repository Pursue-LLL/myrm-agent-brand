# 사례 제출

커뮤니티에서 제공하는 튜토리얼과 사용 사례를 환영합니다. 모든 기여는 누군가가 업무에 AI를 사용하는 새로운 방법을 발견하는 데 도움이 됩니다.

## 콘텐츠 원칙

모든 제출물은 다음 5가지 원칙을 따라야 합니다.

| Principle | Requirement |
|-----------|------------|
| **Reproducible** | Describe the environment, inputs, steps, deliverables, and expected results clearly enough for anyone to follow |
| **Verifiable** | Explain how to confirm the task is truly complete — not just the process, but the acceptance criteria |
| **Facts vs. Experience** | Product facts need sources; personal experience should state its applicability scope |
| **Safety First** | When involving file writes, accounts, keys, publishing, or external operations, state permissions and risks |
| **Privacy & Copyright** | Do not submit personal data, access credentials, or content you don't have permission to share |

## 튜토리얼 구조

각 튜토리얼은 [튜토리얼](/docs/tutorials/overview) 섹션 전체에서 사용되는 5개 요소 구조를 따라야 합니다.

1. **시나리오** — 독자가 인식하게 될 실제 작업 상황
2. **자료** — 시작하는 데 필요한 파일, 데이터 또는 컨텍스트
3. **단계** — 단계별 안내(스크린샷 환영)
4. **전달 가능** — 생성된 구체적인 출력
5. **수락 기준** — 결과가 올바른지 확인하는 방법

해당하는 경우 배포 차이점(로컬 WebUI / Tauri 데스크톱 / SaaS 클라우드)을 참고하세요.

## 제출 중

1. myrm-agent 저장소에서 **tutorial** 라벨이 있는 [GitHub 문제](https://github.com/Pursue-LLL/myrm-agent/issues/new)를 엽니다.
2. 이슈 본문에 튜토리얼 콘텐츠를 포함합니다(위의 5개 요소 구조를 따르는 마크다운 형식).
3. 스크린샷이나 지원 파일을 첨부하세요.
4. 유지관리자 팀이 제출물을 검토한 후 이를 문서 사이트에 통합합니다.

더 쉽게 검토할 수 있도록 문제당 하나의 튜토리얼이 제공됩니다.

## 심사기준

제출물은 다음 사항에 대해 검토됩니다.

- 5가지 콘텐츠 원칙 준수
- 5요소 구조의 완성도
- 단계의 정확성과 예상 결과
- 쓰기의 명확성과 가독성
- 제품 비밀, 자격 증명 또는 PII가 없습니다.
