# 环境变量

通过环境变量配置 Myrm 实例。复制 `.env.example` 为 `.env` 并按需修改。

## LLM 提供商（在 WebUI 中配置，不是环境变量）

提供商凭据**不是**环境变量。请在 WebUI 的**设置 > 模型服务**中添加：每个提供商各自保存自己的 Key，
Myrm 会将其加密存储在本地数据目录（`MYRM_DATA_DIR`，默认 `~/.myrm`）。`.env` 仅承载进程级与运维级配置。

> 服务端随附的 `.env.example` 写明了同一策略：`.env` 中只放 `[P]` 进程级与 `[O]` 运维级变量；
> 业务能力（LLM、向量化、搜索、提供商）一律在 WebUI 设置中管理。

## 应用

| 变量 | 默认值 | 说明 |
|----------|---------|-------------|
| `PORT` | `3000` | HTTP 服务端口 |
| `DATABASE_URL` | （空） | 可选的 Apache AGE（PostgreSQL）图存储；留空则图数据保存在数据目录下的 SQLite 中 |
| `MYRM_DATA_DIR` | `~/.myrm` | 数据根目录（聊天库、向量、记忆、日志）。启动前配置，重启后生效 |

> **搬迁数据目录：**桌面端在设置 → 系统 → 存储中点击更改（向导含空间预检、实时进度、拷贝校验与自动回滚）。独立 WebUI/服务端改 `MYRM_DATA_DIR` 后重启。云托管数据由托管持久化卷管理。

## Docker Compose

| 变量 | 默认值 | 说明 |
|----------|---------|-------------|
| `MYRM_BIND_HOST` | `127.0.0.1` | 端口绑定 IP。设为 `0.0.0.0` 以允许局域网/远程访问 |
| `MYRM_PORT` | `25808` | 后端 API 端口 |
| `FRONTEND_PORT` | `3000` | 前端端口 |
| `MYRM_MEM_LIMIT` | `0`（不限制） | Myrm 容器最大内存，例如 `3g` |
| `MYRM_CPU_LIMIT` | `0`（不限制） | Myrm 容器最大 CPU，例如 `2.0` |
| `MYRM_WORKSPACE` | `./workspace` | 挂载为主机工作区的目录 |

## 安全

| 变量 | 默认值 | 说明 |
|----------|---------|-------------|
| `JWT_SECRET` | （自动生成） | JWT 签名密钥 |
| `ENCRYPTION_KEY` | （自动生成） | AES-256 加密密钥 |

## 可观测性与遥测

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `MYRM_LOG_FORMAT` | `text` | 日志格式：`text` 或 `json`（方便 ELK/Loki 采集） |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | （空） | 标准 OpenTelemetry Collector 端点（如 `http://localhost:4318` 或 `http://localhost:4317`） |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | `http/protobuf` | OTLP 传输协议：`http/protobuf` 或 `grpc`；未设置时，端口为 `4317` 的端点自动选用 `grpc` |
| `OTEL_EXPORTER_OTLP_HEADERS` | （空） | 鉴权请求头，格式 `key=value,key2=value2`（如 `Authorization=Bearer%20<token>`），不会在界面中显示 |
| `OTEL_TRACES_SAMPLER` / `OTEL_TRACES_SAMPLER_ARG` | `parentbased_always_on` | 标准采样配置，例如 `parentbased_traceidratio` 配 `0.1` 表示保留 10% 的链路 |
| `OTEL_SDK_DISABLED` | `false` | 设为 `true` 时关闭全部链路与指标导出 |
| `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` | `false` | 主动开启后，导出的 Span 才包含提示词、回复与工具内容；关闭时只导出元数据 |
| `MYRM_LOCAL_TRACE_ONLY` | `0` | 纯本地 Trace 模式：设为 `1` 时物理拦截任何远端导出，确保 Trace 100% 留在本地 |
| `MYRM_CARDINALITY_FIREWALL` | `1` | 激活指标高基数隔离防火墙，杜绝 Prometheus 内存溢出 |

### 一次请求的链路如何对上

同一个 HTTP 请求只有一个 32 位十六进制 ID：它同时是响应头 `X-Trace-Id`、错误响应里的 `error.trace_id`、服务端日志行里的 ID，以及导出 Span 的 trace ID，所以从错误提示里抄下的 ID 能直接查到对应链路。调用方带上合法的 `X-Trace-Id`（32 位十六进制、不全为 0）或 W3C `traceparent` 时沿用它自己的 ID（`X-Trace-Id` 优先），其他取值一律换成新生成的 ID。

导出的 Span 包括智能体运行、模型调用、工具调用，以及聊天渠道中每条流式回复对应的一条 `stream_reply` 链路。HTTP 请求本身不产生 Span（健康检查只会制造噪音）。`OTEL_*` 变量只有服务端读取：智能体运行的程序（终端命令、脚本、后台进程、浏览器）不会继承它们，需要 OpenTelemetry 的程序请在自己的命令行里设置。
