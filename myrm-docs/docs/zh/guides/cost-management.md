# 费用管理：每一笔 Token 都精确入账一次

Myrm Agent 将 LLM 用量与成本追踪精确到消息级，因此你在任何看板上看到的数字——某个会话的「调用次数 / Token / 美元」、用量雷达、日报或预算摘要——永远等于真实账单：不滞后、不遗漏、不虚高。

## 为什么 Myrm 的用量记账是精确的

| 能力 | Myrm Agent | 典型竞品 |
|---|---|---|
| **数据源** | 消息级 SSOT——`Chat.total_calls/total_tokens/total_usd` 只从每条消息的 `tokenEconomics` 快照聚合 | 会话结束快照；会话进行中总量滞后，崩溃整段丢失 |
| **不漏算（最后一条消息永不丢）** | 进程内缓存携带 `last_message_id` 校验——缓存陈旧自动重算，最新消息必然入账 | TTL 缓存静默复用陈旧聚合，最后一条消息永久缺失 |
| **不虚高（突变后重算）** | 六个突变点（retry / undo / truncate / rewind / regenerate / 切换分支）提交后重新聚合——已作废消息的费用即时剔除 | 删除消息或切换分支后总量持续虚高 |
| **崩溃自愈** | auto-continue 恢复路径将从流中收集的 `tokenEconomics` 快照持久化——崩溃后重跑 turn 的费用自动补录 | 崩溃后该会话用量永久丢失 |
| **端到端验证** | 真实 LLM E2E：同一会话连续两轮，`total_*` 精确等于两轮快照之和（无 mock） | — |

## 实际影响

- **长会话实时更新**：数小时的任务进行中，会话总量与用量看板实时反映每一轮新对话——无需等待会话结束。
- **撤回与分支切换自动纠正账单**：retry、undo、truncate、rewind、regenerate、切换分支都会在变更后重新聚合，作废的工作绝不会渗入你的总量。
- **崩溃不丢账**：进程中途崩溃后，auto-continue 路径会自动补录重跑 turn 的费用。即使重启，你看到的数字也完整无缺。

## 在哪里查看

- **会话详情 / 导出**：每个会话的 `usageSummary`（`totalCalls`、`totalTokens`、`totalUsd`）即消息级聚合结果。
- **用量雷达与统计**（`/statistics/usage/radar` 等）：基于同一套精确总量。
- **预算看板**：预算执行读取同一套精确记账，告警与实际消耗严格一致。
