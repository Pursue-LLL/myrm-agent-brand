# 函数钩子

函数钩子让你在智能体生命周期的关键节点——工具调用前后、会话起止、子代理调度——注入自定义逻辑，**无需修改任何产品源码**。审计每一次工具调用、拦截危险操作、改写参数、通知你的运维群：你的逻辑，你的规则。

## 你能得到什么

- **四类钩子类型**——按场景选最合适的工具：
  - **Python 函数（callable）**：进程内注册的 async 函数，零子进程、零网络往返。
  - **Shell 命令**：一条 shell 命令；`$ARGUMENTS` 展开为 JSON 格式的事件载荷，始终作为数据传入，绝不会被当作 shell 代码解析。
  - **HTTP Webhook**：POST 到任意 URL，自带 SSRF 防护（内网 IP 拦截）、可选 HMAC-SHA256 签名（`X-Webhook-Signature`，GitHub/Stripe 同款约定）、通知类事件可选 fire-and-forget 非阻塞模式。
  - **LLM 智能钩子**：用自然语言描述条件，由模型判定通过与否（`quick`/`thorough` 双深度）。
- **12+ 个内置生命周期事件（含真实发射点）+ 自定义事件键**——`pre_tool_use`、`post_tool_use`、`post_tool_use_failure`/`_cancelled`、`session_start`、`session_end`、子代理 start/stop/cancel、`user_turn`、`approval_correction` 等，任意自定义事件键同样支持。
- **声明式零代码挂载**——在 `SKILL.md` frontmatter 里声明钩子。只有当你亲自调用该技能（在斜杠面板选中，或消息以 `[use 技能名]` 开头）时钩子才生效，且仅限本次运行。模型自行加载的技能不会注册任何钩子：第三方钩子必须经过你的明确同意。
- **上下文防爆仓**——钩子输出超限自动落盘，仅注入预览摘要。
- **运行级隔离**——钩子注册表按会话的异步上下文隔离（ContextVar），技能钩子在其运行结束的瞬间释放：并行会话、连续运行与其他技能之间不会继承彼此的钩子。
- **失败隔离**——单个钩子崩溃或超时绝不影响其他钩子与主流程；需要时按钩子开启 fail-closed。

## 双重安全保障

- **改参自动重过权限门**：`pre_tool_use` 钩子改写参数（例如给危险命令追加 `--dry-run`）后，改写结果会**重新经过合规门与权限引擎审核**再执行——扩展永远不会变成绕过审批的后门。
- **命令钩子走智能体同款安全门禁**：钩子声明的 shell 命令与智能体自身 Shell 命令使用同一个静态命令分析器（破坏性命令检测、BLOCK/ESCALATE 威胁分级）；来自第三方来源（技能/插件/用户配置）的钩子走更严格的窄路，standalone 模式下对第三方来源默认 fail-closed。

## 在 SKILL.md 中声明钩子

```yaml
---
name: my-audit-skill
hooks:
  BeforeToolUse:
    - script: 'echo "$ARGUMENTS" >> ~/.myrm/audit.log'
      tools: ["bash_*"]
  SessionEnd:
    - url: https://ops.example.com/agent-webhook
      secret: ${OPS_WEBHOOK_SECRET}
      fire_and_forget: true
---
```

- 可识别的事件名：`SessionStart`、`SessionEnd`（亦可写 `Stop`）、`BeforeToolUse` / `PreToolUse`、`AfterToolUse` / `PostToolUse`、`PostToolUseFailure`。其他名称会被跳过，并在日志中给出警告。
- `script` 构造命令钩子；`url` 构造 HTTP 钩子。`secret` 开启 HMAC 签名；`fire_and_forget` 使调用非阻塞。
- `tools` 过滤钩子可见的工具：一个模式或一个列表（`bash_*`、`[bash_*, write_file_tool]`），按 fnmatch 匹配运行时工具名（bash 工具名为 `bash_code_execute_tool`）。`tools` 写法不合法时，该钩子会被跳过，而不是放宽为匹配所有工具。
- `failure_mode: fail_closed` 表示钩子失败或被拒绝时阻断对应操作（默认 `fail_open`：跳过并记录日志）。`timeout` 单位为秒（默认 10，范围 1–600）。无效条目会被跳过并告警，不会连累同一技能的其他钩子。

## 编写命令钩子

- **`$ARGUMENTS` 是数据，不是代码**：它展开为 JSON 格式的事件载荷（一个整体字符串），经 `HOOK_PAYLOAD` 环境变量传入，恶意的工具参数或会话 ID 永远不会被当作 shell 代码解析。可以直接写（`printf "%s" $ARGUMENTS`）或放在双引号里；放在单引号里则保持字面量。`HOOK_EVENT` 携带事件名。
- **完整载荷同时写入标准输入**（`cat | jq .tool_name`）。由于 Linux 下单个环境变量不能过大，`HOOK_PAYLOAD` 超过 96 KiB 时会被裁剪：过长的字符串值被截短，并加上 `"payload_truncated": true`。需要检查全部内容的钩子（例如扫描大文件写入中的密钥）请读取标准输入。
- **按你写下的命令审核**，而不是按它将收到的载荷审核，因此同一个钩子对每个事件的审核结论一致。普通 shell 语法（管道、重定向、`;`、`$(…)`、`${…}`）可正常使用。
- **对所有钩子一律拒绝**：破坏性或提权类命令（`sudo`、`rm -rf /`、`history -c`、写入 `~/.ssh/authorized_keys` 或 shell 启动文件）以及混淆写法。**对来自技能、插件、用户配置的钩子额外拒绝**：需要人工决策的命令（`eval`、`curl … | sh`、`crontab` 修改）。
- **被拒绝的钩子按失败处理**：默认跳过并记录日志；若该钩子设置了 `failure_mode: fail_closed`，则阻断对应操作。
- **不支持内联解释器代码**：`python3 -c …`、`node -e …` 会被拒绝，请把逻辑写进脚本文件再调用。

## 事件速查

| 事件 | 触发时机 | 典型用途 |
|------|---------|---------|
| `pre_tool_use` | 每次工具调用前 | 拦截、审计、改写参数 |
| `post_tool_use` / `post_tool_use_failure` / `post_tool_use_cancelled` | 每次工具调用后（成功/失败/取消） | 记录结果、失败告警 |
| `session_start` / `session_end` | 会话生命周期边界 | 初始化、成本/用量上报 |
| `subagent_start` / `subagent_stop` / `subagent_cancel_complete` | 子代理调度 | 编排可观测 |
| `user_turn` | 用户输入时（fire-and-forget） | 提示词级日志 |
| `approval_correction` | 用户在审批中编辑或拒绝工具调用 | 学习信号 |
