# 代码图谱查询

改一个函数的签名之前，你需要知道它的所有调用点。对常见名字做文本搜索，会返回一堆不相干的匹配；结果太长时被截断，还不告诉你丢了什么。**`repo-call-graph`** 技能为 Agent 增加一个工具 `code_graph_tool`：它回答关于代码结构的问题，并标明每个答案能信到什么程度。

## 能问什么

直接用自然语言问，例如「谁调用了 `select`？」，由 Agent 选择动作。

| 你问的 | 动作 | 返回什么 |
|---|---|---|
| 它定义在哪里？ | `resolve`、`definition` | 限定名、种类、文件和行范围；`definition` 还附带文档注释 |
| 谁调用了它？ | `callers` | 每个调用点，以及包含该调用的函数 |
| 它调用了什么？ | `callees` | 函数内部发出的调用 |
| 哪些类继承了它？ | `implementors` | 子类及其声明位置 |
| 谁导入了这个模块？ | `importers` | 导入它的文件（只覆盖 Python） |
| 哪些测试调用了它？ | `tests_calling` | 直接调用它的测试 |

覆盖 Python 与 TypeScript/JavaScript。

## 如何开启

1. 打开 **设置 → 技能**，打开 **`repo-call-graph`** 的开关。
2. 弹出 **Skill 权限审批** 对话框，申请 **读取文件**。你可以点 **批准**，也可以选一个包含它的权限模板（例如 **数据分析**），或者点 **拒绝**。
3. 打开一个 Agent 带有工作区目录的对话（例如你关联的项目文件夹），直接提问。

这个技能默认关闭。**拒绝** 后技能保持关闭、不记录任何授权，下次再打开会重新询问；之后撤销该权限也一样。你批准之后，因为这个工具只读文件，调用时不会再弹窗。

## 怎么读答案

「谁调用了 `select`？」的答案（节选）：

```json
{"action":"callers","query":"select","total":2,"rows":[
  {"at":"app.py:5","caller":"app","callee":"select","match":"exact","args":1},
  {"at":"app.py:6","caller":"app","callee":"db.select","match":"name","args":1}],"definitions":1}
```

- **`match`**（调用点类答案：`callers`、`tests_calling`）：`exact` 表示调用处的文本就是你问的名字；`name` 表示只有最后一段相同，所以 `db.select(...)` 可能是另一个同名函数。
- **`definitions`**（同样两个动作）：有多少个定义叫这个名字。大于 1 时，用某个 `name` 行之前先打开代码看一眼。
- **`total`**（所有动作）：完整的匹配总数。最多显示 50 行，最可能指向该定义的调用点排在前面；超过 50 行时，答案会附上每个文件的命中数和缩小范围的建议。
- **字母大小写要一致**：`select` 不会匹配 `db.Select(...)`。

## 它做不到什么

- 它按名字匹配，不推断类型、不跟随导入，所以语义类问题上语言服务器更精确。动态调用（`getattr`、字符串、装饰器、依赖注入）看不到，所以结果为空也不等于没人调用。
- 导入关系只索引 Python。被 git 忽略的文件、依赖与构建目录、超过 1 MB 的文件、符号链接和有语法错误的 Python 文件不会被索引；过大的工作区只索引一部分，这时答案的 `notes` 会说明。
- 没有图形界面，答案是对话里的文本行。
- 大型仓库的第一次调用要建索引，需要几秒到几十秒；之后只重新读取变化的文件。索引存放在工作区之外的应用数据目录，体积约为源码的四倍。
