# 证据纪律

大多数 AI 的失败并不是戏剧性的幻觉，而是「看起来合理的中间结果被升级成更强结论」：

- 命令退出码为 0，Agent 就说系统修好了；
- 文件被改了，Agent 就说功能可用了；
- 本地构建通过，Agent 就说部署已经上线；
- 搜索没有结果，Agent 就说「不存在」；
- 你随口说的前提，Agent 当成「已独立核实的事实」复述。

Myrm 的**证据纪律**技能通过给默认智能体（`builtin-economy`）的每一个回答套上「**结论对证据契约**」，让这些失败变得罕见。

## 它做什么

技能按证据类型区分结论，并按结论强弱施加对应层级的**证明义务**：

| 证据状态 | 含义 |
|---------|------|
| **亲眼验证 Observed** | Agent 通过工具、文件、日志或运行时检查直接看到 |
| **来源背书 Source-backed** | 有可指认的具名来源支持 |
| **用户告知 User-reported** | 你告诉 Agent 的——按你的陈述复述，**不是**独立核实 |
| **推断 Inferred** | 从其他事实推理得出，明确标注为推断 |
| **未知 Unknown** | 无法验证——如实说未知，不糊弄 |
| **存在矛盾 Contradicted** | 证据互相冲突——Agent 保留不确定性，不强行下结论 |

## 安全契约

除了标注证据，技能还堵住 Agent 常见的「温和撒谎」方式：

- **绝不声称访问了任务中实际不可用的资源。**
- **绝不把「计划」或「尝试过的动作」说成「已经发生的动作」。**
- **绝不把工具报错、空结果、部分同步或不可访问的数据重新解释成「验证成功」。**
- **绝不为了拿到更强证据而做无关的破坏性操作。**
- **否定性结论**（如「不存在」）只限于真正检查过的范围。

## 内置的过度谨慎平衡

证据纪律是一把双刃剑，所以技能同时防止走向另一个极端：

- **不要滥用 UNKNOWN。** 当证据合理可得时就去验证——别拿谨慎当跳过检查的借口。
- **先自查再询问。** 能自己检查证据的话，先查，再请用户重复信息。

最终效果：一个对自己不知道的事情诚实、能验证的就主动验证、从不把自己的作业推给用户的 Agent。

## 如何使用

**零配置。** 技能默认绑定在通用内置智能体（`builtin-economy`）上，在每一次对话中生效——包括 Web 会话、定时任务和渠道。

你还可以：

- 在**设置 → 技能**中查看它，它和其他预置技能并列展示。
- 把它绑定到任意新建智能体，或从不需要它的智能体上移除。
- 在智能体自定义提示词里加强触发，例如「回答前先证明重要结论」。

## 验证与契约测试

技能的行为契约由 **33 项架构契约测试**守护——逐条断言每一条行为条款都存在、frontmatter 版本号保持合法，技能不会悄悄漂移或退化。完整管线（同步 → 绑定 → 可见性）由无 mock 的集成测试覆盖。

## 机制级强制（框架门禁）

上面的技能属于提示词层面的纪律，依赖模型自觉遵守；同一份契约在框架层同样强制执行，模型绕不过去：

- **完成声明必须对上本轮真实工具记录。** 回答里出现验证结论、外发动作或代码修改时，框架会先把它与本轮真实工具调用对齐，再让回答到达你面前。测试类只认真实测试运行器**且真跑**——只收集用例、零用例、用 `PATH=` 改写 runner、只读 MCP 调用都不算证据；外发类必须真有发送动作，只读调用与单纯写文件都不算。对不上就拦下，只给两条出路：**现在去取证**，或**如实说清做了什么、没做什么**。
- **每条回答自带证据档，用户一眼知深浅。** 回答会被标注为**已验证**（真跑过测试/lint/构建或通过复核）、**有工件**（真写了文件）、**有来源**（真检索到来源）或**计划**（暂时没有可验证产出——只在回答自称完成时出现，纯聊天不打扰）。展开徽章即可看到背后的物理证据：验证类别、写入的文件路径、来源条数。
- **未落盘的交付物会被保全并披露。** 写代码的一轮如果没有把草案落盘，框架会把它安全暂存到 `.myrm/staged_artifacts/`，并在回答末尾给出「草案已暂存」横幅列出文件——草案不会静默消失在对话里。
- **证据扛得住审批，回合之间互不干扰。** 一轮任务被 HITL 审批拆成多段时，证据台账按回合累积；每个回合有独立的拦截预算，同一进程里的并行会话、后台续跑与定时任务既不会互相耗尽，也不会互相重置。

这些门禁、披露与暂存同时由单元/契约测试与「真实浏览器 + 真实模型」的验收用例覆盖；六家竞品横向对照见[竞品对比](/zh/getting-started/competitor-comparison)。
