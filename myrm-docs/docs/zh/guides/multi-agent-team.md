# 多智能体团队协作 (AI 包工队模式)

当面对复杂的研发或运营项目时，传统的“人与单一 AI 对话”模式往往会遇到上下文过载、步骤混乱和目标漂移等痛点。此时，你需要从“单聊”升级为“管理一个 AI 包工队”。

Myrm Agent 原生提供了业内领先的 **全可视化多智能体编排系统**。不仅超越了传统依赖 CLI 黑盒的调度工具，还能极大地为你节省模型使用成本。

## 核心优势

### 1. 人机同屏的 GUI 任务看板 (Kanban)
再也不用盯着滚动且难懂的终端日志（CLI）。
Myrm 拥有原生的 **31 组件 GUI 任务看板**，每个任务包含 `backlog`、`ready`、`running`、`in_review`、`completed` 等精确的 9 态生命周期（含任务级人工审批门 IN_REVIEW）。你和你的多个 AI 员工在同一块看板上协同工作。看板状态毫秒级实时推送（SSE），并且支持一键深链跳转，真正做到所见即所得。

### 2. 自动化的依赖图与上下文接力 (Automated Context Routing)
拒绝“人肉信息搬运工”。
在竞品中，用户往往需要手动复制 A 模型的搜索结果，再粘贴给 B 模型去写代码。而在 Myrm 中，只需在创建任务时通过 **DAG (有向无环图)** 设定好依赖关系。上游智能体完成后的关键 `metadata`（如文档、总结片段）将自动被 Orchestrator 提取并无缝注入到下游智能体的上下文中。

### 3. 基于角色的智能降本路由 (Cost-Aware Agent Tiering)
让对的模型做对的事，告别天价账单。
你可以为每个智能体分配不同的能力与预设模型：
*   **资料搜集员 (Scout)**：配置低成本的轻量级模型（如 Gemini Flash / Claude Haiku）。
*   **架构师 (Architect)**：配置强推理模型。
*   **程序员 (Coder)**：分配最强大的代码生成模型（如 Claude 3.5 Sonnet）和代码修改权限。

系统将自动根据你设定的 Agent Profile 和复杂度阈值进行智能路由（Cost-Aware Routing），实测在同等任务量下，能为你**节省超过 86% 的 Token 费用**。

### 4. 无死角的安全与容错 (Hard Halt & Privacy Bound)
遇到报错时，未经优化的 AI 极易陷入无尽的“死循环重试”中消耗资源。
Myrm Harness 在执行层内置了严苛的 **Max-Iteration** 卡点强阻断逻辑，一旦发现异常循环会礼貌暂停，并在看板附带诚实的用户可见修复提示。此外，借助完善的本地模型集成与执行沙箱（Git Worktree 支持），即使是复杂的代码库重构也能安全并行，绝不互相干扰。

### 5. 事前成本透明可控 (Pre-Flight Cost Estimation)

多智能体协作意味着更高的模型调用成本。Myrm 在 **批量委派、委员会审查（Council）、多方案并行（Alternatives）** 三种模式启动前，自动预估总 LLM 调用成本：

- **批量模式**：根据任务数 × 单任务模型定价预估
- **委员会模式**：精算公式 `专家数 × (1 + 交叉审查轮数) + 1（主席综合）`
- **多方案模式**：根据并行专家数预估

当预估成本超过 **$0.50** 时，聊天界面会弹出交互式审批卡片，展示预估费用、调用次数和剩余预算。你可以一键批准或拒绝——**未批准前不会消耗任何 Token**。

这意味着你永远不会因为一次复杂的多 Agent 操作而收到意外账单。

### 6. 共享工作区并发锁 (Shared Workspace Turn Lock)

多个 Agent 共享同一项目时，可能在文件、记忆和任务状态上发生竞争。Myrm 通过**项目级 Turn Lock** 对同一项目内的 turn 严格串行，同时保证不同项目完全并行：

- **公平排队 + 实时可见**——排队的 turn 会实时推送 `waiting_for_turn` 进度步骤（"正在等待项目中的其他 Agent 完成..."），你始终清楚 turn 为何暂停。
- **可取消的等待**——锁获取循环分片轮询取消令牌，点击停止可在约 1 秒内中断排队，而不是一直被其他 Agent 阻塞。
- **无泄漏释放**——`lock_acquired` 标志保证只有真正持锁的请求才释放锁（取消的等待者绝不会偷走持有者的锁），预占 gateway 会话也会被清理，取消的 turn 永远不会让工作区永久卡死。
- **确定性验证**——seed 端点真实持有项目锁，E2E 验证等待步骤出现、干净取消、重发重新排队，由 29 项后端 + 13 项前端测试与真实 Chrome E2E 背书。

### 7. 后台子代理父流存活（派发即交付）

竞品编排（如 Claude Code 的进程隔离、Hermes 的 session 绑定子代理）在父消息流结束时立即杀掉后台子任务——你刚看到“完成”，委派出去的异步深度任务就被取消了，结果再也看不到。

Myrm 将后台子代理生命周期与父流解耦：

- **`wait=false` 异步子代理在父 run 正常完成后继续运行**——`cleanup_run` 与 spawn finally 级联在正常完成时传 `include_detached=False`，只有用户显式取消或失败级联才清理后台任务。
- **完成结果持续可查**——`COMPLETED_SUBAGENT_RESULTS` 强引用注册表（3600s TTL + LRU 上限），刷新后 Dashboard 树状图仍显示子代理最终状态（已完成 / 失败 / 取消），父会话早已结束也无妨。
- **双轨可信指示**——Dashboard 同时呈现*执行进度*（实时步骤、token / 成本 / ETA）与*验证状态*（已完成 / 失败 / 取消 + 对抗验证结果），既知道“做到哪了”，也知道“可不可信”。

由 **18/18 Chrome E2E**（UI 套件 + baseline 套件，含真实用户 textarea 输入路径）、**3 项 API 集成测试**、**70 项 harness 单测**（含 5 个 `include_detached` 专项断言）背书。

## 如何开始使用？

1.  打开 **Myrm Agent WebUI**，进入工作流（Workflow）或看板（Kanban）界面。
2.  新建任务，分配给特定的子 Agent（例如 `Architect` 或 `Coder`）。
3.  通过设置 `depends_on` 指定任务依赖。
4.  喝杯咖啡，在漂亮的界面上观看你的“包工队”自动接力完成工作！
