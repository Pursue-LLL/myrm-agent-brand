# 浏览器自动化

Myrm Agent 可自主浏览网页、填表、提取数据并执行操作。

## 浏览器引擎

**双隐身引擎（Patchright + Camoufox）** — 站点拦截默认 Chromium 路径时，Myrm 可热切换到基于 Firefox 的隐身引擎，**且不丢失登录 Cookie**，已认证工作流不会跳回登录页。

三层交互栈：

1. **无头 Chrome / Camoufox** — 完整渲染，含反爬回退
2. **DOM 解析器** — 结构化内容提取（自愈定位器、Shadow DOM）
3. **视觉** — 复杂 UI 的截图交互

### 12 层反检测隐身体系

Myrm 注入全方位反检测系统，让自动化浏览与真实用户无法区分。已通过 5 大主流反 bot 系统（BrowserScan、Fingerprint.com、CreepJS、Cloudflare、DataDome）验证，并在 10+ 高风控平台（微信公众号、微博、知乎、小红书、抖音、Twitter/X、Instagram、Facebook）生产环境中验证通过。

- **CDP 泄露修补** — Patchright 从协议层消除 `Runtime.enable`、`Console.enable`、`--enable-automation` 等检测向量
- **13 项 JS 隐身脚本** — `navigator.webdriver` 隐藏、`window.chrome` 伪造、插件/语言模拟、自动化工件清理、WeakMap `toString()` 伪装、反调试中和、Performance API 清理等
- **Camoufox 指纹持久化** — 设备指纹（canvas、audio、字体、WebGL、插件）一次生成后持久存盘，后续会话自动复用，网站看到的始终是同一台"回访设备"而非可疑的新设备。双层自愈机制确保指纹文件损坏时 100% 自动恢复
- **拟人化交互** — 随机打字延迟（30-100ms/字符）+ 随机点击延迟（50-150ms）+ Bézier 鼠标轨迹 + **真实滚轮惯性滚动**（加速→匀速→减速的滚轮节奏，绝不使用一眼可识别的 JS `scrollBy` 跳转）+ 动态超时自适应
- **代理智能轮换与自愈** — 坏代理自动隔离、上下文热替换获取新 IP、跨引擎状态无缝迁移（Cookie + localStorage 在引擎切换时完整保留）

## 页面理解 — 双路径 ARIA 快照

Myrm 使用**语义无障碍树**而非原始 DOM 来理解页面。Agent 像屏幕阅读器一样看到页面 — 结构化、无噪音、聚焦可交互元素。

### 工作原理

| 路径 | 使用场景 | 速度 | 方法 |
|------|---------|------|------|
| **快速路径** | 90% 页面 | 5-10ms | Playwright 原生 `ariaSnapshot()` — 零 JS 注入 |
| **自定义路径** | 复杂边缘场景 | 20-50ms | JavaScript 遍历，支持深度控制 |

### Agent 看到什么

取代数千个 DOM 节点，Agent 获得简洁的语义树：

```yaml
- heading "登录" [level=1]
- textbox "邮箱" [ref=1]
- textbox "密码" [ref=2]
- button "登录" [ref=3]
- link "忘记密码?" [ref=4]
```

每个可交互元素获得稳定的 **ref ID**，Agent 用于精确定位 — 告别脆弱的 CSS 选择器。

### 内建韧性

- **Shadow DOM 穿透** — 自动穿越 Web Components
- **iframe 提取** — 跨域 iframe 内容纳入树中
- **范围过滤** — `full`、`interactive` 或 `focused` 视图控制 token 消耗
- **增量 diff** — 仅展示快照间的变化

### 为何不做遮挡检测？

某些工具（如 OpenCLI）用 `elementFromPoint` 逐个扫描元素来剪枝被遮挡节点。我们刻意不做，因为：

1. 每次快照增加 100-500ms（每个元素触发 reflow）
2. 可能误剪有效元素（下拉菜单、提示框）
3. Playwright 的 `click()` 已内建 actionability 检查，拒绝点击被遮挡元素
4. 点击失败时，**自愈定位器**以 O(1) 时间修复

最终效果：5-10ms 快照，比 DOM 方案节省 60-80% Token，零精度损失。

## 拟人化交互

Myrm 发送到真实浏览器的每一个输入，都以物理上真实的人类手势回放——绝不做瞬时的程序化跳转。三档拟人化等级（`FAST` / `DEFAULT` / `CAREFUL`）自动匹配当前站点的防护等级。

### 滚轮惯性滚动

一次逻辑滚动被拆解为一连串细小的 `mouse.wheel` 事件——20–40px 的步进、8–20ms 的停顿间隔，遵循**加速 → 巡航 → 减速**的节奏。CDP 追踪里看到的是人类的滚轮节拍；任何钩住 `window.scrollTo` / `scrollBy` 的反 bot 脚本都一无所获。负向增量自然向上滚动；确实没有滚动的操作会如实报告结果，绝不谎报成功。

### Bézier 鼠标轨迹

每次点击 / 双击 / 悬停 / 拖拽 / 画布输入前，光标沿三次贝塞尔曲线移动——缓入缓出、垂直摆动、偶发越过目标后回落——正是人手的动作轮廓。点击之前必有 hover 轨迹，绝无"无轨迹直接按下"的机械点击。

### 拟人化时序

点击与逐字符打字延迟服从高斯分布（点击 ≈120±30ms），而非固定常量，任何时序检测器都看不到两个相同的交互。

### CAREFUL 预滚动居中

当点击目标位于视口之外时，Myrm 会先用拟人化滚轮把它滚入中心带，再执行点击。该能力穿透嵌套滚动容器与同源 iframe。在锁定滚动页面（如 `overflow: hidden`）上，要么通过原生兜底真实落地，要么响亮失败——绝不静默点空并谎报成功。

### 画布 / 富编辑器视觉模式

对于 DOM ref 无法映射到可见元素的页面（Google Docs、Figma、Sheets），坐标交互（`interact_at`）在指定视口位置执行点击、双击、键入、按键、悬停、滚动与拖拽——使用同一套拟人化 Bézier + 滚轮技术栈，详见下文[画布/富编辑器视觉模式](#画布富编辑器视觉模式)。

## 智能无限滚动

使用懒加载内容的页面（社交信息流、电商目录、新闻站）通常需要 10-20+ 次滚动检查循环。每次循环消耗一次 LLM 调用。

Myrm 的 `scroll_to_bottom` 动作用**一次调用**完成：

1. Agent 调用 `browser_interact(action="scroll_to_bottom")`
2. 引擎自动逐屏滚动，等待新内容加载
3. 当页面高度连续 3 次无变化时自动停止
4. 返回摘要：滚动步数、耗时、高度变化和完成状态

**效果**：一次工具调用替代 10-20 次 LLM 往返 — 每个无限滚动页面节省约 90% Token 成本。

可通过参数配置：`max_steps`（最大滚动次数）、`delay_ms`（每次滚动间隔）、`stable_count`（判断到底的稳定次数）。

**拟人化派发**：每一步都是真实滚轮事件（加速→巡航→减速节奏 + 自然停顿），而非 JS 瞬间跳转——CDP 追踪看到的是人类的滚轮节拍，而不是 `scrollTo`/`scrollBy` 调用。无溢出的页面会立即以诚实的「no scrollable overflow」报告退出——Agent 不会在无法滚动的页面上空转，也绝不会被假成功消息误导。

## 按需媒体提取

一次工具调用提取页面中所有图片、视频、音频的直链 URL，无需编写 JavaScript。

### 工作原理

1. Agent 调用 `browser_extract(mode='media')` — 一次调用。
2. 工具遍历所有 frame 并收集：
   - **图片**：`<img>` 标签（含懒加载解析：`data-src`、`data-lazy-src`、`data-original`、`srcset`、`data-srcset`、以及通配符 `data-*src*` 兜底）
   - **视频**：`<video>/<source>` 元素 + iframe 嵌入（YouTube、Vimeo、Dailymotion、Wistia）
   - **音频**：`<audio>/<source>` 元素
   - **Meta 图片**：OpenGraph 和 Twitter Card 图片标签
3. 装饰性元素（图标、Logo、favicon、<50px 小图）自动过滤。
4. 跨 frame URL 去重确保输出干净无重复。

### 核心优势

- **按需获取** — 仅在需要时提取，不像竞品每次响应都附带媒体信息浪费上下文。
- **选择器范围限定** — 使用 `selector` 参数限定提取区域。
- **懒加载感知** — 自动解析所有主流懒加载属性。
- **跨 frame 去重** — 自动遍历所有 iframe 并去重。

### 示例

让 Agent：*"提取这个电商页面的所有产品图片"*

Agent 使用 `browser_extract(mode='media', selector='.product-gallery')` 获得干净的图片 URL 列表（含尺寸和 alt 文本），无需编写 JavaScript。

## Canvas/富编辑器视觉交互模式

Google Docs、Figma、Google Sheets、Excalidraw 等 Web 应用将内容渲染在 `<canvas>` 元素或高度虚拟化的 DOM 中——ARIA 树 ref 无法映射到可见的文本、按钮或单元格。Myrm 自动检测这些页面并切换到**坐标交互模式**。

### 工作原理

1. **自动检测**：`browser_snapshot` 运行时，Myrm 的内容提取器会检查 `<canvas>` 元素和无角色的视觉区域。如果检测到大面积视觉内容，快照结果会附加 `[VISUAL_CONTENT_DETECTED]` 提示。

2. **模式切换**：Agent 看到提示后，自动从 ref 模式切换到坐标模式——通过截图识别元素位置，然后用 `(x, y)` 坐标执行操作。

3. **拟人化交互**：坐标模式操作与 ref 模式共享同一个 Bézier 鼠标轨迹引擎——点击和拖拽沿自然曲线移动，而非瞬间传送。

### 支持的操作

| 操作 | 参数 | 用途 |
|------|------|------|
| `click` | `x`, `y` | 单击画布元素（支持 Bézier 轨迹） |
| `dblclick` | `x`, `y` | 双击进入编辑模式 |
| `type` | `x`, `y`, `text` | 先点击定位再输入文字（拟人化延迟） |
| `press` | `x`, `y`, `text` | 先点击定位再按键组合 |
| `hover` | `x`, `y` | 悬停触发提示信息（支持 Bézier） |
| `scroll` | `x`, `y`, `text` (delta) | 定点滚动，带方向 |
| `drag` | `x`, `y`, `target_x`, `target_y` | 拖拽（支持 Bézier 轨迹） |

### 示例

```text
# 1. Agent 执行快照，看到 [VISUAL_CONTENT_DETECTED]
browser_snapshot → "... [VISUAL_CONTENT_DETECTED: canvas-based content detected] ..."

# 2. Agent 请求截图来识别坐标
browser_manage(action="screenshot")

# 3. Agent 点击 Google Sheets 中的单元格
browser_interact(action="click", x=350, y=200)

# 4. Agent 输入内容并视觉验证
browser_interact(action="type", x=350, y=200, text="Q3 营收",
                 verify_goal="单元格显示 'Q3 营收'")
```

### 安全保障

- **视口边界校验**：超出可见视口的坐标会被拒绝并返回清晰的错误信息
- **互斥校验**：`ref` 和 `x/y` 不能同时使用——防止歧义操作
- **视觉验证**：坐标模式同样支持 `verify_goal`——3 层视觉管道（dHash → 像素对比 → Vision LLM）确认操作达到预期效果

## URL 域名黑名单（全局 Settings + 按 Agent）

在浏览器**发起连接之前**拦截敏感或不允许的域名，而不是等导航失败后再报错。

| 层级 | 行为 |
|------|------|
| **权限引擎** | hostname 命中合并黑名单时，`browser_navigate` 直接 DENY |
| **Session navigate** | 硬拦截并返回 `BROWSER_URL_BLOCKLIST`，聊天里可见完整原因 |
| **HTTP domain filter** | 黑名单域名及其子资源不会加载 |

**GUI（无需 YAML）：** **Settings → 安全** 配置全局列表；**Agent → 安全** 配置按 Agent 追加。列表取并集——Agent 只能追加拦截，不能绕过全局策略。

**Browser Doctor：** **Settings → 系统** 一键完成浏览器全面体检 — 引擎、内存、磁盘、代理、扩展桥接共 8 项真实探测并分级评分，每项失败都附具体修复指引，无需看日志。崩溃残留的 Chromium/Driver 孤儿进程可在全机范围内检测，并在确认安全门后一键清理。

**已验收：** Live 模型 E2E + Chrome WebUI 均可见 `Navigation blocked: domain … is on the URL blocklist`。

## 语义 DOM 安全 — Session 层 HITL

删除、支付、提交、改账号等**高危 DOM 操作**，以及 **会改页面的 JavaScript**（如 `element.click()`、`form.submit()`、`innerHTML=`），在执行前都会弹出**人机共驾审批卡**——无论由哪个工具发起。

### 为什么要在 Session 层统一

竞品常只 guard 外层 tool API。Myrm 在 **`BrowserSession`** 统一拦截，以下路径共用同一套守卫：

- `browser_interact_tool`（click / dblclick）
- `browser_execute_script_tool`（脚本内 `session.interact()`）
- `browser_manage_tool` evaluate（L1 放行后仍走 L2 语义 guard）

### WebUI 里你能看到什么

| 操作类型 | 审批卡展示 |
|----------|------------|
| 高危点击 | 元素 role、可访问名称、ref，以及 `click(e5)` |
| 变异 evaluate | **完整 JavaScript 表达式**（等宽字体块 — 知情同意，不是盲批） |

可批准、拒绝或附反馈；拒绝后 Agent 会收到结构化阻断信息并需换方案。

全局 **Approval Drawer** 会持久化 interrupt 载荷（含 `tool_input`、`page_url` 与 click 的 `element` 元数据），展示多态审批卡；批准后以 `{decision: "approve"}` 正确 resume Agent。服务端 `/approvals/{id}/resolve` 会发布 `APPROVAL_RESOLVED` 事件——审批不是「只改 HTTP 状态、Agent 仍卡死」。

### evaluate 双层策略

1. **L1 工具审批**：安全策略默认 **DENY** `browser_evaluate`（YOLO/allowlist 可覆盖）。
2. **L2 语义 guard**：L1 放行后，变异表达式仍须 HITL；只读表达式如 `document.title` 直接执行。

## 弹窗策略（自动处理弹窗）

JavaScript 弹窗（`alert`、`confirm`、`prompt`、`beforeunload`）若不处理会阻塞所有页面交互。Myrm 提供**四种可配置策略**，按智能体独立设置：

| 策略 | 行为 | 适用场景 |
|------|------|----------|
| **智能**（默认） | 接受 alert/confirm，关闭 prompt | 通用浏览 |
| **全部接受** | 接受所有弹窗 | 批量自动化、数据采集 |
| **全部关闭** | 关闭所有弹窗 | 数据提取、只读场景 |
| **等待 Agent** | 暂停让 AI 决策（超时自动回退） | 关键确认操作 |

### 配置方式

在 **设置 → 智能体 → 能力配置 → 弹窗处理** 中为每个智能体设置策略。

智能体也可在运行时通过 `browser_manage` 工具的 `dialog_policy` 操作动态切换策略。

### 工作原理

- **智能模式**（默认）：Agent 不会被 Cookie 横幅或提示性弹窗卡住。
- **等待 Agent 模式**：弹窗内容会出现在下一次浏览器快照中，AI 拥有完整上下文来决策。超时后自动安全回退。
- 弹窗历史始终对 Agent 可见——它知道处理了哪些弹窗以及如何处理的。

## Cookie 同意弹窗自动消除

全球所有网站（尤其欧洲 GDPR/CCPA 合规网站）都会显示 Cookie 同意横幅。如果不自动化处理，Agent 每访问一个页面都要浪费一次 LLM 调用来点击"全部接受"。

Myrm 的 **ConsentDismisser** 在每次页面导航后自动运行——零配置：

1. **75+ CMP 专用选择器** — OneTrust、Cookiebot、Didomi、Quantcast 等数十个主流 CMP，按市场份额排序。
2. **泛用属性匹配** — 通过 `accept`、`agree`、`allow` 等模式捕获自定义同意实现。
3. **10 种语言文本匹配** — 英语、德语、法语、西班牙语、意大利语、荷兰语、葡萄牙语、中文、日语、韩语、波兰语、瑞典语、丹麦/挪威语。
4. **Shadow DOM 穿透** — Usercentrics、Axeptio 等使用 Shadow DOM 的 CMP。
5. **CMP JavaScript API** — 直接调用 Didomi、Cookiebot、Osano、Klaro 的 JS API 确保消除。
6. **容器强制移除** — 最后手段：当所有点击尝试失败后，移除 55+ 已知 CMP 容器和 iframe。
7. **滚动恢复** — 移除 CMP 设置的 body 滚动锁定和 CMP 专用 CSS 类。

### 实际效果

- 每页约 **50ms**，零 LLM 成本
- 每次导航到 EU/CCPA 网站节省 1 次 LLM 调用（约 300 token）
- 100 页爬取：节省约 100 次 LLM 调用和 30K token
- Agent 看到干净的页面快照——没有 Cookie 横幅干扰

### 配置

默认**自动启用**。如需为某个智能体禁用，在智能体浏览器配置中设置 `auto_dismiss_consent: false`。

## 凭证库（登录而不泄露密码）

需登录的站点与应用，在 **设置 → 凭证** 配置 **表单凭证库** 条目：

1. 添加**标签**（如 `company-admin`）、密码与可选 TOTP 种子。
2. 让 Agent 登录 — 仅引用标签。
3. Myrm 在浏览器 DOM 或桌面输入层注入凭证；值不出现在对话中。

**意义：** 工具参数与聊天历史持久化。通过 `type`/`fill` 传 `"hunter2"` 会把密码复制到日志、重试与上下文。基于标签的注入将秘密留在库边界内——与研究级浏览器库设计同原则，并扩展到桌面 Computer Use 与产品 GUI。

## 视觉验证（自动 QA）

每个浏览器操作都可自动验证——无需手动检查。

操作时传入 `verify_goal` 参数，Myrm 的 **3 层验证漏斗** 自动启动：

1. **dHash 检测**（~2ms）— 感知哈希快速判断页面是否变化。无变化则跳过 LLM 调用，节省 Token。
2. **像素级 Diff** — Canvas API 对比 + YIQ 色彩空间 + 抗锯齿检测，精准定位变化区域。
3. **Vision LLM 评分** — 多模态 AI 对结果打分 1-5 并给出理由，确认目标是否达成。

### 示例

向 Agent 提问：*"点击'加入购物车'，验证购物车数量显示为 2"*

Agent 使用 `verify_goal="购物车数量显示为 2"`。点击后，系统自动截图并验证结果。评分低于 4 时，Agent 收到反馈并可自主重试。

### 设计技能集成

设计类技能（`ui-design`、`popular-web-designs`、`infographic`）的 allowed-tools 包含 `browser_navigate_tool`。当 Agent 生成 HTML 设计稿时会自动：

1. 在后台启动本地 HTTP 服务器
2. 使用 `verify_goal` 描述预期的视觉效果进行导航
3. 接收 3 层验证反馈（DOM + dHash + Vision LLM 评分）
4. 修复渲染问题并重新验证，直到评分 ≥ 4

这意味着您首次看到的 HTML 设计稿就是**经过验证的高质量结果**——减少 1-3 轮手动反馈。当浏览器工具不可用时，此步骤自动跳过，零影响。

### 隐私保护

密码输入框在截图时**自动遮蔽**——Vision LLM 不会看到敏感凭证。

## Schema 驱动结构化提取

无需将整页原始文本灌入对话（浪费上下文 Token），你可以传入 **JSON Schema**，提取工具直接返回验证过的结构化 JSON。

### 工作原理

1. Agent 调用 `browser_extract`，附带 `extraction_schema` 参数（JSON Schema 字符串）。
2. 工具提取页面文本，然后用 LLM 生成符合 Schema 的结构化输出。
3. 你得到干净、验证过的 JSON——而非数千 Token 的原始 HTML。

### 示例

向 Agent 提问：*"提取页面上所有产品名称和价格"*

Agent 使用如下 Schema：

```json
{
  "type": "array",
  "items": {
    "type": "object",
    "properties": {
      "name": { "type": "string" },
      "price": { "type": "string" }
    },
    "required": ["name", "price"]
  }
}
```

结果：仅包含你需要数据的干净 JSON 数组。

### 核心特性

- **对象和数组 Schema** — 提取单个对象或项目列表。
- **分页去重** — 传入 `already_collected` 避免跨页重复。
- **双策略可靠性** — 优先 `structured_output`，兼容性回退到原始 JSON 解析。
- **Token 节省** — 相比原始文本提取减少 70–97%。
- **Schema 复杂度保护** — 限制属性数量和嵌套深度，防止滥用。

### 从提取数据到交互式电子表格

提取到结构化 JSON 后，Agent 可直接写入 CSV 或 Excel 文件——自动成为对话中的富交互工件。

**全自动流水线**（无需额外工具）：

1. Agent 通过 `extraction_schema` 提取结构化数据
2. Agent 用内置文件工具写入 `.csv` 文件 → 工件自动注册
3. 前端通过实时 SSE 推送接收工件
4. `SpreadsheetPreview` 在对话中渲染交互式数据表格

**用户在 DataGrid 中看到的：**

- 虚拟滚动表格，轻松处理 10,000+ 行数据
- 点击列标题排序（升序/降序）
- 全单元格实时搜索
- 一键复制行或整个表格到剪贴板
- 导出/下载为 CSV

对于多 Sheet 的 Excel（`.xlsx`）文件，Agent 可使用代码执行工具配合 Python `openpyxl` 生成——前端自动显示 Sheet 标签页切换。

**对比竞品：** 大多数浏览器自动化工具（如 BrowserAct）仅生成可下载文件。Myrm 将数据作为**对话内的实时交互表格**呈现——用户可先浏览、排序、搜索，再下载。

## 临时会话隔离

每个浏览器上下文**默认为临时模式**——通过 `browser.new_context()` 创建，不使用持久化配置。会话结束时 Cookie、localStorage 和缓存自动销毁。Agent 永远无法访问你的真实浏览器配置，从根源杜绝会话泄露风险。

## 隐私优先的已登录访问（不读取 OS 浏览历史）

Myrm **不会**读取 Chrome/Edge 的 `History.db`、书签数据库或其他 OS 级浏览记录。已登录站点与内网访问走显式、用户可控的路径：

| 需求 | Myrm 方案 | 我们刻意不做 |
|------|-----------|-------------|
| 复用你已登录的站点 | **Extension Bridge** — 在真实 Chrome 标签页中操作，沿用现有登录态 | 批量索引历史/书签 |
| 登录一次，跨 Agent 运行保持登录 | **Session Vault** — 按域名 AES-256-GCM 加密保存 Cookie + localStorage | 从浏览器配置导入 Cookie DB |
| 回忆与 Agent 讨论过的 URL | **`memory_search_tool(corpus=sessions)`（opt-in）** | OS 级历史搜索 |

**行业对齐：** 主流 claw 竞品（OpenClaw、Hermes、CoPaw、DeerFlow、CodePilot、LobsterAI、JiuwenClaw）均未提供读取 `History.db` 或书签 JSON 的 Agent 工具。部分产品（如 Orca、Holaboss）支持将 Chrome Cookie/配置一次性导入内置浏览器——架构不同，目标相同。CoPaw 明确建议不想暴露历史/Cookie 时使用 `private_mode`。

## 加密 Session 库（跨会话保持登录）

会话默认临时，但你可以为每个 Agent 配置 **auto_restore_domains**，在对话之间保持登录状态。

### 工作原理

1. **配置域名** — 在 Agent 设置 WebUI 中，将 `twitter.com`、`github.com` 等域名添加到 Agent 的 `auto_restore_domains` 列表。
2. **加密存储** — Cookie 和存储数据通过 AES-256-GCM 加密保存在 Session Vault 中。
3. **启动时自动恢复** — 每次 Agent 启动新浏览器会话时，已配置域名的登录态自动恢复。
4. **Agent 可显式管理** — Agent 也可通过 `browser_manage(action="save_session")` / `restore_session` / `list_sessions` / `delete_session` 进行精细控制。

### 架构亮点

- **AES-256-GCM 加密** — Session 数据落盘加密，绝不以明文存储。
- **O(1) LRU 内存缓存** — 热点 Session 直接从内存读取，无磁盘 I/O。
- **Singleflight 去重** — 并发请求同一域名时合并为一次解密操作。
- **TTL 自动过期** — 过期 Session 被自动垃圾回收。
- **智能体级物理隔离** — 每个智能体的会话存储在独立的 `agent_id` 子目录中。智能体 A 保存的登录态对智能体 B 完全不可见，即使在同一服务器实例上。
- **全场景覆盖** — Web 对话、Channel 渠道、Cron 定时任务、Eval 评测均支持。

### 使用场景

| 场景 | 建议 |
|------|------|
| 一次性浏览 | 默认（临时模式）——无需配置 |
| 频繁访问需认证的网站 | 添加到 `auto_restore_domains` |
| Agent 工作流中途需要登录 | Agent 调用 `save_session` / `restore_session` |
| 多 Agent 共享凭证 | 每个 Agent 独立配置域名列表 |

### Session–Memory Bridge（零成本会话感知）

当记忆系统启用时，已保存的浏览器会话**自动出现在 Agent 上下文中**——无需额外工具调用。

- **工作原理：** 每次保存或删除 session 时，`SessionMemoryBridge` 自动更新 Agent 的 `active_browser_sessions` Profile 属性。该属性通过 memory context middleware 注入到每轮 LLM 上下文中。
- **效果：** 当用户说"帮我发推文"时，Agent 已知道 `twitter.com` 可用——直接调用 `restore_session("twitter.com")`，**跳过 `list_sessions` 步骤，节省 1 次 LLM 推理**。
- **Prompt Cache 安全：** Profile 属性仅在 save/delete 时变更（极低频），不影响缓存命中率。

| 无 Bridge | 有 Bridge |
|-----------|----------|
| 用户："帮我发推文" → Agent 调用 `list_sessions` → 发现 twitter.com → 调用 `restore_session` | 用户："帮我发推文" → Agent 上下文已有 twitter.com → 直接调用 `restore_session` |
| 2 次工具调用 + 2 次 LLM 推理 | 1 次工具调用 + 1 次 LLM 推理 |

## OAuth 弹窗自动捕获

当 Agent 点击"使用 Google 登录"、"GitHub 登录"或任何会打开新窗口的链接时，Myrm 自动捕获弹窗并管理其生命周期。

### 工作原理

1. **自动捕获** — 每个页面自动注册 popup 监听器。当 `window.open()` 触发（OAuth、`target=_blank` 等），新窗口立即被捕获为子 Tab。
2. **焦点切换** — 活跃 Tab 自动切换到弹窗，Agent（或会话保险箱的自动恢复）可以与认证流程交互。
3. **父页面恢复** — 弹窗关闭后（用户完成登录或 OAuth 重定向完成），Agent 自动切回父页面。
4. **递归支持** — 弹窗页面本身也会监听嵌套弹窗（如 Google OAuth → SAML IdP → MFA 提供商）。

### 实际场景

| 场景 | 发生了什么 |
|------|-----------|
| Agent 访问 GitHub，点击"使用 Google 登录" | 弹窗被捕获 → Agent 观察 OAuth 流程 → 弹窗关闭 → Agent 回到 GitHub，已登录 |
| 网页表单包含 `target=_blank` 链接 | 新标签被捕获为子 Tab → Agent 在新页面继续 → 关闭后回到表单 |
| 会话保险箱 + OAuth | 首次：弹窗捕获，登录完成，会话保存。下次：自动恢复跳过 OAuth |

竞品（Hermes、OpenClaw、CoPaw、LobsterAI、DeerFlow、JiuwenClaw）均未实现自动弹窗捕获——已通过代码库扫描 `page.on('popup')` 验证。

## 站点经验库 — 越用越聪明的域名级智能

Agent 每次浏览网站都在学习。**站点经验库**自动捕获域名级知识，并在后续访问中复用——让重复交互更快、更可靠。

### 学到了什么

| 维度 | 示例 |
|------|------|
| **平台特征** | "该站有无限滚动"、"支持 GraphQL API" |
| **URL 模式** | `/user/{id}/posts`、`/search?q={query}&page={n}` |
| **已知陷阱** | "滚动3次后弹登录框"、"首次访问有 Cookie 同意墙" |
| **成功流程** | "搜索 → 按日期筛选 → 排序 → 提取结果" |

### 工作原理

1. **导航时自动注入** — 当 Agent 访问已知域名时，相关陷阱和成功流程会自动注入浏览器快照。Agent 一上来就"有经验"，而非盲目探索。
2. **交叉验证** — 当域名近期失败率飙升（24小时内≥3次失败）时，经验自动标记为过期，避免过时知识导致错误。
3. **Agent 自主管理** — Agent 可通过 `browser_manage` 工具保存、列出和删除经验（`save_site_experience`、`list_site_experience`、`delete_site_experience`）。
4. **HTTP/3 学习** — 对 HTTP/3 响应更快的域名会被记住，后续请求优先使用。

### 效果对比

| 没有站点经验 | 有站点经验 |
|------------|-----------|
| 每次从零探索网站 | 已知陷阱自动规避，成功流程直接复用 |
| 复杂站点多花 3-10 次 LLM 调用 | 重复访问减少 30-50% 探索步骤 |
| 相同错误跨会话反复犯 | 错误自动记忆并规避 |

配合**引擎亲和记忆**（记住哪些站需要隐身浏览）和**会话保险箱**（保持登录状态），Agent 构建了一套完整的域名级记忆体系，越用越强。

## CAPTCHA 检测 & 人类接管

Agent 在浏览网页时遇到验证码或需要人工介入的场景，系统自动处理：

### 自动 CAPTCHA 检测与解决

系统自动识别 10 种验证码类型（Cloudflare Turnstile、reCAPTCHA、hCaptcha、DataDome、Akamai 等）。三层解决机制：

1. **自动解决**（CapSolver API）：Cloudflare、reCAPTCHA、hCaptcha 自动完成——无需任何操作
2. **行为式 WAF 绕过**：DataDome、Kasada、Akamai、Imperva、PerimeterX 被即时识别，引擎静默升级至 Camoufox（深度反检测）——对你完全透明
3. **人工兜底**：仅在自动解决失败时才暂停——VNC 面板打开，你完成验证，Agent 自动恢复

### Agent 主动请求人类接管

对于验证码之外的场景——短信验证、支付网关、专有表单——Agent 可以主动请求你帮助：

1. Agent 判断自己无法继续（如"需要短信验证码"）
2. 调用 `browser_ask_human`，附带清晰的说明
3. **Extension 路径**（日常 Chrome / Extension Bridge）：聊天内 **`ExtensionTakeoverBanner`** 横幅显示原因、截图预览和实时标签链接——在本地浏览器完成操作后点击 **完成** 或 **无法完成**
4. **Managed 路径**（沙箱 / VNC）：VNC 面板弹出并展示原因——在面板内完成操作后点击 **完成**
5. Agent 捕获新页面状态并继续

两条路径共用同一结构化 resume 契约（`{action:'completed'|'skipped'}`），已通过 Chrome MCP E2E 验证（READ ×3 + LIVE ×1，2026-07）。

### 终端挑战硬停机

当验证码在引擎自动升级（Chromium → Camoufox）后仍然无法解决时，Agent 立即停止浪费时间：

1. 抛出结构化 `ToolError`，错误码为 `BROWSER_TERMINAL_CHALLENGE`
2. 该域名被记忆 10 分钟——后续访问该域名的导航在 **0ms** 内直接失败，无需重试
3. Agent 收到明确指导："不要重试此域名，告知用户并切换到其他方案"

### 对比竞品

| 没有 Myrm | 有了 Myrm |
|-----------|-----------|
| Agent 在验证码上无限循环 | 自动检测、暂停、通知 |
| Agent 在 2FA 上静默失败 | 主动请求帮助 |
| 用户必须时刻盯着 | 仅在真正需要时才打断 |
| 人工操作后上下文丢失 | 捕获操作后的页面状态并自适应 |
| Agent 反复尝试被封域名 | 终端挑战记忆，0ms 快速失败 |

## 5层反封锁防护

大规模爬取时，IP封禁、速率限制和验证码不可避免。Myrm 的5层防御体系自动处理一切，确保任务永不中断。

### 全自治会话生命周期

浏览器会话完全自管理——无需手动启动、停止或恢复浏览器会话：

| 层 | 功能 | 响应时间 |
|:---|:-----|:---------|
| **L1: 断连检测** | 通过 `disconnected` 事件检测浏览器进程崩溃 | 即时 |
| **L2: 页面崩溃** | 通过 `crash` 事件检测渲染器崩溃 | 即时 |
| **L3: 定期巡检** | 每30秒探测所有浏览器，驱逐无响应实例 | 30s |
| **空闲回收** | 零活跃页面超过可配置超时后自动回收 | 自动 |
| **弹性伸缩** | 负载时按需创建浏览器，空闲时缩至零 | 自动 |

**意味着什么：** 启动 Agent，分配浏览任务，然后放手。如果浏览器崩溃，登录态保存在加密 Session Vault 中，下次请求自动恢复。多 Agent 并发时，每个 Agent 获得隔离的浏览器上下文——零干扰，零手动协调。

**竞品对比：** BrowserAct 需要手动执行 `session list` / `session close` CLI 命令管理会话。其他竞品（Hermes、OpenClaw、CoPaw）完全没有会话生命周期管理。Myrm 全自动。

### 防护层

| 层 | 功能 | 用户收益 |
|:---|:-----|:---------|
| **检测** | 识别HTTP 403/429状态码 + Cloudflare/DataDome/CAPTCHA签名 + 13种网络错误模式 | 捕获简单状态码检查遗漏的封锁 |
| **代理隔离** | 被封代理以指数退避隔离（60s → 5min → 1hr），轮询时自动跳过 | 坏代理不再浪费请求 |
| **会话恢复** | 被封时：隔离代理 → 换新代理重启会话 → 从断点恢复，零状态丢失 | 无需从头重新开始爬取 |
| **熔断器** | per-domain熔断器，连续失败超阈值自动熔断，超时自动恢复 | 一个坏域名不会拖垮整个任务 |
| **限速** | per-domain令牌桶算法，防止请求过快触发反爬 | 设计层面保持低调 |

另外：10种验证码自动检测+人类接管（见上文），自适应路由器学习哪些网站需要隐身浏览并跨会话记忆。

## 浏览器扩展桥接（Extension Bridge）

当你需要 Agent 在你的**真实浏览器**中操作——保留现有登录态、扩展程序和浏览上下文时，Myrm 支持 Chrome 扩展桥接方案。

### 适用场景

| 场景 | 推荐方案 |
|------|---------|
| 全新的自动化浏览 | 默认方案（临时引擎） |
| 复用特定登录会话 | SessionVault `auto_restore_domains` |
| 需要完整浏览器指纹一致性 | **Extension Bridge** |
| Agent 需在真实 Chrome 中操作（沿用现有登录态/扩展） | **Extension Bridge** |
| SaaS 模式远程控制用户浏览器 | **Extension Bridge** |

> **隐私说明：** Extension Bridge 仅控制已授权标签页，**不会**批量读取 OS 浏览历史或书签数据库。回忆与 Agent 讨论过的 URL 请使用 `memory_search_tool(corpus=sessions)`（需在设置中开启历史会话搜索）。

### 工作原理

1. **安装 Myrm 扩展** — 一个轻量级 Chrome MV3 扩展，维持与 Myrm 服务器的 WebSocket 连接。
2. **授权域名** — 在设置 → 集成 → Extension Bridge 中添加允许 Agent 控制的域名（如 `github.com`、`*.google.com`）。支持通配符模式。
3. **Agent 连接** — 当任务需要访问已授权域名时，Agent 通过扩展的 WebSocket 通道和 `chrome.debugger` API 连接到你的真实浏览器。

### 后台窗口隔离（无感执行）

当 Agent 通过扩展桥接操作时，所有自动化在**专属后台窗口**中运行——你的活动标签页完全不受影响：

- 扩展创建一个不获取焦点的隐藏窗口（`focused: false`）用于 Agent 任务
- 所有标签操作在此隔离窗口中进行——不抢焦点、不切换标签
- 后台窗口 ID 通过 `chrome.storage.local` 持久化，Service Worker 重启后自动恢复
- 如果你手动关闭后台窗口，下次任务时自动重建
- 断开连接时自动清理所有后台标签，防止资源堆积

**三层会话安全网** —— 杜绝僵尸进程和残留会话：

| 层级 | 触发条件 | 响应时间 |
|------|---------|----------|
| L1：WebSocket 断开 | 服务端崩溃、网络中断或用户停止 Agent | 即时 — 立即释放所有 Debugger |
| L2：心跳超时 | 扩展无响应 | 30 秒 — 服务端主动断开并清理 |
| L3：标签生命周期事件 | 用户关闭浏览器或 Chrome 回收标签 | 即时 — 扩展通知服务端 |

**效果**：你正常浏览，Agent 在后台全速工作。无窗口闪烁、无焦点抢占、无任何打扰。

### 安全模型

- **域名级授权** — 仅显式授权的域名可被控制。Agent 无法访问授权列表外的任何标签页。
- **Token 认证** — 扩展使用密钥令牌向服务器认证，防止未授权连接。
- **Service Worker 保活** — MV3 扩展使用 `chrome.alarms` 实现持久连接和指数退避重连。
- **重连时域名同步** — 扩展重新连接时立即与服务器同步授权域名列表。

### 前端管理

Extension Bridge 设置面板（设置 → 集成）提供：

- **一键复制 WebSocket URL** — 根据当前部署模式自动生成正确的连接地址，带复制按钮和提示反馈
- **Auth Token 状态** — 显示服务器是否已配置 `EXTENSION_AUTH_TOKEN`（不暴露 token 明文）
- **可复制扩展路径** — 显示 `~/.myrm/myrm-agent/myrm-agent-extension`，一键复制用于 Chrome「加载已解压的扩展程序」
- **分步引导** — 扩展未连接时显示：加载扩展 → 复制 URL → 连接
- **实时连接状态** — 已连接/断开指示器，含扩展版本和浏览器名称
- **域名授权管理** — 添加、删除，支持通配符模式
- **可用标签页列表** — 按授权域名过滤，标记活跃标签

### 架构

Extension Bridge 跨越 5 层：

1. **Harness 协议层** (`ExtensionBridge`) — 在框架层定义契约
2. **Server 服务层** (`ExtensionBridgeService`) — 管理 WebSocket 生命周期、心跳和标签页控制
3. **API 路由层** — WebSocket + REST 端点，服务扩展和前端
4. **Chrome 扩展** — MV3 Service Worker，具备 chrome.debugger 附加能力
5. **前端面板** — React 设置组件，用于状态和域名管理

### Wiki 网页剪藏 — 右键保存到 Agent 知识库

在浏览器内将任意网页剪藏进智能体 Wiki **raw** 语料，无需打开 WebUI：

1. **连接** — 与 Extension Bridge 同一扩展；在 popup 配置服务器 URL 与 token（设置 → 集成 可查看连接状态与**按智能体选库**）。
2. **剪藏** — 右键页面或选中文字 → **Clip to Wiki**。扩展提取正文（Readability）、解析 **srcset** 最高清图片，并 POST 至 `POST /api/v1/wiki/clip`。

4. **反馈** — Chrome 系统通知（成功 / 重复 / 安全拦截），深链至 Settings（Wiki / 重复审核 / 安全对话框）。

| --- | --- |
| **成功** | raw 新增剪藏；通知可打开 Wiki 设置 |
| **重复** | 不覆盖；通知链至 Duplicate Review |
| **安全拦截** | 凭证/注入被拒；通知链至 Security 对话框 |

### 混合 URL 路由（云托管/SaaS 模式）

在云端部署模式下，智能体无法直接访问您的内网服务（localhost、192.168.x.x、内部域名）。Myrm 自动检测私网 URL 并通过 Extension Bridge 路由：

- **公网 URL**（google.com、github.com）→ 由云端沙箱浏览器处理（正常、快速）
- **私网 URL**（localhost:3000、jira.internal、192.168.1.1）→ 透明路由到您的 Extension Bridge

这意味着您的云端智能体可以与本地开发服务器、内部仪表盘和企业工具交互——全部通过您已登录的真实浏览器。无需 VPN 隧道、无需 ngrok、无需将内部服务暴露到公网。

如果遇到私网 URL 时 Extension Bridge 未连接，智能体会提示您安装扩展。

### 配置方式

1. **创建智能体时**：设置 → 智能体 → 创建/编辑 → 能力配置
2. **聊天时覆盖**：点击聊天窗口中的智能体配置图标 → 浏览器设置

所有四项配置在智能体克隆、导出/导入和 API 操作中完整保留。无效值在 API 层即被拒绝，不会写入数据库。

### 池隔离

每个智能体会话运行在独立的 **Chromium BrowserContext** 中——这是浏览器级别的安全边界，等同于运行独立的浏览器配置文件。这意味着：

- **Cookie/存储硬隔离** — 智能体 A 的登录会话、Cookie 和 localStorage 对智能体 B 物理上不可见。无需软件检查，浏览器本身强制执行隔离。
- **Tab 隔离** — 每个智能体的 TabController 仅管理自己的标签页。智能体无法切换、关闭甚至枚举其他会话的标签页。
- **扩展来源分离** — 扩展来源的浏览器（非托管，你的真实会话）绝不会分配给启动模式的智能体（托管的无头实例）。
- **自动扩展** — 新智能体自动获得新 Context，无需注册或协调。每个 Context 内通过 LRU 淘汰强制执行 Tab 上限。

这种架构从根本上强于浏览器扩展智能体使用的基于软件的"Tab 所有权契约"——后者可能因代码 bug 而被绕过，而 BrowserContext 隔离由 Chromium 本身强制执行。

## 本地浏览器零配置自动发现

当 Agent 使用 **Auto** 浏览器源模式（默认）时，Myrm 会自动检测并连接你正在运行的 Chrome——**无需配置，无需 CLI 参数，无需环境变量**。

### 工作原理

1. **DevToolsActivePort 扫描** — Myrm 扫描已知浏览器数据目录中的 `DevToolsActivePort` 文件（Chrome 启用远程调试时自动写入）
2. **多浏览器覆盖** — 支持 Chrome、Edge、Chromium、Brave、Chrome Canary，覆盖 macOS、Linux、Windows
3. **4 阶段验证** — 文件扫描 → HTTP 探测（`/json/version`）→ TCP 回退（兼容 Chrome M144+）→ 固定端口 9222 兜底
4. **优雅降级** — 未发现运行中的浏览器时，自动启动全新的托管实例

### 你只需做一件事

在浏览器中开启远程调试（一次性）：

1. 打开 Chrome，导航到 `chrome://inspect`
2. 打开 **"Open dedicated DevTools for Node"** 开关（启用调试端口）
3. 完成！Myrm 将从此自动发现你的 Chrome

### 对比竞品

| 没有自动发现 | Myrm |
|------------|------|
| 必须设置 `CDP_PORT=9222` 环境变量 | 自动完成，直接使用 |
| 必须用 `--remote-debugging-port` 启动 Chrome | 标准 Chrome + inspect 开关即可 |
| 只能连接单一浏览器 | 按优先级扫描 5 种浏览器 |
| 无法验证端口是否有效 | HTTP + TCP 探测自动过滤失效连接 |

所有发现过程在后台线程运行，不会阻塞 Agent 的事件循环。

## 浏览器操作录制 — 录一次，永久自动化

把一次手动浏览器操作流程变成可复用技能，无需手写一行代码。打开**录制面板**，手动点完一遍流程，Myrm 就会把轨迹变成可执行技能，智能体随时可以回放。

### 使用步骤

1. **开始录制** — 打开录制面板启动会话，Myrm 向页面注入轻量捕获引擎。
2. **执行操作流程** — 像平时一样点击、输入、下拉选择、滚动、悬停、跳转。每个有意义的动作都被实时捕获。
3. **生成技能** — 停止录制，核对步骤列表，一键生成技能。Myrm 会把轨迹提炼成可读、可执行的技能定义。
4. **随时回放** — 任何后续会话中让智能体执行该技能。无需脚本，无需手写 CSS 选择器。

### 语义级录制质量

录制是**语义级的，不是原始堆砌**——每个步骤都携带足够上下文，生成的技能在复杂表单上也能一次命中：

| 能力 | 对你的意义 |
|------|-----------|
| **下拉值 + 标签** | `<select>` 同时记录所选值与其人类可读标签（如「出发城市：东京」），而非晦涩的选项编码 |
| **多选完整保留** | 多选字段保留全部选中项，而非只记最后一个 |
| **字段名消歧** | 表单控件按真实标签描述——`aria-label`、`label[for]`、包裹 `<label>`、placeholder——三下拉机票表单也不会让智能体填错字段 |
| **标签文本去污染** | 字段名永远不会混入选项文本或嵌套控件文本——被 `<label>` 包裹的 `<select>` 不会污染标签措辞 |
| **输入法安全** | 中文/日文/韩文输入法组合期不会碎裂成乱码按键 |
| **导航折叠** | 跳转链与 SPA 路由变更折叠为一步干净的导航 |
| **噪音去除** | 悬停噪音与重复的回车提交点击自动去重 |

### 录制面板

面板实时展示已捕获的步骤列表——可随时暂停、恢复、删除误操作或重置。完成后为技能命名并写描述，预览生成的步骤，保存到技能库，跨会话立即可用。

### 验证场景

28 个录制场景已由自动化浏览器集成测试覆盖——涵盖下拉标签、多选、input/textarea 包裹标签、placeholder 兜底、特殊字符 ID、长标签截断、按钮 aria-label 捕获——全部通过。

### 三层可视化验证

1. **DOM 变更检测** — 操作后自动对比 DOM 变化
2. **dHash 像素比对** — 低开销截图差异检测
3. **Vision LLM 验证** — 发生显著变化时自动调用视觉模型确认操作成功

只有在页面确实发生了变化时才会触发更高级别的验证，大多数操作仅需第 1 层即可确认——无需手动关闭。

## Web Vitals 洞察 — 页面真实加载速度一览

问你的智能体「这个页面快吗？」，它会基于真实浏览器遥测给出确凿答案，而不是靠猜。

### 工作原理

一条 `browser_manage web_vitals` 命令即可测量浏览器会话中真实加载的页面——不需要 DevTools、扩展或外部服务：

- **Core Web Vitals** — LCP、CLS、INP、FCP、TTFB 从实时页面读取，并按谷歌官方阈值打分（`good` / `needs-improvement` / `poor`）
- **慢资源归因** — 最慢的若干资源及其耗时、体积、类型
- **可执行的修复建议** — 报告直接给出具体动作（压缩该资源、预加载字体、把该域名迁到 CDN），智能体可以直接照着做
- **优雅降级** — 仍在加载的页面、以及延迟渲染内容的 SPA 应用会先重试，若仍不可测则给出明确的「暂不可测」提示，而不是报错失败

输出示例：

```text
Web Vitals for https://example.com (measured in the current network environment)
LCP   2460ms   needs-improvement
CLS   0.12     needs-improvement
INP   n/a    —     not measurable yet — interact with the page and re-check
FCP   1180ms   good
TTFB  340ms    good
Slow resources:
  - https://cdn.example.com/hero.jpg — 812ms (img, 214KB)
Suggestions:
  - LCP is driven by https://cdn.example.com/hero.jpg — compress it, lazy-load below-the-fold content, or preload the critical image/font.
```

所有指标都是真实、反映当前网络环境的实测值——报告会明确标注这一点，避免把实验室基准误当成用户真实网络状况。
