# 定时任务实战

## 场景

你已经做好了一份每日简报（或任何可重复的任务），想让它每天早上 9 点自动运行，并把结果推送到微信、Slack 或邮箱 —— 无需手动触发。

## 材料

- 一个已验证可用的任务或 Skill（如[每日简报](/docs/zh/tutorials/daily-briefing)）
- 在 **设置 → 渠道** 中已配置的推送渠道（可选 —— 结果也会显示在任务面板中）

## 步骤

<Steps>
  <Step title="在对话中描述计划">
    在任意对话中告诉 Agent：

    > "每个工作日早上 9 点，运行我的'早间简报' Skill，把结果发到我的微信。"

    Agent 识别出定时意图后，会弹出确认卡片，显示任务名称、执行计划（cron 表达式）、绑定的 Skill 和推送渠道。
  </Step>
  <Step title="确认任务">
    检查确认卡片后点击 **确认**。任务立即创建。对话中会出现一张任务卡片，带有跳转到管理面板的链接。
  </Step>
  <Step title="在面板中监控">
    进入 **设置 → 定时任务** 查看所有定时任务。每条记录显示执行计划、上次运行时间、状态和产出历史。
  </Step>
  <Step title="调整或暂停">
    点击任意任务可编辑计划、更换推送渠道、修改提示词或暂停执行。也可以通过对话管理：

    > "暂停早间简报" 或 "改成 8:30 执行"
  </Step>
</Steps>

<Note>
  **三种任务类型**：Agent 任务（完整 LLM 执行）、Shell 命令（仅本地/桌面端）和 Python 脚本（零 LLM 费用，包括云端均可用）。详见[定时任务](/docs/zh/guides/scheduled-tasks)完整参考。
</Note>

## 交付物

一个按计划自动运行的定时任务，将结果推送到指定渠道，无需人工干预。

## 验收标准

- [ ] 任务在预定时间运行
- [ ] 产出被推送到配置的渠道
- [ ] 任务在定时任务面板中可见
- [ ] 可以暂停、编辑或删除任务

## 下一步

- **增加可靠性** → 先手动成功运行三次再设为自动化（生产环境最佳实践）
- **串联任务** → 使用任务链按顺序执行依赖任务（如：数据采集 → 分析 → 报告）
