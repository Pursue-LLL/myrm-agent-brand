# 竞品对比与迁移指南

Myrm 被设计为完整的 AI Agent 工作空间。与仅面向终端的编程 Agent 不同，Myrm 提供 GUI 优先的体验、持久化沙箱、跨会话记忆与企业级安全——同时保留完整编程能力。

<Note>
**迁移信心**——数据与节奏在你手里：可选 SaaS、自托管或桌面三模；Hermes 技能可 GUI 拖拽 ZIP 导入；先对照下方能力表再决定。文档提供 **3 种语言**（en/zh/ja），产品界面支持 **6 种**（zh/en/ja/ko/de/zh-TW）；首次访问自动识别浏览器语言，三种部署模式均适用。
</Note>

## 思考过程：可见、可停、可回看

大多数 Agent 在模型思考时只留一个静态骨架。Myrm 把推理链变成消息的一部分：

- **实时流式**：推理增量实时附加到助手消息，计时器显示「思考中 · Ns」。
- **可停止**：「停止思考」提前结束推理，用已有信息回答；10 秒超时保障按钮不会卡住。
- **折叠一次**（答案开始 1 秒后折叠），可随时展开。
- **真实 token**：优先使用供应商报告的 `reasoning_tokens`，仅在不可用时使用 `≈` 估算。
- **三种持久化模式**：`off / collapsed / inline`；`off` 阻止服务端发送推理内容。
- **6 语言 + 40px 触控目标**，完整本地化。

## 模型路由与逐答案归属

大多数 Agent 替你选模型但不说谁回答了。Myrm 在每条回答上暴露路由决策：

- **两套路由引擎已在生产接线**：任务复杂度路由（SIMPLE / STANDARD / REASONING）和任务专长路由（CODE / LONG_DOC / REASONING / MULTIMODAL / CASUAL / GENERAL），均带 fallback chain。
- **逐答案归属**：用量面板显示实际模型、路由档位、任务域、路由原因与成本。
- **按 Agent 开启**：在 Smart Routing 里选择轻量/推理模型后生效（3 个 Pareto 预置已内置配置），不是所有 Agent 默认开启。
- **确定性审批**：是否需要审批由规则计算，而非分类器判定。花钱与不可逆动作没有「总是允许」按钮；密钥绑定到已批准命令的 SHA-256，一次性消费。

## 不盯梢：交出去，回来拿结果

长期在线的 Agent，用户最大的抱怨是**盯梢**。Myrm 设计为可以离开：

- **后台任务耐久**：离线任务断线/重启后从数据库恢复；桌面端在长任务期间阻止休眠。
- **完成会找到你**：26 个渠道、站内通知、Catchup 收件箱。
- **空报告不打扰**：定时任务支持 `[SILENT]` 契约。

## 技能质量

安装技能不改变模型——只是往上下文多加一段文本。真正的问题是：Agent 是否照做了？照做后结果是否变好了？

- **已交付**：三态归因（selected / used / observable）、26 类威胁 / 113 条模式静态扫描、权限模板与技能体检、渐进披露。
- **项目级技能**：工作区内 `SKILL.md`（深度 3）自动识别，带信任门禁与 SQLite 快照。`.claude/skills/` 可直接复用。

## Agent 团队：验证优先，不是数量优先

竞品喜欢宣传 Agent 数量。数量不是能力——**一个无法验证自己工作的团队，只是噪音**。

- **已交付**：5 个团队模板、Kanban 任务 DAG、shell/语义验收、26 渠道完成通知、Fleet KPI 看板。
- 无人值守只放行声明过的能力集。

## 复杂任务：完成条件、独立验收、结构化交接

| 断点 | 用户实际遇到 | Myrm 今天 |
|---|---|---|
| 没有完成条件 | 「vague asks are where they all fall apart」 | Kanban 任务 DAG + 可编辑完成条件；验收不通过就 pause |
| Agent 说 done ≠ done | 「all 6 said done, none passed every hidden test」 | CompletionVerifier：shell 硬指标 + 语义判断；模型不能自己宣布完成 |
| 会话一断就丢 | 「most agents restart cold every run」 | 持久会话日志 + 上下文压缩 + ACP CLI 会话续接 |
| 没有在飞任务登记处 | 「one registry of everything in flight so nothing gets built twice」 | Kanban 任务图 + 依赖/owner + heartbeat/zombie 检测 |
| 交接失真 | 「each interaction the idea gets lost」 | AgentHandoverState + Kanban handoff metadata |
| 人成为瓶颈 | 「more permissions requested, intervention more often」 | 三档自主权限（strict / semi-auto / full-auto）+ TOTP 金库 + 移动 HITL |
| Agent 不在你的环境里 | 「you must control the substrate」 | 本地 WebUI / Tauri 桌面 / 每用户独立沙箱 + 持久卷 |

## 记忆后端：Myrm vs 托管记忆服务（GBrain）

GBrain（2026-10）卖的是「托管 Postgres + pgvector 记忆，任意 agent 指向即用」。这个卖点是真的——安装摩擦是非技术用户放弃的第一原因；代价是所有 agent 共用一套向量库、靠应用层作用域约束，而这正是它自己评论区最担心的事。

- **隔离是结构性的**：每个 Myrm 用户的记忆在自己独立的沙箱里（独立 SQLite + 独立向量索引），不存在需要「划作用域」的共享库。
- **写入有治理**：冲突写入进入待审队列，高风险冲突永不自动裁决；删除进归档，物理清除需显式操作。
- **退出成本低**：向量索引可重建（预估 → 执行 → 状态），记忆导出带 SHA-256 校验。
- 诚实差距：「粘贴一条链接，agent 自己完成配置」比我们的「复制配置片段」更顺滑。我们提供可移植的 Agent Plugins 包与分步说明，但没有可抓取的接入清单。

## 更新与恢复：Myrm vs OpenClaw v2026.10.9

OpenClaw 这个补丁版全部在修升级失败：回滚保留本地改动、陈旧索引不再被误判为损坏、失败后不再把网关留在停止态。这一点值得肯定——优先级选对了。

我们也如实说明自己的位置：**数据层更强**（坏页级抢救、校验备份、可撤销的状态交换），但源码/CLI 更新器仍是裸 git pull，没有暂存校验与回滚。分阶段升级、跨版本回归门禁与回滚入口都在路线图上（#167 / #215 / #478），在交付前我们不会宣称已经具备。

## 迁移路径

| 从 | 如何迁移 |
|---|---|
| **Hermes** | 导出技能为 ZIP → 通过 Myrm GUI 向导导入。BYOK 模型与 MCP 工具直接沿用。 |
| **OpenClaw** | 工作区上下文（USER.md）映射为 Myrm 记忆规则。MCP server 直接重连。 |
| **Codex / Claude Code** | CLI 工作流映射为 Goal Mode + cron。BYOK API Key 直接转移。 |
| **DeepSeek Harness** | BYOK 模型与 MCP 工具直接沿用；DSH 专用插件需按 `SKILL.md` 或 MCP 重新挂载。 |

> Myrm 支持 **SaaS 云端**、**自托管 WebUI**、**桌面客户端** 三种部署。技能与记忆可通过 GUI 迁移向导跟随（桌面端 / 本地 WebUI）。
