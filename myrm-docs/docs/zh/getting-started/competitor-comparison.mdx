# 竞品对比与迁移指南

Myrm 被设计为完整的 AI Agent 工作空间。与仅面向终端的编程 Agent 不同，Myrm 提供 GUI 优先的体验、持久化沙箱、跨会话记忆与企业级安全——同时保留完整编程能力。

<Note>
**迁移信心**——数据与节奏在你手里：可选 SaaS、自托管或桌面三模；Hermes 技能可 GUI 拖拽 ZIP 导入；先对照下方能力表再决定。文档提供 **3 种语言**（en/zh/ja），产品界面支持 **6 种**（zh/en/ja/ko/de/zh-TW）；首次访问自动识别浏览器语言，三种部署模式均适用。
</Note>

<Note>
**所有权是真正的差异。** Myrm 的 WebUI、API 服务端、Agent Harness 与 Tauri 桌面壳均为 **MIT 开源**；只有可选的 SaaS 控制平面是专有组件。如果你迁移的理由是「可审计、可自托管、退出成本低」，这一条可以直接在仓库里核对，不需要相信宣传。
</Note>

## 思考过程：可见、可停、可回看

大多数 Agent 在模型思考时只留一个静态骨架。Myrm 把推理链变成消息的一部分：

- **实时流式**：推理增量实时附加到助手消息，计时器显示「思考中 · Ns」。
- **可停止**：「停止思考」提前结束推理，用已有信息回答；10 秒超时保障按钮不会卡住。
- **折叠一次**（答案开始 1 秒后折叠），可随时展开。
- **真实 token**：优先使用供应商报告的 `reasoning_tokens`，仅在不可用时使用 `≈` 估算。
- **三种持久化模式**：`off / collapsed / inline`；`off` 阻止服务端发送推理内容。
- **6 语言 + 40px 触控目标**，完整本地化。

## 模型路由与逐答案归属

大多数 Agent 替你选模型但不说谁回答了。Myrm 在每条回答上暴露路由决策：

- **两套路由引擎已在生产接线**：任务复杂度路由（SIMPLE / STANDARD / REASONING）和任务专长路由（CODE / LONG_DOC / REASONING / MULTIMODAL / CASUAL / GENERAL），均带 fallback chain。
- **逐答案归属**：用量面板显示实际模型、路由档位、任务域、路由原因与成本。
- **按 Agent 开启**：在 Smart Routing 里选择轻量/推理模型后生效（3 个 Pareto 预置已内置配置），不是所有 Agent 默认开启。
- **确定性审批**：是否需要审批由规则计算，而非分类器判定。花钱与不可逆动作没有「总是允许」按钮；密钥绑定到已批准命令的 SHA-256，一次性消费。

## 不盯梢：交出去，回来拿结果

长期在线的 Agent，用户最大的抱怨是**盯梢**。Myrm 设计为可以离开：

- **后台任务耐久**：离线任务断线/重启后从数据库恢复；桌面端在长任务期间阻止休眠。
- **完成会找到你**：26 个渠道、站内通知、Catchup 收件箱。
- **空报告不打扰**：定时任务支持 `[SILENT]` 契约。

## 技能质量

安装技能不改变模型——只是往上下文多加一段文本。真正的问题是：Agent 是否照做了？照做后结果是否变好了？

- **已交付**：三态归因（selected / used / observable）、26 类威胁 / 113 条模式静态扫描、权限模板与技能体检、渐进披露。
- **项目级技能**：工作区内 `SKILL.md`（深度 3）自动识别，带信任门禁。`.claude/skills/` 可直接复用。
- **Anthropic 官方技能可原样使用**：`name / description / license / compatibility / metadata / allowed-tools` 全部解析；在其上再加版本、回滚、A/B 评测与权限收紧。

## Agent 团队：验证优先，不是数量优先

竞品喜欢宣传 Agent 数量。数量不是能力——**一个无法验证自己工作的团队，只是噪音**。

- **已交付**：5 个团队模板、Kanban 任务 DAG、shell/语义验收、26 渠道完成通知、Fleet KPI 看板。
- 无人值守只放行声明过的能力集。

## 复杂任务：完成条件、独立验收、结构化交接

| 断点 | 用户实际遇到 | Myrm 今天 |
|---|---|---|
| 没有完成条件 | 「vague asks are where they all fall apart」 | Kanban 任务 DAG + 可编辑完成条件；验收不通过就 pause |
| Agent 说 done ≠ done | 「all 6 said done, none passed every hidden test」 | CompletionVerifier：shell 硬指标 + 语义判断；模型不能自己宣布完成 |
| 会话一断就丢 | 「most agents restart cold every run」 | 持久会话日志 + 上下文压缩 + ACP CLI 会话续接 |
| 没有在飞任务登记处 | 「one registry of everything in flight so nothing gets built twice」 | Kanban 任务图 + 依赖/owner + heartbeat/zombie 检测 |
| 交接失真 | 「each interaction the idea gets lost」 | AgentHandoverState + Kanban handoff metadata |
| 人成为瓶颈 | 「more permissions requested, intervention more often」 | 三档自主权限（strict / semi-auto / full-auto）+ TOTP 金库 + 移动 HITL |
| Agent 不在你的环境里 | 「you must control the substrate」 | 本地 WebUI / Tauri 桌面 / 每用户独立沙箱 + 持久卷 |

## 记忆后端：Myrm vs 托管记忆服务（GBrain）

GBrain（2026-10）卖的是「托管 Postgres + pgvector 记忆，任意 agent 指向即用」。这个卖点是真的——安装摩擦是非技术用户放弃的第一原因；代价是所有 agent 共用一套向量库、靠应用层作用域约束，而这正是它自己评论区最担心的事。

- **隔离是结构性的**：每个 Myrm 用户的记忆在自己独立的沙箱里（独立 SQLite + 独立向量索引），不存在需要「划作用域」的共享库。
- **写入有治理**：冲突写入进入待审队列，高风险冲突永不自动裁决；删除进归档，物理清除需显式操作。
- **退出成本低**：向量索引可重建（预估 → 执行 → 状态），记忆导出带 SHA-256 校验。
- 诚实差距：「粘贴一条链接，agent 自己完成配置」比我们的「复制配置片段」更顺滑。我们提供可移植的 Agent Plugins 包与分步说明，但没有可抓取的接入清单。

## 更新与恢复：Myrm vs OpenClaw v2026.10.9

OpenClaw 这个补丁版全部在修升级失败：回滚保留本地改动、陈旧索引不再被误判为损坏、失败后不再把网关留在停止态。这一点值得肯定——优先级选对了。

我们也如实说明自己的位置：**数据层更强**（坏页级抢救、校验备份、可撤销的状态交换），但源码/CLI 更新器仍是裸 git pull，没有暂存校验与回滚。分阶段升级、跨版本回归门禁与回滚入口都在路线图上（#167 / #215 / #478），在交付前我们不会宣称已经具备。

## Personal Agent 时代：Myrm vs Muse / Today / GrokBot / Instinct / Dots

闭源 Personal Agent（Meta Muse、Today、xAI GrokBot、Instinct、OpenAI Dots）把「情感化打磨」和「零配置上手」做到了很高水平；Myrm 侧重的是**所有权、控制力与可扩展性**。我们诚实说明：如果你今天只想要最成熟的消费级陪伴体验，Muse/Today 在 3D 形象、安静回复、消息回应、称呼仪式、单助手呈现上更成熟；这些细节已进入路线图（#496 / #497 / #498 / #89），未交付前不对外宣称已支持。

| 维度 | Myrm Agent | 闭源 Personal Agent |
|---|---|---|
| **源码与托管** | WebUI、API 服务端、Tauri 桌面端与 harness 均为 MIT 开源，可本地/私有部署 | 闭源云服务/客户端，模型与数据路径由厂商控制 |
| **部署** | 本地 WebUI、Tauri 桌面、每用户云沙箱，一套服务三端同构 | 多为云端或单一桌面客户端 |
| **模型与成本** | BYOK、100+ 供应商、本地模型、智能路由、Prompt 缓存 | 隐藏或固定模型；订阅档位 |
| **数据** | 本地/桌面数据留在本机；云托管为每用户独立持久沙箱 | 厂商云；保留/训练策略由厂商决定 |
| **持久电脑** | 浏览器、终端、文件、已装软件跨会话保留 | 多数为与厂商账号绑定的云电脑 |
| **记忆** | 8 类记忆、白盒可编辑、冲突评审、可导出/导入 | 多为黑盒，导出能力罕见 |
| **多智能体** | 可配置智能体、各自记忆 + 全局共享记忆、默认主 Agent 绑定 Web/定时/渠道 | 通常单助手感知；多 Bot 流程门槛较高 |
| **扩展** | 技能市场、渐进披露、进化/权限门禁、MCP | 内置技能/插件，扩展面由厂商控制 |
| **安全** | 多层权限、HITL 审批、沙箱隔离、凭据保险箱、审计 | 账号级安全为主，动作级审批因产品而异 |
| **渠道** | 26 个渠道（Telegram、Slack、Discord、飞书、微信、邮件等） | 通常只有少数主渠道 |
| **可观测** | Token/成本 HUD、OTel 追踪、Eval Lab、Doctor 诊断 | 用量看板；成本/质量常为黑盒 |

### 迁移时能带走什么

| 从 | 能带走 | 带不走 |
|---|---|---|
| Muse / Today / GrokBot / Instinct / Dots | 模型 Key、`SKILL.md` 技能、MCP、提示词、渠道 | 厂商私有记忆、Bot 关系、订阅内算力 |
| Hermes / OpenClaw | 技能 ZIP、MCP、`USER.md` / 记忆规则、BYOK Key | 厂商特有插件/运行时 |
| Codex / Claude Code | BYOK Key、MCP、项目上下文 | IDE 专属工作流 |

> 闭源 Personal Agent 没有公开的记忆/Bot 导出格式，**不存在一键迁移**；迁移意味着保留 Key、技能、MCP、提示词与渠道，同时重建记忆与 Bot 关系。我们不做虚假承诺。

### 把闭源 Agent 接进 Discord（Muse / Grok Bot 的连接器）

Muse 与 Grok Bot 都没有官方 Discord 入口。用户要安装社区 connector、去开发者门户建应用、手动打开特权 Message Content Intent（不开会静默收不到消息），再把 Bot Token 贴进聊天框。连接器的权限只有「本人」与「其他人」两档：本人在聊天里说一句，就为其他成员放开联网搜索或图片生成。长任务跑起来没有反馈，额度也由厂商决定。

Myrm 把渠道当产品能力，而不是桥：

- **20+ 内置渠道**（Slack、Discord、Telegram、飞书、微信、企微、钉钉、WhatsApp、邮件等），共享同一份记忆、审批、工件与任务状态；Discord 支持线程、Forum、原生回复链与语音。
- **按人治理**：配对角色（admin/member）+ 每人每日消息配额；未配对发送者自动降为受限访客身份。
- **不可信回合的运行时围栏**：访客、未配对、非管理员成员的 shell、文件写入、记忆写入、桌面控制、子 Agent、cron 与技能管理被物理剥离。
- **长任务可见**：静默超时会发一条进行中消息，并原地更新已用时。
- **审批在聊天里**：一次性确认 token，社交不可逆动作不提供「永久允许」。
- **交付物能打开**：工作区文件转原生附件，HTML/PDF 报告附签名分享按钮，点开落到同一份工件版本。
- **数据归你**：Local WebUI / Tauri 桌面 / 云沙箱三种部署，BYOK，记忆与凭据都在自己的环境。

**尚未交付（不得当作已支持）**：访客回合的读取面隔离（文件读取与已登录浏览器上下文）、IM 内的掩码密钥输入、`/voice` 之外的 Discord 原生斜杠命令、Discord 接入的结构化预检（Intent/权限/邀请）。这些已进 roadmap，落地前对外只能说「写与控制的围栏」，不能说「访客绝对看不到你的数据」。

## 迁移能得到什么

大多数迁移不是「搬一段聊天记录」，而是借机把五套互不相通的工具换成一个有记忆、有控制面、有退出路径的工作台。

| 你要替换的 | Myrm 给你什么 | 仍然可以保留什么 |
|---|---|---|
| 闭源 Personal Agent：记忆与模型由厂商控制 | MIT 产品层、BYOK、本地/桌面/云三端、26 渠道 | 模型 Key、`SKILL.md`、MCP、提示词与规则；重建厂商私有记忆与 Bot 关系 |
| CLI 编码 Agent + 记忆插件 + 定时脚本 | 对话、文件、浏览器、代码、Office 工件、Kanban、定时任务共用一套会话模型 | 已配置的 CLI 可通过 ACP 继续委派；保留原有编码深度 |
| 托管记忆服务：所有 Agent 共享一个向量库 | 每用户独立沙箱与本地记忆、冲突待审、编辑/删除/导出、CJK 关键词兜底 | 支持的格式可导入；自定义数据走记忆 API，再重建索引并跑冲突检查 |
| 没有审计链的自动化脚本 | 确定性权限、审批卡、增量 diff、影子 Git 快照、一键回滚 | 高危动作仍需人审；普通写操作默认不打快照 |

**诚实边界：** 闭源 Personal Agent 没有公开的记忆/Bot 导出格式，所以不存在真正的一键迁移；迁移是「带走可移植资产 + 重建私有部分」。我们在你决定之前说清楚，而不是事后解释。

## Claude Code 的「七层生态」：迁过来能带走什么

网上流传的「7 个仓库升级 Claude Code」是一套栈，不是一个产品。逐层对照，Claude Code 用户迁到 Myrm 能留下什么、不该期待什么：

| 层 | Claude Code 生态 | Myrm 现状 | 诚实边界 |
|---|---|---|---|
| **编码会话** | Claude Code（终端） | GUI 个人 Agent + 持久沙箱内编码 | 纯 IDE 深度与终端手感仍是 Claude Code 的主场 |
| **Agent Skills** | `SKILL.md` 打包可复用工作流 | 技能契约、版本/回滚、A/B 评测、Curator；`.claude/skills/` 直接识别 | 社区技能数量小于头部生态 |
| **Plugins** | 命令 + 子代理 + MCP 打包 | **Agent Plugins 1.0** 导入/导出：技能 + MCP + 专家 + 模板，带安全扫描、权限收紧、回滚 | 插件生态规模更小 |
| **Serena** | LSP 符号导航 | 不内置；集成目录里的 `CodeGraph`、`Code Review Graph` 作为 MCP 服务接入 | 不提供 LSP 级导航；LSP 语义导航在路线图中 |
| **Context7** | 版本准确的库文档 | `context7` 已在内置集成目录（另有 Microsoft Learn、AWS Docs） | 段落级注入由该 MCP 自身负责 |
| **E2B** | 隔离执行 | agent-in-sandbox：本地 WebUI / Tauri 桌面 / 云托管 | 无 GPU 直通，重生成走云端 API |
| **Claude Code Action** | CI 里的 Issue/PR 触发 Agent | PR 交付（push → PR → 评审响应）+ Webhook 触发器可组合 Issue 事件 | 不提供开箱 CI Action——Myrm 是个人 Agent，不是 CI Bot |

**迁移结论**：`.claude/skills/`、`SKILL.md`、插件包、MCP 配置、BYOK Key 与项目规则都可以带走；真正变化的是外围工作区——长期记忆、26 渠道、Kanban、审批，以及本地/桌面/云同一套 server。

## 竞品今天仍然更强的地方

只说自己强、不说别人强的对比页是宣传册，不是对比。截至 **2026-11**，以下方面我们不宣称领先：

| 领域 | 今天更强的是谁 | 对你的意义 |
|---|---|---|
| **纯编码深度** | Claude Code、Codex、终端优先的 Agent | 如果你的工作 90% 是在 IDE 里改代码，先从它们开始。Myrm 是围绕工作的空间——记忆、文件、浏览器、Office、渠道、审批——不是「每个编码基准都更强」的承诺。 |
| **类型精确的代码导航** | DeepSeek-Harness（`lsp` 工具）、OpenCode（文档记载的实验性 `lsp` 工具） | 语言服务器解析类型，装了服务器的语言都能覆盖。Myrm 没有内置的代码导航工具：靠 grep 与 glob 检索，需要符号与调用路径查询时，接入集成目录里的代码图谱 MCP 服务。需要跨多种语言的精确引用时，先用它们的语言服务器工具。 |
| **从 Git worktree 或仓库开始任务** | OpenClaw、OpenCode | 它们的新会话界面可以把任务放进隔离的 Git worktree，OpenClaw 还能从粘贴的仓库地址开始。Myrm 的新任务卡片提供本地工作区、云端沙箱或不绑工作区三种选择；这一步没有 worktree 或仓库目的地。 |
| **原生手机应用** | OpenClaw | OpenClaw 提供 macOS、iOS、Android、Windows 与 Linux 原生应用。Myrm 的手机路线是可安装的网页应用（PWA）。 |
| **情感化与零配置上手** | Muse、Today、GrokBot、Instinct、Dots | 3D 形象、平静语气、称呼仪式、消息反应与消费级首启体验更强。部分在路线图里，未交付前不冒充已支持。 |
| **硬件与开放设备 SDK** | Hermes Gadget | Hermes 已有开放 SDK、桌面模拟器与逐板验证矩阵；我们不做固件，也不宣传不存在的硬件支持。 |
| **插件/技能生态规模** | OpenClaw、Hermes | 它们的第三方插件与技能更多。我们比的是安装前扫描、权限门禁、渐进披露与可回退，不是数量。 |
| **闭源产品的一键迁移** | 没有，诚实地说 | 闭源 Personal Agent 不发布可移植的记忆/Bot 格式。任何声称能一键导入另一家闭源助手私有记忆的厂商，都应该先拿出导出文件。 |

**怎么读下面的表：** `✅` 表示我们在产品/源码里找到并核实了该能力；`—` 表示超出本次验证范围，不等于竞品没有。我们会在重新核对时更新「截至」日期。

## 迁移路径

| 从 | 如何迁移 |
|---|---|
| **Hermes** | 导出技能为 ZIP → 通过 Myrm GUI 向导导入。BYOK 模型与 MCP 工具直接沿用。 |
| **OpenClaw** | 工作区上下文（USER.md）映射为 Myrm 记忆规则。MCP server 直接重连。 |
| **Codex / Claude Code** | CLI 工作流映射为 Goal Mode + cron；`.claude/skills/`、插件包与 MCP 配置可导入；BYOK Key 直接转移。 |
| **DeepSeek Harness** | BYOK 模型与 MCP 工具直接沿用；DSH 专用插件需按 `SKILL.md` 或 MCP 重新挂载。 |

> Myrm 支持 **SaaS 云端**、**自托管 WebUI**、**桌面客户端** 三种部署。技能与记忆可通过 GUI 迁移向导跟随（桌面端 / 本地 WebUI）。
