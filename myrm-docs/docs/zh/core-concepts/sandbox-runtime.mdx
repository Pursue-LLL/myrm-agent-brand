# 沙箱运行时

每位用户获得隔离、持久化的沙箱环境，重启后状态保留。

## 持久化

与临时沙箱不同，Myrm 沙箱保留：

- 已安装的包与工具
- 文件系统状态
- 环境配置
- 运行中的进程（自动重启）

### 崩溃一致性持久化（原子写）

持久化只有在「崩溃后数据仍完整」时才有意义。Myrm 通过统一的**崩溃一致性原子写原语**（`infra/atomic_write`）写入所有关键状态文件：写入临时文件 → `fsync` → 原子 `rename` → `fsync` 父目录。因此目标文件**永远是「完整的旧版本」或「完整的新版本」，绝不存在半截碎片**——无论进程崩溃、断电还是沙箱重启发生在哪一刻。

该保证覆盖最关键的持久化点：

- **上下文快照**——每次压缩周期前写入的会话快照在重启后完整保留，长会话可恢复完整上下文
- **Teammate 邮箱 JSONL**——子 Agent 间消息历史永不中途损坏，多 Agent 协作状态保持一致
- **技能实例与状态文件**——技能配置与运行时状态原子往返
- **加密密钥**——以 `0o600` 权限原子写入，密钥永不截断（否则全部历史数据无法解密）、永不暴露
- **用量账本**——追加写 + 锁保护，并发追加永不交错成损坏账本

竞品通常用直接覆盖写（`open(path, "w")`），写入前先截断原文件——写入中途崩溃会留下损坏、无法解析的文件，造成永久数据丢失。Myrm 的原子写让「崩溃 = 数据丢失」成为不可能。

## 隔离

每个沙箱在独立环境中运行：

- 独立文件系统卷
- 网络命名空间隔离
- 资源限制（CPU、内存、磁盘）
- 运行时强制安全策略
- **UI 交互黑名单**：后台子 Agent 的沙箱会屏蔽 UI 接口（`interactive_feedback`、`send_message`），确保后台任务无法用弹窗打断前台用户，实现物理级隔离。
- **分档进程（PID）限额**：沙箱的进程上限是计费权益——Free 200 / PRO 512 / MAX 1024——随套餐自动下发并在容器创建时校验生效，套餐与容器资源永远一致。进程占用按 cgroup 限额（`pids.current`/`pids.max`）两级阈值监控（70% 预警 / 90% 告警），含浏览器进程归因与 top 内存进程展示，Doctor 面板直接可见——不再出现「进程表满了 Agent 莫名卡死」的哑故障。

### 原生 OS 级沙箱（无需 Docker）

本地和桌面部署时，Myrm 在所有主流平台提供**原生 OS 级进程隔离**：

| 平台 | 隔离机制 | 工作原理 |
|------|----------|----------|
| macOS | Seatbelt (sandbox-exec) | 动态生成 SBPL 策略；零信任挂载，仅允许明确指定路径 |
| Linux | bubblewrap (bwrap) | 内核命名空间隔离 + PID/网络 unshare + 会话隔离 |
| Windows | AppContainer | Win32 原生安全令牌 + 逐路径 ACL 权限控制 |

沙箱 Provider 启动时自动检测，无需配置。若首选 Provider 不可用，系统优雅降级并给出明确警告。

**相比 Docker 方案的优势：**
- 无需安装 Docker Desktop（降低 Windows/macOS 安装门槛）
- 亚毫秒级启动（无需拉取容器镜像）
- 使用 OS 原生安全原语（内核强制，非用户态模拟）
- Local WebUI、Tauri 桌面端、云托管三种模式行为一致

### 显式生命周期与防泄漏资源级联释放

在长时间运行的 Agent 复杂工作流或多轮会话中，后台常驻进程与文件句柄的确定性释放至关重要。Myrm 实现了**双层显式异步释放协议**：

1. **`CodeExecutor` 生命周期契约**：在抽象基类与中间件链路上规范 `async def close(self) -> None:` 与 `__aenter__` / `__aexit__` 异步上下文管理器。
2. **进程树级联终止**：`LocalExecutor.close()` 幂等向常驻 Bash 子进程树发送 `SIGTERM` / `SIGKILL` 并安全关闭 I/O 管道。
3. **OS 级 ACL 安全描述符撤销**：`SandboxProvider.cleanup()` 自动撤销平台安全令牌（如 Windows AppContainer SID 权限），防止句柄和安全描述符累积泄漏。
4. **会话缓存自动解绑**：在 `run_lifecycle` 的 `finally` 钩子中自动出栈并异步关闭缓存的执行器实例。

### 智能错误恢复

当缺少包时，Agent 会自动收到可操作的诊断提示（建议精确的安装命令），消除试错循环。

**自动语言路由：** 内置单一执行工具自动识别 Python 还是 Shell 命令——无需手动包 `python3 -c` 或选择不同工具。语法错误在运行前即被拦截并给出清晰提示，减少无效重试、节省 token。

**对比竞品：** OpenClaw 的 `exec` 仅支持 shell；Hermes 将 shell 与 Python 拆成两个工具。Myrm 对 GUI 用户保持一个简单入口，底层自动路由。

## 上传文件直通

你在消息中附带的文件（拖拽上传或点击上传）会自动在沙箱 workspace 中可用：

- **小文件**（100 KB 以下）：内容直接注入 LLM 上下文，即时分析
- **大文件**（100 KB 以上）：自动复制到 workspace 的 `_uploaded/` 目录，Agent 可通过 `file_read_tool` 读取或使用代码处理（如 `pandas.read_csv()`）

这意味着你可以上传一个 5 MB 的 CSV 文件并要求"用 Python 分析季度趋势"——Agent 直接访问完整文件，无需手动传输文件或配置路径。

## 工作区沙箱（Git Worktree 隔离）

在任何聊天会话中启用 **沙箱模式**，获得项目级隔离：

- **一键开关**：点击消息输入栏的"沙箱"按钮
- **Git worktree**：创建隔离分支，所有变更被限制在临时分支内
- **合并或丢弃**：完成后将好的变更合并回主分支，或丢弃整个实验
- **零风险**：在你显式合并之前，主代码库永远不会被修改

适用场景：
- 重构实验（"不冒风险地试试这个方案"）
- 让 Agent 并行探索多种方案
- 代码审查时想先测试变更再接受

**并行子 Agent 工作区隔离**：运行多 Agent 任务时，每个子 Agent 获得独立的写时复制（COW）工作区克隆（ISOLATED_COPY 策略），附带 1 GiB 安全守卫。并行执行结束后按串行顺序安全合并——零文件冲突、零数据丢失。

7 种编排模式（Spawn / Chain / Batch / DAG / Verified / Swarm Fission / Alternatives）、级联取消、委派预算确保安全且成本可控的并行执行。三层沙箱（OS namespace / Docker 容器 / Workspace COW）毫秒级启动，无需 Docker 依赖。**1,101 项测试验证完整子代理与沙箱栈。**

与 Claude Code 仅 CLI 可用的 `--worktree` 参数不同，Myrm 的工作区沙箱通过 GUI 按钮一键切换，可在会话进行中随时启用/禁用，并提供完整的合并/丢弃工作流与预审批集成。

## Git 与 PR 交付

沙箱让 Git 工作流**开箱即用**，即使在全新环境中也能直接工作：

- **主机限定推送凭据**：当存在 `GITHUB_TOKEN` 且推送目标是 HTTPS `github.com` 远程仓库时，Myrm 会注入内联凭据助手——但仅在沙箱无现成凭据时触发。该助手是**主机限定**的：只对 `github.com` / `www.github.com` 应答，token 绝不会交给第三方 Git 服务器（例如自建 GitLab 远程或裸 HTTPS URL）。token 通过环境变量引用，从不内联在命令中。
- **自动提交身份**：若沙箱没有全局 `git config user.name/user.email`，Myrm 会从已连接的 GitHub 账号解析（`login@users.noreply.github.com`，`TMPDIR` 缓存 + 5 秒超时 + 本地兜底）。`git commit` 一次成功——不再出现「Please tell me who you are」的阻塞。
- **一键 PR 交付**：配合 **设置 > 集成 > GitHub** 的 GitHub 集成——webhook URL 带一键复制按钮显示，且你配置的 Webhook Secret 必须与 GitHub 中填写的一致（负载通过 `X-Hub-Signature-256` 校验）。PR 开启 / issue / push 事件带完整上下文回流到你的聊天。

结果是：对 Agent 说「推送到 GitHub 并创建 PR」即可端到端完成——凭据、身份、事件全部就绪，无需任何手动 Git 配置。

## 休眠与唤醒

沙箱空闲自动休眠，有请求时秒级唤醒，用户全程无感。

- **智能空闲检测**：后台每 60 秒扫描活跃沙箱，根据 `last_active_at` 判断是否超过空闲阈值。有活跃 WebSocket 连接时自动跳过，避免误休眠正在使用的沙箱
- **权益分级超时**：Free 5 分钟、Companion 30 分钟、Pro 1 小时、Enterprise 24 小时，通过 EntitlementService 按用户套餐差异化配置
- **两层缓冲机制**：空闲 5 分钟先 CPU 降至 25%（ResourceScaler），继续空闲达到阈值后再进入休眠。新任务到来时 CPU 立即恢复满血
- **秒级唤醒**：Docker pause/unpause 冻结/恢复进程，内存状态完整保留，唤醒耗时 <100ms。unpause 失败时自动降级为 start 容器
- **消息零丢失**：休眠期间收到的消息自动进入 Redis 队列（最深 10 条），沙箱唤醒后自动排空
- **状态自修复**：StateReconciler 定期校验数据库状态与容器实际状态，发现不一致自动修复
- **长期未用自动回收**：超过配置天数未使用的沙箱自动销毁释放资源

## 企业组织管理与数据资产交接

面向 B2B 团队，Control Plane 提供完整的组织生命周期管理：

- **RBAC 角色体系**：Owner / Admin / Member 三级权限，原子级鉴权
- **成员幂等添加**：重复操作安全返回已有记录，不会产生 500 错误
- **一键离职交接**：管理员冻结沙箱 → 备份 Volume → 转交接任者，一步完成
- **不可篡改审计**：每次交接操作均有合规日志记录
- **跨组织保护**：同一用户无法同时属于两个组织
- **三路撤销对称**：移除成员即时三路清空其 Org MCP / 审批策略 / 模型白名单（fire-and-forget 异步推送）；沙箱休眠时唤醒自动清空残留治理，权限零残留窗口
- **归档保留期自动清理**：离职归档按组织配置的保留天数（`archive_retention_days`，默认 365）自动清除，既满足合规留存又不占磁盘
- **交接安全边界**：显式 `backup_path` 必须位于备份目录内（越界返回 409）；自转（source == target）拒绝；UI 仅将已归档完成的成员列为转交来源

企业数据永远不会随离职员工流失——始终在组织管控下，全程可追溯。

### Zero-Secret LLM 网关

云托管模式下，API Key 永远不进入沙箱：

- 真实密钥存储于控制平面的 **AES-256-GCM 加密保险库**
- 沙箱内仅有 HMAC 签名的**虚拟密钥**（`myrm-vk-...`），对真实 Provider 完全无效
- 所有 LLM 调用经 CP relay 转发：验签 → 注入真实密钥 → 透传请求体
- 请求体**字节级原样转发**，完美保留上游 Prompt Prefix Cache
- 即使沙箱被完全攻破，也无法获取任何可用的 API 凭据

### 企业 SSO 单点登录

企业版支持 OIDC 协议（企微、飞书、钉钉、Google Workspace、Azure AD、Okta）。员工打开应用后通过企业 IdP 认证——无需单独注册，无需管理 API Key。
