# 技能进化

Agent 通过 **42 模块原生进化引擎**自主学习、测试、部署新技能 — 无外部依赖、无 CLI 包装、无 AGPL 风险。

## 工作原理

**Retrieve-Before-Generate**：创建新方案前先搜现有高置信修复，单独即可减少冗余 LLM 调用。

1. **发现** — 识别重复任务模式或失败信号
2. **证据聚合** — 跨多次执行收集成功/失败案例
3. **变体生成** — 并行 3 个候选（竞品常 50–500 次 LLM 调用）
4. **评分** — LLM-as-Judge 四维（功能/质量/安全/兼容）
5. **审批** — GUI 人工审批与 diff 预览
6. **部署** — A/B 测试，回归自动回滚

## 定向技能学习：`/learn`

除了自动技能提取，您还可以在任何对话中使用 `/learn` 命令按需教 Agent 新技能：

| 输入 | 效果 |
|-------|-------------|
| `/learn https://docs.stripe.com/webhooks` | 抓取页面，提取流程和配置，创建可复用技能 |
| `/learn ./scripts/deploy.sh` | 读取文件，分析工作流，提炼为 SKILL.md |
| `/learn 我们刚才做的部署流程` | 回溯对话历史，将步骤封装为技能 |
| `/learn`（无参数） | 自动回顾当前对话，提炼为技能 |

`/learn` 命令在所有渠道可用 — WebUI、Telegram 及任何已接入的 IM 平台。生成的技能遵循严格的编写标准（Frontmatter、8 段式结构、质量要求），并通过与自动捕获技能相同的安全管道保存。

**vs 竞品：** Hermes `/learn` 必须传参（空参数会报错），且仅在 CLI 可用。Myrm 的 `/learn` 优雅处理空参数，跨全渠道可用，并接入完整质量管道（10 维评分、语义去重、生命周期管理）。

## 示例学习（Learning by Demonstration）

给 Agent 看一个"原始 → 期望"范例，它自动推断转换规则：

1. **上传** 原始文件和期望结果（Excel、CSV、文本、代码 — 任意格式）
2. **Agent 分析** 差异，推断转换逻辑，编写脚本
3. **验证** 执行脚本并对比输出与期望结果
4. **固化** 将验证通过的模式通过 `StructuredExtractor` 捕获为可复用技能

整个流程在自然对话中完成——无需向导、模板编辑器或编程。`StructuredExtractor` 自动分类该模式适合成为 `skill`、`cron_job` 还是太琐碎可跳过（`skip`），内置 `safety_analysis` 检测破坏性命令或凭证泄露。

**vs 竞品：** 所有竞品需要手动编写模板或录制宏。Myrm 完全基于对话，利用 LLM 理解力从范例中**归纳泛化**，而非简单录制回放。

## 从人类接管中学习

当 Agent 在浏览器任务中遇到困难时，它会请求你接管控制权。你的操作会自动成为学习材料——完全透明、零干扰：

1. **Agent 请求接管** — 你看到"请求接管控制权"提示
2. **你操作浏览器** — 导航、点击、填写表单
3. **系统捕获变化** — 记录接管前后的页面语义快照（无障碍树 + URL）
4. **Toast 确认** — 显示"行为已记录 — Agent 将从你的示范中学习"
5. **进化引擎消费证据** — 下次 FIX 或 DERIVED 流水线触发时，你的示范作为人类证据与执行轨迹一同呈现给 LLM

这一切零额外成本（录制过程不触发任何 LLM 调用），零干扰。Agent 不会试图重放你的精确点击——进化 LLM 收到的是高层级的"前后页面状态"，理解正确结果应该是什么。

**vs 竞品：** 没有竞品（OpenClaw、Hermes、CoPaw、DeerFlow、LobsterAI）会捕获人类接管操作用于技能学习。当它们的 Agent 卡住时，用户的手动介入会被直接丢弃。

## 四种进化类型

| 类型 | 触发 | 作用 |
|------|---------|-------------|
| **FIX** | 连续 3 次失败或成功率 <50% | 用 trace 分析自动修复失败技能 |
| **DERIVED** | 用户反馈或挫败信号 | 根据显式/隐式反馈优化技能 |
| **CAPTURED** | 空闲时检测会话反模式 | 后台提取 → 10维评分 → 语义去重 → 安全扫描 → 洞察Inbox审批 |
| **OPTIMIZE_DESCRIPTION** | 匹配率低 | 优化技能描述以利语义匹配 |

## 5 层安全

每个进化技能过五道独立安全门：

| 层 | 机制 | 防止 |
|-------|-----------|-----------------|
| **Sandbox** | 隔离执行环境 | 运行时失败与副作用 |
| **AST Signature** | 函数签名完整性 | 核心 API 破坏 |
| **Size Guard** | 最大 120% 增长比 | 代码膨胀 |
| **Anti-Loop** | 每技能 TTL + 尝试上限 | 无限进化循环 |
| **A/B Testing** | 并排性能对比 | 静默回归 |

## 挫败检测

**5 类 38 条双语模式**（中英）检测用户不满，无需显式反馈触发 DERIVED：

- 冗长、风格、格式、工作流、一般挫败表达

## 证据驱动进化

聚合多次执行证据，非单次失败信号：

- 成功案例 — 防回归
- 失败案例 — 根因分析
- 最低阈值 — 至少 3 次执行且 1 次失败才触发

## 最小形式原则

Agent 捕获行为模式时，不会盲目创建技能，而是在**同一次 LLM 调用**中分类最合适的执行形式——零额外成本：

| 分类 | 处理方式 | 示例 |
|------|----------|------|
| **skill** | 正常技能审批流程 | "零宕机滚动部署" |
| **cron_job** | 紫色卡片 + 调度建议 | "每周一 9:00 检查服务器负载" |
| **skip** | 静默丢弃——太琐碎不值得捕获 | "重命名文件" |

收件箱噪音更少，定时任务类模式有明确的调度引导。

**vs 竞品：** 无竞品（Hermes、OpenClaw、Codex）提供自动形式分类。它们全部只输出 skill，用户需手动创建定时任务。

## 主动技能推荐

当 Agent 遇到当前工具无法完成的请求时，会**自动搜索**技能市场，而不是直接拒绝。这种"拒绝前先搜索"的行为通过双层机制强制执行：

1. **系统规则层** — 全模型通用行为规则，指示 Agent 在拒绝前检查 discovery 工具
2. **工具描述层** — 发现工具使用 MUST 级别指令

**对你意味着什么：** AI 助手永远不会轻易说"我做不到"。它会先搜索可安装的技能，找到后推荐你一键安装。

**vs 竞品：** 已验证 8 个竞品仓库（Hermes、OpenClaw、CoPaw、LobsterAI、CodePilot、jiuwenclaw、deer-flow）——无一实现主动技能推荐。Hermes 的 `tool_search`（735 行）是已注册工具的按需加载，不是能力发现。

## 质量监控

**3 维退化检测** + 滑动窗口：

- 成功率（默认阈值 70%）
- P95 延迟告警
- 5xx 服务错误率

退化技能经 **1-Strike**（严重失败）或 **3-Strikes**（渐进退化）隔离。

## 止损：版本回滚、Shadow 验证与批量快照

**通俗说：** 进化改坏了可以在设置里一键回到上一版，不用敲命令。也可以先选「Shadow 验证」——对话仍用旧版，后台对比满意再上线。批量优化多个技能时会先自动存快照，跑一半发现不行可以「取消并回滚」。

**实测（2026-06-06）：** 34 项自动化测试覆盖批量取消/回滚（含多技能、partial HTTP 真写盘、await 超时跳过 rollback）、`OptimizationScheduler.cancel_batch_optimization` + `await_batch_optimization` 接线，以及 `restore_skill_snapshot` 双分支真写盘；取消时 harness 先设 cancellation token 停止后续优化，await 完成后再回滚快照；await 超时则跳过 rollback 并提示用户前往详情页手动回滚；取消并回滚与详情页批量回滚返回相同的 `rolled_back`/`failed`/`total_skills`/`error_message` 统计；Web UI 按结果显示成功、部分恢复（`cancelRollbackPartial` / `rollbackPartial`）或失败提示。完整 GUI 点按 E2E 需后端联调。

| 能力 | 你能得到什么 |
|------|--------------|
| **Versions 面板** | 图形界面一键回滚任意历史版本 |
| **Approve + Shadow** | 成长收件箱 → Shadow 对比 → Guardian 提升或停止 |
| **批量优化** | 提交前快照；运行中可取消并整批恢复 |

**对比竞品：** Hermes/OpenClaw 多为 CLI 或文件回滚；无完整 GUI 的 Shadow 验证 + 批量中途回滚闭环。

## 避坑指南：从失败中自动学习

Myrm 自动从技能执行失败中提取结构化"陷阱"，并注入后续 Prompt——Agent 不会犯同样的错误两次。

| 能力 | 你能得到什么 |
|------|--------------|
| **自动提取** | 确定性错误自动捕获为结构化 trap（严重度 + 触发条件 + 缓解措施） |
| **智能去重** | 相同错误累加 `occurrence_count`，不重复创建 |
| **Prompt 注入** | 高严重度 trap 自动注入进化 prompt 作为 "Known Traps" 约束 |
| **GUI 展示** | 4 级彩色严重度标识 + 触发条件 + 缓解步骤 + 发生次数 |
| **模板库** | 8 种常见陷阱模板（npm 超时、API 限流、文件权限、内存溢出、编码、Python 版本、Docker、Git 冲突） |

**通俗说：** 技能执行失败时（如 npm 超时），Myrm 会记住这个坑并在下次进化时明确提醒 AI 避开。随着使用越来越多，技能自动变得更健壮——无需手动记录。

**对比竞品：** Hermes 仅在技能文本中有一段纯文本 "Pitfalls"。Myrm 提供结构化存储 + 4 级严重度 + 运行时自动提取 + 去重计数 + Prompt 工程注入——完整闭环学习系统。

## 决策历史：正向+负向双闭环学习

每次进化的结果——无论成功还是失败——都会被永久记录并自动注入到未来的进化尝试中。Agent 随着时间积累组织知识，同时记住哪些有效、哪些无效。

| 来源 | 记录内容 | 触发时机 |
|------|---------|---------|
| **FIX 成功** | 错误描述 + 修复推理 | 自动修复成功后（评分 ≥ 0.7） |
| **用户驱动优化** | 用户反馈 + 优化推理 | DERIVED 进化成功后（评分 ≥ 0.7） |
| **证据驱动修复** | 聚合失败模式 + 修复推理 | 基于证据的进化成功后（评分 ≥ 0.7） |
| **筛选器拒绝** | 拒绝原因 + 置信度分数 | 进化提案被自动筛选器拒绝时（置信度 ≥ 0.7） |
| **人工拒绝** | 审核者的拒绝原因 | 用户在 GUI 中拒绝提案时 |

**工作原理：** 最近 5 条约束自动注入 LLM Prompt，作为 "历史约束（必须遵守，否则必被拒绝）"——让下一次进化基于积累的智慧而非从零开始。

**通俗说：** Agent 每次进化都会变得更聪明。修复成功了，记住原因；提案被拒绝了，不会再尝试同样的方向。长期使用后，技能积累了丰富的经验教训——全自动，零维护。

**对比竞品：** 腾讯 SkillHone 使用 Git 服务器（Forgejo）的 Issue/PR/Wiki 记录决策历史——需要 docker compose 搭建且需手动浏览。Myrm 在 SQLite 中存储一切，零外部依赖，自动注入经验到未来 Prompt。其他竞品均不提供正向+负向双闭环持久化学习。

## Curator：生命周期治理

- **真实 usage 驱动** — 选技能 / `[use skill]` 自动写 `.stats.json`；Curator 按真实调用决策，避免空 stats 误判
- **后台零 Token 消耗** — 定期 stale/archive/LRU 为确定性逻辑；consolidation（伞形合并）默认关闭，需显式开启
- **prebuilt 免疫** — 41+ 内置技能路径自动豁免，不会被误归档
- **双入口一键清扫** — 设置页「立即运行」+ 智能体配置 Radar「一键净化」，toast 显示 stale/archived 数
- **never-used 保护** — 新技能 grace + stale 天数双门槛，不会刚安装就被标闲置
- **聚类检测** — 前缀 + embedding 发现语义相似技能
- **伞形合并** — GUI 预览 + 确认执行两步操作，不会误合并
- **自动恢复** — stale 技能再次使用时自动恢复 active
- **Hermes 迁移 usage 保留** — 迁入后 call_count / last_used 不丢，Curator 不误杀活跃技能
- **历史可视化** — GUI 进化时间线，每次扫描可追溯
- **单一卫生 SSOT** — 清理 stale/归档只在 Settings Curator 与 Agent Smart Prune 执行；对话 discover **不会**挂载只读 analyze 工具（7/7 竞品亦无对等 Agent 工具）

## 技能配置热重载

在 WebUI 中修改技能、Agent 绑定或相关设置后，**下一条聊天消息**即生效 — 无需重启服务，也无需手动执行 reload 命令。

**流程简述：**

1. 设置 API 调用 `bump_skill_config_version()`，在数据目录（`MYRM_DATA_DIR/.skill_config_version`）原子写入版本号。
2. Agent 处理下一条消息前读取该文件，与本地缓存对比。
3. 若版本过期，清除 SkillLoader 缓存并按需重初始化。

**Volume 持久化的意义：** 云沙箱或多 Worker（Granian）部署时，各进程通过共享 Volume 读到同一版本号。OpenClaw 类似计数器仅在进程内存中，Worker 可能不一致；Hermes 需手动 `/reload-skills`。

**Prompt Cache：** 仅在技能实际变更时 reinit，未改技能的对话仍享受缓存收益。

### 日报（Daily Journal）

指定日 Agent 活动 consolidated 视图：概览指标、来源分解、统一时间线、日期导航、按 Agent 过滤。聚合 6 个现有数据源，零新存储。

## 多 Agent 技能作用域与共享

- **作用域隔离**：技能归属学习它的 Agent，不污染全局池
- **跨 Agent 挂载**：GUI 一键挂载并显示来源徽章
- **写时复制（CoW）分叉**：B 进化 A 挂载的技能时自动为 B 分叉，A 原技能不变
- **一键回滚**：CoW 分叉上撤销进化可恢复跨 Agent 挂载映射
- **垃圾回收**：删 Agent 级联删专属技能（DB + 物理 `rmtree`，路径边界保护）

## 会话级 Skill 精选

除了 Agent 级别的技能作用域，Myrm 还支持**按会话选择技能**——精确控制每次对话加载哪些技能：

- **可视化切换**：消息输入框旁的星火图标（✦）打开弹出面板，列出所有已启用技能，一键切换
- **Token 节省**：禁用不相关技能可移除其 prompt 片段，典型 9 技能场景下每轮省约 1800 Token
- **更精准的 AI 决策**：候选技能更少意味着更少的 LLM 决策噪声，Agent 选对技能更快
- **持久化覆盖**：选择保存在服务端（`session_loaded_skill_names`），页面刷新、上下文压缩、对话分叉后均保留
- **切换 Agent 自动清空**：更换绑定 Agent 时自动重置到新 Agent 的默认技能集

**竞品对比**：LobsterAI 的 `active_skill_ids` 有类似 UI；OpenClaw 有配置级 `skillFilter`（无 GUI）；CoPaw 支持运行时过滤（无 GUI）；Hermes、DeerFlow、jiuwenclaw 均无会话级技能作用域。

## 跨设备技能同步与隐私保护

Myrm 是唯一同时提供**双向技能同步**和**导出时 PII 自动脱敏**的 AI Agent 平台——没有任何竞品实现这两项能力。

**同步架构**（协议驱动，后端无关）：
- **Pull-first 策略**：先拉取远端变更再推送本地，避免意外覆盖
- **SHA-256 增量追踪**：仅传输变更的技能，无全量扫描开销
- **质量门控**：技能需满足最低阈值（如 ≥3 次执行、≥70% 成功率）才可共享
- **后台自动同步**：空闲时通过 IdleTask 系统自动执行，零打扰
- **即插即用**：支持 iCloud Drive、Dropbox 或任何 NAS 作为同步介质

**导出时 PII 自动脱敏** —— 10 类敏感信息检测并遮蔽：
- API 密钥（GitHub、Stripe、AWS、SendGrid、HuggingFace、Slack、Replicate 等）
- 环境变量、JSON 密钥字段、数据库连接串
- CLI 标志、URL 参数、Telegram Bot Token、HTTP Authorization 头
- PEM 私钥、绝对文件路径（智能排除系统路径）
- 结构化 Diff 预览，支持逐项查看和选择性恢复

**导入安全**：每个导入的技能均由 `SandboxValidator` 安全扫描后才激活——恶意代码无法进入工作区。

### 双视图审查体验

Myrm 技能成长看板支持两种视图模式，一键切换：

| 模式 | 展示内容 | 适用场景 |
|------|---------|---------|
| **简洁**（默认） | 自然语言摘要 + 信心指标（绿≥80%/黄50-79%/红<50%）+ 测试状态 + 大号审批按钮 | 非技术用户、批量快速分诊 |
| **详细** | 完整 ReactDiffViewer 代码对比 + Monaco 编辑器就地修订 + 轨迹分析 | 开发者代码级审查 |

简洁模式下，每张卡片保留「查看变更」链接，按需展开 diff——不展开则零性能开销。偏好设置通过 localStorage 持久化。

所有竞品均无 GUI 技能审核面板。OpenClaw 使用 CLI 命令（`openclaw skills workshop apply <id>`），其他竞品无技能进化系统或仅支持 CLI/文本审批。
