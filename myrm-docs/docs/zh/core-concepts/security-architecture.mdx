# 安全架构

Myrm 六层纵深防御，确保 Agent 在广泛自主权下仍安全运行。

## 安全层

| 层 | 功能 | 机制 |
|-------|----------|--------------|
| **L1** | 预算控制 | Token/WU 花费上限，3 级警告（35/45/48 轮） |
| **L2** | 权限 | 12 维工具与资源访问策略 |
| **L3** | 限流 | HTTP 签名检测 + 最小恢复时间 + SSE 事件节流 |
| **L4** | 循环检测 | 5 检测器（重复、乒乓、无进展、发散、输出递减） |
| **L5** | PII 保护 | 自动检测、脱敏、污点追踪 |
| **L5.5** | 轨迹分类 | 行为分析 + 盲轨迹分类器异常检测 |

## 审批模式

| 模式 | 说明 |
|------|-------------|
| **Auto** | 只读自动批准，写入需确认 |
| **YOLO** | 全部自动批准（可信环境） |
| **HITL** | 每步人工审批 |
| **Always-Allow** | 按工具永久批准，支持 4 级粒度（权限/工具/精确参数/命令模式）与 Agent 身份作用域隔离（防范混淆代理攻击） |
| **Domain-HITL** | 按域/资源分类审批 |

### 会话级安全预设

在输入框工具栏一键切换安全姿态，无需修改全局设置：

| 预设 | 行为 | 适用场景 |
|------|------|----------|
| **HITL**（默认） | 每个工具调用都需审批 | 敏感任务、生产环境 |
| **自动批准编辑** | 文件读写自动批准；Shell、浏览器、MCP 需审批并开启 AI 智能审查 | 编码、文档编辑、日常开发 |
| **只读模式** | 所有写操作被拒绝，读操作自动批准 | 代码审查、探索、调研 |

- 预设与 YOLO 模式**双向互斥** —— 选择非默认预设自动关闭 YOLO，反之亦然。
- "自动批准编辑"预设开启**轨迹分类器**（LLM 智能审查）审核 Shell 命令 —— 比一律放行更安全，可疑命令仍触发人工审批。
- "只读模式"精确拒绝 12 类写操作（文件写入/编辑/删除、Shell、代码解释器、浏览器自动化、技能/定时任务管理），同时保留读取和智能体委派。
- 仅在 Agent 模式下可见；快速搜索模式下选择器自动隐藏。

### 计划审核

在执行复杂任务前，Agent 可以先提出计划供用户审核。在设置 → 安全中开启**计划审核**后：

- Agent 首次创建计划时会在聊天界面弹出 **PlanConfirmationCard**
- 用户可以选择**确认**（按原计划执行）、**编辑**（修改计划后再执行）或**跳过**（让 Agent 自由执行）
- 同时支持深度研究和通用 Agent 两种工作流
- 与审批模式协同工作 —— 即使开启 YOLO 模式，仍可要求计划审核

这提供了 Agent 开始工作前的高层级检查点，与逐工具审批系统互补。

### 结构化澄清

Agent 可以使用 `ask_question_tool` 在执行操作前向用户提出结构化问题：

- 支持单选、多选和自由文本三种问题类型
- 前端通过专用的 **ClarificationInput** 表单渲染 —— 不是普通文本聊天
- 用户的回复作为结构化数据流回 Agent 循环
- 特别适用于模糊任务，Agent 需要用户输入才能正确执行

### 插件沙箱权限模型与能力推导（Plugin Sandbox Permission Model）

针对第三方 Agent Plugins 与 MCP 扩展生态，Myrm 构建了编译时静态推导与全生命周期知情授权防线：

1. **6 级细粒度沙箱权限模型 (`PluginCapabilityTier`)**：
   - `READ_ONLY`（只读探测）、`NETWORK`（网络外联）、`FS_READ`（文件读取）、`FS_WRITE`（文件写入）、`SHELL_EXEC`（系统命令执行）、`DESTRUCTIVE`（破坏性系统高危动作）。
2. **确定性静态推导引擎**：
   - 绝不盲目信任第三方插件在 `plugin.json` 中自行填写的权限声明；底层纯函数引擎毫秒级穿透 `mcp.json`，自动从 `stdio` 命令、执行脚本、运行时参数及网络端口中反推其真实的物理能力。
3. **声明 vs 实际 Diff 审查与特权提升告警**：
   - 当插件声明为“只读”但实际包含了拉起系统 Shell 进程的 `stdio` 服务时，系统自动捕获并在导入时生成 `capability_undeclared_privilege` 诊断，前端弹出醒目提权告警。
4. **导入前知情授权与持久化闭环**：
   - WebUI 导入对话框以彩色标签矩阵直观呈现每个服务的有效能力与综合风险等级；一旦确认导入，能力特征自动固化并落盘至服务元数据中，为后续运行调度提供强制性约束。


### 10 层渐进式审批架构

每个工具调用经过最多 10 层确定性和智能检查后才会呈现给用户：

| 层级 | 机制 | 作用 |
|------|------|------|
| L0 | **YOLO 全量自动** | 除 DENY 硬规则外全部自动批准 |
| L1 | **能力声明引擎** | 检查已声明的能力集，负向规则优先 |
| L2 | **命令风险分类器** | 按风险级别分类 Shell 命令（SAFE / UNKNOWN / DANGEROUS） |
| L3 | **URL 域名白名单** | 自动允许访问受信域名 |
| L4 | **路径策略** | 强制文件访问边界（仅工作区、禁止列表等） |
| L5 | **只读 MCP 快速通道** | 自动批准 `readOnlyHint=true` 且无破坏性/开放世界标志的 MCP 工具 |
| L6 | **白名单持久化** | 4 级匹配：权限 → 工具 → 精确参数哈希 → 命令 glob 模式 |
| L7 | **污点感知升级** | 当会话包含被污染数据（PII、凭证）时，将已 ALLOW 的工具升级为 ASK |
| L8 | **Cron 能力围栏预批** | 在定时任务中自动批准已声明的能力；无声明时 fail-closed |
| L9 | **Domain HITL 运行时** | 在同一会话中自动批准已审批过的域名 |
| L10 | **LLM 安全审核** | AI 分类器处理 ASK/污点/Shell 升级/出站检查场景 |

### 多平台审批交互

所有审批在 WebUI 与消息渠道提供统一的四种操作：

| 操作 | WebUI | Telegram/Slack/飞书 |
|------|-------|------------------|
| **批准**（单次） | 按钮 | `/approve`、`1`、`y`、👍 emoji |
| **编辑后批准** | 内联编辑器 + 自动安全校验 | 需在 WebUI 操作 |
| **拒绝**（带反馈） | 按钮 + 反馈输入框 | `/deny`、`2`、`n`、👎 emoji |
| **永久允许** | 按钮 → 确认弹窗（Shell 四级：权限 / 工具 / 精确 / **命令模式**） | `/approve-always`、`!y`、♾️ emoji |

**永久允许**提供四级粒度：
- **权限级**：允许该权限类型的所有工具（如：允许所有文件写入）
- **工具级**：允许该工具的所有调用（如：允许 bash_tool）
- **精确级**：仅允许该工具 + 相同参数的调用（Shell 默认，最安全）
- **模式级**（仅 Shell）：允许匹配推导 glob 的命令（如 `curl -sS *`）。复合 shell（`&&`、`|`、`;`）**永不保存**。所有模式规则在**设置 → 允许记录**中展示，可随时删除。

<Note>
**迁移收益**：部署脚本第一次选「始终允许（此命令模式）」后，后续同类命令自动放行，无需 YOLO。Claude Code / OpenClaw 多止于工具名白名单或 CLI 签名；Myrm 提供 GUI 管理、可撤销的模式规则，并有 Chrome LIVE E2E 签收（2026-07）。
</Note>

批量审批支持 `/batch a,d,aa`（批准、拒绝、永久允许）及 WebUI 批量按钮。

### 批量高危二次确认与 Safe-Only 安全分流

当多 Agent 协作或并发执行产生多个待审单据时，一键批量全放行可能引入误放行破坏性操作（如递归删除、格式化磁盘或删库）的严重风险。Myrm 构建了**端到端批处理风险守护体系**：

- **深度破坏性参数静态识别**：Harness `batch_risk.py` 与前端 `batchRisk.ts` 穿透解包 `payload.command`、`payload.args` 及工具调用深层参数，对 `rm -rf`、`mkfs`、`DROP TABLE/DATABASE` 等高危模式毫秒级静态拦截，严防模型借通用 `bash` 工具伪装绕过；
- **高危二次确认弹窗（BatchHighRiskConfirmDialog）**：当批量单据中包含高危指令、被智能否定（`smartDenied`）或禁止永久允许时，系统强制弹出警示对话框，清晰呈现风险原因与涉及单据列表；
- **Safe-Only 精准分流与 Pre-Resume 根治**：提供「仅放行安全操作」选项，安全读取项秒级放行并恢复 Agent 执行流，高危操作继续安全挂起等待单独审查；客户端严格过滤恢复单据 ID，彻底杜绝高危流被提前唤醒的逻辑泄漏；
- **服务端 HTTP 409 状态机防护**：全高危单据在 Safe-Only 模式下明确返回 409 Conflict（`NO_SAFE_ITEMS_TO_APPROVE`），防止空循环与假死。

### 社会性不可逆外溢动作硬防线（Social Irreversible Action Gate）

在真实团队开发与外部协作场景中，某些操作具有不可逆的外部社会性影响（如代码推送到远程主干、公共通道全员广播、发布公开包等），一旦误发将造成生产污染或事故。Myrm 建立了**社会性不可逆动作绝对防线**：

- **核心动作精准识别**：覆盖 `git push`（含 `-C /dir`、`--force`、`--no-pager` 及分段管道等复杂变体）、`npm/pnpm/yarn publish`、`twine upload`、`docker/podman push`、`gh release/pr` 与 `channel_notify`/`artifact_publish`；
- **强行拦截 Allowlist 绕过与 YOLO 逃逸**：此类操作永久剥夺「始终允许（Allow Always）」特权，即使用户之前为 `shell_exec` 授予了通用模式白名单，亦强制阻断并降级为单次人工审批；
- **前端高风险警示横幅**：审批卡片动态挂载琥珀色警示条，清晰提示「社会性不可逆操作：代码推送/发布将直接影响外部远程环境，请确认无误后批准」。

### 跨轮次会话级熔断防穿透（Session-scoped Denial State）

为了防止恶意 Prompt 注入通过跨轮切分、小步试探绕过安全策略，Myrm 打破了竞品将熔断计数局限在单次执行协程内的架构缺陷：

- **会话级违规计数追踪**：将连续拒绝（3 次）与累计拦截（20 次）状态提升至 Session 级注册表；单轮执行结束重置协程上下文时，不会抹去会话累积的拒绝计数；
- **智能模式挂起（AUTO_MODE_SUSPENDED）**：一旦触发连续 3 次或累计 20 次安全违规，自动挂起 Auto Mode，审批卡片顶部展示红色预警横幅；
- **用户显式决策自愈**：在用户人工介入显式批准后，连续计数立即清零，累计违规执行自愈衰减（每 3 次连续安全执行衰减 1 次），兼顾极致安全与流畅体验。

### 侧边栏注意力指示

当 Agent 暂停等待审批时，侧边栏会在对应会话旁显示实时琥珀色脉冲指示点 — 即使你正在查看其他会话也能一眼发现需要操作的对话：

- **琥珀色脉冲点**：Agent 正在等待你的审批/澄清
- **绿色脉冲点**：Agent 正在生成中
- **无指示点**：会话空闲

指示器在页面刷新后自动恢复（通过服务端审批恢复机制），并通过 SSE 多路复用在所有浏览器标签页之间实时同步。当你完成审批后，指示器立即消失，Agent 恢复执行。

### 审批超时竞态保护

当审批超时自动触发与用户手动审批几乎同时发生时，系统通过幂等 `resolve_if_first` 守卫确保**恰好执行一次**：

- **WebUI**：后端返回 HTTP 409 → 前端显示友好提示并自动移除过期审批卡片
- **IM 频道**：Agent 以本地化消息（中/英）告知用户该审批已被处理
- **并发安全**：仅首个决策者生效，后续尝试全部为 no-op

这杜绝了 Agent 双重执行、重复 LLM 消耗和矛盾操作——这是大多数竞品框架存在的安全缺口。

### 会话目录授权与透明内核拦截（本地与桌面）

当 Agent 需要访问**当前工作区之外**的文件夹（例如 `~/Downloads` 或你口头提到的项目目录）时，Myrm 采用**内核透明拦截（Kernel Transparent Interception）+ 前端主动预授权**，彻底摒弃了向 LLM 暴露冗余申请工具（如废弃的 `request_directory_tool`）的低效模式：

| 机制 | 发生什么 | 用户与架构收益 |
|------|----------|----------------|
| **透明内核拦截** | 当 Agent 尝试操作未授权路径或尝试向只读目录写入时，底核 PathPolicy 自动截获并返回 `ASK`，触发 HITL 动态提权审批卡片 | **Prompt Cache 零抖动**：工具定义静态冻结，LLM 无需学习申请目录工具；Prompt Cache 命中率提升；Action Space 干净纯粹 |
| **只读到写入平滑升级** | 当一个目录被授权为只读，Agent 尝试写入时系统自动触发「写入权限升级审批」 | 无需重启会话或重置目录白名单，平滑完成动态提权 |
| **用户主动预授权** | 用户可在 WebUI/桌面端随时通过文件选择器或拖拽一键添加授权目录（支持 RO 只读 / RW 读写） | 输入框上方实时展示授权目录 Chip，随时点击 × 撤销授权，误授权立即可逆 |
| **部署感知安全底线** | 绝对高危目录（`~/.ssh`, `~/.aws`, `/etc` 等）与特殊系统设备（`CON`, `NUL`, `\\.\*`, `/dev/*`）由 `SandboxMountSecurityGate` 严格 DENY 且不可被用户覆写；云沙箱模式强制沙箱隔离 | 桌面/本地端拥有极致灵活的动态提权体验，云端 fail-closed 物理隔离 |
| **沙箱挂载安全门禁** | 在进入 macOS Seatbelt、Linux Bwrap 或 Windows AppContainer 执行环境前，所有挂载通过 `mount_security_gate.py` 执行 10 重双向 fail-closed 严苛判定（源与目标路径穿越、Windows UNC/SMB 凭据防外泄、容器特权路径覆写防御 `/etc/ld.so.preload`、软链接逃逸、设备名注入、APFS/NTFS 大小写折叠、批量目标冲突自愈、只读最小特权） | 彻底斩断恶意仓库通过软链接诱导挂载、容器动态链接器劫持与 Windows NTLM Relay 的逃逸路径 |
| **云沙箱三级隐私阶梯** | 沙箱快照与文件每轮事件驱动持久化时，通过 `privacy_ladder.py` 执行三级 Fail-Closed 判定（Tier 1 文件凭据/系统特权阻断、Tier 2 会话只读态熔断、Tier 3 工作区边界穿透与大小写折叠归一） | 彻底封死机密泄漏与软链接穿透持久化，保障企业云沙箱数据绝对纯净 |
| **持久化写入损坏检测与密封** | 快照与状态持久化写入采用 `sealed_io.py` 三阶段原子密封写（Temp File -> Hardware fsync -> Atomic Replace）与 SHA-256 Checksum 完整性信封，非法篡改与断电截断数据自动进入 `.corrupted/` 隔离区 | 彻底杜绝断电损坏导致 Agent 启动崩溃，保障持久化状态 100% 具备工业级崩溃一致性 |

**竞品对比：** OpenWorker Cowork 仍在使用过时的 `request_directory` 占用 LLM Action Space 破坏 Prompt Cache；OpenClaw、Hermes、DeerFlow、LobsterAI、CoPaw、jiuwenclaw 的代码库中均无会话级目录 HITL。Myrm 率先实现内核透明拦截 + 动态提权 + 前端拖拽预授权 + Prompt Cache 保护。

### 审批纠错学习

当你编辑已审批动作的参数或拒绝工具调用时，系统自动学习你的偏好：

- **零 LLM 成本**：确定性 dict-diff 分类（无额外推理调用）
- **路径偏好**：对文件操作的拒绝或编辑 → 记忆为工作区约定
- **命令规则**：对 shell 命令的拒绝 → 写入程序性记忆作为永久规则
- **重复追踪**：相似模式的反复拒绝 → 自动拒绝（不再询问）

随着使用时间增长，审批弹窗会自然减少，Agent 逐渐与你的工作风格对齐。

## 认证与健康监控

实时监控凭证有效性和系统健康状态，自动告警：

| 能力 | 说明 |
|------|------|
| **认证检测器** | 识别 15+ 种认证失败模式（覆盖 OpenAI、Anthropic、Google 等主流 Provider） |
| **熔断保护** | 永久性认证失败时立即停止重试，避免无意义的 Token 消耗 |
| **探测策略** | 智能恢复探测（会话过期 60s / 永久认证 600s），自动检测 Key 何时恢复可用 |
| **暴力破解告警** | 后台监控异常认证模式（10+ 次/IP/小时），创建去重系统通知 |
| **健康历史** | 每 3 分钟记录系统健康分数到数据库，保留 7 天趋势 |
| **实时推送** | 健康状态变更和内存指标通过 ServerEventBus 专用通道实时推送前端（与聊天工具进度 SSE 分轨） |
| **部署感知** | Local 模式跳过网络审计（省资源），远程模式启用全量监控 |

## 会话标识白名单（防路径穿越）

用户可控的会话标识（`chat_id` / `session_id`）在被拼入文件系统路径时，绝不能逃逸事件日志目录。所有接受用户提供标识的 API 入口，都会在业务逻辑执行前通过共享白名单校验（`is_safe_session_id`，字符集 `[A-Za-z0-9:_-]`）**fail-fast**：

| 入口 | 校验 |
|------|------|
| OpenAI 兼容 `/v1/chat/completions` | 非法 `chat_id` → HTTP 400 |
| 语音 Realtime `/realtime-tool-exec` | 非法 `chat_id` → HTTP 400 |
| 语音 WebSocket `/voice/session`（`type: config`） | 非法 `chat_id` → 拒绝连接 |
| Web 对话 `/chats/{id}/turn` | DB 存在性校验 → 404（天然防护） |

非字符串输入（例如发送到无 Pydantic 强制转换的 WebSocket 路径的整数）同样被拒绝——校验器对任何非 `str` 值返回 `False` 而非抛出 `TypeError`。这使路径穿越（`..`、反斜杠、空字节）防护在 REST、WebSocket、Realtime 全部入口保持统一，不存在异常处理不一致。

## 提示词注入防御

### 内容边界（输出侧）

5 层防御包装外部内容与工具输出，**覆盖全工具链**（内置工具 + 第三方 MCP 工具 + PTC 内置工具）：

| 层 | 技术 | 拦截 |
|-------|-----------|-----------------|
| **1** | Unicode 折叠 | 隐形字符走私 |
| **2** | 结构框架剥离 | 仿系统标签的 XML/HTML |
| **3** | 标记消毒 | 已知边界/分隔符模式 |
| **4** | 随机边界 | 不可预测 `===BOUNDARY_xxx===` |
| **5** | 模式检测 | 角色/指令覆盖、系统模拟 |

第三方 MCP 工具返回的数据自动经过 5 层防护后才进入 LLM 上下文，恶意 MCP 服务器无法通过工具输出注入指令。

### Intake 危险意图前置路由器（Layer 0.5 模型前门禁）

在进入大模型推理及 ReAct 循环之前，用户输入通过零延迟（<0.15ms）前置安全路由器完成句级高危意图识别：

- **三维高危意图拦截**：覆盖 `MASS_DESTRUCTION`（`rm -rf /`、`DROP DATABASE`、`TRUNCATE TABLE`、磁盘格式化及删库跑路俚语）、`MASS_EXFILTRATION`（批量凭证/.env 外发）与 `PRIVILEGE_MUTATION`（越权关闭安全防御、绕过沙箱）；
- **双阶零误报漏斗**：自动剥离 Markdown 代码块内容，结合句法行动性/代码生成分析（识别“为什么/如何分析/写一个清理脚本”为良性分析与生成），保障正常开发问答 100% 放行；
- **多环境策略流转**：无人值守渠道（Cron/Webhook）自动执行 `fail_closed` 熔断拦截，桌面与 Web 交互会话触发 `hitl` 人工警示与确认。

### Prompt Guard（输入侧）

113 条模式、26 个威胁类别扫描用户消息、项目规则、技能文件；含反混淆与双语（如「忽略之前的指令」）检测。

### 记忆写路径扫描

输入侧防护保护的是对话，写路径扫描保护的是**持久化记忆**——它在每次记忆写入、落库**之前**确定性执行，即使上游注入已经成功骗过 Agent，恶意指令、密钥或伪系统标签也无法存入长期记忆：

- **指令形态检测** — 越权指令（guardrail-bypass）与非信任通道写入被拦截（双语攻击样式库）
- **凭据零落库** — API Key、密码、PIN/OTP 数字凭据原地消毒；显式排除年份与手机号误报
- **伪系统标签拦截** — `System:`/`Assistant:` 冒号前缀视为注入
- **写路径统一护栏** — 手动存储、批量写入、更新、画像、规则、MCP 工具、Agent 自动提取、导入恢复共用同一道
- **CI 投毒基准门禁** — 双阶段预期测试（检测层 + 提取层）在 CI 运行，防止攻击样式库退化

### 文件锁符号链接防御

即使上游内容护栏全部生效，被提示注入诱导的 Agent 仍可能在框架目录内放置一个**符号链接**指向敏感文件（如 `~/.env`、SSH 密钥）。后续任何以"创建/截断"语义打开该锁路径的代码都会**静默销毁**链接指向的文件——对框架级公共 API 而言是一条真实的数据破坏路径。

harness 的 `FileLock`（供投递队列使用）以 `O_NOFOLLOW` 打开锁文件（Windows 平台用 `hasattr` 守卫），被植入的符号链接会被**拒绝而非跟随**：

| 行为 | 结果 |
|------|------|
| 锁目录被植入 symlink → `acquire()` | 返回 `False`（未取到锁），**目标文件原封不动** |
| 锁文件权限 | `0o600` — 仅沙箱属主可读写 |
| 无 `O_NOFOLLOW` 平台（如 Windows） | 优雅降级为普通 `O_CREAT\|O_RDWR`，加锁仍正常工作 |
| 移除 symlink 后 | 资源立即重新可获取 — 拒绝永不污染锁路径 |

这是又一道纵深防御：即便提示注入攻击在文件系统层面得手，通过锁路径实现任意文件截断在结构上已不可能。

除符号链接防御外，harness `FileLock` 对整个加锁生命周期做了防误用与防静默失败加固：

| 守卫 | 行为 |
|------|------|
| **mode 白名单** | 仅接受 `exclusive` / `shared`；拼写错误如 `exclusiv` 立即 fail-fast，绝不静默降级为共享锁而破坏互斥 |
| **阻塞 fail-fast** | 同步 `blocking=True`（会冻结 asyncio 事件循环）直接抛 `TypeError`，而非挂起 |
| **锁键消毒** | 资源 ID 过滤到安全字符集、上限 128 字符并做 SHA-256 哈希——杜绝路径注入与隐藏文件 |
| **异常不吞没** | 持锁期间业务异常原样传播，不再被包装成误导性错误 |
| **崩溃自愈** | 锁基于 OS 级 `fcntl.flock`，进程退出内核立即释放——无需心跳/TTL/人工清理；投递去重保证消息 at-most-once，服务重启也不重复 |

跨进程互斥在 CI 中经 subprocess 测试验证（macOS），并叠加 asyncio 并发集成测试。

## 技能安装安全

从任何来源（GitHub、SkillHub、文件上传）安装技能时，每个技能必须通过**三层安全门禁**才能激活：

| 层级 | 机制 | 检测目标 |
|------|------|---------|
| **正则扫描** | 113 规则覆盖 26 类威胁 | Shell 注入、凭证窃取、数据外泄、混淆攻击载荷 |
| **AST 分析** | Python 抽象语法树结构分析 | 危险导入（`os.system`、`subprocess`）、隐藏函数调用、可疑代码模式 |
| **LLM 审计** | 语言模型语义威胁评估 | 社工攻击、多步外泄链、意图伪装的恶意逻辑 |

### 信任等级

技能被分配四个信任等级之一，决定其运行时能力范围：

| 等级 | 来源 | 能力 |
|------|------|------|
| **TRUSTED** | 内置/官方 | 完整工具访问 |
| **INSTALLED** | 用户安装，扫描通过 | 限定 `allowed_tools` 范围 |
| **UNTRUSTED** | 扫描标记警告 | 仅只读工具，无网络/文件系统 |
| **REJECTED** | 扫描发现严重问题 | 隔离，无法执行 |

`quarantine_aware` 装饰器在运行时自动过滤被隔离的技能——被隔离的技能从 Agent 可用工具列表中静默消失，不会产生错误。

### 运行时权限边界

技能安装通过后，运行期敏感操作仍受**技能权限门禁**（`SkillBoundaryProvider`）约束：写文件、执行命令、联网、读环境变量等敏感权限类型必须已被授权，否则工具调用在引擎层直接拒绝（`skill_boundary.violation`，fail-loud，绝不静默降级）。

- **单点权威**：工具名 → 权限类型由工具注册表 `resolve_permission_type` 统一解析（SSOT），避免映射漂移导致「以为拦截、实则放行」。
- **授权一次自动执行**：已授权权限自动放行，无人值守任务不被逐次弹窗打断；撤销（revoke）通过缓存失效回调秒级生效，无需重启。
- **粒度分离**：沙箱代码执行（`code_interpreter`）与原生 shell（`shell_exec`）独立授权，互不越权。
- **全程审计**：每次权限判定（授权/拒绝 + 目标）写入权限使用日志，可追溯。
- **使用统计面板**：审计日志聚合为可视化统计——按权限类型聚合总次数 / 放行 / 拒绝次数、精确的拒绝原因、最近 10 条操作明细，支持 1/7/30/90 天窗口筛选；异常行为（如技能反复探测环境变量全被拒）一眼可见，而不是埋在原始日志里。
- **验证**：技能边界 100% 单元覆盖 + 真实 DB 全链路集成验证（授权 → 门禁 → 执行 → 撤销 → 即时拒绝）。

### 可信来源与沙箱边界诚实披露门禁（Trusted Source & Honest Sandbox Disclosure）

在安装外部第三方扩展或技能插件包时，进程内半截 JS 沙箱防不住大模型执行 bash 窃密。Myrm 在 WebUI 技能 URL 导入（`SkillUrlImportDialog`）与插件包导入（`PluginImportDialog`）全链路建立**诚实权限披露与强制可信勾选守卫**：

- **拔除单 URL 静默自动安装后门**：彻底消除输入单个合规 URL 即直接绕过用户确认静默执行安装的供应链钓鱼后门；
- **环境自适应诚实告知（Honest copy）**：智能感知当前部署模式——本地/桌面端（Local/Tauri）诚实展示 `Local OS Permissions`，明确告知技能具备当前操作系统的用户权限；云托管端（Cloud）展示 `Cloud Sandbox` 徽标，解释独立容器 Volume 的隔离边界；
- **提示注入与脚本攻击风险示例**：客观警示不可信扩展可能通过间接 Prompt 注入诱导 Agent 执行越权命令读取私钥；
- **可信复选框物理门禁（Trusted Source Checkbox）**：新增 `trusted-source-checkbox`，默认未勾选；未显式勾选前，【确认安装】按钮保持物理禁用，彻底堵塞供应链盲目信任漏洞。

### GUI 安全审查

三处前端组件协同展示安全扫描结果，每个发现都包含**精确行号定位**（如 `L42 Command injection: recursive delete`），帮助开发者快速跳转到问题代码：

| 组件 | 触发场景 | 展示内容 |
|------|---------|---------|
| **ScanConfirmDialog** | 从 SkillHub 搜索安装时 | 扫描发现列表 + 严重程度徽章 + 行号 + 确认/取消 |
| **Blocked Dialog** | 启用含 CRITICAL 发现的技能时 | 阻止原因 + 发现详情 + 行号 + "Force Enable" 选项 |
| **SecurityScanSection** | 技能详情页 | 按严重程度分组的完整发现列表 + 行号 + 安全评分（0-100） |

安全评分采用百分制，从 100 分起扣：CRITICAL 扣 25、HIGH 扣 15、MEDIUM 扣 8、LOW 扣 3。同时生成 `trust_recommendation`（trusted/installed/untrusted/reject）指导信任决策。

### Stdio 进程环境变量注入防御与全生命周期子进程凭证隔离门禁

对于 Stdio 类型的 MCP 服务器及所有派生执行的子进程（Bash Shell、Python 解释器、后台守护进程、CUA 驱动），Myrm 构建了静态配置拦截与运行时动态清洗的双层纵深防御体系：
- **静态预检阻断**：在解析配置时若包含 `LD_PRELOAD`、`DYLD_INSERT_LIBRARIES`、`NODE_OPTIONS`、`PYTHONPATH`、`HTTP_PROXY`、`GIT_SSH_COMMAND` 等 50+ 种危险变量，直接标记 `CRITICAL` 严重级别阻断安装。
- **运行时自动剥离与子进程凭证隔离（ChildProcessCredentialTokenIsolation）**：
  - 在子进程启动前（`env_isolation.py:build_isolated_child_env`）自动执行严格的环境清洗；
  - 核心凭据全面绝缘：`NOISE_AUTH_TOKEN`、`CODEX_EXEC_SERVER_NOISE_AUTH_TOKEN`、`AUTH_TOKEN`、`ACCESS_TOKEN`、`BEARER_TOKEN`、`DATABASE_URL`、`MYRM_VAULT_MASTER_KEY` 等全量敏感密钥在下发给任何第三方脚本前物理剥离；
  - 8 维词根通配符拦截：精确过滤 `KEY`、`SECRET`、`TOKEN`、`PASSWORD`、`CREDENTIAL`、`AUTH_`、`_AUTH`、`AUTHORIZATION`、`AUTHENTICATION`、`BEARER`、`SIGNATURE`，彻底杜绝任何脚本偷窥宿主环境凭证；
  - 零误杀设计：采用词形区分算法，安全放行 `GIT_AUTHOR_NAME`、`GIT_AUTHOR_EMAIL` 等合法 Git 提交者身份，确保开发者工作流顺畅；
  - 三档继承策略（`CORE` 严格白名单 / `ALL` 清洗模式 / `NONE` 零环境变量），三部署同构适配。
- **零 Prompt Cache 损耗**：纯框架底座运行时计算，0 Token 消耗，0 性能抖动。


### 基础安全

工具名 `mcp__{server}__{tool}` 隔离；OSV 恶意包检测；按 Agent 工具过滤；`destructiveHint` 默认禁用。

### 内置工具治理门禁

每个内置工具在发布前必须携带显式治理声明——不存在隐式默认。Harness 通过**注册级 CI 门禁**强制这一约束：门禁遍历真实注册的工具全集（core/common/extended 层 + server 供应商工具），而非人工维护的名单：

- **零静默绕过** — 新增内置工具若没有权限映射、没有动态解析声明、没有自动放行声明、也没有显式 `mcp_invoke` 兜底，构建直接失败，绝不可能悄悄退化为模糊的运行时默认
- **显式三态模型** — 每个工具要么显式自动放行（只读类）、要么显式映射到权限类型（受规则集治理）、要么显式声明为保留"默认询问"基线的 `mcp_invoke` 兜底（高危工具如 `browser_execute_script_tool` / `send_teammate_message_tool`）
- **双向一致性** — 声明双向交叉校验：`BUILTIN_TOOL_NAMES` 必须是注册全集的子集（失去锚点的声明会失败）；权限类型白名单条目不得 stale（已被 `DEFAULT_RULESET` 覆盖）或 orphan（无任何工具映射）——审计报表永远不会与代码自相矛盾
- **动态解析 SSOT** — 按 action 动态解析权限类型的工具（浏览器交互、桌面控制）从单一事实源声明动态分支，门禁只消费该源而非复制名单
- **模块加载安全门禁** — 每个内置工具必须声明安全元数据（只读/破坏性/并发安全），缺失在导入时即被标记，而非生产环境才发现

结果：新增任何能力都不可能静默削弱治理；CI 输出的覆盖矩阵是一份真实、机器可读的审计——每个工具被允许做什么一目了然。

### 动态工具变更安全

当 MCP 服务器在运行时添加或移除工具（通过 `tools/list_changed` 通知）时，Myrm 在不打断工作流的前提下确保安全：

- **自动安全审查** — 新增工具会经过与配置时相同的 13 类威胁扫描，不通过则拒绝并记录警告，不安全的工具绝不会被静默激活
- **提示词缓存保护** — Agent 面向的工具列表保持冻结状态，动态变更仅更新内部执行层，确保提示词前缀缓存命中率不受外部 MCP 服务器行为影响
- **零用户打断** — 与需要手动 `/reload` 确认的 CLI 竞品不同，Myrm 透明处理工具变更，用户不会被无法有效评估的确认对话框打断

### SSRF 防护

- **统一出站 HTTP 层**：web_fetch、HTTP 工具、OpenAPI 执行器、技能 ZIP 安装、媒体解析、robots/sitemap、渠道媒体下载、飞书附件等全部收敛到 `secure_fetch` / `async_pin_url`，消除历史裸 httpx 盲区
- **手动重定向循环**：`follow_redirects=False`，逐跳重新验证目标地址，消除 DNS 重绑定 TOCTOU 攻击
- **DNS Pinning**：解析后的 IP 直接替换域名，绕过 DNS TTL 刷新窗口
- **全面 IP 黑名单**：RFC1918 私网、CGNAT、链路本地、多播、云元数据端点（AWS/GCP/阿里云/腾讯云）+ IPv4-mapped IPv6 检测
- **数据外泄检测**：6 类模式（API 密钥、文件路径、base64、JWT、密钥模式、数据库连接串）防止敏感数据通过 URL 参数泄漏
- **Domain HITL 审批**：非白名单域名自动触发人工审批（`domainHitlEnabled`），每个 Agent 可独立配置网络域名白名单
- **URL 解析混淆防护**：阻断 Tab/换行/反斜杠等混淆字符，防止 urlparse 与 HTTP 客户端的解析歧义（CVE 级 SSRF 绕过防御）
- **内网后缀阻断**：`.local`、`.svc`、`.cluster.local`、`.home.arpa` 等后缀默认拦截，防止 mDNS 和 Kubernetes 内网访问
- **审计链**：拦截请求写入 `SSRF_BLOCKED` 安全决策，可在审计面板追溯
- **Agent API 范围**：`/v1/chat/completions` 仅运行 Myrm 智能体（无 LLM 直通）。用户配置的 Provider apiUrl 在智能体内 LLM 调用路径仍执行 SSRF 检查，deploy 模式感知——本地模式允许 localhost/127.0.0.1 等 loopback（Ollama/vLLM），云/沙箱模式阻断私网和云元数据端点
- **461+ 项专项测试**：覆盖核心守卫、Agent 安全、浏览器导航、DNS Pinning、媒体验证、A2A 解析、深度爬取、SessionVault、权限引擎和 Provider URL 校验

### 恶意 URL 架构级免疫

面对钓鱼/诈骗网站，Myrm 不依赖静态域名黑名单（如 2.5M 钓鱼域名库），而是通过架构级机制从根本上消除威胁：

- **SessionVault 域名绑定**：凭证（cookie/密码）严格按域名隔离，`bank.com` 的登录态不会被发送到 `bank-secure-login.xyz` 等钓鱼域名，从机制上杜绝凭证窃取
- **浏览器沙箱隔离**：Agent 在独立沙箱中运行浏览器，即使访问恶意网站也不影响用户主系统
- **四层深度域名过滤**：CSP 策略（浏览器内核级网络限制）+ 协议拦截（context.route 阻断非白名单域名）+ 主线程加固（WebRTC/WebTransport/ServiceWorker 阻断）+ CDP 审计监控

这一架构使得维护庞大的钓鱼域名库变得不必要——域名库每天有数千个新域名产生，静态列表迅速过时，且占用 50-100MB 内存。

## 操作级语义风险检测

### Smart Intent Guard

AI 分类器（`TranscriptClassifier`）审查工具调用是否符合用户原始意图：

- **推理盲**：仅看用户消息+工具调用序列，不看 Agent 推理过程，防止自我合理化
- **确定性**：`temperature=0` 确保同一输入永远得到同一结论

- **失败安全**：错误或歧义回退到 HITL 而非自动放行

## Shell 命令安全

5 层引号感知流水线：

| 层 | 检测 | 响应 |
|-------|-----------|----------|
| **L1** | 二进制字符、12 类不可见 Unicode（零宽、方向覆盖等） | BLOCK |
| **L1.5** | ANSI-C 引号 `$'...'`、区域引号 `$"..."` | BLOCK |
| **L2** | 6 种注入向量（`$()`、反引号、`${}`、`;`、进程替换）+ 70+ 危险命令模式 | BLOCK → DENY |
| **L2.5** | SQL 语法级守卫：检测 DB 客户端命令中的破坏性 SQL（`psql`、`mysql`、`sqlite3` 等），防御多语句注入和 WITH CTE 绕过 | ESCALATE → ASK |
| **L3** | 可疑模式（`curl\|sh`、`eval`、`base64 -d`、kill/pkill） | ESCALATE → ASK |
| **L4** | 递归分析嵌套命令：`bash -c '...'`、`sh -lc '...'`、`zsh -c '...'`、`trap '...'` 中的内层命令——深度限制防 DoS | 递归 BLOCK/ESCALATE |

**引号感知预处理**：字符级状态机 `_strip_quoted_content` 在 L2/L3 扫描前将单引号内容替换为占位符，避免 `echo 'rm -rf /'` 误报，同时保留双引号中命令替换的检测能力。

**特权提升无条件地板**：所有 `sudo` 命令在 L2 层被无条件 BLOCK——包括 `sudo apt install`、`sudo -S`（stdin 管道密码注入）、`env sudo cmd`、以及 `bash -c 'sudo ...'`（由 L4 递归捕获）。此规则不可被 YOLO 模式、Smart Guard 或用户审批绕过。竞品 Hermes 仅阻断 `sudo -S`（密码猜测向量），仍允许配合 SUDO_PASSWORD 的常规 sudo——攻击面更大。其他 6 家竞品无任何 sudo 防护。

**破坏性命令自动快照**：匹配破坏性模式的命令（`rm`、`mv`、`git reset/clean/checkout/restore/apply` 含任意前置 flag、`sed -i`、重定向覆盖）会在执行前自动触发工作区快照，确保无论结果如何均可完整恢复。

**SQL 守卫（L2.5）**：分析*原始命令*（引号去除前）以检测嵌入在数据库客户端命令中的破坏性 SQL 操作（`DROP`、`DELETE`、`TRUNCATE`、`ALTER`、`INSERT`、`UPDATE`、`CREATE`）。防御两种高级绕过向量：多语句注入（`SELECT 1; DROP TABLE`）和 WITH CTE 包裹（`WITH x AS (...) DELETE FROM`）。支持 flag 模式（`psql -c '...'`）和管道模式（`echo '...' | psql`）。竞品无此能力。

**安全执行路径**：无 Shell 元字符的简单命令通过 `create_subprocess_exec` 直接执行（不经 shell 解释器），从结构上消除 `$IFS`、通配符展开、命令替换等注入类型。

### AI 轨迹分类器（Layer 5.5）

静态分析返回 ASK（不确定）时，AI 分类器提供语义级判断：

- **推理盲设计**：仅看到用户消息和工具调用序列，永远不接触助手推理或工具输出，防止 Agent 通过合理化推理欺骗分类器
- **结构化输出**：Pydantic Schema 强制 JSON 格式（非自由文本），缩小注入面
- **确定性**：`temperature=0`、`max_tokens=200`，确保可复现
- **失败安全**：任何错误、超时或解析失败均返回 UNCERTAIN → 回退到人工审批
- **上下文感知**：接收污点标签（EXTERNAL_NETWORK、SECRET）和可信域名列表，支持细粒度判断

### Smart DENY → 用户一次性覆写

当智能审查器判定 DENY 时，**不会**静默拒绝，而是弹出审批卡片让用户决定：

| 行为 | 说明 |
|------|------|
| **视觉指示** | 琥珀色警告框，显示审查器的拒绝理由 |
| **可用操作** | 仅"覆写一次"和"拒绝"（隐藏 session/always/edit） |
| **覆写行为** | 本次执行，但不写入 allowlist——下次相同命令仍触发审查 |
| **审计追踪** | 记录 `LLM_REVIEW_DENY_USER_OVERRIDE` 事件及理由 |
| **无人值守** | Cron 和 Shadow Agent 直接拒绝，无覆写选项（fail-closed） |
| **高风险路径** | 污点升级、出站委托、Shell 升级始终硬拒绝——不可覆写（安全红线） |

防止"误判锁死"——AI 审查器误分类合法操作时用户不会被困住，同时保持完整审计可追溯。

**vs 竞品**：Hermes 仅提供 CLI 的 `once`/`deny` 按钮，无可视化理由展示，无审计日志，无分层硬拒绝。

### 高风险场景隐藏「始终允许」

在 6 种高风险场景下，审批卡片自动隐藏「始终允许」按钮——用户只能逐次审批或拒绝，防止误操作永久放行危险命令：

|---------|---------|

| **Shell 升级不确定** | 非安全 Shell 命令在 AI 审查下存在不确定性 |
| **LLM 审查不确定** | AI 审查器对任意工具调用的通用不确定判定 |
| **自动模式暂停** | 连续拒绝次数超阈值——系统回退到人工审批 |
| **Shell 威胁检测** | 命令分析器标记了威胁模式 |

普通低风险审批仍正常显示「始终允许」。用户对安全操作的体验零影响。

**vs 竞品**：Hermes 仅在 `tirith` 内容安全告警时隐藏永久允许（1 个触发点）。OpenClaw 通过后端 `allowedDecisions` 控制并显示"始终允许不可用"警告文案。Myrm 覆盖 6 种触发场景——行业最全面。

### Install Slopcheck（防包名幻觉 / Anti-Slopsquatting）

每次 `pip install` / `npm install` / `yarn add` / `bun add` 执行前，预检链自动验证所有包名是否真实存在：

| 方面 | 细节 |
|------|------|
| **检测方式** | HEAD 探活 PyPI JSON API (`/pypi/{name}/json`) 和 npm registry (`/{name}`) |
| **名称标准化** | PEP 503 规则（下划线、点、大小写 → 统一小写连字符） |
| **并发** | 所有包名通过 `asyncio.gather()` 并发探活 |
| **缓存** | 会话内内存缓存已验证包名，零重复网络请求 |
| **私有仓库** | 含 `--index-url`、`--extra-index-url`、`--registry` 的命令自动跳过 |
| **容错** | 网络超时或 DNS 异常 → 放行安装（不阻断正常工作） |
| **响应** | 未知包 → `ToolError` 阻断安装并说明哪些包未找到 |

此机制防范 **slopsquatting 攻击**——攻击者注册 LLM 常见幻觉包名并植入恶意代码。

### 企业 TLS 兼容

企业网络常部署 TLS 检查代理（Zscaler、Netskope、Palo Alto Prisma 等），可能导致 Agent 的所有 HTTPS 出口连接失败。Myrm 提供一键企业网络兼容：

- **设置 → 高级 → Enterprise Network Compatibility** 开启，或设置环境变量 `MYRM_TLS_STRICT=0`
- 精确放松 Python 3.13+ 的 `VERIFY_X509_STRICT` 标志，不禁用证书验证
- 支持自定义 CA 证书：`SSL_CERT_FILE`（替换系统信任库）或 `NODE_EXTRA_CA_CERTS`（追加到系统信任库）
- **MCP 服务器级 TLS**：每个 MCP server 可独立配置 `ssl_verify`（true/false/自定义CA路径）和 `client_cert`/`client_key`/`client_key_password` 实现完整 mTLS 双向认证
- 4 层自动注入：infra (`tls_compat.py`) → server (`tls_config.py`) → MCP (`client.py`) → LLM (`llm.py`)，覆盖 28+ 个 HTTP 客户端调用点
- TLS 连接失败时自动诊断：8 种错误模式检测 + 5 语言修复提示
- **144 项 TLS 专项测试验证**（38 项 TLS 核心 + 31 项 MCP TLS + 75 项错误诊断）

### 无痕模式深度解析

消息输入区一键 Toggle 激活 per-session 隐私隔离：

- **Harness 层**：`IncognitoPolicy` 物理跳过 MEMORY 和 ARCHIVE 上下文场景的所有写入
- **Server 层**：不绑定 memory manager，不挂载全部记忆工具（`memory_search_tool`、`memory_save`、`memory_manage`），不注入记忆上下文，禁用归档检查点与会话清理回调
- **数据库层**：`is_incognito` 标记确保无痕会话不在侧边栏显示、不可被全文搜索命中
- **Self-hosted 架构优势**：竞品（如 SaaS 产品）需要额外的"本地模式"开关来防止数据上传至厂商服务器；Myrm 的 self-hosted 架构意味着用户数据天然不离开本机——无痕模式在此基础上叠加了会话级的非持久化保护

## 凭证保护

### 表单凭证库

密码与 TOTP **永不进 LLM 上下文**。在 **设置 → 凭证** 配置带标签凭证；Agent 只见标签名（如 `github-personal`），调用统一的 `fill_credential`（浏览器与桌面相同动作）；Harness 在 DOM/OS 层注入，明文不回流对话或工具日志。Server 侧 AES-256-GCM 加密存储，启动时同步到 Harness 内存金库。

| 模式 | 动作 | 场景 |
|------|------|------|
| **WARN** | 仅记录检测结果 | 纯监控环境 |
| **REDACT** | 类型感知不可逆脱敏（如 `138****5678`） | S2 数据生产默认 |
| **PSEUDONYMIZE** | SQLite 持久化可逆假名替换 + 流式 chunk 边界安全还原 | AI 需要上下文但用户看到原文 |
| **BLOCK** | 完全阻断消息 | S3 级机密数据 |

**隐私感知模型路由**：根据敏感度自动路由 — S1 发云端，S2 脱敏后发云端或本地处理，S3 纯本地（数据永不离机）。可配置回退策略：阻断或强制脱敏后发云端。

**GUI 完整配置**：设置面板提供隐私开关、逐级动作选择、深层扫描开关、本地模型连接测试、自定义关键词/正则/敏感工具标记、实时测试匹配。

### 隐私安全规则分享

分享程序性记忆规则（如与队友或社区）时，自动应用额外的隐私保护：

- **路径匿名化** — 用户目录路径自动替换为 `<USER>` 占位符
- **凭证脱敏** — API Key 和密钥截断为安全前缀（如 `sk-pro...f456`）
- **元数据剥离** — 时间戳、更新计数、内部 ID 从导出规则中移除

确保分享的规则中不会泄露个人文件路径或凭证。完整说明参见[记忆系统 → 隐私安全规则分享](/zh/core-concepts/memory-system#隐私安全规则分享)。

### 密码保护分享

工件和对话分享链接支持**可选密码保护**，采用无状态、零数据库设计：

| 功能 | 实现方式 |
|------|---------|
| **密码门** | 密码 SHA-256 哈希参与 HMAC 签名密钥派生——密码错误 = 签名无效，无需数据库查询 |
| **可选有效期** | 创建链接时可选 1、7、14、30 天 TTL（服务端自动 clamp 上下限） |
| **限流防护** | 公共端点限流 30 次/分钟（内容）和 60 次/分钟（静态资源），防暴力破解 |
| **暗色适配密码页** | 自包含 HTML 页面，支持暗色/亮色模式、错误提示反馈，无外部依赖 |
| **Salt 隔离** | 工件和对话分享使用不同 HMAC salt——同一密码也会产生不同的签名密钥 |

密码保护完全可选。不设置密码时行为与普通分享完全一致，无额外性能开销。

#### 随时撤销、即时生效、永不复活

工件与对话分享链接**支持随时主动撤销**：

| 能力 | 行为 |
|------|------|
| **一键撤销** | 撤销后链接**立即**返回 404「Link Revoked」——无宽限期、缓存不可绕过 |
| **已撤销密码链接** | 生命周期校验（撤销/删除）**前置干密码门**——已撤销密码链接对新访客直接显示失效页，绝不弹出密码框 |
| **撤销后缓存不可绕过** | 所有公开分享响应统一携带 `X-Robots-Tag: noindex, nofollow` + `Cache-Control: no-store` + `Referrer-Policy: no-referrer`（chat/artifact 双端共享 `share_headers`） |
| **撤销过的 token 永不复活** | 持久化 `share_token_fingerprint`（活跃）+ `share_revoked_fingerprints`（已撤销集合）；公开入口先查已撤销集合——撤销后重新分享永远签发全新 token，旧链接永久 404 |
| **状态始终诚实** | `GET /chats/{id}/share` 返回四态：`unshared` / `revoked` / `active` / `password_protected`；已过期链接（无论是否密码保护）一律返回 `unshared`，不误报生效中 |
| **撤销审计日志** | 每次撤销操作均记入审计日志，随时可追溯访问撤回轨迹 |
| **删除会话级联失效** | 删除源会话立即令其分享失效（404「Content Unavailable」） |

WebUI 分享对话框每次打开都展示实时状态（链接地址、剩余有效期、撤销按钮），与 ChatGPT/Notion 分享对话框基线一致；撤销后对话框保持打开显示「已撤回」状态，控制入口永不失联。

<Note>
所有竞品（Hermes、OpenClaw、LobsterAI、CoPaw、deer-flow、jiuwenclaw）均无工件或对话分享功能，更无密码保护与撤销。Myrm 是唯一同时具备双通道分享、密码门和完整撤销生命周期的 AI 助手产品。即便是主流产品（ChatGPT Shared Links、Claude Shared Chats）也缺少 TTL 自动过期、密码保护与防搜索引擎收录——Myrm 在与其共享「撤销即时失效」基线之上，额外补齐了这三项能力。
</Note>

### Agent 密钥管理——零明文暴露架构

每个 Agent 的自定义密钥（API Key / Token / 环境变量）采用**零明文暴露架构**：

| 安全特性 | 实现方式 |
|----------|----------|
| **前端永不接收密钥值** | `listAgentSecrets` API 仅返回 key 名列表（`string[]`），绝不返回值 |
| **无 reveal 端点** | 竞品需要"显示明文"端点，Myrm 没有这个路径 |
| **编辑必须输入新值** | 密码输入框，占位符"输入新值以覆盖" |
| **无需 sentinel 防护** | 旧值从未到达前端，不存在 "****" 回传覆盖风险 |
| **静态加密** | AES-256-GCM + 服务端主密钥 |
| **原子文件写入** | tempfile + `os.replace` + `fsync` 防崩溃 |
| **日志自动脱敏** | `SensitiveDataFilter` 自动替换 token/key/secret 为 `***REDACTED***` |
| **Agent 隔离** | 每个 Agent 只能通过 `agent_id` 访问自己的密钥 |

<Note>
竞品（如 Multica）向前端返回明文环境变量，必须依赖 sentinel 值（"****"）防止意外覆盖。Myrm 从架构上消除了这个攻击面。
</Note>

## 智能审批（Auto Mode）

智能意图守护**默认对所有新用户开启**。辅助 LLM（Transcript Classifier）实时审查工具调用，实现长时间无人值守 Agent 会话。如果未配置专用审查模型，Myrm 会自动使用用户的默认模型作为 fallback——无需额外设置即可享受智能审批：

| 层级 | 机制 | 触发时机 |
|------|------|---------|
| **确定性规则** | 静态权限引擎评估 | 始终（第一层） |
| **CommandRiskLevel** | Shell 管道感知分级：SAFE 自动放行 / UNKNOWN 需审查 | Auto Mode + shell_exec |
| **Allowlist 记忆** | 「始终允许」选择永久免打扰 | 曾被用户批准的 ASK 操作 |
| **Taint 升级** | 会话含 PII/凭据 → 即使 ALLOW 也送 LLM 审查 | ALLOW + 受污染会话 |
| **Transcript Classifier** | 推理盲 LLM → ALLOW/DENY/UNCERTAIN | Auto Mode + ASK 操作 |
| **Outbound 委派检查** | invoke_external_agent 强制 LLM 审查 | 外部 CLI 委派 |
| **Shell 升级检查** | 非 SAFE 命令即使规则 ALLOW 仍送 LLM | shell_exec + UNKNOWN 风险 |
| **阈值熔断** | 连续拒绝 → 停止自动审批，回落 HITL | 过多拒绝 |

故障安全保证：分类器报错 → 回落 HITL（绝不在失败时自动批准），`temperature=0` 确保确定性，Pydantic 强制结构化输出。

## 命令黑名单（用户自定义安全地板）

用户可以定义 glob 模式永久拦截特定命令 — 无论 YOLO 模式、智能意图守护决策还是权限规则，均不可绕过。这是用户可控的最终安全防线。

| 特性 | 工作原理 |
|------|---------|
| **Glob 模式匹配** | 大小写不敏感的 `fnmatch` 匹配（如 `git push --force*`、`rm -rf /*`、`DROP TABLE*`） |
| **全局 + Per-Agent** | 在安全设置中配置全局黑名单，在 Agent 配置中设置独立黑名单 |
| **并集合并** | Per-Agent 黑名单与全局黑名单取并集合并 — Agent 只能增加限制，不能移除全局规则 |
| **YOLO 不可绕过** | 被拒绝的命令即使在 YOLO 模式下也会被阻断 — 这是所有审批层之下的硬地板 |
| **GUI 可视化编辑器** | 可视化模式编辑器，支持添加/移除、示例占位符和验证 — 无需 CLI 或 YAML 编辑 |

命令黑名单在审批管道的 **Layer 2a.5** 位置运行 — 在权限规则之后、YOLO 绕过之前，确保被拒绝的命令始终被阻断。

## 记忆写入信任隔离

所有记忆写入都经过统一安全管道 — 即使是 AI 内部触发的也不例外：

| 防护层 | 防止什么 |
|--------|---------|
| **审批队列** | Cognitive Deriver 提取的隐式偏好走标准审批队列（无绕过），外部内容无法静默污染用户 Profile |
| **安全扫描** | 每次记忆写入均执行 `scan_and_clean_memory` 注入检测（CLEAN/WARN/REDACTED/BLOCKED） |
| **偏好稳定性** | 多轮观测生命周期验证（Candidate → Provisional → Active），确保只有经过验证的偏好才能进入 Profile — 过滤单次对话的偶然性 |
| **AGENT_SELF 优先级上限** | Agent 自生成的程序性规则优先级上限为 HIGH — 无法占据 CRITICAL（免压缩）位，防止提示词膨胀 |
| **Profile 安全晋升** | 核心偏好（沟通风格/认知深度/主动性）仅在稳定性验证通过后，经 `set_system_profile_attribute` 安全写入 Profile |

没有竞品实现记忆写入信任隔离 — 大多数 Agent 将提取的偏好直接写入用户画像，无审批、无验证、无优先级护栏。

MyRM 提供三种内置安全配置档位，用户可在设置页一键切换：

## 定时任务执行策略（按任务最小权限）

定时 Agent 任务在绑定智能体之外，还支持**双层执行策略**：

| 层级 | 控制内容 | 用户收益 |
|------|---------|---------|
| **能力围栏**（`required_capabilities`） | PermissionEngine 拦截 Shell/写文件/MCP/代码等 | 即使智能体配置很宽，单个任务仍可禁止危险操作 |
| **工具范围**（`tools_allowed`） | 收窄 Turn1 挂载的内置工具（运行时与智能体配置求交） | 更小 schema、利于 prompt cache、无人值守最小权限 |

**编辑入口：** 设置 → 定时任务 → 打开任务 → 运行历史中的**执行策略**编辑器（与「允许的路径」同一产品模式）。新建任务默认不限制。

**内置保护：**
- **默认 fail-closed** — 未显式声明能力的任务自动拒绝危险操作（Shell、代码执行、MCP），并在 UI 显示警告引导用户配置能力围栏或在智能体安全设置中启用 YOLO 模式。
- **预设组合**（仅联网 / 研究 / 运维）一键双写能力围栏 + 工具范围，与蓝图 SSOT 对齐。
- **稍后读蓝图** 使用 **router 模式**（`__wiki_source_sync__`），**无工具挂载** — 服务端确定性 pull，零 LLM agent turn，不会误开浏览器或代码执行。
- **生命周期守卫** 拒绝 prompt/命令/**预检脚本**中的 `./myrm restart/stop`、`pkill myrm-agent` 等 — 防止定时任务把服务打挂。
- **受限任务不偷偷继承基线工具** — 仅 file_ops 的任务不会自动启用 `code_execute`；未限制任务仍继承智能体基线。

**对比竞品：** Hermes 仅提供全局 `cron_mode: deny/approve` 布尔开关——所有任务共享同一策略。OpenClaw/LobsterAI/CoPaw/deer-flow/jiuwenclaw 无定时任务功能。Myrm 提供按任务粒度的能力声明 + GUI 编辑 + 蓝图自动填充 + fail-closed 默认策略。

## 子代理递归隔离：5 层防护

当 Agent 将任务委派给子代理时，最常见的失控场景是子代理无限递归衍生，耗尽 Token 预算。

MyRM 实施 5 层隔离防护：

| 层级 | 机制 |
|------|------|
| **L0** | 类型准入白名单（仅目录注册的 Agent 类型） |
| **L1** | 全局黑名单（LEAF 角色下 7 种编排工具 + 2 种特权工具被剥离） |
| **L2** | 配置级黑名单 + readonly 模式额外拦截 |
| **L3** | 子⊆父工具交集（子代理的工具永远不会多于父代理） |
| **L4** | 双重深度限制（全局最大 3 层 + 按配置 max_spawn_depth） |

额外安全网：Payload hash 去重防止委派循环、结果缓存避免冗余工作、3 种记忆隔离策略（EPHEMERAL / READ_ONLY_GLOBAL / COLLABORATIVE_SESSION）防止跨代理数据污染。

## 多代理文件保护：8 层纵深防护

当多个代理在同一工作空间并行工作时，文件冲突是数据损坏的首要原因。MyRM 实施 8 层防护 — 全部代码强制，零 Prompt 依赖：

| 层级 | 机制 | 防护目标 |
|------|------|---------|
| **L1** | **先读后写**（staleness_guard） | 阻止盲改 — 必须先读取文件才能写入 |
| **L2** | **版本匹配**（file_integrity_guard） | 阻止过期编辑 — 文件内容变更后拒绝基于旧版本的写入 |
| **L3** | **完整读取前置**（file_integrity_guard） | 阻止部分读取 — 仅读取文件片段不允许编辑 |
| **L4** | **行级冲突检测**（file_conflict_guard） | 阻止重叠编辑 — 两个代理修改同一行范围时拦截 |
| **L5** | **跨代理活动追踪**（file_activity_tracker） | 追踪并发访问 — 记录每个代理在每个文件的写入行范围 |
| **L6** | **自动工作空间隔离**（workspace_policy） | 防止共享状态污染 — 并行写入时自动升级为 ISOLATED_COPY 策略 |
| **L7** | **延迟串行合并**（batch_merge） | 防止合并冲突 — 隔离的工作空间逐个串行合并回主空间 |
| **L8** | **完成自动清理**（subagent_manager） | 清除过期追踪 — 子代理完成后自动清理所有追踪记录 |

**实际运行流程：**

1. 父代理将 3 个编码任务委派给并行子代理
2. `workspace_policy` 检测到 ≥2 个并行写入者 → 自动升级为 ISOLATED_COPY
3. 每个子代理获得独立的 COW（写时复制）工作空间克隆
4. 子代理独立工作 — 无锁竞争、无阻塞
5. 完成后 `batch_merge` 将变更逐个串行合并回父工作空间
6. 若两个子代理编辑了重叠行范围，`file_conflict_guard` 在合并时抛出冲突

**对比竞品：** AWS Codex Agent Team 依赖 Prompt 指示（"不能让两个活跃任务写同一文件"）— LLM 可以无视此约束。MyRM 在应用代码层面强制每一层防护 — 无论模型行为如何，均不可绕过。

## vs CaMeL Guard

CaMeL 单信任边界；Myrm **6 层**洋葱防御、5 域循环检测、3 层错误分类、4 策略凭证池、PTC 沙箱隔离、20+ 模块上下文流水线等更深覆盖。

### 运行面彻底离场与可逆副作用清退 (Runtime Capability Eviction & Side-Effect Purge)

针对插件/能力卸载后容易在系统中残留暗线与幽灵资源的问题，Myrm 构建了完整的**四维彻底清退流水线与采购合规自检体系**：
*   **D1 接口与代理全面解绑**：Teardown 终止 MCP 进程并自动从所有绑定的 Agent 移除工具引用。
*   **D2 Tool Registry 内存即时注销**：基于读写锁（`_PTC_LOCK`）实现 \(O(1)\) 粒度的线程安全工具元数据与扁平索引注销，彻底杜绝内存中幽灵工具（Ghost Tools）误匹配。
*   **D3 关联后台定时任务双轨级联清退**：插件专属的定时任务自动物理销毁；引用了插件工具的用户业务任务自动切换为 `PAUSED` 暂停保护状态并发出警告，杜绝孤儿 Cron 轮询空跑。
*   **D4 物理文件与隔离目录彻底清除**：安全清理插件数据与存储目录，并记录合规审计日志。
*   **政企采购合规六问自检（ComplianceAuditEngine）**：内置 Q1 路由、Q2 注册表、Q3 定时任务、Q4 文件系统、Q5 进程、Q6 凭据全维度自检引擎，无缝集成至 `Doctor` 全局诊断。

### 后台任务隐式凭证拦截 (Anti-Leak Background Tasks)

在 Myrm Agent 中，安全防护不仅限于主对话流程，还深入到每一个后台辅助任务（如自动生成会话标题、自动总结）。

*   **O(1) 早期截断**：彻底消除超大文本在异步事件循环中执行正则和香农熵计算导致的 CPU Blocking DoS 隐患。
*   **军工级脱敏管线**：内置凭证探测器（Shannon Entropy + 正则），在发送给廉价模型生成标题前，自动抹除 API Key 等敏感凭证。
*   **深度结构降噪与隔离**：自动剥离代码块、URL 链接、HTML 标签等噪音，并使用 `<user_input>` XML 标签严格隔离用户输入，防止 Prompt 注入攻击。

## 技能下载全流程隔离与蓝绿原子安装

为防范第三方技能供应链攻击与意外中断导致的环境污染，Myrm 在执行引擎框架层（Harness）部署了完整的**隔离沙箱与原子替换体系**：

1. **临时隔离区先验落地（Quarantine Directory）**：远程技能文件（Git 仓库 / ZIP 压缩包）下载时，先落入独立的临时隔离沙箱目录，杜绝在生产工作空间中边下载边写盘。
2. **路径逃逸强阻断（Path Traversal Containment）**：对包内所有相对路径执行规范化解析与边界校验，任何试图包含 `../` 逃出技能安装目录的恶意文件全部被实时拦截并丢弃，免疫 Zip Slip 攻击。
3. **安全扫描前置门禁**：在隔离目录内完成正则规则、AST 语法树分析与 LLM 语义检测，只有安全推荐通过时才允许进入安装流程，拦截立即彻底清理隔离目录。
4. **双向蓝绿原子替换与失败回滚（Atomic Replace with `.bak` rollback）**：安装升级时将旧版本安全备份为 `.bak` 目录，执行毫秒级原子重命名移动。若遇到磁盘 IO 或权限异常，自动无损恢复旧版本，确保技能目录永远处于可用一致状态。
5. **多源聚合搜索容错隔离**：在聚合搜索官方源、国内镜像及第三方 Registry 时，各个源独立受限超时与异常隔离，单个源故障不会拖垮整体搜索体验。

## 防数据污染与 Canary 金丝雀审计防护门禁

为了确保评测基准的绝对真实性与防止题库泄漏被外部爬虫污染：

1. **动态 Canary Token 与全局 GUID 双轨防护**：自动识别并注入评测基准的金丝雀水印（全局 `CANARY_GUID` 与基准专属的 `canary_token`）。
2. **运行期外网检索实时脱敏**：在 Agent 发起联网搜索/抓取时，毫秒级拦截并抹除查询中的 Canary 水印，防止基准提示词泄露至公网搜索引擎或下一代预训练语料库中。
3. **Pre-Run 工作区物理纯净度检查**：评测轮次开始前，递归扫描 Agent 工作空间，确保标准答案补丁与判分脚本物理隔离在工作区之外。
4. **轨迹反作弊与机密探测防御**：在沙箱执行期全程审计 Agent 工具调用轨迹，精准识别探测隐藏评分文件（`/hidden_tests/`、`verifier.toml`）或窃取环境变量/密钥（`printenv`、`export`、`/proc/*/environ`）的投机行为，一经发现即时判负并记录结构化违规证据。
5. **端到端 WebUI 违规穿透卡片**：直接在前端评测详情中呈现 Canary 保护徽标与结构化违规诊断卡片，打通全流程透明度。

## 渠道与操作人记忆作用域安全门禁 (防投毒与防越权召回)

当企业微信、飞书、Telegram、Slack 等外部多用户渠道接入 Agent 时：

1. **写平面防投毒门禁 (`allow_shared_write=False`)**：在工具层底层物理拦截，外部群聊中大模型尝试写入全局共享记忆（`shared`）时，自动防御性降级为当前会话私有（`bound`），杜绝群聊恶意参与者投毒企业全局向量知识库。
2. **读平面防越权召回隔离 (`default_scope="same_source"`)**：服务端历史召回适配器强制锁定检索来源必须为同渠道同会话，彻底防御 Prompt 越狱攻击诱导大模型跨渠道召回 WebUI 私有会话中的凭据与敏感记录。
3. **零 Prompt Token 损耗与 100% 缓存保留**：门禁逻辑由后端运行时与适配器纯内存执行，Tool Description 保持 100% 静态不变，系统提示词缓存命中率毫无损耗。

## 控制台全表面错误展示安全脱敏 (Control UI Surface Error Redaction)

为了彻底根治开发者在投屏演示、截图求助或控制台报错回显时的敏感凭证外泄：

1. **UI 弹窗与 API 异常双级过滤**：前端 `errorRedactor.ts` 在所有 `toast.error`、`toast.warning` 以及 API Client 报错管线中前置挂载高熵过滤器，自动掩码 API Key、Bearer/JWT 认证头、数据库连接串密码。
2. **本地文件系统路径归一化**：自动将报错堆栈或提示中的敏感本地开发路径（如 `/Users/username/...` 或 `/home/username/...`）统一替换为 `~/...`，避免泄露内部系统目录名与私有用户名称。
3. **服务端序列化兜底防线**：FastAPI 全局异常处理 `errors.py` 在向客户端分发 JSON 错误体前执行强约束清洗，杜绝原始报错携带凭据外溢。

## 已批准脚本变更防护 (Approved Scripts TOCTOU Drift Guard)

为防御 Time-of-Check to Time-of-Use（TOCTOU，CVE-2026-32921 级）替身攻击：

1. **评估阶段快照锁定**：在用户审批包含外部可变脚本的 Shell 或代码解释器调用（如 `python script.py`）时，Harness 在评估阶段自动解析并计算该操作数文件的 SHA-256 内容哈希快照。
2. **执行边界实时重验**：在审批通过最终下发执行（`apply_approval_decisions`）时，实时重新计算文件当前 SHA-256。若脚本在用户查看审批弹窗期间被外部恶意进程篡改、覆盖或软链接替换，立即触发 `SCRIPT_OPERAND_DRIFT_REJECT` 并物理阻断执行。
3. **禁止永久放行（Hide Allow Always）**：涉及外部动态脚本操作数的高风险命令自动禁用「永久允许」权限，从根源堵死恶意借道既有白名单命令执行未授权代码的漏洞。

## 子进程敏感凭证隔离门禁 (Child Process Credential Token Isolation)

为杜绝第三方库与用户脚本窥探宿主进程环境变量（超越 OpenAI Codex #38941 局部修补）：

1. **三档继承策略体系（SSOT）**：
   - `CORE`：严格 POSIX / Runtime 白名单模式（仅保留 `PATH`、`HOME`、`USER`、开发工具链及 `GIT_AUTHOR_*` 身份，阻断一切潜在恶意或敏感变量）；
   - `ALL`：全量继承 + 57 项动态链接器/代理劫持黑名单 + 8 维词根通配符深度净化；
   - `NONE`：绝对零变量物理绝缘模式；
2. **执行全生命周期 100% 覆盖**：覆盖持久 Shell 会话、Python 子进程、后台守护进程、浏览器沙箱与 CUA 驱动，消除任何脚本偷窥宿主环境凭证的供应链攻击隐患；
3. **零误杀与开发者工具链无损兼容**：精确区分秘密变量（`AUTH_TOKEN`、`API_KEY`）与开发者提交身份（`GIT_AUTHOR_NAME`、`GIT_COMMITTER_EMAIL`），在筑起最高安全屏障的同时保障本地 Git 提交丝滑顺畅。

## 前端 Mermaid 图表 SVG 工业级安全净化 (Mermaid Preview Strict Sanitization)

为防御大模型生成或外部导入的 Mermaid 图表中的 Stored XSS 向量：

1. **配置收敛（Strict Security Level）**：将 Mermaid 渲染引擎全面约束为 `securityLevel: 'strict'` 与 `htmlLabels: false`，彻底封死底层内部 HTML 解析器的脚本执行通道；
2. **DOMParser 递归属性白名单二次净化**：在渲染生成原始 SVG 后，统一经由 `sanitizeMermaidSvg` 纯函数过滤，递归剔除 `<script>`、`<foreignObject>`、`<iframe>`、`<object>` 等危险标签；
3. **内联事件与链接伪协议彻底中立化**：剥离任何大小写混淆的 `on*` 事件属性（如 `oNload`），剥离 `href` 与 `xlink:href` 伪协议，确保工件与 Markdown 图表在普通预览与全屏弹窗下 100% 免疫 XSS 攻击。

## 插件打包完整性与静态构建产物前置校验门禁 (Plugin Packaging Integrity Guard)

为彻底消灭第三方插件因遗忘构建产物导致 Agent 运行时抛出 `ENOENT` 崩溃的问题：

1. **解压摄取第一时间静态校验**：在插件 ZIP 解压阶段，第一时间静态比对 stdio MCP 服务声明的入口脚本与构建产物（如 `dist/index.js`、`server.py`、`./bin/run`）是否物理存在于包内。
2. **组件级精准局部熔断**：坏 MCP 服务自动标记并跳过，好 Skills 与 Agents 正常入库，彻底避免单个未构建组件导致整包导入失败或运行时全盘崩溃。
3. **全解释器参数自适应剥离**：智能跳过 `-u`、`--loader` 等标志参数，统一归一化 Windows 反斜杠与 `${PLUGIN_ROOT}` 宏，精准识别裸相对路径。
4. **WebUI 工业级防呆与防误触**：展示醒目红色警告徽章并附带 `npm run build` 指引，默认跳过并禁用单项启用，批量全选自动规避损坏服务。

## 零密钥外泄与子进程环境脱敏防线 (Zero-Key Subprocess Sanitization vs MITM Proxy)

为杜绝类似竞品 OpenClaw 方案引入自签名 MITM 代理对 TLS 生态的破坏与性能雪崩：

1. **源头物理脱敏基线（Fail-Closed SSOT）**：Myrm 在子进程环境构建阶段通过 `env_isolation.py` 与 `executor.py` 强制剔除包含 `KEY`、`TOKEN`、`SECRET`、`AUTH_` 等全部敏感变量，第三方脚本无论如何 `printenv` 都无法探测到真实明文。
2. **受控底座内存内联调用**：Agent 核心大模型推理直接在受控进程内存中与官方网关建立加密 TLS 连接，0 证书报错（免除 `CERTIFICATE_VERIFY_FAILED` 生产事故），0 代理损耗。
3. **专属容器沙箱隔离（Agent-in-Sandbox）**：结合独立 Volume，从操作系统和网络物理层面提供极致防护，实现 0 配置负担下的企业级凭据安全。

## 多轮对抗越狱与真实执行防御底座 (Deterministic Execution-Defense vs Red-Teaming)

针对大模型容易受 PAIR 或 Many-Shot 等对抗提示词诱导越狱的行业挑战：

1. **去特权化物理信封机制（Untrusted Data Envelope）**：将网页抓取与外部不可信文本强制包裹在专用隔离信封内，系统提示词协议层剥离一切指令特权，杜绝间接提示词注入。
2. **非旁路 Layer 1~5 洋葱硬门禁**：不依赖脆弱且易被绕过的外挂打分小模型，而是在系统调用入口强制执行五层物理非旁路硬拦截（Fail-Closed & Deny-First），任何越狱模型下发的破坏性系统命令、敏感目录越界或凭证探测在内核交互前即被物理诛杀。
3. **全因果审计链溯源**：每一笔工具调用与阻断决策均记录不可篡改的流水与审计签名，原生满足企业级合规与审计需要。
